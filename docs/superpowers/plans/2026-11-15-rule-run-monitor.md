# 규칙 가동의 관제 — 구현 계획 (W5c · 2026-11-15)

> 설계 [모의투자·관제](../specs/2026-11-14-paper-trading-monitor-design.md) §6 · 받은 결정 §12(D6 W5a → W5b → W5c). 앞 조각: [규칙 가동(기록 전용)](2026-11-14-rule-arming-shadow.md).
> 방식: 조각마다 빨강 먼저 → 짝 · 변이 → 게이트 → HISTORY → 커밋 · 푸시. 하위 에이전트 없음.
> ★관제는 읽기만 한다★ — 주문 경로 · 가동기의 뜻 · 저장소의 줄은 0줄 바뀐다. 가동 · 정지 · 비상 정지는 이미 있는 문이 한다.

## 0. 구현 전에 조사로 정한 것 (설계와 달라지는 점 포함)

1. **자리**: 설계는 절 이름을 '오늘의 가동'이라 했다. 지금 있는 가동은 재생(지난 하루를 다시 흘리기)뿐이라 '오늘'이 아니다 →
   새 절을 만들지 않고 ★'규칙 가동' 절의 가동 줄 안에 관제 판★을 편다(ADR 006 §7 — 기존 모듈 안에). 장중 공급(W5d)이 생기면 같은 판이 오늘의 가동을 보인다.
2. **설정은 가동 줄의 사본에서 읽는다.** 가동 기록은 그때 돌린 설정(`request`)을 품고 있다 — 시행 줄이 사라지거나 달라져도 관제는 ★그때 돌린 것★으로 계산한다.
   사본을 지금의 규칙 틀로 읽지 못하면 손익 · 한도 · 백테스트 견줌은 값 없음 + 사유다.
3. **주문 수의 근거는 주문 기록이다.** 가상 체결 줄에는 그 신호가 받은 답의 상태와 사유 코드만 있다 — 거절의 ★문장★(위험 검사가 무엇을 말했는지)은 주문 기록(`live_orders`)에만 있다.
   관제는 계좌 실행기의 `list_orders(strategy_id=가동 번호)` 로 읽어 주문 번호(`client_order_id`)로 가상 체결 줄과 잇는다. 같은 번호를 쓰는 다른 출처의 줄은 번호가 맞지 않아 섞이지 않는다
   (거절 줄에는 `signal_source` 가 없어 그것으로는 가를 수 없다 — 관측).
   - 신호는 있는데 주문 기록에 줄이 없으면 ★그 수를 센다★(`unrecorded` — 주문 기록의 INSERT 는 실패해도 조용하다. 관제가 드러낸다).
   - 주문 기록을 못 읽으면 가동 기록에 적힌 답으로 열화하고 ★그렇게 적는다★(`basis: "run_record"` + 사유 · 거절 문장은 없음).
4. **실현손익은 매매일지 엔진이다.** `analyze(가상 체결, 그 설정의 비용 가정, master)` — 분봉 백테스트(`intraday.run`)와 같은 부름이다.
   가상 체결 줄에는 시장 · 상품 칸이 없다. 분봉 준비(`minute_feed`)는 그 칸을 매매일지와 ★같은 함수★(`market_and_instrument`)로 종목 마스터에서 정하므로, 같은 마스터를 넘기면 같은 답이 된다(저장소 칸을 늘리지 않는다).
   - ★거절된 신호의 가상 체결도 손익에 든다★: 가상 체결은 "시뮬레이터가 계산한 체결"이고 걸음 엔진은 주문 경로의 답을 모른다. 거절이 없었다고 지어내지도, 거절 뒤의 세계를 새로 지어내지도 않는다 —
     거절된 신호 수와 "실제 주문이었다면 이 체결은 없었습니다"를 함께 적는다.
   - 미청산 수량은 평가하지 않는다(매매일지의 규칙 그대로) — 수만 적는다.
5. **일 손실 한도까지 남은 폭**: 시뮬레이터의 판정과 같은 값으로 잰다 — ★비용 전★ 실현손익(청산 완료 + 일부 청산)의 그날 누계. `남은 폭 = 한도 + 누계`.
   한도는 ★한 번 닿으면 그날 새 진입이 없다★(뒤의 청산으로 누계가 회복돼도) → 누계가 한 번이라도 한도에 닿았는지(`touched`)를 매도 순서대로 따로 잰다(매매일지의 왕복 매칭을 그대로 쓴다 — 포지션 계산을 새로 쓰지 않는다).
   설정에 한도가 없으면 값 없음 + 사유.
6. **"그날의 백테스트와 같다"는 관측으로 말한다.** 끝까지 돈 가동이면 지금 적재된 봉으로 그날을 한 번 다시 계산해(`simulate`) 가상 체결과 줄 단위로 견준다 → 같음 / 다름(줄 수) / 미상(그날의 봉을 지금 읽지 못함) /
   견주지 않음(끝까지 돌지 않은 가동). 구조상 같아야 한다는 것(걸음 엔진의 성질 시험)을 화면이 되풀이하지 않는다 — 다르면 봉이 가동 뒤에 바뀌었거나 결함이다.
7. **봉의 지연**: 재생에는 벽시계가 없다 → `lag_seconds: None` + 사유. 장중 공급이 생길 때 잰다.
8. **갱신**: 관제 판을 편 가동이 ★도는 동안만★ 주기 조회(5초). 끝난 가동은 다시 묻지 않는다. 실시간 푸시는 만들지 않는다(설계 그대로).
9. **하루가 끝난 뒤의 매매일지**: 끝난 가동(끝까지 · 정지 · 중단)에만 일지 전체를 싣는다 — 화면은 매매일지 결과와 같은 부품으로 그린다. 도는 가동은 요약만(주기 조회의 본문을 작게).

## 2. c1 — 서버

`GET /api/v1/broker-accounts/{account_id}/rule-runs/{run_id}/monitor` — 로그인 · 본인 계좌만(의존성) · 답 = 가동의 문과 같은 머리(`mode · kill_switch · limits · gate`) + `run`(가상 체결 포함) + `monitor`.

```python
# src/execution/rule_monitor.py — 읽기만. src.api 를 들여오지 않는다(봉을 짓는 일은 문 층이 넘긴다).
def view(username, account_id, run_id, *, master=None, day_of=None) -> dict:
    """가동 하나의 관제. `day_of(tickers, rule, day) -> (Day, session) | None` — 그날의 봉(백테스트와 같은 준비)."""
```

`monitor` 의 모양:

| 칸 | 내용 |
|---|---|
| `orders` | `basis`(`order_log` · `run_record`) · `reason` · `signals` · `by_status`(상태 → 수) · `rejected`(순번 · 시각 · 종목 · 방향 · 수량 · 사유 코드 · 문장) · `unrecorded`(주문 기록에 없는 신호 — 모르면 `None`) |
| `fills` | `virtual` · `broker`(주문 기록에서 체결 수량이 있는 줄 — 모르면 `None` + 사유) |
| `pnl` | `available` · `reason` · `gross` · `cost` · `net`(비용을 모르면 `None`) · `net_reason` · `closed_trades` · `open_positions` · `includes_rejected` · `basis`(일지의 근거 블록) |
| `loss_limit` | `limit` · `reason` · `realized_gross` · `room` · `touched` |
| `kill` | `active` · `own`(이 계좌가 건 정지인지) |
| `feed` | `kind` · `lag_seconds`(`None`) · `lag_reason` |
| `backtest` | `state`(`same` · `differs` · `unknown` · `not_compared`) · `reason` · `run_fills` · `backtest_fills` |
| `journal` | 끝난 가동이고 체결이 있으면 매매일지 전체(`not_covered` 는 분봉의 것) · 아니면 `None` |

시험(빨강 먼저 — `tests/test_rule_run_monitor.py`):
- 문: 등록 · 로그인 전 401 · 남의 계좌 404 · 다른 내 계좌의 가동 번호 404.
- 손 계산: 끝까지 돈 가동 — 비용 전 (10,100 − 10,080) × 99 = 1,980원 · 비용 뒤 = 분봉 백테스트의 문이 낸 값 · 주문 `기록 전용` 2 · 증권사 체결 0 · 백테스트와 같음.
- 도는 가동: 청산 0건 · 미청산 1 · 일지 없음 · 견주지 않음.
- 거절: 위험 검사가 거절한 신호 — 상태별 수 · 문장(주문 기록의 것) · 손익에 든 거절 수.
- 주문 기록: 줄이 사라지면 `unrecorded` ↔ 평소 0 · 못 읽으면 `run_record` 로 열화 + 사유.
- 한도: 없으면 사유 · 닿음 ↔ 안 닿음(짝) · 닿았다가 회복(순수 함수) · ★시뮬레이터의 진입 차단과 같은 판정★(엔진 시험).
- 백테스트: 봉이 달라지면 `differs` · 그날이 적재돼 있지 않으면 `unknown` · 정지한 가동은 `not_compared`.
- ★쓰기 0★: 관제를 두 번 읽어도 모든 표의 줄 수가 같다 · 주문 경로를 부르지 않는다.
- 사본을 못 읽으면 손익 · 한도 · 견줌은 값 없음 + 사유(가동 줄과 주문은 그대로 보인다) · 저장소를 못 읽으면 503.

## 3. c2 — 화면

- 가동 줄에 단추 **'관제'**(펴고 접는다) → 판: 맨 위 한 줄 요약(상태 · 신호 · 주문) → 주문(상태별 · 거절은 서버 문장) → 체결(가상 · 증권사) → 실현손익(비용 전 · 비용 · 비용 뒤 · 미청산) →
  일 손실 한도(한도 · 누계 · 남은 폭 — 막대 하나 · 닿았으면 그렇게) → 비상 정지 → 백테스트 견줌 문장 → (끝난 가동) 매매일지 결과 부품.
- 도는 가동이면 5초마다 다시 읽는다 — 판을 접으면 멈춘다.
- 합성 분봉의 가동이면 판 맨 위에 적는다. 값이 없으면 0 이 아니라 사유(서버 문장은 `data-server`).
- 새 클래스만(`ma-mon-*`). 문구는 개조식 + 합니다체 · 용어집.

## 4. 하지 않는 것

모의투자(PAPER) 가동과 증권사 체결 받아 적기(W5d) · 장중 공급과 봉 지연 재기 · 실시간 푸시 · 계좌 단위의 합계(가동마다만) · 미청산의 평가손익 · 정지한 가동의 앞부분 견줌 ·
주문 경로(`execute_signal` · 위험 검사 · 비상 정지)의 뜻 · 가동기의 멈춤 조건 · 저장소의 칸.

## 5. 구현하며 달라진 것 (2026-11-15)

| # | 계획 | 구현 | 까닭 |
|---|---|---|---|
| 1 | 실현손익 = 일지의 청산 완료 합계 | ★청산 완료 + 일부 청산한 몫★(그날 실현한 전부) · 칸 `net_reason` 추가 | 한도가 보는 누계와 같은 값이어야 한 판의 두 숫자가 어긋나지 않는다. 비용을 모르는 거래가 하나라도 있으면 비용 뒤는 값 없음 + 사유(아는 거래만의 합을 전체처럼 적지 않는다) |
| 2 | (정하지 않음) 시험의 종목 마스터 | 손 계산 시험에 '마스터가 이 종목을 안다' 고정물 · 시험 환경의 기본 마스터(시장 모름)는 '비용을 모르면' 시험이 본다 | 손으로 만든 봉은 시장 칸을 직접 적고 시험 환경의 마스터는 시장을 모른다 — 제품의 준비(`minute_feed`)는 그 칸을 ★같은 마스터★에서 정하므로 제품 경로에서는 둘이 같다 |
| 3 | `touched` ⇔ 시뮬레이터가 진입을 막았다 | `touched` = 매도 순서대로의 누계가 한 번이라도 한도에 닿았다(시뮬레이터의 멈춤과 같은 값) · ★막힌 진입 ⇒ 닿음★(역은 아니다) | 내 시험의 주장이 틀렸다 — 닿은 뒤에 신호가 없으면 막힌 진입도 없다(하루 끝의 청산으로 닿는 날) |
| 4 | (없음) 주문 기록의 조회 상한 | `ORDER_SCAN`(1,000줄)에 닿으면 '기록에 없는 신호' · '증권사 체결'을 세지 않고 모른다고 적는다 | 같은 번호를 쓰는 다른 출처의 줄이 많으면 이 가동의 줄이 잘릴 수 있다 — 잘린 것을 '없다'로 세지 않는다 |
| 5 | 소유는 가동기가 본다 | 문의 소유 확인(의존성)이 ★먼저★ — 시험이 건다 | 문은 가동기를 부르기 전에 계좌의 상태(모드 · 비상 정지)를 읽는다. 의존성이 없으면 남의 계좌의 실행기가 뜬다(답은 404 로 같아 보인다 — 변이가 살아남아 찾았다) |
| 6 | 매매일지 부품 그대로 | 공용 `Section` 과 일지 부품 셋(요약 · 거래 목록 · 값의 근거)에 제목 단계(`level` · 기본 2) | 절 안의 절이다 — 판 안에서 h2 가 h3 아래에 오지 않게 한다. 기본값은 지금 화면 그대로(클래스 불변) |
| 7 | 새 클래스만 | + 판 안의 보조 단추 · 무채색 표식에 표면색과 선 | 판의 배경이 그것들의 배경과 같은 색이라 경계가 사라졌다(스크린샷으로 찾음) |

**남던 한계 → 고침(2026-11-15 · 꼬리 묶음)**: 가상 체결 줄에 시장 · 상품 칸이 없어 관제의 매도세를 ★읽는 때★의 종목 마스터로 정했다 — 가동 뒤에 마스터가 달라지면
지난 가동의 비용 뒤 손익이 움직였다. 시뮬레이터의 체결 줄은 그 두 값을 이미 갖고 있었다(준비가 마스터에서 정한 값). 이제 줄에 `market` · `instrument` 와 '그때의 값'이라는 표시
(`classified`)를 함께 적고, 관제는 그 값을 쓴다(그때 몰랐으면 지금의 마스터가 채우지 않는다 — ★미상 ≠ 미기록★). 칸이 생기기 전에 적힌 줄은 전처럼 읽는 때의 마스터로 정하되
`pnl.classification` 과 화면이 그렇게 적는다. 옛 줄을 소급해 채우지는 않는다(그때의 값을 모른다).
