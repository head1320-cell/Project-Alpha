# UI/UX 전문화 ② — U1 공용 표 + 스크리너: 구현 계획 (2026-11-21)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> (이 저장소의 받은 결정: 하위 에이전트는 쓰지 않는다 — 같은 세션에서 조각 순서대로 실행한다.)

**Goal:** 스크리너의 결과 표를 공용 표(`shared/ui/table`)로 옮기고 작업 단 · 촘촘 밀도로 그려, 스크롤 없이 견줄 수 있는 줄을 늘린다. ★요청 · 조건식 · 서버는 0줄★.

**Architecture:** 표의 논리(정렬 · 쪽 · 줄 초점 · 내보내기)를 순수 모듈로 꺼내고, 낱 `<table>` 을 그리는 부품 하나가 밀도 토큰만 읽는다. 스크리너는 경로 표에 올라 `html` 의 속성 둘을 받고, 제 범위(`.scr …`)의 규칙만 토큰으로 옮긴다. 옛 클래스 이름은 같은 요소에 갈고리로 남긴다(E2E 계약).

**Tech Stack:** Next.js(app router) · 순수 CSS(`globals.css`) · Playwright(E2E · 순수 스펙) · pytest(소스 훑기 가드). 새 의존성 0.

## 5. 검증

- 조각마다: 새 스펙의 빨강을 먼저 본다 → 초록 → `/screener` 를 지나는 스펙 + 자판 · 초점에 기대는 스펙(`skip-link` · `canvas-select` · `focus-ring` · `kit-names`) → 변이(가드마다 — 예: 합성 칩을 촘촘에서 숨김 · `aria-sort` 를 한 머리에만 · 값 없음을 0 으로 · 값 없는 줄을 앞으로 · 요청 본문 한 글자) → 푸시 → CI 두 실행.
- 불변: 요청 골든 바이트 그대로 · 특성 스펙(U1-0)은 의도한 변화 둘(값 없는 줄의 자리 · CSV 열)만 빨강을 본 뒤 고친다 · 다른 경로의 라이트 골든 변화 0.
- 끝: 전체 E2E · 전후 표(다 보이는 줄 · 표 머리 y · 조작 지연 · 첫 화면 JS) · 스크린샷 검수.

## 6. 주장의 범위

구조(`structural`)까지다 — 줄 수 · 이름 · 자판 길 · 요청 불변. 화면이 읽기 쉬워졌다 · 일이 빨라졌다는 재지 않는다(ADR 007 §11 — 가설이다). 실제 낭독기 · 실제 트레이더로는 미검증이고, 값은 mock 서버의 합성 값이다. 투자 타당성과는 무관하다.
