## 1. M1 — 군집 팔의 씨앗 안정성 + k-평균 넷째 팔

### 1.1 계약

- `regime_ensemble.SEEDS = 10`(설정값 — 재 본 값이 아니다). GMM 팔은 씨앗 `0 … SEEDS−1` 로 적합(설정은 지금 그대로: 성분 수 규칙 · `covariance_type="full"` · `n_init=3`).
  - `probs` = 씨앗마다 마지막 점의 소속 확률을 성분 중심의 사분면으로 모은 것의 **평균**(합 1) · `argmax` = 그 평균의 최빈 국면.
  - `stability = {seeds, modal, agree, shares, stable}` — 씨앗마다의 최빈 국면을 센 것. `modal` 은 가장 많이 나온 국면(동률이면 `REGIMES` 순서의 앞), `agree` 는 그 수, `shares` 는 국면별 비율(합 1), `stable` 은 `agree × 2 > seeds`.
  - `detail` 은 성분 수 · 관측 수 · **씨앗 0 의** 성분 중심(그렇게 이름 붙인다) · 모든 씨앗이 수렴했는지.
- 새 팔 `kmeans`(`_kmeans_probs`): `sklearn.cluster.KMeans(n_clusters=같은 규칙, n_init=10, random_state=s)` 를 씨앗마다 → 마지막 점이 속한 중심의 사분면.
  - `probs` = 씨앗 비율(합 1) · `probs_kind = "seed_share"`(GMM 팔은 `"probability"`) · `argmax` = 최빈 · `stability` 는 같은 모양 · `note` 가 "확률이 아니라 씨앗 비율"이라고 말한다.
  - 표본 부족 · scikit-learn 없음 · 결측 · 적합 실패 → `available: False` + 사유(GMM 팔과 같은 규칙).
- `regime_ensemble` 은 도구 넷을 나란히 낸다(합치지 않는다 — 지금 규칙 그대로). 문장: 합의 "모든 방법이 같은 국면을 가리킵니다" · 맺음 "방법마다의 판정을 평균하지 않습니다 …".
- 소비자: 합의 보기(`regime_consensus_view` — 고칠 것 없음 · 넷이 들어간다) · 캔버스 노드 설명과 해설(`allocation_graph_nodes_bl2` — 이름표에 k-평균 · '세 방법' 문장) ·
  추정기 등록부(`estimator_evidence.EXCLUDED_SITES` 에 `_kmeans_probs` — 사유: 진단 전용) · 화면 형(`entities/macro/api.ts`) · 캔버스 결과 판(`Bl2Results.EnsembleResult` — 이름표 · 씨앗 비율의 주석 · 안정성 한 줄).

### 1.4 구현에서 달라진 것 · 더한 것 (2026-11-16 · 끝난 뒤 적음)

- **더함 ① 합의의 독립성 문장**: GMM 과 k-평균은 같은 (성장, 물가) 좌표를 묶어 서로 독립이 아니다. 넷째 팔을 더하면 "4개 중 3개" 같은 다수가 군집 두 팔에 기울 수 있어,
  둘이 **함께 답했을 때만** `regime_consensus_view` 가 `note` 에 `CLUSTER_DEPENDENCE_NOTE` 를 붙인다(합의 규칙 · 키 모양은 그대로). 짝: 하나가 답하지 못하면 붙이지 않는다.
- **더함 ② 스레드 하나로**: 시드 10개 반복이 기본 스레드에서 느렸다(60개월 앙상블 0.16 → 0.70초). 원인은 반복 횟수가 아니라 작은 2차원 자료에서의 BLAS · OpenMP 스레드 부담이었다
  (한 번 적합 약 55ms → 1스레드 약 20ms) → `threadpoolctl.threadpool_limits(1)` 로 묶어 0.35초. 기계마다 합산 순서가 같아지는 덤이 있고, 제한이 프로세스 전체에 걸린다는 사실은 주석에 적었다.
- **이름표**: 군집 두 팔을 가른다 — 캔버스 `군집(GMM)` · `군집(k-평균)`, 서버 해설 `군집 모형(GMM)` · `군집 모형(k-평균)`, 매크로 화면 `군집(GMM)` · `군집(k-평균)`(키 `kmeans` 는 곁에 남는다).
- **화면 낱말**: 문서의 '씨앗'은 화면에서 용어집 §3.8 의 `난수 시드`로 쓴다.
- **`detail.centers` → `centers_seed0`**: 어느 시드의 중심인지 이름에 적는다(소비자 없음을 확인함 — 프론트 · 서버 모두).
- **안정성의 뜻(설계 그대로)**: `stable` 은 시드별 **최다 답**이 엄격한 과반인지다. GMM 팔의 답(평균 확률의 최댓값)과 최다 답은 다를 수 있다 — 화면 줄은 최다 답의 국면 이름을 함께 적어 굵은 칸과 헷갈리지 않게 했고, 서버 해설은 갈리면 '미상' 줄을 단다.
- **더함 ③ 흔들리는 팔 위의 만장일치**(스크린샷 검수에서 찾음 — 개발 자료 us 60개월: 네 방법 모두 Stagflation · GMM 최다 답 3/10): `unanimous` 는 그대로 참이고(답이 같다는 사실),
  앙상블 문장 · 캔버스 해설 제목에 "다만 난수 시드에 따라 답이 갈리는 방법이 있습니다"를 단다. 합의는 `seed_unstable`(늘 실림 · 키 목록)과 팔 이름을 적은 문장을 낸다(합의 규칙 그대로).
  화면의 띠는 '같다 + 과반 미만 팔 없음'일 때만 초록이다(캔버스 앙상블 · 합의 판) · 매크로 화면은 합의 블록에 "난수 시드에 따라 답이 갈리는 도구가 있습니다".
- **팔 이름표 한 곳**: 서버 문장의 팔 이름은 `regime_ensemble.TOOL_NAMES` 하나(캔버스 두 노드의 해설이 같은 표를 쓴다).
- **머리 칸**(스크린샷 검수에서 찾음): 열이 다섯이 되자 '상태 전/환' · '군집(k-평/균)' 처럼 낱말 가운데에서 끊겼다 → 이름표를 띄어쓰기나 여는 괄호 앞에서 두 덩어리로 나눠 덩어리 안은 끊지 않는다(글자는 그대로 · E2E 계약 불변).
- **표 맞춤**(스크린샷 검수에서 찾음 — 1440px 미만 창): 열이 다섯이 되자 처음 폭(344px) 판에서 표가 판보다 25~34px 넓어 k-평균 열이 잘리고 숫자가 붙었다 →
  국면 이름도 두 덩어리(괄호 덩어리는 늘 둘째 줄) · 이름 칸 폭 고정 풂 · 숫자 칸 사이 · 좁은 판(감싼 칸 280px 이하)은 글자 12px(컨테이너 쿼리) · 마지막 수단 가로 밀기.
  E2E 가 판 폭 셋(344 · 392 · 300px)에서 '판 안에 든다 · 숫자가 붙지 않는다 · 행 높이가 같다'를 본다.

### 1.5 M1b — 앙상블 입력의 지어낸 0 걷기 (M2 감사에서 찾음 · 2026-11-16)

- **찾은 것**: 앙상블의 `_axis_history` 는 축 성분이 없는 달의 점수를 0 으로 채웠다(`compute_axis_detail` 의 빈 값). (0, 0) 은 사분면으로 Reflation 이라,
  계산되지 않은 달이 한 국면으로 찍혀 Markov · 군집 두 팔(M1 포함)의 적합에 들어갔다 — CLAUDE.md §4 '미상 ≠ 0' 위반.
  개발 자료에서는 두 축이 다 계산된 달이 최근 53개월뿐이라 60개월 요청에 7점, 120개월 요청에 67점이 지어낸 값이었다(잰 값).
- **고침**: 앙상블의 입력을 `regime_path` 의 점(두 축이 다 계산된 달만)으로 바꾼다 — 국면 예측 비교(M2)와 같은 입력. 응답에 `dropped_incomplete` ·
  뺀 달이 있으면 문장 "축이 둘 다 계산되지 않은 N개월은 빼고 셉니다(0 으로 채우지 않습니다)." · 빼고 나서 36개월이 안 되면 Markov · 군집 두 팔은 값 없음 + 사유(기존 규칙).
- **바뀌는 관측**: M1 의 'us 60개월 GMM 최다 답 3/10 · 시드에 따라 갈림'은 지어낸 점 탓이었다 — 고친 뒤 7/10(과반). 개발 자료에는 이제 과반 미만인 팔이 없어
  M1 캔버스 E2E 의 흔들림 갈래는 실행 응답을 심어 그린다(서버의 셈은 pytest 가 건다).
- **불변**: 축 팔(지금 달의 축 — 이 고침과 무관) · 합의 규칙 · 배분 경로 · 화면 부품.

  문턱을 올리는 것(예: 7/10)은 답이 아니다 — 흔든 원 30개에서 7 이상이 GMM 6개 · k-평균 9개였다(잰 것).

### 2.1 계약

- 새 순수 모듈 `src/engine/regime_skill.py` — `regime_skill(points, *, k=1, min_history=36, alpha=0.05, arms=…)`. `points` 는 `regime_path` 의 점(`growth` · `inflation` · `regime`, 과거 → 현재).
  `arms(g_hist, i_hist)` 는 군집 두 팔(`regime_ensemble._cluster_probs` · `_kmeans_probs` — 앙상블과 같은 함수 · 같은 입력)을 부르는 자리다 — 시험은 가짜를 넣어 시점마다 받은 자료의 길이를 센다. 문은 축 값의 튜플을 열쇠로 기억하는 판(`cached_arms`)을 넣는다.
  전이 사후평균 행렬은 `regime_forecast` 에 공개 도우미(`transition_posterior_mean` · `propagate`)로 빼고 `_posterior_forecast` 가 그것을 쓴다(동작 불변 — 기존 적중률 시험이 건다).
- 평가: t = `min_history` … n − k 마다 ★`points[:t]` 만으로★ 후보를 세워 `points[t + k − 1]` 의 국면을 예측한다(`forecast_coverage` 와 같은 칸 맞춤). 평가 점이 20(`MIN_EVAL_POINTS`)보다 적으면 값 없음 + 사유.
  `min_history` 는 36 — 군집 팔의 표본 하한(`MIN_OBS`)과 같게 해 ★모든 후보가 같은 시점에서 채점된다★.
- 후보 여섯(순서 고정 · 점수로 줄 세우지 않는다):
  ⓐ `persistence` 오늘 국면 유지(그 국면에 확률 1) ⓑ `base_rate` 기저율(그때까지의 빈도) ⓒ `transition` 전이 예측(`_posterior_forecast` — 지금 배분의 출처)
  ⓓ `gmm_start` GMM 시작 분포 × 전이 사후(π₀ · P̄^k — π₀ 는 시점 t 에서 적합한 GMM 의 시드 평균 소속 확률, P̄ 는 같은 경로의 전이 사후평균 — M3 의 출처) ⓔ `gmm_now` GMM 지금 값 그대로 ⓕ `kmeans_share` k-평균 시드 비율.
- 지표(후보마다): 적중(가장 높은 확률의 국면 = 실현 · 동률은 `REGIMES` 순서) · 브라이어 점수(Σ(p − o)² · 0 ~ 2)의 평균 · 유지 대비 브라이어 차의 평균(양이면 유지보다 낫다).
- 순차 증거(e-값): d_t = 브라이어(유지) − 브라이어(후보) 는 늘 [−2, 2] 안이라 G1 의 `evalue.log_path(d, cap=2)` 가 ★상한 가정 없이 정확하다★. 기준 = 비교한 후보 수(다섯) / α.
  ★k = 1 에서만★ 계산한다 — k > 1 이면 앞 예측이 실현되기 전에 다음 예측이 나와 평가 결과가 겹치고 순차 검정의 전제가 서지 않는다 → 값 없음 + 사유.
  (G1 의 `evidence()` 문장은 '하루 손익 · 손실 상한'의 말이라 그대로 쓰지 않고, 이 모듈이 자기 문장으로 낸다.)
- 한 시점이라도 세우지 못한 후보는 ★값 없음 + 사유★(처음 실패한 시점과 까닭) — 다른 표본으로 채점한 점수는 나란히 놓을 수 없다.
- 응답에 '가장 나은 후보' 같은 키를 두지 않는다.

## 3. M3 — 배분의 셋째 국면 가중 'GMM 시작 분포'

> 답하는 물음: ② 전달 — 보유 기간의 국면 분포를 'GMM 시작 분포 × 전이'로 잡으면 배분 입력 π 가 그렇게 바뀐다. ★예측력 · 경제적 가치를 주장하지 않는다★ —
> 출처의 실측 점수(M2 의 워크포워드 점수)를 **같은 응답에 싣는 것**이 계약이다. 받은 승인: "모든 옵션을 다 진행해"(CLAUDE.md §3) — 바뀌는 것은 사용자가 이 방식을 고른 경우의 π 뿐이고
> 기본값(`hard`)은 그대로다(바꾸는 것은 M4). 최적화기 · `constrained_solve` · 조건부 모멘트 함수(`regime_mixture_moments`)의 뜻은 0줄.

### 3.0 먼저 잰 것 (2026-11-16 · 합성 축 120개월 · 버릴 스크립트)

- GMM 한 번(시드 10개 평균) 0.29초 · M2 점수(k = 1 또는 3) 첫 계산 33초(군집 두 팔) · GMM 팔만 26초 · 기억한 뒤 0.00초 · 부트스트랩 20회 0.36초(그 자료에서 같은 답 18/20).

### 3.1 계약 (`regime_probability`)

- 새 출처 `SOURCE_GMM_START = "gmm_start_forecast"` 를 `_PORTFOLIO_SOURCES` 에 넣는다 — ★생성자 `from_gmm_start_path` 하나만 usage = portfolio★.
  π₀ 는 확률 벡터(국면 넷 · 음수 없음 · 합 1)여야 하고, π_j = π₀ · P̄^j(j = 1 … h · P̄ 는 `from_posterior_mean_path` 와 같은 행 재정규화 — 같은 사슬).
- ★값으로 거른다★ `require_portfolio_source` 가 이 출처에는 `detail.skill` 을 요구한다 — M2 후보 `gmm_start` 의 결과가 `available` 이고 평가 시점이 하한 이상이어야 한다.
  없으면 거부(ValueError) — 생성자를 건너뛰어 손으로 지은 객체도 같은 문지기에서 걸린다.
- 점수의 k 는 보유 기간(`h_hold` — 한 달 1 · 한 분기 3). 순차 증거는 k = 1 에서만(M2 그대로) — 증거가 없다는 사실도 그대로 싣는다.

### 3.2 엔진 `src/engine/regime_gmm_start.py`(새 · 순수)

- `gmm_start_path(points, h_hold, *, mode, arms=None, bootstrap=None)` → `{available, probs: [RegimeProbabilities …], P, pi0, skill, stability, robustness}` 또는 `{available: False, reason}`.
  π₀ = 그 경로 전체 축으로 적합한 GMM 의 시드 평균 소속 확률(`regime_skill.cached_arms` — 앙상블 · M2 와 같은 함수 · 같은 기억) · 점수 = `regime_skill(points, k = h_hold)` 의 `gmm_start` 후보.
- **자료 흔들기에 대한 강건성(M1c 에서 넘긴 것)**: 부트스트랩(달을 복원 추출해 다시 적합 · 20회 · 결정적 씨앗) — 지금 점의 최다 국면이 같은 비율을 `robustness` 로 **관측만** 한다.
  ★π₀ 를 부트스트랩 평균으로 바꾸지 않는다★(배분 입력을 바꾸는 정교화는 이 조각의 범위 밖 — 잰 값을 보이기만 한다). 문턱도 두지 않는다(M1c: 문턱은 한계를 없애지 못한다).
- 세우지 못하는 경우마다 사유: 경로가 짧다 · 축 값이 없다(고정 스냅샷 경로) · GMM 적합 실패 · 점수 없음(평가 시점 부족 · 한 시점이라도 못 세움).

### 3.3 파이프라인 · 백테스트 · 문

- `allocation_pipeline._conditional_stack`: `regime_weighting = "gmm"` → GMM 시작 분포로 혼합. ★세우지 못하면 명시적으로 열화★ — 전이 예측(`probabilistic`)으로 계산하고
  `meta` 에 `requested_weighting: "gmm"` · `regime_weighting: "probabilistic"`(실제로 쓴 것) · `gmm_fallback: 사유`(뜻이 알려져 있고 · 라벨이 붙고 · 같은 품질로 위장하지 않고 · 관측된다). 전이 예측까지 못 하면 기존대로 하드 + 사유.
  성공하면 `probability_source` 에 출처 · π₀ · 점수(적중률 · 브라이어 · 유지 대비 · 평가 시점 · 증거) · 시드 안정성 · 부트스트랩 안정성.
- `allocation_backtest`: 팔 `gmm`(이름표 `G`). 재조정 달마다 **그 달까지 자른 경로**로 π₀ · 점수를 다시 낸다(앞보기 0 — 시험이 가짜 팔이 받은 자료 길이로 건다) · 그 달에 못 세우면 그 달만 전이 예측 + `regime_audit` 의 사유.
  부트스트랩은 백테스트의 달마다 돌리지 않는다(달마다 0.36초 — 이 조각에서는 라이브 경로만 · 하지 않은 것에 적는다).
- 문: `AnalyzeRequest.regime_weighting` 의 패턴에 `gmm`. 공개 백테스트 문(`BacktestRequest`)은 국면 가중을 받지 않는다 — 그대로(평가 스크립트 · 시험만 팔을 쓴다).

### 3.5 시험 (빨강 먼저)

- 계약: 점수 없는 GMM 출처 거부 ↔ 점수 있으면 통과 · 손으로 지은 위조 객체 거부 · π₀ 검사(합 · 음수 · 키) · π_j = π₀ · P̄^j 손 계산 · 혼합 일관성 검사 통과(같은 사슬).
- 엔진: 가짜 팔로 π₀ · 점수 · 안정성 · 부트스트랩(뭉친 자료 20/20 ↔ 원 자료는 그보다 낮다 — 기계와 무관한 성질만) · 세우지 못하는 경우마다 사유.
- 파이프라인: 성공하면 `regime_weighting: gmm` + 출처 블록 ↔ 개발 자료(점수 없음)는 전이 예측 + `gmm_fallback` 사유 · ★`hard` · `probabilistic` 의 응답은 한 바이트도 바뀌지 않는다★(고정 입력의 골든).
- 백테스트: 팔 G · 앞보기 0 · 달마다 열화 사유 · 다른 팔 골든 불변. 문: 422 ↔ `gmm` 받음. 캔버스: 선택지 이름 · 해설(방식마다 가정 · 열화 사유 · 점수 줄) · E2E(개발 자료에서 GMM 을 고르면 최적화 해설에 열화 사유).
- 변이: 생성자 우회 · 점수 검사 빼기 · π₀ 대신 하드 라벨 · 전이를 안 곱함 · 미래 달로 적합 · 열화를 조용히(사유 없이) · 열화 대신 하드 · 옛 이름표 · 해설의 가정 고정 등.

### 3.6 하지 않는 것

기본값 전환(M4) · 근거 관문(M4) · 최적화기 · `constrained_solve` · `regime_mixture_moments` 의 뜻 · π₀ 를 부트스트랩 평균으로 바꾸기 · 문턱 · 백테스트 달마다의 부트스트랩 ·
공개 백테스트 문에 국면 가중 열기 · 평가 스크립트(`ms1b_eval` · `regime_control`)의 팔 목록 · 매크로 화면의 새 블록 · 경제적 가치(④).

### 3.7 달라진 것 (구현하며 · 2026-11-16)

- **이름의 자리**: 선택지 이름표 `WEIGHTING_PLAIN` 은 `allocation_graph_explain` 에 둔다(이름의 출처는 여전히 `regime_skill.CANDIDATE_NAMES` 한 곳).
  노드 모듈이 엔진을 직접 들이지 못하게 하는 구조 가드(`test_the_nodes_do_not_import_the_arithmetic_directly`)에 걸렸다 — 허용 목록을 넓히지 않고 해설 모듈이 이름을 짓고 노드가 받는다.
  화면 이름은 §3.4 의 'GMM 시작 분포'가 아니라 M2 후보 이름 그대로 **'GMM 시작 분포 × 전이'**(두 화면이 같은 말).
- **전문가 칸 · 추정 결과가 코드를 보였다**(고침): 검사기의 고르기 칸과 추정 결과 표가 `hard` · `probabilistic` 같은 코드를 보였다 →
  서버의 선택지 이름(`x-ui.options`)과 값 이름표(`value_labels`)를 보인다. 문서에 남는 값은 코드 그대로(E2E ⓪ 이 건다).
- **혼합이 뺀 국면을 말한다**(찾음 · 고침): 개발 자료의 756거래일 창에는 스태그플레이션 달이 0개라 혼합이 그 국면을 빼고 재정규화한다 — 캔버스는 그 칸을 '—' 로만 보였다.
  블록에 `dropped_regimes` · `dropped_notes`(국면 · 사유 · 뺀 질량 최대) · 화면 칸 '추정 불가'(0% 가 아니다) · 해설의 가정 줄.
- **조건부를 아예 못 만든 경우를 캔버스가 말한다**(고침): 전에는 최적화 노드가 아무 말 없이 과거 표본으로 냈다 → 블록 `available: false` + 사유 · 해설의 가정 줄 하나 · '국면 가중 방식' 사실 줄 없음.
- **관문이 막은 경우**('확인된 국면 판정만 쓰기'): 블록 `applied: false` + 화면의 차단 줄 · 해설은 기존 차단 줄 하나뿐(쓰지 않은 방식을 사실 줄 · 대체 줄로 적지 않는다) — 실제 서버로 E2E ⑤.
- **열화 걸음마다 그 걸음의 두 방식**(변이 n3 을 죽이는 시험을 쓰다 찾음): GMM → 전이 예측 → 오늘 국면 유지 두 걸음이면 해설의 두 줄이 모두
  'GMM … 을 쓰지 못해 오늘 국면 유지로 산출했습니다' 라고 적어 가운데 걸음이 글에서 사라졌다 → 블록이 걸음마다 서버 문장을 짓고(`weighting_fallback_sentence` —
  앞 걸음은 '넘어갔습니다', 산출한 방식에 닿은 걸음만 '산출했습니다') 해설의 대체 줄은 그 글을 그대로 싣는다(결과 판의 사유 줄 = 해설의 대체 줄 · 한 문장 두 자리).
- **지금 점의 이름표 = GMM 의 답**: `label` 은 시작 분포의 최다 국면이고 경로의 하드 라벨(사분면)과 다를 수 있다 — 다시 뽑기도 그 답과 견준다(변이 e6 을 죽이는 시험).
- **점수 서식의 타입**: `entities/macro/skill.ts` 의 서식 함수가 후보 전체가 아니라 쓰는 칸만(`Pick<…>`) 받는다 — 블록의 점수가 M2 화면과 같은 서식.
- **골든은 코드를 바꾸기 전에 얼렸다**: `hard` · `probabilistic` 스택 6경우와 B0 · B1 · N 팔의 워크포워드(`tests/golden/regime_weighting_stack.json` · `regime_arms_walk_forward.json`)를
  바꾸기 전 HEAD 의 worktree 에서 짓고, 바꾼 뒤 정확 비교 — 파이프라인을 나눈 것(`_omega_confidence` · `_pi_sharpness` · `_mixture_meta`)이 뜻을 바꾸지 않았다는 증거.
