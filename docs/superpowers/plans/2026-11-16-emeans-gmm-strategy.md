## 1. M1 — 군집 팔의 씨앗 안정성 + k-평균 넷째 팔

### 1.1 계약

- `regime_ensemble.SEEDS = 10`(설정값 — 재 본 값이 아니다). GMM 팔은 씨앗 `0 … SEEDS−1` 로 적합(설정은 지금 그대로: 성분 수 규칙 · `covariance_type="full"` · `n_init=3`).
  - `probs` = 씨앗마다 마지막 점의 소속 확률을 성분 중심의 사분면으로 모은 것의 **평균**(합 1) · `argmax` = 그 평균의 최빈 국면.
  - `stability = {seeds, modal, agree, shares, stable}` — 씨앗마다의 최빈 국면을 센 것. `modal` 은 가장 많이 나온 국면(동률이면 `REGIMES` 순서의 앞), `agree` 는 그 수, `shares` 는 국면별 비율(합 1), `stable` 은 `agree × 2 > seeds`.
  - `detail` 은 성분 수 · 관측 수 · **씨앗 0 의** 성분 중심(그렇게 이름 붙인다) · 모든 씨앗이 수렴했는지.
- 새 팔 `kmeans`(`_kmeans_probs`): `sklearn.cluster.KMeans(n_clusters=같은 규칙, n_init=10, random_state=s)` 를 씨앗마다 → 마지막 점이 속한 중심의 사분면.
  - `probs` = 씨앗 비율(합 1) · `probs_kind = "seed_share"`(GMM 팔은 `"probability"`) · `argmax` = 최빈 · `stability` 는 같은 모양 · `note` 가 "확률이 아니라 씨앗 비율"이라고 말한다.
  - 표본 부족 · scikit-learn 없음 · 결측 · 적합 실패 → `available: False` + 사유(GMM 팔과 같은 규칙).
- `regime_ensemble` 은 도구 넷을 나란히 낸다(합치지 않는다 — 지금 규칙 그대로). 문장: 합의 "모든 방법이 같은 국면을 가리킵니다" · 맺음 "방법마다의 판정을 평균하지 않습니다 …".
- 소비자: 합의 보기(`regime_consensus_view` — 고칠 것 없음 · 넷이 들어간다) · 캔버스 노드 설명과 해설(`allocation_graph_nodes_bl2` — 이름표에 k-평균 · '세 방법' 문장) ·
  추정기 등록부(`estimator_evidence.EXCLUDED_SITES` 에 `_kmeans_probs` — 사유: 진단 전용) · 화면 형(`entities/macro/api.ts`) · 캔버스 결과 판(`Bl2Results.EnsembleResult` — 이름표 · 씨앗 비율의 주석 · 안정성 한 줄).

### 1.4 구현에서 달라진 것 · 더한 것 (2026-11-16 · 끝난 뒤 적음)

- **더함 ① 합의의 독립성 문장**: GMM 과 k-평균은 같은 (성장, 물가) 좌표를 묶어 서로 독립이 아니다. 넷째 팔을 더하면 "4개 중 3개" 같은 다수가 군집 두 팔에 기울 수 있어,
  둘이 **함께 답했을 때만** `regime_consensus_view` 가 `note` 에 `CLUSTER_DEPENDENCE_NOTE` 를 붙인다(합의 규칙 · 키 모양은 그대로). 짝: 하나가 답하지 못하면 붙이지 않는다.
- **더함 ② 스레드 하나로**: 시드 10개 반복이 기본 스레드에서 느렸다(60개월 앙상블 0.16 → 0.70초). 원인은 반복 횟수가 아니라 작은 2차원 자료에서의 BLAS · OpenMP 스레드 부담이었다
  (한 번 적합 약 55ms → 1스레드 약 20ms) → `threadpoolctl.threadpool_limits(1)` 로 묶어 0.35초. 기계마다 합산 순서가 같아지는 덤이 있고, 제한이 프로세스 전체에 걸린다는 사실은 주석에 적었다.
- **이름표**: 군집 두 팔을 가른다 — 캔버스 `군집(GMM)` · `군집(k-평균)`, 서버 해설 `군집 모형(GMM)` · `군집 모형(k-평균)`, 매크로 화면 `군집(GMM)` · `군집(k-평균)`(키 `kmeans` 는 곁에 남는다).
- **화면 낱말**: 문서의 '씨앗'은 화면에서 용어집 §3.8 의 `난수 시드`로 쓴다.
- **`detail.centers` → `centers_seed0`**: 어느 시드의 중심인지 이름에 적는다(소비자 없음을 확인함 — 프론트 · 서버 모두).
- **안정성의 뜻(설계 그대로)**: `stable` 은 시드별 **최다 답**이 엄격한 과반인지다. GMM 팔의 답(평균 확률의 최댓값)과 최다 답은 다를 수 있다 — 화면 줄은 최다 답의 국면 이름을 함께 적어 굵은 칸과 헷갈리지 않게 했고, 서버 해설은 갈리면 '미상' 줄을 단다.
- **더함 ③ 흔들리는 팔 위의 만장일치**(스크린샷 검수에서 찾음 — 개발 자료 us 60개월: 네 방법 모두 Stagflation · GMM 최다 답 3/10): `unanimous` 는 그대로 참이고(답이 같다는 사실),
  앙상블 문장 · 캔버스 해설 제목에 "다만 난수 시드에 따라 답이 갈리는 방법이 있습니다"를 단다. 합의는 `seed_unstable`(늘 실림 · 키 목록)과 팔 이름을 적은 문장을 낸다(합의 규칙 그대로).
  화면의 띠는 '같다 + 과반 미만 팔 없음'일 때만 초록이다(캔버스 앙상블 · 합의 판) · 매크로 화면은 합의 블록에 "난수 시드에 따라 답이 갈리는 도구가 있습니다".
- **팔 이름표 한 곳**: 서버 문장의 팔 이름은 `regime_ensemble.TOOL_NAMES` 하나(캔버스 두 노드의 해설이 같은 표를 쓴다).
- **머리 칸**(스크린샷 검수에서 찾음): 열이 다섯이 되자 '상태 전/환' · '군집(k-평/균)' 처럼 낱말 가운데에서 끊겼다 → 이름표를 띄어쓰기나 여는 괄호 앞에서 두 덩어리로 나눠 덩어리 안은 끊지 않는다(글자는 그대로 · E2E 계약 불변).
- **표 맞춤**(스크린샷 검수에서 찾음 — 1440px 미만 창): 열이 다섯이 되자 처음 폭(344px) 판에서 표가 판보다 25~34px 넓어 k-평균 열이 잘리고 숫자가 붙었다 →
  국면 이름도 두 덩어리(괄호 덩어리는 늘 둘째 줄) · 이름 칸 폭 고정 풂 · 숫자 칸 사이 · 좁은 판(감싼 칸 280px 이하)은 글자 12px(컨테이너 쿼리) · 마지막 수단 가로 밀기.
  E2E 가 판 폭 셋(344 · 392 · 300px)에서 '판 안에 든다 · 숫자가 붙지 않는다 · 행 높이가 같다'를 본다.

### 1.5 M1b — 앙상블 입력의 지어낸 0 걷기 (M2 감사에서 찾음 · 2026-11-16)

- **찾은 것**: 앙상블의 `_axis_history` 는 축 성분이 없는 달의 점수를 0 으로 채웠다(`compute_axis_detail` 의 빈 값). (0, 0) 은 사분면으로 Reflation 이라,
  계산되지 않은 달이 한 국면으로 찍혀 Markov · 군집 두 팔(M1 포함)의 적합에 들어갔다 — CLAUDE.md §4 '미상 ≠ 0' 위반.
  개발 자료에서는 두 축이 다 계산된 달이 최근 53개월뿐이라 60개월 요청에 7점, 120개월 요청에 67점이 지어낸 값이었다(잰 값).

  뺀 달이 있으면 문장 "축이 둘 다 계산되지 않은 N개월은 빼고 셉니다(0 으로 채우지 않습니다)." · 빼고 나서 36개월이 안 되면 Markov · 군집 두 팔은 값 없음 + 사유(기존 규칙).
- **바뀌는 관측**: M1 의 'us 60개월 GMM 최다 답 3/10 · 시드에 따라 갈림'은 지어낸 점 탓이었다 — 고친 뒤 7/10(과반). 개발 자료에는 이제 과반 미만인 팔이 없어
  M1 캔버스 E2E 의 흔들림 갈래는 실행 응답을 심어 그린다(서버의 셈은 pytest 가 건다).
- **불변**: 축 팔(지금 달의 축 — 이 고침과 무관) · 합의 규칙 · 배분 경로 · 화면 부품.

  문턱을 올리는 것(예: 7/10)은 답이 아니다 — 흔든 원 30개에서 7 이상이 GMM 6개 · k-평균 9개였다(잰 것).

### 2.1 계약

- 새 순수 모듈 `src/engine/regime_skill.py` — `regime_skill(points, *, k=1, min_history=36, alpha=0.05, arms=…)`. `points` 는 `regime_path` 의 점(`growth` · `inflation` · `regime`, 과거 → 현재).
  `arms(g_hist, i_hist)` 는 군집 두 팔(`regime_ensemble._cluster_probs` · `_kmeans_probs` — 앙상블과 같은 함수 · 같은 입력)을 부르는 자리다 — 시험은 가짜를 넣어 시점마다 받은 자료의 길이를 센다. 문은 축 값의 튜플을 열쇠로 기억하는 판(`cached_arms`)을 넣는다.
  전이 사후평균 행렬은 `regime_forecast` 에 공개 도우미(`transition_posterior_mean` · `propagate`)로 빼고 `_posterior_forecast` 가 그것을 쓴다(동작 불변 — 기존 적중률 시험이 건다).
- 평가: t = `min_history` … n − k 마다 ★`points[:t]` 만으로★ 후보를 세워 `points[t + k − 1]` 의 국면을 예측한다(`forecast_coverage` 와 같은 칸 맞춤). 평가 점이 20(`MIN_EVAL_POINTS`)보다 적으면 값 없음 + 사유.
  `min_history` 는 36 — 군집 팔의 표본 하한(`MIN_OBS`)과 같게 해 ★모든 후보가 같은 시점에서 채점된다★.
- 후보 여섯(순서 고정 · 점수로 줄 세우지 않는다):
  ⓐ `persistence` 오늘 국면 유지(그 국면에 확률 1) ⓑ `base_rate` 기저율(그때까지의 빈도) ⓒ `transition` 전이 예측(`_posterior_forecast` — 지금 배분의 출처)
  ⓓ `gmm_start` GMM 시작 분포 × 전이 사후(π₀ · P̄^k — π₀ 는 시점 t 에서 적합한 GMM 의 시드 평균 소속 확률, P̄ 는 같은 경로의 전이 사후평균 — M3 의 출처) ⓔ `gmm_now` GMM 지금 값 그대로 ⓕ `kmeans_share` k-평균 시드 비율.
- 지표(후보마다): 적중(가장 높은 확률의 국면 = 실현 · 동률은 `REGIMES` 순서) · 브라이어 점수(Σ(p − o)² · 0 ~ 2)의 평균 · 유지 대비 브라이어 차의 평균(양이면 유지보다 낫다).
- 순차 증거(e-값): d_t = 브라이어(유지) − 브라이어(후보) 는 늘 [−2, 2] 안이라 G1 의 `evalue.log_path(d, cap=2)` 가 ★상한 가정 없이 정확하다★. 기준 = 비교한 후보 수(다섯) / α.
  ★k = 1 에서만★ 계산한다 — k > 1 이면 앞 예측이 실현되기 전에 다음 예측이 나와 평가 결과가 겹치고 순차 검정의 전제가 서지 않는다 → 값 없음 + 사유.
  (G1 의 `evidence()` 문장은 '하루 손익 · 손실 상한'의 말이라 그대로 쓰지 않고, 이 모듈이 자기 문장으로 낸다.)
- 한 시점이라도 세우지 못한 후보는 ★값 없음 + 사유★(처음 실패한 시점과 까닭) — 다른 표본으로 채점한 점수는 나란히 놓을 수 없다.
- 응답에 '가장 나은 후보' 같은 키를 두지 않는다.

## 3. M3 — 배분의 셋째 국면 가중 'GMM 시작 분포'

> 답하는 물음: ② 전달 — 보유 기간의 국면 분포를 'GMM 시작 분포 × 전이'로 잡으면 배분 입력 π 가 그렇게 바뀐다. ★예측력 · 경제적 가치를 주장하지 않는다★ —
> 출처의 실측 점수(M2 의 워크포워드 점수)를 **같은 응답에 싣는 것**이 계약이다. 받은 승인: "모든 옵션을 다 진행해"(CLAUDE.md §3) — 바뀌는 것은 사용자가 이 방식을 고른 경우의 π 뿐이고
> 기본값(`hard`)은 그대로다(바꾸는 것은 M4). 최적화기 · `constrained_solve` · 조건부 모멘트 함수(`regime_mixture_moments`)의 뜻은 0줄.

### 3.0 먼저 잰 것 (2026-11-16 · 합성 축 120개월 · 버릴 스크립트)

### 3.1 계약 (`regime_probability`)

- 새 출처 `SOURCE_GMM_START = "gmm_start_forecast"` 를 `_PORTFOLIO_SOURCES` 에 넣는다 — ★생성자 `from_gmm_start_path` 하나만 usage = portfolio★.
  π₀ 는 확률 벡터(국면 넷 · 음수 없음 · 합 1)여야 하고, π_j = π₀ · P̄^j(j = 1 … h · P̄ 는 `from_posterior_mean_path` 와 같은 행 재정규화 — 같은 사슬).
- ★값으로 거른다★ `require_portfolio_source` 가 이 출처에는 `detail.skill` 을 요구한다 — M2 후보 `gmm_start` 의 결과가 `available` 이고 평가 시점이 하한 이상이어야 한다.
  없으면 거부(ValueError) — 생성자를 건너뛰어 손으로 지은 객체도 같은 문지기에서 걸린다.
- 점수의 k 는 보유 기간(`h_hold` — 한 달 1 · 한 분기 3). 순차 증거는 k = 1 에서만(M2 그대로) — 증거가 없다는 사실도 그대로 싣는다.

### 3.2 엔진 `src/engine/regime_gmm_start.py`(새 · 순수)

- `gmm_start_path(points, h_hold, *, mode, arms=None, bootstrap=None)` → `{available, probs: [RegimeProbabilities …], P, pi0, skill, stability, robustness}` 또는 `{available: False, reason}`.

- **자료 흔들기에 대한 강건성(M1c 에서 넘긴 것)**: 부트스트랩(달을 복원 추출해 다시 적합 · 20회 · 결정적 씨앗) — 지금 점의 최다 국면이 같은 비율을 `robustness` 로 **관측만** 한다.

### 3.3 파이프라인 · 백테스트 · 문

- `allocation_pipeline._conditional_stack`: `regime_weighting = "gmm"` → GMM 시작 분포로 혼합. ★세우지 못하면 명시적으로 열화★ — 전이 예측(`probabilistic`)으로 계산하고
  `meta` 에 `requested_weighting: "gmm"` · `regime_weighting: "probabilistic"`(실제로 쓴 것) · `gmm_fallback: 사유`(뜻이 알려져 있고 · 라벨이 붙고 · 같은 품질로 위장하지 않고 · 관측된다). 전이 예측까지 못 하면 기존대로 하드 + 사유.
  성공하면 `probability_source` 에 출처 · π₀ · 점수(적중률 · 브라이어 · 유지 대비 · 평가 시점 · 증거) · 시드 안정성 · 부트스트랩 안정성.
- `allocation_backtest`: 팔 `gmm`(이름표 `G`). 재조정 달마다 **그 달까지 자른 경로**로 π₀ · 점수를 다시 낸다(앞보기 0 — 시험이 가짜 팔이 받은 자료 길이로 건다) · 그 달에 못 세우면 그 달만 전이 예측 + `regime_audit` 의 사유.
  부트스트랩은 백테스트의 달마다 돌리지 않는다(달마다 0.36초 — 이 조각에서는 라이브 경로만 · 하지 않은 것에 적는다).
- 문: `AnalyzeRequest.regime_weighting` 의 패턴에 `gmm`. 공개 백테스트 문(`BacktestRequest`)은 국면 가중을 받지 않는다 — 그대로(평가 스크립트 · 시험만 팔을 쓴다).

- 엔진: 가짜 팔로 π₀ · 점수 · 안정성 · 부트스트랩(뭉친 자료 20/20 ↔ 원 자료는 그보다 낮다 — 기계와 무관한 성질만) · 세우지 못하는 경우마다 사유.
- 파이프라인: 성공하면 `regime_weighting: gmm` + 출처 블록 ↔ 개발 자료(점수 없음)는 전이 예측 + `gmm_fallback` 사유 · ★`hard` · `probabilistic` 의 응답은 한 바이트도 바뀌지 않는다★(고정 입력의 골든).
- 백테스트: 팔 G · 앞보기 0 · 달마다 열화 사유 · 다른 팔 골든 불변. 문: 422 ↔ `gmm` 받음. 캔버스: 선택지 이름 · 해설(방식마다 가정 · 열화 사유 · 점수 줄) · E2E(개발 자료에서 GMM 을 고르면 최적화 해설에 열화 사유).
- 변이: 생성자 우회 · 점수 검사 빼기 · π₀ 대신 하드 라벨 · 전이를 안 곱함 · 미래 달로 적합 · 열화를 조용히(사유 없이) · 열화 대신 하드 · 옛 이름표 · 해설의 가정 고정 등.

## 4. M4 — 기본 배분 경로를 근거 관문으로 (D1-b)

### 4.1 계약 — 근거 관문 `evidence`
- 같은 경로 · k = 보유 기간의 M2 점수에서 세 후보(GMM 시작 분포 × 전이 · 오늘 국면 유지 · 전이 예측)가 모두 섰고
  GMM 시작 분포의 브라이어가 ★둘보다 엄격히 낮으면★ GMM 시작 분포 × 전이(M3 의 길 그대로 — 그 길의 열화도 그대로), 아니면 전이 예측 + 사유.
- ★오늘 국면 유지가 가장 낮아도 전이 예측이다★(받은 결정 D1-b — 기본 경로의 두 후보는 GMM 과 전이 예측) — 사유가 그 사실을 적는다.
- 점수가 없거나(평가 시점 부족) 세 후보 가운데 하나라도 못 섰으면 전이 예측 + 사유(견주지 못했다는 사실).
- 블록(엔진 `evidence_gate` 의 답 = 응답 `conditional.gate` = 캔버스 `reg.gate`):
  `{available, chosen: "gmm" | "probabilistic", chosen_name, reason, k, n_eval, n_compared: 3, compared: [{key, name, brier, available}](gmm_start · persistence · transition 고정 순서), digits, note}`.
  `available` = 세 점수를 견줬는가(무엇을 골랐든). `digits` = 3 에서 시작해 서로 다른 값이 같게 보이면 6 까지(표 · 해설이 그 자릿수로 보인다 — 3자리에서 같아 보이는데 '낮아'라고 쓰지 않게).
  `note` = "같은 자료로 세 후보를 견줘 고른 값이라 고른 쪽의 점수는 낙관적입니다(견준 후보 셋). 합성 축에서 나온 점수는 …"(승자의 저주 · 받은 결정이라는 사실).
- 사유 문장(숫자 없이 — 숫자 뒤 조사를 피하고 숫자는 표 · 해설 사실 줄이 싣는다):
  고름 "브라이어 점수에서 ‘GMM 시작 분포 × 전이’가 ‘오늘 국면 유지’와 ‘전이 예측’보다 모두 낮아 ‘GMM 시작 분포 × 전이’를 씁니다." ·
  안 고름 "… ‘{이기지 못한 후보}’보다 낮지 않아 ‘전이 예측’을 씁니다." (+ 유지가 엄격히 가장 낮으면 "가장 낮은 것은 ‘오늘 국면 유지’이지만 기본 경로는 ‘GMM 시작 분포 × 전이’와 ‘전이 예측’ 가운데서만 고릅니다.") ·
  점수 없음 "같은 경로의 워크포워드 점수가 없어 ‘전이 예측’을 씁니다. {사유}" · 후보 못 섬 "‘{이름}’ 후보의 점수가 없어 ‘전이 예측’을 씁니다. {사유}".
- 응답 `meta`: `requested_weighting: "evidence"` · `gate` · (관문이 GMM 을 고른 경우에만) `gmm_fallback`. `regime_weighting` 은 늘 실제로 쓴 방식.
- 백테스트 팔 `evidence`(이름표 `E`): 재조정 달 m 의 관문은 ★m 까지 자른 경로의 점수만★ 쓴다(앞보기 0) · 달마다의 선택과 사유를 감사 줄의 `gate` 에(E 팔에만 — B1 · N · G 의 감사는 골든 그대로) ·
  요약에 `gate_gmm_months` · `gate_transition_months`. 하네스의 암묵 기본값은 바꾸지 않는다(팔은 늘 이름으로 부른다) — 주석의 'B1 = 현행 프로덕션'을 'B1 = 오늘 국면 유지(M4 전의 기본값) · E = 근거 관문(M4 의 기본값)'으로.

### 4.4 시험 (빨강 먼저)
- 관문(엔진): GMM 이 둘보다 낮으면 GMM ↔ 전이와 같으면 전이 예측 ↔ 유지보다 높고 전이보다 낮으면 전이 예측 ↔ 전이보다 높고 유지보다 낮으면 전이 예측 ↔ 유지와 같으면 전이 예측 ·
  유지가 가장 낮아도 전이 예측(사유가 그 사실을) · 점수 없음 → 전이 예측 + 사유 · 후보 하나 못 섬 → 이름 + 사유 · k = 보유 기간 · 받은 경로 그대로 · `digits` 손 계산(0.5121 · 0.5124 → 4) ·
  실제 `regime_skill`(가짜 팔)로 끝까지 한 번(점수표의 값 = 관문의 값).
- 파이프라인: 기본 요청 = 관문의 길(`requested_weighting: "evidence"` · `gate`) · 관문이 GMM 을 고르면 M3 스택과 같다(가짜 팔) ↔ 전이 예측을 고르면 전이 예측 스택과 같다 · 개발 자료 = 전이 예측 + 점수 없음 사유 ·
  명시한 `hard` 는 M3 골든 그대로(짝) · 백테스트 모드 닫힘 그대로.
- 백테스트 E 팔: 달 m 의 관문이 받은 자료 길이 = m 까지(가짜 팔이 적는다) · 뒤 달을 바꿔도 앞 달의 선택 불변 · 달마다의 감사 줄 · 요약의 달 수 · B1 · N · G 골든 불변.
- 캔버스: 선택지 넷(근거 관문 맨 앞) · 관문 절(고름 · 못 견줌 · 고른 GMM 을 못 세움) · 해설 줄 · 넘겨받은 고침의 짝.
- 의도한 변화 목록: 기본값에 기대던 시험 · 골든 · E2E 를 하나씩 — 바뀐 까닭과 함께 HISTORY 에(파급 실험의 ① · M3 E2E ⓪ 의 선택지 목록).
- 변이: `<` → `<=` · 유지와만 견줌 · 전이와만 견줌 · 미래 점수(백테스트) · 사유 없이 열화 · 기본값을 `hard` 로 되돌림 · 낙관 줄 빼기 · 후보 수 빼기 · 유지가 이기면 하드로 · `digits` 고정 3 ·

### 5.1 계약 — 엔진 `src/engine/intraday/day_types.py`(새 · 순수 · 파일을 읽지 않는다)
- **특징**(종목 · 날마다 · `Session` 의 정규장 봉): t0 = 그날 그 종목의 첫 봉 시각. 창 = 첫 N개 봉이 t0, t0 + 1분, …, t0 + (N − 1)분에 ★하나씩★ 있어야 한다 —
  아니면 제외 `short_window`(그날 봉이 N개 미만이거나 창 안에 빠진 분이 있다). 첫 봉 시가 o₀ 와 창의 종가가 모두 유한하고 0 보다 커야 한다 — 아니면 제외 `bad_price`(나눗셈 가드).

## 6. T2 — 지표 '하루 유형' (직접 구성의 조건)

> 설계 §3 T2(승인됨) · 받은 결정 D3 사용자별. 이 절은 T1 을 커밋한 뒤 쓴다(2026-11-17). 그 뒤의 결합 묶음 K 가 이 절의 '규칙 맥락' 장치를 그대로 쓴다(K3 국면 조건).

### 6.0 감사에서 본 것 (읽기 전용)

- 지표는 `(Session, **params)` 의 순수 함수이고 매개변수는 수만 받는다(`indicators.Range` · `resolve`). 나무 잎의 매개변수 검사는 `expr._check` → `indicators.resolve` 한 곳이다.
- 시뮬레이터는 세션마다 `expr.evaluate(tree, session)` 를 부른다 — 세션 밖의 값을 볼 길이 없다. 걸음 엔진 `stepper._upto` 는 `Session(...)` 을 칸마다 옮겨 새로 짓는다(새 칸이 생기면 잃는다).
- 규칙을 돌리는 길은 다섯이다: `simulate` · `run_validation`(문 + 캔버스 실행 단추) · `prepare`(문 + 캔버스 설정 노드의 읽기 전 검사 — 사용자를 받지 않는다) · `divergence_report` · 규칙 가동(`broker_account_routes._day_of` — 시작과 관제).
- 하루 유형 모형의 몸통에는 중심이 따로 없고 `types[j].path`(유형 j+1 의 중심 · float64 를 JSON 으로 — 되읽으면 같은 수) · `minutes` · `k` · `days`(학습한 날) · `first_day` · `last_day` 가 있다(`intraday_day_types.model_of`).
- 등록부 전체의 앞보기 시험(`test_intraday_indicators.py::test_no_indicator_looks_ahead`)은 매개변수의 `low` · `high` 로 값을 짓고 맥락 없는 무작위 세션을 쓴다 — 새 지표에는 맥락이 있어야 한다.
- 편집기는 지표 매개변수를 숫자 칸으로만 그린다(`RuleEditor.Num` · `tree.inRange`).

### 6.1 계약

- **지표** `day_type_is` — 매개변수 `model`(모형 열쇠 · 64자리 소문자 16진) · `type`(유형 번호 1 ~ 16 · 그 모형의 k 이하인지는 맥락에서 본다) · 단위 `flag` · 이름표 "하루 유형".
  값: 세션의 첫 봉부터 N(모형의 분 수)개의 봉이 1분마다 있고 가격이 유효하면(`day_types.window` 그대로) ★창의 마지막 봉부터★ 하루 끝까지 `1.0`(가장 가까운 중심 = `type` · `day_types.assign` 그대로) 또는 `0.0`, 그 앞 봉은 `NaN`.
  창이 어긋난 날(빠진 분 · 0 이하 가격)은 하루 내내 `NaN` — 조건은 충족으로 보지 않는다. 결정 시각 = 창의 마지막 봉이 닫힌 때(시뮬레이터는 그 봉에서 판단해 다음 봉 시가에 체결한다).
  ★지표가 세션 자신의 첫 N 봉으로 센다★ — 미리 세어 싣지 않으므로 잘린 세션(걸음 엔진)에서도 인과다.

  ★맥락이 없거나 그 모형이 맥락에 없으면 명시적 실패(`IndicatorError("rule_context_missing")`)★ — 미상으로 두면 규칙이 조용히 거래 0 이 된다. 걸음 엔진 `_upto` 는 `dataclasses.replace` 로 맥락을 잇는다.
  `Indicator.context: str | None`(어느 맥락이 필요한가) — 등록부 전체 시험이 그 지표에 맞는 맥락을 지어 준다(맥락 없이 공허하게 통과시키지 않는다).
- **문 층** `src/api/intraday_context.py`(새)
  - `uses(spec) → dict[열쇠, set[유형 번호]]` — 나무 셋에서 `day_type_is` 의 모형 열쇠와 쓰인 번호(읽기만 · 평가하지 않는다).

### 6.3 시험 (빨강 먼저)

1. 손 계산 하루: 심은 네 유형 모형 + 유형 3 의 경로를 따르는 새 날 → 창의 마지막 봉부터 `type=3` 은 1 · 다른 번호는 0 · 앞 봉은 NaN.
2. 앞보기 0(접두 성질): 잘린 세션(봉 L 개)의 값 = 전체 값의 앞 L 개(L = 1 … 끝) — 무작위 하루 여럿 + 등록부 전체 시험에 맥락.
3. 창 어긋남(창 안의 빠진 분 · 0 가격)은 하루 내내 NaN ↔ 창 뒤의 빠진 분은 상관없다(짝).
4. 맥락 없음 · 그 모형 없음 → 명시적 실패 ↔ 다른 지표만 쓰는 나무는 맥락 없이 그대로(기존 골든 바이트 불변).
5. 문 층: 학습 마지막 날 = 판정 시작일 → 거절 ↔ 하루 앞이면 통과 · 뒤의 모형 거절 · 남의 · 없는 · 운영의 합성 모형 = 같은 거절 · 번호 > k 거절 · 저장소 실패 503 · ★봉을 읽기 전에★ 거절(읽기 함수를 막아 둔 채).
6. 다섯 길이 모두 맥락을 싣는다 — 각 길에서 그 조건으로만 진입이 생긴다(동작으로 건다 · 맥락이 빠지면 실패).
7. 걸음 엔진: 하루 유형 조건 규칙의 걸음마다 낸 체결 이어 붙임 = 한 번에 돌린 체결.
8. 시행: 같은 나무 · 다른 모형 → 시행 둘 ↔ 같은 모형 → 하나.
9. 글 · 주석 · 문법 표 · 판정 사실 줄(같은 종목 ↔ 다른 종목).
10. 화면 E2E: 모형 고르기 → 조건 '하루 유형 3 > 0.5' → 판정 → 사실 줄 · 체결이 손 계산 날에만 · 겹치는 기간은 서버 거절 문장 · 캔버스 설정 노드도 같은 부품 · 모형이 없으면 안내.

### 6.4 변이

창 앞에도 값을 냄 · 창 끝을 한 봉 늦춤 · 같은 거리 큰 번호 · 맥락 없음을 NaN 으로 · 겹침 검사 빼기 · `≥` → `>`(학습 마지막 날 = 시작일 통과) · 주인 검사 빼기 · 운영 합성 숨김 빼기 · 번호 상한 빼기 ·
`_upto` 가 맥락을 버림 · 한 길(divergence)에서 attach 빼기 · 편집기가 모형 열쇠를 싣지 않음 · 번호 칸 상한을 16 으로.

### 6.5 하지 않는 것

그날 전체 경로로 유형을 다시 셈(앞보기) · 모형 자동 고르기 · 남의 모형 · 학습 날과 겹친 판정을 '표본 안'으로 돌리기(거절한다) · 시뮬레이터 · 체결 규칙 · 주문 경로 · 시행 열쇠의 뜻.

### 7.5 K4 — 매매 몫 결합 (감사 · 계약 · 시험 · 변이 — 2026-11-17)

**감사(읽기 전용 · 관측)**
- 핵심(배분 결과)을 내는 포트는 `BacktestResult` 하나이고 생산자는 '정책 백테스트'(`backtest`) 하나다(등록부 관측). 그 값은 `_policy_backtest` → `simulate_walk_forward` 의 답 그대로 —
  `dates`(시뮬 구간 · `YYYY-MM-DD`) · `equity_curve`(소수 5자리 · 재조정 날에는 ★비용을 먼저★ 물리고 그날 수익을 복리 → 비용 후) · `config.cost_bps` · `perf_label`.
  일별 수익(비용 후) = 곡선의 이웃 비(첫날의 앞 값은 시작 자본 1). 요약의 샤프 · 변동성은 비용 전(CI 고침 때 찾은 것 · 결정 대기) — 이 노드는 요약을 읽지 않고 곡선만 쓴다.
- 위성(분봉 결과)은 '분봉 결과 조회'(`intraday_load`)의 `IntradayRun` = `{trial_key, grade, gates}` 뿐이라 일별 손익이 실려 있지 않다 → 노드가 실행자(본인)로 `trials.daily_of` 를 ★읽기만★ 한다
  (K2a 와 같은 길 · 남의 것 = 없는 것 · 못 읽음 ≠ 없음). `daily` = `{basis: net|gross, values, trades, wins, dates}` — 기간 안 분봉이 적재된 ★모든★ 거래일(거래 없는 날 0) ·
  `basis` 가 `gross` 면 그 시행은 비용 후 손익을 모른다(수수료율을 정하지 않았거나 매도세를 산출하지 못했다).
- ★기존 가드★: `IntradayRun` 을 받는 노드는 가동 요청 하나뿐이라는 시험 둘(`test_allocation_graph_arm_request.py::test_the_result_node_hands_its_run_only_to_the_request_node` ·
  `test_allocation_graph_intraday.py::test_results_cannot_be_ranked_or_compared_the_only_way_out_is_the_arm_request`) — 뜻은 '분봉 결과를 비교 · 순위 · 비중에 잇는 길이 구조에 없다'.
  K4 는 받은 결정(설계 §5 — 입력에 분봉 결과)으로 받는 노드가 하나 는다 → 두 시험을 {가동 요청 · 매매 몫 결합}으로 넓히고 ★매매 몫 결합은 출력이 없다★
  (더 나갈 길 · 순위 키 · 주문 경로 import 없음)를 함께 건다. 가드의 뜻(비교 · 순위 · 비중으로 가는 길 없음)은 그대로다.
- 진입 금액 `amount` · 동시 보유 상한 `max_open_positions`(비우면 상한 없음) · 종목 하나에 포지션 하나(`tk.pos`) · 수량 = 내림(금액 ÷ 가격) → 한 시각에 묶이는 돈은
  금액 × min(상한, 종목 수) 이하이고 매수 수수료(편도 bp)가 그 위에 붙는다(시뮬레이터 관측).
- 국면 = `regime_answer(index, k, from, to)`(K1 문 · K2 나눔 · K3 조건과 ★같은 함수★ · 기간 ≤ 366일 = 분봉 시행 기간의 상한) · 날마다의 줄은 지수 일봉이 있는 날만.
- 모의 모드의 시세 · 지수 · 분봉은 모두 평일 달력(휴장일 없음) — 운영은 KRX 적재 · 증권사 분봉의 거래일이라 어긋날 수 있다(그래서 어긋남을 검사한다).
- 캔버스 칸의 `show_if` 는 문서 값 비교(JSON) — 국면 수에 따라 국면별 몫 칸을 보이고 숨길 수 있다. 숨은 칸의 값은 서버가 쓰지 않는다(다른 노드와 같은 규칙).
- 같은 모양의 견줌 블록이 이미 있다: '두 실행 비교'의 `compare`(`perf_compare.align_curves` · `drawdown_episodes`) → 화면 `BacktestCompareResult` 의 `PerfCompare` · `DrawdownEpisodes` 를 다시 쓴다.

**감사에서 정한 것** (설계 §5 가 적지 않은 세부 — 받은 결정을 바꾸지 않는다)
1. 기간 = 두 곡선이 겹치는 날. ★겹친 구간 안에서 날이 하나라도 어긋나면 거절★(어느 쪽에만 있는 날 수) — 위성의 그날 손익을 모르는 날을 0 으로 채우지 않는다(미상 ≠ 0).
2. 몫을 정하는 날 = 겹친 구간의 첫날과 그 뒤 달마다 첫 거래일. 몫 = Σ 그날 국면 확률(전 거래일 종가까지 · K1) × 표. 그 확률을 모르는 날이 하나라도 있으면 ★거절★(달 · 사유) —
   몫을 지어내지도, 앞 달 몫으로 미루지도 않는다(어느 쪽이든 받지 않은 정책이다).
3. 재조정 = 그날 장 시작 전(전 거래일 종가에 아는 확률로 정한 몫) → 그날의 핵심 수익 · 분봉 손익이 그 몫에 붙는다. 재조정 사이에는 두 몫이 각자의 수익으로 표류한다(날마다 되돌리지 않는다).
   옮긴 몫 = |목표 − 표류한 지금 몫| · 비용 = 옮긴 몫 × ★정책 백테스트의 비용 가정★(`config.cost_bps` — 새 가정을 만들지 않는다). 첫날 핵심에서 위성으로 옮기는 몫도 비용에 든다(두 판 모두).
4. 몫 고정 판 = 같은 날 · 같은 재조정 날 · 같은 비용에 목표만 국면 몫 판의 ★날 가중 평균 목표 몫★으로 고정한 판 — 국면이 몫을 바꾼 것만 뺀 견줌이다. 줄 세우지 않는다(이긴 쪽 키 · 색 없음).
5. 자본 하한 = 진입 금액 × min(동시 보유 상한, 종목 수) × (1 + 수수료율) — 설계의 '진입 금액 × 동시 보유 상한'에 상한이 없을 때(종목 수)와 매수 수수료를 더했다(좁힌 것).
6. 위성 수익률 = 그날 분봉 손익(비용 후) ÷ 매매 몫 자본. ★가정★: 몫이 바뀌면 진입 금액도 같은 비율로 바뀐다고 본다(분봉 시행은 바꾸지 않고 그 손익을 자본 비율로 쓴다) ·
   놀리는 자본은 0%(이자 없음). 둘 다 결과에 적는다.
7. 노드는 출력이 없다(끝 노드) · AI 추천 · 말로 설계의 후보가 아니다(`NOT_OFFERED` — 도구는 표와 자본을 고르지 않는다) · 단추가 없다(계산은 쓰기 0 · 시행이 아니다).

### 7.6 K5 — 하루 유형 비중을 시장 국면의 셋째 특징으로 (감사 · 잰 값 · 계약 · 시험 · 변이 — 2026-11-18)

**감사(읽기 전용 · 관측 · 잰 값은 이 기계 · CPU 빈 때 · csv.gz — 이 환경에 pyarrow 없음)**
- 필요한 분봉: K1 적합 창 750 + 비중 창 20 + 하루(d−1) ≈ 771거래일 + 판정 기간(≤ 366일 ≈ 250거래일) ≈ **1,060거래일 × 바구니 종목**. K1 문은 이미 판정 시작일의
  1,250 달력일 앞부터 지수를 읽는다(`HISTORY_CALENDAR_DAYS` — 750 + 20 + 여유 40 거래일).
- 세는 값: 바구니 30종목만 든 하루 파일(241KB)은 읽기 + 세션 짓기 33ms/일 · 창 벡터 + 배정 ≈ 1ms/일 → 1,000일 34초. 전 종목 하루 파일(2,700종목 · 105만 줄 · 21MB)은
  읽기 0.56초 · 30종목 꺼내기 0.66초/일 → 1,000일 11분. 한 요청의 상한(`MAX_TICKER_DAYS` 2,000 · `MAX_LOAD_BYTES` 200MB · `CHECK_BUDGET_SEC` 8초)에 들지 않는다 → ★나눠 세어 저장★.
- 운영 분봉 이력: KIS 일별분봉의 소급 한도는 문서에 없다(`kis_client.get_minute_bars_dated` 주석) · 탐침(`python -m src.data.minute_bars --probe` · 최대 365일 전)은 이 환경에서 못 돈다 → 미상.
  수집 비용(소급이 허락되면): 종목·일 13콜 · 초당 16콜 → 30종목 × 1,060일 ≈ 41만 콜 ≈ 7.2시간.
- 유형 비율 전체(유형 4 ~ 16)는 합이 1 이라 full 공분산이 특이하고, 국면 4 × 18차원이면 매개변수 약 756개 > 적합 창 750일 → 비율 전체를 그대로 넣을 수 없다.
- 다시 쓰는 것: 세는 준비 = `minute_feed.build_days`(실행 · 학습 · K2b 와 같은 준비) · 배정 = `day_types.collect` + `assign`(모형의 분 수 · 저장된 중심) · 학습 날 검사 =
  `intraday_context` 의 '학습 마지막 날 < 판정 시작일'(`day_type_model_overlaps`) · 국면 = `regime_answer`(K1 문 · K2 · K3 · K4 와 같은 함수) · 등급 = `session_grade` 의 규칙 ·
  화면 = `useDayTypeModels` · `RegimeBand` · `RegimeFacts`. 모의 지수 걸음(2000-01-03 부터)과 모의 분봉은 둘 다 평일 달력이라 날이 맞는다.

**받은 결정(2026-11-18 · 질문 둘)**: ① 적합 창은 K1 과 같은 **750거래일 그대로**(운영에서는 바구니 분봉이 쌓일 때까지 미상 + 사유) · ② 특징은 **"1번 + 3번"** —
사용자가 고른 유형 **하나 이상**(전부는 안 됨)의 **20거래일 합친 비중**. 유형 하나만 고르면 1번(유형 하나의 20거래일 비중)과 같아 1+3 은 1 을 품고, 특징이 숫자 하나라 논리가 어긋나지 않는다.

**감사에서 정한 것** (설계 §6 의 글을 좁히거나 바꾼 것 — 받은 결정은 그대로)
1. '전일 비율' → **전일까지의 20거래일 비중**: 거래일 d 의 국면은 K1 그대로 X[d−1] 을 쓰므로 비중은 d−20 ~ d−1 의 표본만 본다(그날 비율은 쓰지 않는다 — 장 초반 창이 끝나야 안다).

3. 창 안에 세지 않은 날 · 분봉이 없는 날 · 분류된 표본이 0 인 날이 하나라도 있으면 그 창은 미상 + 사유(0 이나 앞 값으로 채우지 않는다 — K1 의 '종가 21개가 모두'와 같은 엄격함).
