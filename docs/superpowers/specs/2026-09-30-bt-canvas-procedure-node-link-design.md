# BT — 캔버스: 설계 절차 · 노드(부품) · 링크(관계) 설계 (2026-09-30)

사용자 지시(`/frontend-design`): "캔버스 공간에서 더 디테일하게 포트폴리오 설계 절차와 노드(컴포넌트)

**참고한 도구**: Houdini(표시 깃발 — 단계마다 결과를 본다 · 선택과 판 동기화) · KNIME(노드를 기존 노드 위로 끌어

### 감사로 확인한 캔버스의 빈틈 (근거)

1. **"다음에 뭘 하지?"가 어디에도 없다.**
   - 관문 사유는 `{state,text}` 뿐이다(`src/domain/workflow_gates.py:37`). 노드 id 도, 붙일 것도 없다.
   - 팔레트는 그래프를 모른다(`NodePalette.tsx:20-32`).
   - 아래 안내 줄은 고정 문구다(`PortfolioCanvas.tsx:1187`).
2. **절차 어휘 둘이 서로 안 이어진다.**
   - 팔레트 6단계(`allocation_graph_nodes.py:114-121`)와 관문 8개(`workflow_gates.py:24-28`)가 따로 논다.
   - 서버가 내는 `category` 17개는 캔버스가 쓰지 않는다.
3. **관문이 노드 종류에 묶여 있다.**
   - cost·oos 는 `backtest` 만 읽는다(`workflow_gates.py:183-188`).
   - 그래서 `strategy_backtest`·`backtest_load` 가 있어도 "과거로 돌려 보는 단계가 없어요"라고 **사실과 다르게** 말한다.
   - 부분 계산 뒤에는 관문이 아예 안 나온다.
4. **노드를 추가해도 선이 안 이어진다.**
   - 팔레트 클릭·Ctrl+K 는 선 없이 가운데에 놓는다(`PortfolioCanvas.tsx:631-643`).
   - 카드의 "‘X’을 이어 주세요"도 누를 수 없다(`GraphNode.tsx:214-218`).
5. **연결 거부가 조용하다.**
   - 같은 타입만 받는데 거부해도 사유가 없다(`PortfolioCanvas.tsx:609-628`).
   - 타입은 맞는데 계산할 때만 실패하는 규칙이 둘 있다.
     - `backtest` 는 옵티마이저의 `req` 가 필요하다 — 비중을 내는 9종 중 8종은 이으면 실패한다.
     - `risk` 는 `sigma_annual` 이 필요하다(`allocation_graph_nodes.py:336-369`).
6. **링크가 불투명하다.**
   - 선에 클릭·호버가 없다(`PortfolioCanvas.tsx:1044-1080`).
   - 선이 싣는 것은 `{evidence, forward, brief}` 뿐이다(`EvidenceEdge.tsx:20-25`).
   - 선 요약은 포트당 첫 선에만 나온다.
   - Belief·BacktestRun·StrategyResult 에는 선 요약이 없다(`allocation_graph_glance.py:363`).
7. **영향이 안 보인다.**
   - "예전 결과"가 전역 불리언 하나다(`store.ts:88`). 설정 하나만 바꿔도 **모든** 카드가 낡은 것이 되고 선 모양이 사라진다.
   - 하류 계산(`descendantsOf`)이 없다.
   - 설정의 "내는 것"은 타입 이름만 보인다(`SettingsPanel.tsx:486`).
8. **컴포넌트로서의 노드가 약하다.**
   - 84종 중 35종은 포트가 없다(혼자 쓰는 도구). 그런데 흐름 노드와 구분이 없다.
   - 같은 자리에 다른 방법으로 **바꾸기**가 없다.
   - 선 **사이에 넣기**가 없다.
   - 포트 이름은 호버로만 보인다.
   - 연습용 칩은 문구 부분일치로 판정한다(`GraphNode.tsx:52`).
   - `universe`·`views`·`estimate` 는 자세히 탭에 원시 JSON 으로 나온다.
9. **시작점이 한 번뿐이다.** 목표·템플릿은 캔버스를 통째로 바꾸고 끝난다. 그 뒤에 남은 단계를 알려 주지 않는다.

### 지켜야 할 기존 결정 (문서 감사)

- **설명은 서버가 쓴다.** 화면은 그리기만 한다(BJ 스펙, ADR-002:73-75). 그래서 절차·다음 한 걸음·링크 역할 문장은 **서버**가 낸다.
- **값을 지어내지 않는다.** 포트 값 팝오버는 BM 에서 기각됐다(값을 지어내게 되므로). 링크 보기는 서버가 준 선 요약·계보·역할만 쓴다.
- **"최선"을 자동으로 고르지 않는다.** BM 에서 자동 스윕·"best branch" 는 기각됐다. 다음 한 걸음은 **빠진 단계**를 제안할 뿐 설정값을 추천하지 않는다.
- **툴팁 금지**(ADR-001:214-216). 사유는 보이는 줄에 둔다.
- **CSS 클래스·data 속성은 E2E 계약**이다(`.pg-*` 전부). 바꾸면 스펙도 같은 커밋에서 고친다.
- **다른 탭 토스화는 이 셋을 바꾼다.** 그래서 ADR-003 으로 명시적으로 정정한다.
  - BJ 는 "앱 전체 재단장"을 하지 않을 일로 적었다(BJ:86-88).
  - ADR-002 는 "시각 언어는 `.pg-theme` 안에만"이라고 정했다(:82).
  - ADR-001 은 "institutional, data-dense, 장식 그림자 없음"을 스타일로 정했다(:117-123).
- **BS5 라이트 골든**(`frontend/e2e/golden/light-styles.json`, 13 라우트)은 라이트가 바뀌면 깨진다.
  - 모듈을 하나씩 바꿀 때마다 **의도적으로** 다시 뜬다.
  - 전·후 PNG 를 눈으로 보고, 바뀐 조합 수를 커밋 메시지에 적는다.
- 금지 표현(검증됨·입증됨·견고함·프로덕션 레디·투자 우위·더 나은 전략)은 서버 테스트가 막는다. 새 서버 문장도 그 검사를 통과해야 한다.


## 설계 — 그래프가 스스로 절차를 말한다 — "그래프가 스스로 절차를 말한다"

**한 가지 생각**: 절차는 따로 있는 마법사가 아니다. **지금 그래프에서 읽어 낸다.**
- 서버는 그래프를 보고 세 가지를 말한다: 어느 단계가 채워졌는지, 어느 관문을 잴 수 있는지, 다음에 무엇을 붙이면 되는지.
- 캔버스는 그것을 세 곳에 그린다: 왼쪽 **절차** 탭, 아래 **다음 한 걸음** 줄, 관문 알약.
- 노드는 **바꿔 끼울 수 있는 부품**이고, 선은 **무엇이 왜 흐르는지 말하는 관계**다.
- 눈에 띄는 요소는 하나만 둔다: **절차 탭 ↔ 캔버스 양방향 하이라이트**. 나머지는 조용히 둔다.

### BT1 · 서버: 절차 모델 + 관문의 노드 연결 + 포트 역할·조건 (순수, TDD)

- **새 `src/domain/design_procedure.py`** (순수 — DB·설정·네트워크를 읽지 않는다. `workflow_gates` 처럼 AST 테스트로 막는다).
  - 입력: 노드·선·`stage_of`·카탈로그 포트.
  - 출력 `procedure`:
    - `steps[6]`: STAGES 를 그대로 쓴다. 각 단계는 `{key, label, need, state, node_ids, feeds_gates, text}`.
      - `need`: 필수(data·build) · 권장(check — 거래비용·처음 보는 기간을 잴 수 있게 한다) · 선택(signal·belief·act).
      - `state`: 채움 · 비어 있음 · 막힘(그 단계 노드에 빠진 입력이 있음).
    - `next`: **한 가지** `{kind, text, attach:{node, port, to_port}|null, unlocks:[gate]}` 또는 `null`.
    - `by_gate`: 관문마다 붙일 것 하나. 관문 알약이 쓴다.
  - `next` 규칙(앞 규칙이 이긴다):
    1. 있는 노드에 **빠진 필수 입력** → 그 타입을 내는 노드를 제안하고 그 포트에 잇는다.
    2. 데이터 없음 → `returns`.
    3. 비중 없음 → `optimizer`.
    4. 옵티마이저는 있는데 과거로 돌려 보기가 없음 → `backtest` 를 옵티마이저 Weights 에 잇는다(unlocks cost·oos).
    5. 확인하기 단계 없음 → `risk`.
    6. 다 찼음 → `null`, 문구 "절차를 다 채웠어요 — 계산해 보세요".
  - ★문장은 "잴 수 있게 돼요"까지만 쓴다★ — "좋아져요·통과해요"는 쓰지 않는다. 금지 표현 검사도 통과해야 한다.
  - ★설정값은 추천하지 않는다★ — 빠진 **단계**만 제안한다(BM 기각 사항 준수).
- **`/validate` 가 `procedure` 를 싣는다.**
  - 편집마다 이미 debounce 로 불리므로 계산 전에도 절차가 보인다.
  - `/run` 은 `gates` 옆에 같은 `procedure` 를 싣는다.
  - ★빈 그래프도 검증한다★: 지금은 `PortfolioCanvas.tsx:598` 이 노드가 0 이면 검증을 건너뛴다. 그래서 빈 캔버스에 절차가 없다 → 빈 문서도 보낸다(서버는 ok 를 준다).
  - 검증이 네트워크로 실패하면 절차 칸은 "절차를 불러오지 못했어요 · 다시 시도" 상태가 된다(`:602` 의 `null` 을 그대로 두지 않는다).
- **관문마다 `node_ids`** — 그 관문 판정에 쓰인 노드(관문 단위. 사유 단위로 나누지 않았다 — 알약에서 노드로 건너뛰는 데는 관문 단위로 충분하다).
- **관문 문장 정정 (사실과 다른 "단계가 없어요")**:
  - `NodeSpec` 에 **명시적 깃발 `simulates_history: bool`** 을 둔다. `perf_label` 로 추론하지 않는다 — 옵티마이저도 백테스트 `perf_label` 을 싣는다(`allocation_graph_nodes.py:326`).
    - 켜는 종류(구현): `backtest` · `strategy_backtest` · `backtest_setup` · `backtest_load` · `backtest_compare` · `backtest_attribution` · `timing_simulation` · `counterfactual` · `record_robustness` — 전략을 과거에 돌려 본 **기록**을 내거나 읽는 것만.
    - 뺀 것: `alpha_validate`(신호 검증) · `sleeve_analytics`(표본 안 관측) · `rolling_sharpe`·`strategy_health`·`regime_forecast_coverage`·`scenario_stress` — 비용·처음 보는 기간과 관계가 없어 "있지만 읽지 않아요"라고 말할 대상이 아니다.
    - 트립와이어는 목록을 고정하고, 추가되면 사람이 판단하게 한다.
  - `evaluate(..., history_types=)` 로 **라우트가 넘긴다**. 순수 모듈은 `src.*` 를 import 하지 않는다(`test_workflow_gates.py:124-130`).
  - 그 노드가 있고 `backtest` 가 없으면 cost·oos 를 바꾼다.
    - 상태는 **unknown**, 사유는 "‘전략 백테스트’가 있지만 이 관문은 아직 그 결과를 읽지 않아요".
    - 건너뜀보다 정확하다. 통과는 여전히 아니다.
  - 부분 계산 뒤 `gates:null` 은 그대로 둔다(기존 결정).
  - 짝 테스트 둘: 없으면 skipped, 있으면 unknown.
  - ★판정 규칙을 넓혀 그 노드의 비용을 "확인"으로 읽는 것은 하지 않는다 — 별도 감사 사항.★
  - 프런트의 `OWN_PERF_LABEL`(`NodeResultPanel.tsx:293`)도 같은 지식을 손으로 들고 있다. 카탈로그 깃발로 대체할 수 있으면 대체하고, 못 하면 HISTORY 에 적는다.
- **포트에 칸을 더한다** (`Port` frozen dataclass 끝에 기본값 `""`·`()` — 해시 가능하게 둔다. 모든 등록은 `P("name","Type")` 위치 인자라 그대로 동작한다).
  - `role: str` — 받는 쪽이 이 입력을 **무엇에 쓰는지**. 예: "비중 계산이 종목끼리 같이 움직이는 정도(공분산)를 재는 데 써요".
    - 흐름 노드 49종의 입력 포트에 쓴다. 못 쓴 곳은 비워 두고 화면도 그 줄을 생략한다(지어내지 않는다).
  - **입력 `needs`** — 받는 쪽 조건:
    - `req` 가 필요한 것은 **셋**이다: `backtest`(`allocation_graph_nodes.py:364-369`) · `rebalance_decision`(`_alloc_extra.py:86-89`) · `sensitivity`(`_check.py:235-238`).
    - `sigma_annual` 이 필요한 것은 `risk` 하나다(`:335-338`).
  - **출력 `gives`는 세 모양이어야 한다**(정적 튜플 하나면 오늘 되는 것을 틀리게 막는다):
    - `always` — 늘 준다. 예: 옵티마이저의 `req`·`sigma_annual`.
    - `when_input` — 그 입력이 이어졌을 때만 준다. 예: `scores_to_weights` 는 선택 입력 `returns` 가 있으면 `sigma_annual`.
    - `from_input` — 입력에서 넘겨받는다. 예: `exposure_overlay` 는 받은 비중의 `sigma_annual`.
  - **`needs_unmet` 은 `validate()`/`/validate` 라우트에서만, `_analyse` 뒤에 낸다.**
    - `_analyse` 안에 두면 `_execute` 가 노드를 `blocked` 로 바꿔 계산 결과가 달라진다(`portfolio_graph.py:517-524`). 그러면 bk0·bl4·combine·w3 테스트가 깨진다.
    - **실패가 정적으로 확실할 때만** 낸다(넘겨받기 사슬까지 따라간다). 확실하지 않으면 내지 않는다.
    - 템플릿 6개는 `v.errors == []` 여야 한다(`e2e/portfolio-graph.spec.ts:553-557`). 스크리너 템플릿(점수→비중 + 수익률 → risk)은 걸리면 안 된다.
    - 실행 때의 기존 거절은 그대로 둔다(두 겹).
  - 카탈로그가 `role`·`needs`·`gives` 를 싣는다.
    - 정확 비교 테스트 둘을 같은 커밋에서 고친다: `tests/test_allocation_graph.py:296-300` · `tests/test_portfolio_graph_engine.py:266-268`.
    - 프런트 `CatalogPort`(`types.ts:69-73`)도 넓힌다.
  - **선언이 참인지 검증한다**(트립와이어보다 강하게): 비중을 내는 9종을 mock 으로 실제로 돌린다.
    - 선언한 키는 None 이 아니어야 한다.
    - 짝으로, 선언하지 않은 키는 None 이어야 한다(조건부는 입력 유무 두 경우 모두).
- **선 요약**: Belief("과거 기준"/"경기 국면 반영" — 추정 노드를 실제로 돌려 값 모양을 확인했다). BacktestRun·StrategyResult 는 저장된 실행 없이 모양을 확인할 수 없어 BN N2 결정대로 요약하지 않는다.
- **`fix` 문장**(보완 참조): 오류 코드마다 고치는 법 한 줄. 서버가 쓴다.
- **pytest**:
  - 단계 상태: 빈 그래프 · 핵심 사슬 · 입력 빠짐.
  - `next` 규칙 1~6 각각. 짝으로, 해당 조건이 없으면 그 제안이 나오지 않는다.
  - `unlocks` 가 관문 키와 일치한다.
  - `needs_unmet`

    - overlay(옵티마이저 비중) → risk 는 오류 없음.
    - `/run` 결과는 기존 테스트 그대로다.
  - 관문 `node_ids`, `simulates_history`, 금지 표현, 순수성 AST.

  - 규칙 순서 바꾸기
  - `needs` 검사 빼기
  - `when_input` 을 `always` 로
  - `from_input` 무시
  - unknown 을 skipped 로
  - `node_ids` 비우기
  - "잴 수 있게" 를 "통과" 로

### BT2 · 절차 탭 (왼쪽 판) + 관문 알약 ↔ 노드

- **왼쪽 판 머리에 분할 단추 `절차 | 노드 추가`** (`.pg-left-tabs`).
  - 필수·권장 단계가 비어 있으면 절차 탭을 먼저 연다. 마지막 선택은 localStorage 에 둔다(try/catch).
- **절차 탭** (`.pg-proc`): 세로 단계 목록 6줄(`.pg-proc-step[data-step]`). 실제로 순서가 있는 내용이라 번호를 쓴다.
  - 각 줄:
    - 상태 표식(채움 ● · 비어 있음 ○ · 막힘 !)
    - 단계 이름
    - 한 줄 상태 — 서버 `text`, 예: "비중 계산 1개 · 위험 성향 보통"
    - 필수/권장/선택 꼬리표
    - 이 단계가 재는 관문 점(알약 점과 같은 색)
  - 비어 있는 필수·권장 단계에는 `[붙이기]` 단추를 둔다. 누르면 서버 `by_gate`/`next` 의 노드를 **이어서** 추가한다(되돌리기 한 번).
  - **양방향 하이라이트**:
    - 단계에 올리거나 초점을 두면 그 단계 노드가 또렷해지고 나머지는 흐려진다(기존 `.pg-dim` 재사용). 누르면 그 노드들로 fitView.
    - 반대로 노드를 고르면 그 단계 줄에 표시가 켜진다(`.pg-proc-step--here`).
  - 계산 전이면 이렇게 쓴다: "계산하면 관문마다 무엇을 확인했는지 여기서 알려 드려요."
- **관문 알약** (`GateRail.tsx`):
  - 역을 누르면 뜨는 팝오버(`.pg-gate-pop`)에 두 가지를 더한다.
    - "이 관문을 만든 노드" 목록(`.pg-gate-node`) — 누르면 그 노드로 이동하고 고른다.
    - 건너뛴 관문이면 `[‘과거로 돌려 보기’ 붙이기]`(`.pg-gate-fix`) — `by_gate` 를 쓴다.
  - `IDLE_STATIONS` 클라이언트 사본을 없애고 카탈로그의 관문 이름을 쓴다(서버에 `gates_meta` 추가).
- **E2E** (`canvas-procedure.spec.ts` 새로):
  - 빈 캔버스에서 절차 탭이 열리고, 데이터 단계에 `[붙이기]` 가 있다.
  - 누르면 노드가 생기고 **선이 이어진다**.
  - 단계에 올리면 그 노드만 또렷하다(짝: 다른 단계 노드는 `.pg-dim`).
  - 노드를 고르면 단계 표시가 켜진다.
  - 알약 cost 역 → `[붙이기]` → backtest 가 옵티마이저에 이어진다.
  - 역의 노드 목록 → 누르면 선택된다.

### BT3 · 다음 한 걸음 + 추가하면 이어진다

- **아래 안내 줄**(고정 문구)을 서버 `next` 로 바꾼다(`.pg-next`).
  - 예: "거래비용을 아직 재지 않았어요. ‘비중 계산’ 뒤에 ‘과거로 돌려 보기’를 붙일까요?" + `[붙이기]`·`[다음에]`.
  - `[다음에]` 는 그 그래프 모양(노드 종류 집합)에 대해 이번 세션 동안 숨긴다.
  - `next` 가 없으면 예전 조작 도움말로 돌아간다.
- **목표로 시작·템플릿 뒤**에는 다음 한 걸음이 남은 단계를 이어서 말한다. 따로 체크리스트를 만들지 않는다 — 절차 탭이 그 체크리스트다.
- **팔레트·Ctrl+K 로 추가할 때 사용자가 노드를 직접 골라 두었으면**:
  - `addNode` 는 새 노드를 자동으로 고른다(`store.ts:378`). 그래서 이것을 "직접 고름"으로 치면 두 번 연속 누를 때 사슬로 이어져 버린다.
    - 사용자 클릭·키보드로 고른 것만 센다. store 에 `pickedByUser` 를 두고 `addNode` 가 지운다.
  - 새 노드의 입력이 고른 노드의 출력을 받을 수 있으면, 고른 노드 **오른쪽 열**(`COL`)에 놓고 잇는다.
  - 토스트: "‘비중 계산’ 뒤에 이었어요 · 되돌리기". 이을 수 없으면 지금처럼 놓는다.
- **카드의 "‘수익률’을 이어 주세요"를 단추로** (`.pg-node-need` 는 그대로 두고 안에 `button` 을 둔다).
  - 누르면 그 입력 포트에서 끈 것과 같은 QuickAdd 가 연다(target 쪽 — `quickadd.ts` 가 이미 지원한다).
  - 고르면 왼쪽 열에 놓고 잇는다.
- **E2E**:
  - 다음 한 걸음이 서버 문구 그대로 보인다.
  - `[붙이기]` 뒤 문구가 바뀐다(다음 규칙으로).
  - 노드를 고른 채 팔레트 클릭 → 선이 1개 는다. 짝: 고르지 않았으면 선 0.
  - 팔레트를 두 번 연속 누르면 선은 1개만 는다(자동 선택으로 사슬이 생기지 않는다).
  - "이어 주세요" 단추 → QuickAdd 가 수익률을 내는 노드만 보인다.

### BT4 · 링크 = 관계 — 선 살펴보기 · 연결 안내 · 사이에 넣기

- **선을 누르면 오른쪽 판에 "선" 탭**이 열린다(`data-tab="wire"`, `.pg-wire-sheet`).
  - 판 폭·여닫기는 BQ 규칙을 따른다. 내용은 서버 값만 쓴다.
  1. **무엇이 흐르나요** — 포트 타입 쉬운 이름 + 선 요약(서버 brief). 예: "수익률 표 · 3종목 · 756일".
  2. **어디서 어디로** — "‘수익률 불러오기’의 수익률 → ‘비중 계산’의 수익률 자리". 두 노드 이름은 누를 수 있다.
  3. **무엇에 쓰이나요** — 받는 포트의 `role`(BT1). 없으면 줄을 생략한다.
  4. **믿을 수 있나요** — 흐르는 값의 계보 칩(연습용 · 지금 시점 전용 · 노출 조절됨). 선 모양 범례와 같은 말을 쓴다. ★"실데이터"라고 부르지 않는다(BM :44)★.
  5. **끊으면** — "‘비중 계산’부터 4개 노드가 계산되지 않아요" + 이름 목록(하류 — BT5 `descendantsOf`).
  - 단추: `[사이에 노드 넣기]` · `[끊기]`(되돌리기 토스트).
- **선에 올리거나 초점을 두면** 가운데에 타입 이름 알약이 뜬다(`.pg-wire-type`). 툴팁이 아니라 보이는 요소다. 키보드 초점도 받는다(선에 `tabIndex`).
- **끌고 있는 동안**:
  - 이을 수 있는 포트는 또렷해진다(`.pg-port--can`). 안 되는 포트는 흐려진다.
  - `needs` 조건이 안 맞는 포트는 다른 표시(`.pg-port--needs`)와 사유를 함께 띄운다.
- **거부를 말한다**: 안 되는 곳에 놓으면 토스트에 사유를 적는다.
  - 타입이 다를 때: "‘비중’은 ‘수익률’ 자리에 이을 수 없어요 — 같은 색 점끼리 이어요."
  - 입력이 이미 있을 때: "이 자리에는 이미 ‘수익률 불러오기’가 이어져 있어요."
  - 고리가 생길 때: "이으면 고리가 생겨요."
  - `needs` 가 안 맞을 때: 서버 사유를 쓴다.
  - 지금처럼 조용히 거부하지 않는다.
- **사이에 넣기**:
  - 선 판의 단추 → 같은 타입을 받아 같은 타입을 내는 노드만 보이는 QuickAdd. 예: 비중 → 노출 조절(비중에 적용) → 비중.
  - 팔레트에서 노드를 끌어 선 위에 놓으면 선이 강조되고, 놓으면 끼워진다(KNIME 식).
  - 되돌리기는 한 번이다.
- **선 요약 표시**: 포트당 첫 선에만 그리던 규칙은 둔다(겹침 방지). 선 판에는 **모든** 선의 요약이 나온다.
- **E2E**:
  - 선 클릭 → 선 탭 다섯 줄이 서버 값 그대로 나온다.
  - `role` 없는 포트는 3번 줄이 없다(짝).
  - 연습용 계보 칩이 보인다. 짝으로, 연습용이 아닌 흐름에는 없다.
  - 사이에 넣기 → 선 2개 · 노드 1개가 는다.
  - 잘못 이으면 사유 토스트가 뜨고 선 수는 그대로다.
  - 끄는 동안 `.pg-port--can` 수가 0보다 크다. 짝으로, 안 되는 포트에는 없다.

### BT5 · 영향 — 노드별 "예전 결과" + 바꾸기 전에 보이는 하류

- **`store.ts` 의 전역 `reportStale` 을 `staleIds: Set<string>` 으로 바꾼다.**
  - 쓰는 곳은 store 약 23곳, 읽는 곳은 `PortfolioCanvas`·`GraphNode`·`GroupFrame`, props 로 받는 곳은 Story·BranchCompare·SaveBox·NodeResultPanel·SimpleView 다.
  - 호환용 파생값 `reportStale = staleIds 중 결과가 있는 노드가 하나라도 있음` 을 두어 읽는 곳을 한 번에 다 바꾸지 않아도 되게 한다.
  - 규칙:
    - 설정을 바꾸면 그 노드와 하류가 낡는다.
    - 선을 더하거나 빼면 받는 노드와 하류가 낡는다.
    - 노드를 지우면 하류가 낡는다.
    - 무리 이름 편집은 `portfolio_combine` 설정을 바꾸므로 그 노드와 하류가 낡는다.
    - 갈래 만들기·지우기·승격은 영향받는 노드와 하류가 낡는다.
    - 붙여넣기로 생긴 새 노드는 결과가 없다.
    - `loadDoc` 은 결과를 비운다(기존).
    - **되돌리기·다시하기**는 스냅샷 전·후를 비교해 설정·선이 달라진 노드와 하류를 낡게 한다. 비교가 불가능하면 결과가 있는 모든 노드를 낡게 한다(보수적 대체 — 이름을 붙여 기록).
  - 나머지 카드는 결과·선 모양·glance 를 **그대로** 둔다.
  - 계산이 끝나면: 전체 계산은 비운다. 부분 계산은 **계산한 노드만**(`report.partial.computed`) 지운다.
  - ★정직성★ 관문 알약은 낡은 노드가 하나라도 있으면 "예전 결과 기준"이라고 쓴다(관문은 그래프 전체 판정이라서).
  - `descendantsOf` 를 `store.ts` 에 더한다(`ancestorsOf` 옆).
- **도구줄 요약**: "예전 결과 3개 · [바뀐 곳만 계산]". 단추는 낡은 노드들을 `targets` 로 하는 부분 계산(기존 "여기까지 계산" 경로)이다.
  - 부분 계산은 관문을 내지 않는다는 기존 사유 문구를 그대로 보인다.
- **설정 판 머리에 한 줄**: "이 노드를 바꾸면 4개 노드가 다시 계산돼요". 올리면 그 하류가 캔버스에서 또렷해진다.
- **"내는 것"**: 타입 이름 대신 **받는 노드** 목록(누를 수 있음)으로 바꾼다. 아무도 안 받으면 "아직 아무 노드도 받지 않아요".
- **테스트**:
  - store 단위 테스트는 E2E 로 한다(프런트 단위 러너가 없다 — 기존 결정).
  - 하류 설정을 바꾸면 상류 카드는 결과를 유지한다. 짝으로, 하류 카드는 `.pg-node--stale`.
  - 선 모양도 상류는 유지된다.
  - `[바뀐 곳만 계산]` 이 낡은 표시를 지운다.
  - 영향 줄 숫자가 실제 하류 수와 같다.
  - 되돌리기 뒤에는 바뀐 노드와 하류만 낡는다.
  - 부분 계산 뒤에는 계산 안 한 낡은 노드가 계속 낡은 것으로 남는다(짝).
  - 기존 `canvas-workspace.spec.ts:303-307` 을 새 의미로 고친다.
    - 지금은 `views` 복제(Ctrl+D)로 전역 낡음을 기대한다.
    - `views` 설정 변경으로 바꾸고, 상류 선 모양이 **유지**되는 짝을 더한다.
    - `.pg-summary--stale`·`.pg-simple-stale`·저장 잠금(`portfolio-graph.spec.ts:444-449`)은 결과 있는 노드가 낡으면 계속 보여야 한다.
  - 변이: 하류 전파 빼기(바로 아래만) · 상류까지 표시 · 부분 계산 뒤 모두 비우기.

### BT6 · 부품 — 바꿔 끼우기 · 혼자 쓰는 도구 · 팔레트가 그래프를 안다

- **"다른 노드로 바꾸기"** (우클릭 메뉴 + 설정 판 머리 `.pg-swap`):
  - 후보는 지금 들어오는 선의 타입을 모두 받고, 나가는 선의 타입을 모두 내는 종류다.
  - 자리·선을 유지하고 설정은 새 종류의 기본값으로 둔다. 이 점을 토스트에 쓴다.
  - 되돌리기는 한 번이다. 예: 기대 수익 추정 방법끼리, 비중 방법끼리.
  - 후보가 없으면 메뉴 항목을 흐리게 하고 사유를 적는다: "같은 선을 받는 다른 노드가 없어요".
- **혼자 쓰는 도구 35종**(포트 없음):
  - 팔레트 각 단계 안에서 아래쪽 소제목 "혼자 계산하는 도구"로 모은다(`.pg-palette-solo`).
  - 카드에는 포트 자리 대신 한 줄을 둔다: "선 없이 혼자 계산해요"(`.pg-node--solo`).
  - 포트를 새로 만들지는 않는다(백엔드 계약 변경 — 하지 않는 것).
- **팔레트 머리 "지금 이을 수 있어요"**(노드를 골랐을 때만 보인다, `.pg-palette-next`):
  - 고른 노드의 출력을 받는 종류를 단계 순서로 최대 5개 보인다.
  - 누르면 BT3 규칙으로 이어서 추가한다.
- **E2E**:
  - 바꾸기 → 노드 종류가 바뀌고 선 수·자리가 같다.
  - 후보가 없으면 흐린 항목과 사유가 보인다(짝).
  - 혼자 도구 카드에 포트 핸들이 0개다. 짝으로, 흐름 노드에는 있다.
  - 팔레트 "지금 이을 수 있어요" 항목 누름 → 선이 1개 는다.

### BT7 · 노드 카드·판 다듬기 (부품 명세)

- **설정 판 머리를 "이 노드" 명세로 모은다** (`.pg-passport`). 흩어진 것을 한곳에 둔다.
  - 단계
  - 받는 것(포트 쉬운 이름 ← 보내는 노드)
  - 내는 것(→ 받는 노드)
  - 가정 n
  - 재지 않은 것 n
  - 계산 시간
  - 계보 칩
- **포트 이름**: 확대 "가까이"에서는 점 옆에 쉬운 이름을 보인다(Blender·Unreal 식). 중간·멀리는 지금처럼 점만.
- **연습용 칩**: 판정은 지금처럼 노드 자신의 `explain.trust` 로 둔다.
  - 계보 `practice` 로 바꾸면 합성 `returns` 의 하류 **모든** 노드에 칩이 붙는다(계보가 전이된다). 결과가 같지 않다.
  - 하류의 연습용 여부는 이미 선 모양(점선)과 BT4 선 판이 말한다.
