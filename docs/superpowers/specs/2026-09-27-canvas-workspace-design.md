# 캔버스 작업실 설계 (BM) — 결과가 보이는 노드 · 전략 × 단계 지도 · 갈래 비교 · 처음 사용자

> 2026-09-27 · 사용자 승인 · 계획 `happy-percolating-falcon.md` §BM. 앞선 캔버스 설계: `2026-09-25-aas-node-canvas-design.md` · ADR 002.

## Context

BL0~BL4 로 플랫폼의 분석 도구 82 종이 노드가 됐고 마법사는 사라졌다(`/allocation` = 캔버스 하나). 이제 캔버스가 유일한 작업
공간인데, 사용자가 꼽은 불편(우선순위 순):
1. **결과가 캔버스에 안 보인다** — 노드를 눌러 오른쪽 '자세히' 탭을 열어야 숫자가 보인다.
2. **큰 그래프가 금방 엉킨다** — 그리고 캔버스는 설계 스튜디오이면서 **전체 포트폴리오(여러 퀀트 전략)의 흐름을 파악하는
   공간**이어야 한다(사용자 추가 요구). 전략들은 **합쳐서 하나의 포트폴리오**가 된다.
3. **'이 조건이면?' 비교가 번거롭다** — 지금은 노드를 복제해 손으로 잇는다.
4. **처음 쓰는 사람에게 어렵다.**
+ 조사에서 발견한 것도 함께 반영(아래 "덧붙인 것").

사용자 결정(이번 질문): 확대 수준별 노드(더 적합한 게 있으면 발전) · 단계 레인 + 묶음을 노드로 접기 · 여러 전략을 한 캔버스에서
합쳐 한 포트폴리오로 · '내 블록'은 브라우저 저장 + 파일 · 비교는 **갈래 만들기 + 차이만 보기**(사람이 정한 갈래 ≤4 — 자동 스윕 금지) ·
처음 사용자는 **목표로 시작 + 간단히 보기**.

## 설계

### 디자인 방향 (frontend-design)
- 토큰·서체는 BJ 그대로(Pretendard · `--pg-*` · 단계 색 6). 새 토큰은 **전략 띠 6색**(단계 색·상태 색과 겹치지 않는 저채도 —
  라이트/다크 각각, AA 대비 검사) 과 **증거 선 3 모양**만.
- **대담함은 한 곳: 포트폴리오 지도.** 멀리서 보면 캔버스가 "전략(가로 띠) × 단계(세로 레인)" 격자가 되고, 노드는 헤드라인 숫자
  하나, 선은 증거 모양(실선 = 합성 아님(등급은 노드가 말함) · 점선 = 연습용 합성 · 짧은 가로 눈금 = 지금 시점 전용 · 끊긴 회색 =
  막힘)으로 흘러 오른쪽 포트폴리오 레인에 모인다. ★실선을 '실데이터' 라고 부르지 않는다★ — DB 적재분 등급은 미상이다(범례 문구 그대로).
  나머지(카드·패널)는 조용히.
- 모션은 사용자 동작에 답할 때만: 목표로 시작 → 노드가 위상 순서로 한 번 자라남(감속 모션 존중) · 들어가기/나오기 전환.

### C1 · 결과가 캔버스에 보인다 (우선 1)
**확대 수준별 노드(semantic zoom)** — `useStore(s => s.transform[2])` 로 세 단계:
- 멀리(< 0.55): 단계 색 점 + 쉬운 이름 + **헤드라인 숫자** 하나(+ 상태 점). 텍스트 최소 11px 유지(가독 하한은 CSS 역보정).
- 보통: 지금 카드 + 칩 + **제목 줄 경고 수**(trust 의 실패·모름).
- (구현 메모) 단계 문턱은 `ZOOM_FAR=0.55`·`ZOOM_NEAR=1.05`, 최소 확대 0.2. 확대 값은 캔버스 요소의 `data-zoom`·`--pg-z` 로만 옮겨 노드를 다시 그리지
  않는다. 멀리의 글자 크기는 `min(34px, 11.5px / z)` — 화면에서 11px 이상이 **확대 약 0.34 까지** 지켜진다(그 아래는 줄어든다 — 계획의 "11px 유지" 는
  이 범위에서만 참). 미리보기 고정은 화면 정보이고 **파일에 저장하지 않는다**(세션 한정 — 문서 포맷 불변).
- 가까이(> 1.05) 또는 노드의 **미리보기 고정** 켜짐: 카드 안 **작은 그림(glance)** — 막대(비중·기여) · 선(곡선) · 분포(히스토그램) ·
  값 목록 중 하나 + **계산 시간**.
- **glance 는 서버가 만든다**(화면이 계산하지 않는다는 BJ 원칙): `NodeSpec.glance(view) -> {kind, points≤24, labels, unit, caption}` 선택
  함수. 없으면 `explain.headline` 만(그림 없음 — 지어내지 않는다). 우선 20 종(옵티마이저·위험·백테스트·충격·VaR·MC·프런티어·국면·
  타이밍·노출 조절·알파·가치평가 등)에 구현. 값이 없으면 glance = null(빈 그림 금지).
- **선 위 요약** — ~~`summary.ts` 재사용~~ → **구현에서 바꿈**: `summary.ts` 는 파라미터 요약이라 선을 흐르는 **값**을 모른다. 그래서 서버가 쓴다:
  `Registry.set_port_brief(포트 타입, fn)` → 결과의 `briefs: {출력 포트: 한 줄}`(Universe "3종목" · Returns "3종목 · 756일" · Weights "2종목 · 합 100%" —
  보유 수는 보기 `_w_dict` 와 같은 잡음 문턱, 합이 NaN 이면 "합 모름"). 요약 함수가 없는 타입은 키가 없다(라벨 없음). 보통 이상 확대에서만.
  보통 이상 확대에서만.
- **증거 선** — 선 모양 = 원천 노드 계보(`lineage.practice`·`pit`·상태). 범례는 상단 바 한 줄.
- **실행 시간** — 엔진이 노드별 `elapsed_ms` 를 보고(`portfolio_graph._execute`), 카드(가까이)와 전략 상자 합계에 표시.
- **원인 경로** — 막힌/실패 노드의 사유를 누르면 실패한 첫 상류까지 경로가 밝아지고 나머지는 흐려짐(BL1 '여기까지 계산' 경로 강조 재사용).

### C2 · 큰 그래프와 여러 전략 (우선 2)
- **전략 상자** — 묶음 상자(BL1 `GroupFrame`)를 확장: `groups[].kind: "group" | "strategy"`, `color`, `output`(전략의 비중을 내는 노드 id).
  문서 포맷은 **선택 칸만 추가**(옛 문서 그대로 읽힘 — 버전 불변). 서버로 가는 그래프에는 여전히 없다(화면 정보).
- **접기 = 포트 달린 노드**(ComfyUI) — 접힌 상자는 경계를 넘는 선을 상자 가장자리의 대리 포트로 다시 그린다(실제 간선은 불변).
  더블클릭 = **들어가기**: 나머지를 흐리고 그 상자에 맞춰 확대, 상단 빵부스러기 "포트폴리오 › 전략 A"(Esc 로 나옴).
- **단계 레인 × 전략 띠 격자** — 배경에 단계 레인 6(데이터→신호→생각→비중→확인→실행) + 맨 오른쪽 **포트폴리오 레인**. 전략 상자는 가로 띠.
  **자동 정리**는 (전략 띠 행 × 단계 열) 칸에 배치하도록 BL1 위상 깊이 정리를 확장(새 의존성 없음).
  > **BN N1 (2026-09-27) 로 바뀜** — 사용자 결정: "전략 지도도 원래 캔버스의 노드 링크 UI 로". 배경 레인·포트폴리오 레인을 걷고, 자동 정리는 전략마다
  > 한 줄(흐름 깊이 순서) + 포트폴리오 노드는 오른쪽(여럿이면 세로로 쌓음). **접은 전략 = 노드 카드 한 장**(노드와 같은 몸·포트, 큰 숫자 = 서버 몫).
  > 선은 모두 포트 타입 색·같은 굵기(몫만큼 굵은 선은 만들지 않음). `docs/HISTORY.md` 의 BN N1 참고.
- **포트폴리오 노드 `portfolio_combine`**(백엔드 새 노드 — 기존 `sleeve_combine.combine_sleeves` 를 **그대로** 부름, N 지원 확인됨):
  입력 Weights 8(2 필수 + 6 선택, 포트 이름 = 전략 이름 라벨) · 방식은 `sleeve_combine` 과 같은 선택지 · 출력 Weights + 보기(전략별 몫·위험
  분담·상관). 골든 = `combine_sleeves` 직접 호출. 두 전략 미만·시세 부족은 사유 실패. **배분 정책 변경이 아니다**(같은 함수, 입력 수만).
- **전략 추가** — 명령 팔레트·빈 띠의 "+ 전략": 템플릿 또는 '내 블록'을 새 띠로 넣고 비중 출력을 포트폴리오 노드 빈 포트에 잇는다.
- **내 블록** — 상자를 "내 블록으로 저장": `localStorage`(try/catch — 없으면 파일만) · 팔레트 "내 블록" 절("이 브라우저에만" 라벨) ·
  `*.pgblock.json` 내보내기/불러오기(포맷 검사·모르는 노드 보존은 그래프 파일과 같은 규칙).
- **찾기·필터** — 팔레트 검색과 별개로 캔버스 필터 칩(실패 · 막힘 · 연습용 · 지금 시점 전용 · 가정 있음): 맞지 않는 노드·선을 흐린다(Dataiku).
  고른 노드와 무관한 선은 흐리게(Houdini). 미니맵은 전략 색.

### C3 · 갈래 만들기 + 차이만 보기 (우선 3)
- 노드 도구줄 **"갈래 만들기"** — 그 노드와 **같은 전략 안의 하류**를 복제해 바로 아래 줄에 놓고(점선 틀 "갈래 B"), 들어오는 선은 원본과 같이
  잇는다. 문서 `branches[]: {id, label, root, of_root, map: {복제 id: 원본 id}}`(선택 칸).
- **갈래 뿌리 칩**에 바꾼 설정만("δ 2.5 → 6") · 갈래 노드 카드에 원본 대비 **Δ 칩**(glance 헤드라인끼리의 차이 — 같은 단위일 때만, 아니면 칩 없음).
- **갈래 비교 표**(오른쪽 패널 탭) — 원본·갈래들 열, **값이 다른 행만**. 계산 못 한 칸은 "—"(0 아님).
- ★다중 비교 정직성★ — 한 뿌리에 갈래 ≤ 4. 표 위 한 줄: "갈래 N개를 같은 과거로 비교했어요 — 여러 번 고를수록 우연히 좋아 보이는 쪽을 고를
  위험이 커져요(표본 밖 확인 전 결론 금지)". 자동 파라미터 스윕·최적 갈래 추천은 **하지 않는다**(저장소 금지 사항).

### C4 · 처음 사용자 (우선 4)
- **목표로 시작** — 빈 캔버스(또는 명령 "새로 시작")에서 질문 2~3개: 무엇을 하려나요(새 포트폴리오 만들기 · 지금 포트폴리오 점검 · 타이밍 규칙
  시험 · 기업 하나 깊게) → 종목(유니버스) → 위험 성향/기간(기본 칸). 답으로 템플릿을 조립(규칙을 새로 정하지 않음 — 빈 칸은 서버 기본값)하고
  노드가 위상 순서로 한 번 자라난다.
- **간단히 보기**(Figma Weave App Mode · 토스식) — 상단 토글. 노드 없이 한 줄 흐름: 전략별로 ① 입력 질문 카드(각 노드의 기본 층 파라미터 — 설정 탭의
  질문형 위젯 재사용) ② 결과 카드(glance + 서버 explain 제목 + 믿음 칩 + 무엇을 안 쟀는지). 여기서 바꾸면 노드 파라미터가 바뀐다. 이야기 탭(BJ3)을
  대체하지 않고 넓힌 것.

### 덧붙인 것(조사에서 발견)
실행 시간 · 제목 줄 경고 · 증거 선 · 원인 경로 · 상태 필터 · 무관한 선 흐리기 · **키보드로 노드 사이 이동**(방향키 = 선을 따라 이웃 노드 — 접근성).

## 하지 않는 것
- 핀 데이터(n8n) — 결과를 얼려 하류를 돌리면 "이전 계산" 과 섞일 위험(BL1 원칙). 이미 '여기까지 계산' 이 이전 결과를 라벨로 보인다.
- 자동 파라미터 스윕 · 최적 갈래 추천 · 서버 그래프/블록 저장 · 실시간 공동 편집 · LLM 생성 노드 · 배분·최적화기 의미 변경
  (`portfolio_combine` 은 기존 함수 그대로).
