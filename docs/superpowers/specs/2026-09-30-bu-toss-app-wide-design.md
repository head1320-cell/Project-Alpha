# BU · 다른 탭 토스화 — 화면마다 답 한 문장, 근거는 그 아래

작성 2026-10-01 · 앞 프로그램 BT(`2026-09-30-bt-canvas-procedure-node-link-design.md`) · 결정 기록 [ADR 003](../../decisions/adr-003-toss-visual-language-app-wide.md)

## 1. 왜

캔버스·설정·프로필은 토스식인데 나머지 탭(대시보드·스크리너·백테스터·매크로·기업·위험·데이터·파생)은 옛
"터미널" 모습이다: 고정폭 글꼴, 영어 대문자 라벨(STRESS INDEX), 01/02 번호, 원시 오류 문장(`torch:
ModuleNotFoundError`)이 화면에 그대로 나온다. 한 제품으로 보이지 않고, 무엇보다 **화면이 무엇을 답하는지**가
보이지 않는다.

사용자 결정(2026-09-30): 다른 탭은 **구조까지** 바꾼다(한 화면 한 일, 고급 기능은 접되 빼지 않는다) ·
**한국식** 등락색 · 파생상품 계산기 · 첫 화면·로그인 · 관리 화면 셋(보이는 것만, 동작 불변)도 포함 ·
"더 좋은 방법이 생각나면 보완해서 추가해".

## 2. 이 제품만의 한 가지 — "답 문장 + 근거 줄"

화면마다 맨 위에 그 화면의 질문에 대한 **한 문장 답**을 둔다. 바로 아래에 그 답의 근거 칩(연습용 · 가정 n ·
재지 않은 것)을 둔다 — 캔버스의 "믿어도 되나요?"와 같은 말이다. 대담함은 여기에만 쓴다. 목록·표·시트는
조용하게 둔다. 첫 안의 "큰 숫자 + 작은 라벨 + 그라디언트" 머리는 흔한 기본값이라 뺐다 — **문장이 먼저**이고
숫자는 문장을 받친다.

★답 문장은 서버 값으로만 만든다★(ADR-003 §2.6). 판단 필드가 없으면 판단 없이 잰 값만 말한다.

흐림 글자는 `#6b7684` 대신 캔버스와 같은 `#5f6b7a`(`#6b7684` 는 바탕 위 4.19:1). 토스 빨강·파랑 `#f04452`·`#3182f6` 은

위험 `#e42939` 는 흰 바탕 4.49:1 이라 `#d22a3b` 로 낮췄다. 크기 단계 12·13·15·17·20·24·32, 숫자는 `tabular-nums`.

## 4. 글꼴

Pretendard(npm, OFL)를 `app/layout.tsx` 에서 앱 전체로 불러오고 캔버스의 import 는 지운다. 본문 글꼴은 끝 블록에서
`--bs-body-font-family` 를 덮어써 바꾼다(보호된 첫 `:root` 는 그대로). TSX 인라인 `fontFamily`(약 155곳)는 이 변경을
따르지 않으므로 각 모듈 단계에서 옮긴다. 고정폭은 종목코드·실행 id 같은 **식별자에만** 쓴다. Google Fonts
`@import` 의 JetBrains Mono 는 남기고, IBM Plex 는 쓰임이 모두 없어진 BU10 에서 뺀다.

## 5. 배치

1. 머리 — 쉬운 한국어 이름 + 한 줄 설명. 중첩 경로만 "상위 › 현재" 한 줄(`.tcrumb`).
2. 답 영역 — 문장 + 핵심 숫자 1~3 + 근거 칩 + 다음 행동 하나.
3. 절들 — 회색 바탕 위 흰 표면. 절 반경 20, 안쪽 행 12, 그림자 없음.
4. 자세히 — 1440 에서는 오른쪽 시트, 390 에서는 아래 시트.

읽는 화면은 최대 폭 1080(홈·위험·데이터·설정), 일하는 화면은 전체 폭(종목 찾기 표·백테스트 편집기). 글은 왼쪽,
숫자는 오른쪽 정렬. 번호 표식은 실제로 순서가 있는 곳(백테스트 단계, 캔버스 절차)에만 둔다.

## 6. 원칙

- 한 화면 한 일. 고급 기능은 지우지 않고 "더 보기/전문가"로 접는다.
- 해요체. 영어 약어는 처음 한 번 풀어 쓴다. 대문자 라벨은 없앤다.
- 오류는 무엇이 · 왜 · 어떻게 고치는지. 원시 예외 문장은 "자세히"로 내린다 — 지우지 않는다(정직성).
- 빈 화면은 할 일 하나를 준다. 미상은 "몰라요" + 사유이고 0 으로 그리지 않는다.
- 움직임은 사용자의 행동에 답할 때만(시트 열림·펼침). `module-motion` 의 0/0.12/0.18/0.26s 규칙을 지킨다.

## 7. BU0 · 기반 (이 문서와 같은 묶음)

### 7.1 토대 커밋 — 보이는 변화는 글꼴·상태 문구뿐

- `--tx-*` 토큰 + 다크 짝(§3) · Pretendard 앱 전체(§4).
- `shared/lib/format.ts` — 한국식 숫자 단위 한곳: `num` · `krUnit`(1.2조 · 3,400억 · 5,600만) · `won` · `pct`(비율 →
  %) · `signedPct` · `pp`(%p) · `direction`. 유한하지 않은 값은 **"몰라요"** 를 돌려준다(`NaN`·`0` 으로 그리지 않는다).
  사유를 아는 호출자는 `Unknown` 부품을 쓴다.
- `shared/ui/tx/` 공용 부품 — **평범한 props 만** 받는다(FSD: `shared` 는 `entities`·`widgets` 를 import 하지 않는다):
  `PageHead` · `Answer` · `Chips` · `Section` · `ListRow` · `Stat`(등락은 부호 + 색) · `Segmented`(radiogroup, 화살표 키) ·
  `Tabs`(tablist, 로빙 tabindex, 화살표·Home·End) · `Notice` · `Unknown`(사유 필수 — 타입으로 강제).
  `Sheet` 는 첫 소비처(BU2 종목 찾기 행 → 시트)에서 캔버스 `Sheet.tsx` 를 올리며 함께 옮긴다 — 쓰지 않는 부품을
  미리 옮기면 캔버스만 위험해진다.
- `/dev/ui` 갤러리에 tx 절과 서식 표를 더하고 `dev-ui.spec` 이 **동작**을 본다: 탭 화살표 이동 · 분할 단추 선택 ·
  `Unknown` 사유 · 등락 부호와 색의 짝 · 서식 표 입력 → 출력.
- `States.tsx` — `[ LOADING ]`·`[ ERROR ]`·`[ N/A ]`·`◇` 를 해요체로. 클래스·역할(role)은 그대로. 로딩은 뼈대(줄 셋)
  이고 **400ms 안에 끝나면 보이지 않는다**(CSS 지연 — 타이머 없음, 줄인 움직임에서도 같다). 미가용은 글자 표지
  대신 `.tstate-unavail` 와 "지금은 못 재요" 꼬리표로 구별한다. `dev-ui.spec`·`macro-studios.spec` 은 클래스로 단언한다.

### 7.2 셸 커밋

- 머리 줄 64px(`profile.spec`) · 흰 표면 · 브랜드 "Project Alpha"(대소문자 그대로, 고정폭 아님).
- **찾기**(`.tx-find`, `/` 키): 종목은 기존 `GET /api/v1/screener/stock-search`(→ `stock_master.search_stocks`)로 찾아
  `/insights?code=` 로 간다. 화면 이름으로도 이동한다. 실패하면 "찾지 못했어요" 가 아니라 "검색에 닿지 못했어요"
  라고 말한다(빈 결과와 실패를 섞지 않는다). 새 종목 판정 로직은 만들지 않는다.
- 메뉴 — 한국어 이름 + 아이콘. 번호·고정폭·"Core Modules"·격자 무늬·모서리 표식을 없앤다. 홈 · 종목 찾기 · 백테스트 ·
  경제 흐름 · 기업 분석 · 위험 점검 · 포트폴리오 설계 · 데이터 상태, 구분선 아래 파생상품 계산기 · 설정, 관리자에게만
  관리(실거래 · 여러 전략 백테스트 · 현실성 점검). `.terminal-header`·`.terminal-sidebar`·`.nav-item` 클래스와 2px 초점 링 유지.
- 브레드크럼은 **중첩 경로에만**(백테스트 실행·결과·비교 · 경제 흐름 스튜디오 · 관리 화면). 한국어, 고정폭 없음.
  `.tcrumb`·`.tcrumb-cur`·`.tcrumb-sep` 클래스는 유지.
- `nav.spec` 은 번역이 아니라 다시 쓴다: 최상위는 메뉴의 `aria-current`, 중첩은 `.tcrumb`. 겹침 검사는 상자가 null 이
  아님을 먼저 단언한다(null 이면 공허하게 통과한다).
- 골든: 이 커밋의 라이트 변화는 `shell:` 키와 `main:` 의 `.tcrumb*` 키(브레드크럼은 본문 안에 그려진다)뿐이어야 한다 —
  `golden-diff.mjs --expect-scope shell --allow-keys tcrumb` 로 확인한 뒤 다시 뜬다.

## 8. BU1~BU10

계획 파일의 모듈 순서를 따른다: BU1 홈 → BU2 종목 찾기(요청 골든 먼저) → BU3 백테스트 편집기 → BU4 실행·결과·비교 →
BU5 경제 흐름 → BU6 기업 분석 → BU7 위험·데이터·파생 → BU8 첫 화면·로그인 → BU9a 관리 화면 동작 골든 → BU9 관리 화면 셋 →
BU10 정리. 각 단계: 전 PNG → 정직성 E2E 먼저 → 구현 → 범위별 골든 diff → 다크 AA → 변이(연습용 표시 빼기 · PerfLabel 빼기 ·
오류 삼키기 · 답 문장에 금지 표현) → 후 PNG → 전체 게이트 → HISTORY → 커밋.

## 9. 하지 않는 것

- 전역 `--color-bull/bear`·`--t-accent` 뒤집기(쓰임별로 모듈 단계에서 옮긴다).
- 관리 화면의 동작·요청·확인 단계 변경 · `src/` 변경.
- 클라이언트 임계값으로 판단 만들기 · 설정값 추천.
- 쓰지 않는 공용 부품을 미리 옮기기(`Sheet` 는 BU2).
- 죽은 코드 손질 — 삭제 제안만 HISTORY 에 적는다.
