# 견고성 검증 · 노드 글자 크기 · 머리 줄 프로필 설계 (BR)

> 2026-09-28 · 사용자 승인 · 계획 `happy-percolating-falcon.md` §BR. 앞선 캔버스 설계: `2026-09-27-canvas-workspace-design.md`(BM).

## Context

사용자 요청:
1. **노드끼리·전략끼리 견고성을 본다** — 상관 분석, 상관 추이, 스트레스 테스트.
2. **전략 지도 노드 안의 글자가 커 보인다** — 다른 노드 링크 플랫폼을 참고해 적당한 크기로.
3. **머리 줄 오른쪽의 국면 배지(GOLDILOCKS · 52) 자리를 회원 프로필로** — 토스처럼 동그라미를 누르면 펼쳐진다.

사용자 결정은 다음과 같다.

| 질문 | 결정 |
|---|---|
| 견고성을 어디에 | 둘 다 + 지름길 — 전략 합치기에 자동 절, 노드끼리 비교 노드, 고른 노드 '견고성 비교' 단추 |
| 무엇을 재나 | 상관 추이 · 위기 때 상관 · 상관 급등 충격 · 최악 구간 겹침(+ 떠오르면 추가) |
| 프로필 모양 | 아래로 펼치는 카드 |
| 프로필 내용 | 이름·역할·로그인/로그아웃 + 화면 테마(국면 줄·설정 페이지 없음) — **BS1(2026-09-29)에서 사용자 지시로 설정 페이지를 더했다**(`2026-09-29-bs-br-leftovers-design.md`) |

**범위.** 견고성은 **관측·분석만** 한다. 배분 결과, 합치기 방법·몫, 최적화기 의미는 바꾸지 않는다(CLAUDE.md §3). 이 절의 수는 **질문 ② 전달 안정성**에 대한 관측이다. 예측 스킬(③)이나 경제적 가치(④)의 증거가 아니다.

## R1 · 견고성

### 흐름 — 무엇의 상관인가

- 전략(또는 비교 노드의 입력) 하나 = **지금 비중을 지난 기간 내내 들고 있었다면의 일별 수익**이다. `sleeve_combine._sleeve_return_series` 가 만들며, 전략 합치기가 몫을 정할 때 쓰는 것과 **같은 흐름**이다(리밸런싱 주기·거래비용 포함).
  - 이것은 **실제 운용 기록이 아니다.** 믿음 칸에 '가정'으로 적는다.
  - 실제 기록(`StrategyRegistry.load_returns_matrix`)으로 재는 일은 하지 않았다(다음 단계).
- 숏 비중은 이 흐름이 빼고 잰다. 엔진은 바꾸지 않고 "숏 비중 n개는 빼고 쟀어요"라고 밝힌다.
- 로더에는 **날짜가 없다.** 종목 흐름의 끝을 맞춘다(같은 날까지). 그래서 가로축은 "n거래일 전"이고 응답에 날짜 키가 없다. 날짜를 지어내지 않는다.
- mock(`KIS_USE_MOCK=1`)이면 흐름이 합성이므로 `practice` 꼬리표 → '연습용'.

### 블록 (엔진 `src/engine/strategy_robustness.py` — 순수)

각 블록은 값 또는 `available: false` + `reason` 을 담는다. `{}` 나 0 으로 메우지 않는다.

| 블록 | 뜻 | 계산 | 모름 |
|---|---|---|---|
| `rolling` 상관 추이 | 쌍마다 창 W 거래일의 상관이 어떻게 변했나 | 창 상관 + 95% 띠 = Fisher z `tanh(atanh ρ ± 1.96/√(W−3))` · 평균 쌍 · 지금·최소·최대 | 흔들림 없는 창은 `null`(0 아님) + 빈 창 수 · 창보다 짧으면 블록 없음 + 사유 |
| `crisis` 위기 때 상관 | 시장이 나쁜 날에도 따로 움직였나 | 위기일 = 시장(KODEX 200 `069500`) 하위 10% 날. 평소 날 상관 대 위기일 상관 · **같이 떨어진 날**(둘 다 제 하위 10%) 대 **평소 관계라면 기대 날 수** = T × Φ₂(z_q, z_q; ρ) | 시장 자료가 없으면 전략 평균 하위 10% 로 고르고 `basis: "strategy_mean"` + "상관이 부풀 수 있어요" · 위기일 20일 미만이면 `small_sample` |
| `shock` 상관 급등 충격 | 전략끼리 상관이 치솟으면 합친 흔들림이 얼마나 커지나 | `stress_correlation_report`(노드 층) — 목표 ρ*(0.7·0.8·0.9) + **실제로 본 가장 높은 평균 창 상관** | 지금 상관이 이미 ρ* 이상이면 올리지 않고 사유 |
| `drawdown` 최악 구간 겹침 | 가장 많이 잃은 구간이 겹치나 | 전략마다 최대 낙폭 구간(고점→저점) · 쌍마다 겹친 거래일 ÷ 합친 거래일 · 합친 흐름의 최악 20일에 각 전략이 낸 수익 | 낙폭 0 이면 그 전략 구간 없음 + 사유 |
| `stability` 상관 안정성 | 앞 절반과 뒤 절반의 상관이 우연 이상으로 다른가 | Fisher z 차이 z = (atanh ρ₁ − atanh ρ₂)/√(1/(n₁−3)+1/(n₂−3)), \|z\| > 1.96 | 절반이 창보다 짧으면 없음 |
| `effective_n` 실질 독립 개수 | 전략 n개가 실제로는 몇 개처럼 움직이나 | `deflated_sharpe.participation_ratio`(상관행렬 고유값 참여비) | 상관을 못 잰 쌍이 있으면 없음 |
| `diversification` 분산 효과 | 따로 움직여 줄어든 흔들림 | Σ wᵢσᵢ / σ_p (1 = 분산 효과 없음) | σ_p = 0 이면 없음 |

**왜 '같이 떨어진 날 대 기대'를 붙이나.** 나쁜 날만 골라 상관을 재면 관계가 그대로여도 변동이 커진 만큼 상관이 높아 보인다(조건부 상관 치우침 — Forbes·Rigobon 2002, Boyer·Gibson·Loretan 1999). 그래서 위기일 상관만으로 '위기에 같이 무너진다'고 말하지 않는다. 대신 제 순위 하위 10% 에 함께 든 날 수를 같은 전체 상관의 정규 관계가 주는 기대와 나란히 보인다.

### 정직성 고침 (같은 단계에서)

- `sleeve_analytics` 는 `np.nan_to_num(corr, nan=0.0)` 로 흔들림 없는 묶음의 상관을 **0 이라고** 보고했다.
  - 고친 뒤에는 `None` + `correlation_reasons` 를 준다.
  - 평균 상관·군집은 잰 쌍만으로 계산하고, 잰 쌍이 없으면 `None` 이다.
- '묶음 분석' 노드는 엔진의 `{"error": True}` 를 `available is False` 로 봐서, 실패가 "완료 + 빈 표"로 보였다. 이제 `NodeFailure` 다.

### 표면

- **전략 합치기** — 이미 불러온 흐름으로 `view.robustness` 를 붙인다. 합치기의 몫·비중은 비트 단위로 같다(골든).
- **견고성 비교** — 기존 '묶음 분석'(`sleeve_analytics`, 비중 a·b 필수 + c·d 선택)을 올린다.
  - 종류 id 는 그대로라 저장된 파일이 열린다.
  - 설정: 기간 1년·3년(받은 실제 길이를 적는다) · 창 20·60·120 · 충격 ρ 0.7·0.8·0.9.
- **지름길** — 비중을 내는 노드 2~4개를 고르면 선택 위 막대에 '견고성 비교'가 생긴다.
  - 누르면 비교 노드를 오른쪽에 두고 a~d 에 잇는다(되돌리기 한 번).
  - 조건이 안 되면 단추가 꺼지고 사유를 보인다.
- **화면** `RobustnessView` 구성:
  - 한 줄 요약.
  - 상관 추이: 띠 있는 선 + 쌍 고르기.
  - 위기 때: 평소 대 위기 막대 + 같이 떨어진 날 대 기대.
  - 충격: 지금 → 충격 흔들림, '가정' 꼬리표.
  - 최악 구간: 거래일 축 위 구간 막대 + 최악 20일 표.
  - 더 보기: 안정성·실질 개수·분산 효과.
  - 색만으로 구분하지 않는다.
- **주장 어휘** — "견고함·검증됨·입증됨" 을 쓰지 않는다. 재지 않은 것: 앞으로도 같을지 · 돈이 되는지 · 날짜로 맞춘 비교.

## R2 · 노드 글자 크기

- 참고한 결: n8n·ComfyUI·Node-RED 는 제목 13~14px · 본문 11~12px · 포트 10~11px, React Flow 기본은 12px 이다.
- 보통 확대에서 바꾼 크기:

  | 요소 | 전 | 후 |
  |---|---|---|
  | 제목 | 16/700 | 14/600 |
  | 값 | 24/700 | 18/700(표 숫자) |
  | 종류 | 12 | 11 |
  | 노드 안 꼬리표 | 12 · 22 | 11 · 20 |
  | 번호 | 18 칸 | 16 칸 |
  | 접은 전략 이름 | 16 | 14 |
  | 접은 전략 몫 | 24 | 18 |
  | 전략 상자 이름 | 15/800 | 13.5/700 |

- 멀리 볼 때는 화면 11px 바닥을 지키되 **더 크게 부풀리지 않는다**.
  - 이름 `min(28px, 11px/z)`·600, 숫자 `min(32px, 12.5px/z)`·700(전: 11.5/700 · 15/800).
  - 펼친 전략의 결과 줄은 멀리서 숨긴다(흐름 크기 그대로라 읽히지 않았고, 같은 수가 머리의 몫에 있다). '이 전략만 계산' 단추는 남긴다.
- **한국어는 어절에서 꺾는다**(`word-break: keep-all`). 전에는 "수익률 불러\n오기", "상관이 치솟\n으면"처럼 음절 가운데서 꺾여 글자가 더 커 보였다.
- 카드 폭·높이·배치 간격은 바꾸지 않았다.

## R3 · 머리 줄 프로필

- 국면 배지는 머리 줄에서 뺀다. 국면은 /macro 에 그대로 있다.
- 그 자리에 32px 동그라미를 둔다. 로그인 중이면 이름 첫 글자, 아니면 사람 모양이다.
- 누르면 아래로 카드가 펼쳐진다:
  - 이름 + 역할(관리자·분석가 — 서버 `role` 어휘)
  - 화면 테마(라이트·다크·시스템)
  - 로그아웃 또는 로그인
- **신원은 `GET /api/v1/auth/me` 로 확인한다.** 미상 ≠ 로그아웃이다.

  | 상황 | 보이는 것 |
  |---|---|
  | 토큰 없음 | 로그인 안 됨 |
  | 200 | 이름·역할 |
  | 401 | 토큰을 지우고 "로그인이 끝났어요" |
  | 그 밖의 실패 | "계정 정보를 확인하지 못했어요" + 다시 시도(토큰 유지, 이름을 지어내지 않음) |

- **로그아웃** = 토큰을 지운다(JWT, 서버 세션 없음).
- **테마는 다크를 지원하는 화면에서만 적용한다.**
  - 저장소 규칙(globals.css §47 S1f): "절반만 대응된 앱을 내보내면 사용자는 다크모드가 깨졌다고 읽는다."
  - 다크 규칙은 포트폴리오 설계·백테스트 결과·`.aas-root` 에만 있다.
  - 다른 화면은 밝게 두고, 카드에 "이 화면은 아직 밝게만 볼 수 있어요"라고 밝힌다(라벨이 붙은 열화).
  - 저장은 이 브라우저(`alpha_theme`)에 한다. 기본값은 라이트(지금 화면 그대로)다.
