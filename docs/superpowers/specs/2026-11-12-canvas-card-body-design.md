# 캔버스 카드 본문 활용 — 결과 자리를 보통·먼 확대에서도 쓴다 (2026-11-12)

> 사용자 요청: "캔버스 공간을 더 기능적으로 고도화". 방향을 여쭈었고 답은 **"선호 없음"** → 추천안(카드의 빈 공간 활용)으로 정했다.
> 다른 세 후보(메모·북마크·구역 색 / 노드 건너뛰기·갈래 비교 표·승격 / 결과 보드)는 이번에 하지 않는다.
> ★이 문서가 답하는 질문은 "화면이 이미 계산된 사실을 더 잘 보여 주는가"다 — 정보 표현력. 예측력·경제적 가치와는 무관하다.★

## 1. 관측 — 무엇이 비어 있었나

- 카드는 모든 확대에서 같은 상자다(폭 240 · 높이는 카탈로그가 정함 — `entities/portfolio-graph/size.ts`). 결과 자리(`.pg-node-slot`)는 156px.
- ★그림 없는 종류★(서버가 `glance` 를 내지 않는 노드 — 예: 유니버스 · 수익률 데이터 · 투자 뷰): 계산이 끝나도 결과 자리가 비었다.
  서버는 이미 그 노드의 사실 줄(`explain.facts`)을 보냈고, 오른쪽 창의 이야기 탭만 그것을 보였다.
- ★먼 보기★(확대 < 0.55 — 맞춤 단추로 흐름 전체를 담으면 45~67%): 카드에 이름과 값 하나뿐이었다. 본문 대부분이 비고, 작은 그림은 '그림 고정'한 노드만 보였다.
- ★보통 확대★(0.55 ~ 1.05 — ★기본으로 열리는 화면★: 처음 맞춤의 확대 바닥이 0.55 라 창이 좁아도 여기서 열린다 · 1440 창에서 79%): 작은 그림은 가까이(≥ 1.05)나
  '그림 고정'한 노드에만 보여, 그림이 있는 노드까지 결과 자리 156px 가 통째로 비어 있었다.
- 2026-10-17 에 "결과 그림이 없는 카드의 빈 결과 자리는 그대로 둔다"로 정했었다(CF 스펙 CF1). 이번에 그 결정을 바꾼다 — 그 스펙에 날짜와 함께 적었다.
- ★계획과 달라진 점(정직하게)★: 승인받은 계획은 가까이(D1)와 먼 보기(D2)만 적었다 — "기본 화면이 45~67% = 먼 보기"라고 잘못 전제했기 때문이다.
  README 그림을 다시 찍다가 기본 화면이 보통 확대임을 봤고, 그대로면 처음 보는 화면은 하나도 달라지지 않는다. 같은 방향(카드 빈 공간 활용) 안이라 보통 확대까지 넓혔다.
  그 대가로 2026-10 의 '확대 3단계'(보통 = 그림 없음) 계약 하나와 '그림 고정' 시험의 전제가 바뀌었다 — 아래 §4.

## 2. 설계

### D1 · 그림 없는 종류의 결과 자리 (가까이)
- 계산이 끝났고(`status: ok`) 그림도 도넛도 없으면, 결과 자리에 **서버 `explain.facts` 앞 세 줄**을 그대로 놓는다(`.pg-node-facts > li`).
  줄마다 두 줄까지 — 넘치면 말줄임. 전부는 오른쪽 창의 이야기 탭에 그대로 있다.
- ★새 수치 0 · 새 문장 0★ — 화면은 서버가 보낸 문장을 고르거나 고치지 않는다(앞에서부터 세 줄). 사실 줄이 없으면 자리도 없다.
- 그림이 있는 노드는 그림만(둘을 겹쳐 놓지 않는다). 계산 전의 "계산하면 결과가 여기에 표시됩니다" 안내 · 막힘·실패 사유 · 이전 결과 안내는 그대로.
- 가까이와 ★보통 확대★에서 보인다(작은 그림과 같은 규칙 — 아래 D2 의 보기 설정을 끄면 예전처럼 가까이에서만).

### D2 · 보통 확대와 먼 보기
- **보통 확대**: 카드 구성은 그대로 두고 결과 자리에 작은 그림(그림 있는 종류) 또는 사실 줄(D1)을 보인다. 상자는 원래 가장 큰 그림이 들어가게 잡혀 있어 자라지 않는다.
- **먼 보기(확대 < 0.55)**: 이름 + 값 하나 → **이름 · 설정 요약 한 줄(`nodeSummary`) · 값 · 증거 칩 · 작은 그림**.
  - 설정 요약: 보통 확대의 제목 줄과 같은 글(`.pg-node-far-sum`). 요약이 없는 종류는 줄도 없다(이름을 두 번 적지 않는다).
  - 증거 칩(`.pg-node-far-ev`): 상태 줄의 칩과 ★같은 사실 · 같은 순서★, 글자만 짧게(합성 데이터 → 합성 · 가정 2개 → 가정 2 · 지키지 못한 조건 → 조건 위반 …).
    원문은 `data-full` 에 둔다. 클래스는 제 것(`.pg-far-chip`) — 상태 줄 칩(`.pg-tag`)을 다시 쓰면 카드 안의 `.pg-tag` 를 세는 기존 E2E 가 숨은 사본까지 잡는다(전체 E2E 가 찾음). 먼 보기 글자는 화면 11px 바닥을 지키려고 확대의 역수로 커지므로 원문 그대로는 한 줄에 칩 하나밖에 못 놓는다.
  - 작은 그림: 계산된 노드 전부(예전에는 '그림 고정'한 노드만).
- **'보기 → 카드에 결과 표시'**(기본 켬 · 명령 찾기에도 같은 항목). 끄면 예전대로(보통 = 그림·사실 줄 없음 · 멀리 = 이름 + 값). 끈 채로도 '그림 고정'은 그대로 동작한다.
  켬/끔은 이 브라우저에만 남는다(`view.ts` — 단계 레인·미니맵·추천 유령과 같은 자리). ★문서가 아니다★ — 저장 파일·요청 본문은 바이트 그대로.
- 구현은 CSS 가 한다: 캔버스 요소의 `data-card-results`("1"|"0") × `data-zoom`. 확대가 바뀌어도 노드를 다시 그리지 않는다(R8 의 규칙 그대로).

### 지키는 것 (불변)
- 상자 크기·자리(★모든 확대에서 같은 상자★) · 포트 DOM · 기존 CSS 클래스(새 클래스만 더함) · 문서 형식 · 요청 본문 · **서버 0줄**.
- 먼 보기에서는 카드가 상자 높이를 넘지 않는다(`max-height: var(--pg-box-h)`): 내용이 넘치면 결과 자리(작은 그림)가 줄어들고 카드는 자라지 않는다.
  먼 보기에서 자랄 수 있는 것(막힘 사유·고치는 법·오류 목록)은 이미 숨겨져 있었다.
- 새 `var(--pg-z)` 사용처 둘은 `zoomVar.ts` 의 `PG_Z_USERS` 에 더했다(안 더하면 그 글자는 확대와 무관한 크기가 된다 — `canvas-perf.spec.ts` 가 건다).

## 4. 시험 (`frontend/e2e/canvas-card-body.spec.ts` — 먼저 쓰고 빨강 7건을 본 뒤 구현)
① 사실 줄 = 서버 응답 그대로(응답을 바꾸면 글이 바뀐다 · 그림 있는 노드엔 없다 · 사실 줄이 없으면 자리도 없다)
② 계산 전에는 안내만 · 보통 확대에서도 사실 줄·작은 그림이 보임 → 끄면 둘 다 숨고 가까이에서는 꺼도 보임(짝)
③ 먼 보기: 요약 = 보통 확대의 제목 줄 · 칩 = 상태 줄의 칩(원문 대조) · 그림 보임 → 끄면 셋 다 숨음(짝) · 고정한 노드는 꺼도 보임 · 다시 열어도 끈 채
④ 세 확대 모두 내용이 상자 밖으로 안 넘침 · 카드 높이가 확대·켬/끔과 무관하게 같음 · 먼 보기 새 글자도 화면 11px 이상
⑤ 보기 설정을 켜고 꺼도 작업 중 문서는 바이트 그대로 · 라이트/다크 AA
변이는 HISTORY 에 결과와 함께 적는다. ★계약이 바뀌어 함께 고친 기존 시험★(`canvas-workspace`): "확대 3단계"의 보통·먼 보기 단언 둘(작은 그림 숨김 → 보임) ·
"그림 고정"은 보기 설정을 끈 뒤에 본다(고정은 이제 그 설정을 끈 사람을 위한 기능이다). 화면·명령 골든은 새 요소·새 명령만큼 다시 얼렸고 문서 골든(`canvas-doc.json`)은 그대로다.

## 5. 한계 · 하지 않은 것
- 먼 보기의 작은 그림 속 글자(축 이름·값)는 확대만큼 작아진다 — 모양만 읽힌다('그림 고정'이 원래 그랬다). 읽으려면 가까이 가거나 오른쪽 창을 본다.
- 확대가 아주 낮고(0.35 아래) 이름이 두 줄 · 칩이 두 줄 · 그림이 가장 큰 종류(막대 5줄)면 그림 아래쪽이 조금 잘릴 수 있다(카드를 키우지 않기로 한 대가).
- 사실 줄은 앞에서부터 세 줄이다 — 어느 줄이 더 중요한지는 화면이 판단하지 않는다(서버가 쓴 순서).
- '그림 고정'의 쓸모가 줄었다 — 기본에서는 모든 계산된 노드의 그림이 보통·먼 확대에 보이므로, 고정은 보기 설정을 끈 사람에게만 뜻이 있다. 단추는 그대로 두었다.
- 성능: 보통·먼 확대에서 그리는 것이 늘었다 — 전후 수치는 HISTORY 에 적는다(R8 과 같은 방법 · 이 컨테이너 기준이라 실제 기기 성능은 미검증).
