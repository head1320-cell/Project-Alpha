# BC · 체결 규칙 옵트인 — ★비용이 아니라 체결 가능성이고, 기본은 꺼져 있다★

작성 2026-09-24 · 엔진 `src/kis_backtest_engine.py`(`enforce_price_limit`·
`round_fills_to_tick`·`_fill_price`·`fill_rules`) · 규칙 출처(읽기만)
`src/data/market_rules.py` · 등록 `src/engine/cost_model_registry.UNAPPLIED_RULES` ·

## 1. 무엇이 비어 있었나

AK 가 `tick_size`·`price_limit_pct` 를 *"비용이 아니라 체결 가능성"* 이라며
`absent` 로 등록했다. 규칙은 `market_rules` 에 이미 있었고 백테스트만 안 썼다.

## 2. ★옵트인 — 기본 꺼짐★

CLAUDE.md §5 *"데이터 무결성을 고치기 전에 모델을 키우지 말라 — 금지가 아니라
순서다."* 기본으로 켜면 저장된 모든 백테스트의 뜻이 바뀐다. AK 가 세금·스프레드·
충격에 쓴 **그 선례 그대로** `BacktestConfig`·`run_backtest` 에 둘을 더했다.
꺼져 있으면 `_fill_price` 는 가격을 **그대로** 돌려준다(골든이 지킨다).

## 3. 규칙

| | 켜면 | ★하지 않는 것★ |
|---|---|---|
| 가격제한 | 전일 종가 ±`price_limit_pct` 밖 → **그날 미체결** | ★클립해서 체결하지 않는다★ — 실재하지 않는 체결이다 |
| 전일 종가 미상 | 거부하지 않고 `n_limit_unknown` 으로 센다 | ★미상 ≠ 위반★ |
| 가격 정의 `mixed` | 비율이 뜻이 없어 미상으로 센다 | |
| 호가 | ★원주가 척도에서만★ 매수 `up`·매도 `down` | 수정주가·미상 척도에서는 반올림하지 않고 `n_tick_not_raw` 로 센다 |
| 순서 | 반올림 **후** 가격으로 제한을 본다 | |

**적용 지점** — `exec_price` 를 계산하기 **직전** 세 곳(분할매수 · 신규매수 ·
매도, 매도는 보유 확인 뒤). *"그날 하지 않았을 주문"* 을 거부로 세지 않기 위해서다.
손절·익절·트레일링도 `_execute_sell` 을 타므로 **같은 규칙**을 받는다(하한가
잠김이 실재한다). ★래더 매수 단계·ETF 슬리브는 이 지점을 안 탄다★ — 결과의
`not_covered` 가 이름으로 말한다.

## 4. ★결과가 말한다 — `cost_model` 이 아니다★

새 진단 키 `fill_rules`: 두 규칙의 on/off · 쓴 제한폭(꺼졌으면 `None`) ·
`n_rejected_by_limit` · `n_limit_unknown` · `n_rounded` · `n_tick_not_raw` ·
`not_covered` · `note`. `DIAGNOSTIC_KEYS` 에 넣었고, 스냅샷 테스트의 약속대로
★같은 커밋에서★ 텔레메트리(`_TELEMETRY_FIELDS`)와 프런트 **타입**
(`bridgeModel.ts`)을 함께 고쳤다(화면은 0줄).

## 5. ★실측이 계획을 뒤집었다 — 둘★

**① 기본 지연에서는 가격제한이 거의 안 걸린다.** `signal_lag=1`(기본)이면 다음
봉에서 체결하고, 그 봉의 전일 종가는 이미 움직인 값이다. **일봉 종가끼리는 제한을
넘기 어렵다** — 이 규칙이 무는 곳은 같은 봉 체결(`signal_lag=0`), 지정가·오프셋
체결, 그리고 가격 불연속(수정주가 경계)이다.

**② mock 실행에서 호가 규칙은 아무것도 반올림하지 않는다.** mock OHLCV 에는
`price_basis` 라벨이 없어(`unknown`) ★척도를 모르니 반올림하지 않았고★ 그 사실이
`n_tick_not_raw` 에 전부 찍혔다. 계획의 *"켠 쪽만 계수가 0 보다 크다"* 는 mock
실물에서 성립하지 않았다 — 메커니즘은 **원주가 라벨을 단 합성 계열**에서 증명했다.

## 6. ★호가 표가 두 벌이다 — 이름 붙이고 고치지 않는다★

`market_rules.tick_size`(`<=`)와 실주문 경로 `OrderExecutor._get_tick_size`(`<`)가
**여섯 경계 전부**에서 다른 틱을 낸다. 1원 단위로 60만 원까지 훑어 ★갈리는 가격이
정확히 그 여섯뿐★임을 확인했다. 여섯 경계는 두 틱의 **공배수**라 `is_on_tick`·
반올림은 같은 답이고(★BC 는 영향을 안 받는다★), 갈리는 것은 *"다음 호가"* 다.

★둘 다 고치지 않았다★ — `OrderExecutor` 는 실주문 경로(§6 최우선), `market_rules`
를 고치면 `execution_plan` 보고값이 바뀐다. KRX 1차 출처는 이 환경에서 CONNECT
403 이다. **어느 쪽이 맞는지는 사용자가 답할 미상**으로 로드맵에 등록했다.

> ★후속 (BD, 같은 날)★ — 사용자가 **`<`(미만)** 로 답했고(증권사 안내·보도와
> 일치) 표를 `market_rules` 하나로 합쳤다. 이 절의 불일치 관측은 해소됐다.

## 7. ★이 설계가 하지 않는 것★

- **기본으로 켜지 않는다.** 별도 결정이다.
- **부분체결·호가 잔량·단일가 매매를 모델링하지 않는다.**
- **래더 매수 단계·ETF 슬리브에 적용하지 않는다.** `not_covered` 가 말한다.
- **호가 표 둘 중 어느 것도 고치지 않는다.**
- **매매 단위(`board_lot`)·공매도(`shortable`)는 안 한다** — `absent` 그대로.
- **새 호가 표를 만들지 않는다.** `market_rules` 를 읽는다.
- **채점표를 올리지 않는다.** #6 은 여전히 **부분**이다.
