  "고객군을 전업투자자, 헤비트레이더라는 사실을 잊지마" · "따로 화면을 만들기 보다 기존에 있는 백테스터 모듈, 캔버스 공간 모듈에서 작업하면 더 좋지 않을까?"

### 3.2 추천과 까닭
**A(자체 구현).** 판이 여섯 · 넷뿐인 화면에서 필요한 것은 '열 셋 · 칸 둘 · 탭 묶음 · 옮기기 · 저장'이고, 그 가운데 가장 비싼 '키보드로 옮기기'는 B · C 모두 직접 만들어야 한다.

### 3.3 B · C 를 다시 볼 조건 (그때의 규칙)
- 다시 보는 때: 떠 있는 판 · 자유로운 끌어 놓기(열 셋 · 칸 둘을 넘는 배치)가 필요해질 때 · 2b(창 띄우기)의 수단을 고를 때.

## 5. 배치 모형

### 5.1 꼴(저장 형식 v1 — 순수 자료 · 개인정보 없음)
```json
{ "v": 1, "screen": "intraday", "cols": [
    { "w": 480, "rows": [ { "tabs": ["setup"], "active": "setup" } ] },
    { "w": null, "rows": [ { "tabs": ["result", "bars", "verdict"], "active": "result" },
                           { "tabs": ["daytype", "regime"], "active": "daytype", "h": 0.4 } ] } ],
  "closed": [] }
```
- `cols` 1 ~ 3 · 열마다 `rows` 1 ~ 2 · `w`(px)는 열 하나만 `null`(남는 폭) · `h` 는 아래 칸의 높이 비율(0.2 ~ 0.8).
- 판은 `tabs` 와 `closed` 를 통틀어 ★정확히 한 번★ · 닫기 없는 판은 `closed` 에 올 수 없다 · `active` 는 그 칸의 `tabs` 안.

### 5.2 순수 함수(`shared/ui/workspace/layout.ts` · 화면 없음 · 브라우저 없는 시험)
`readLayout(raw, spec) → { layout, notes[] }`(꼴 검사 — 모르는 판은 빼고 사유 · 빠진 판은 닫힌 판으로 · 닫기 없는 판이 빠졌으면 첫 칸에 · 판이 틀리면 기본 + 사유) ·
`move(layout, id, target)`(target = 칸의 탭 자리 · 새 열(최대 3) · 위 · 아래 칸(최대 2)) — 빈 칸 · 빈 열은 접는다 · `close` · `reopen` · `activate` ·
`fold(layout, workWidth, spec)`(그릴 때만 — 들어가지 않는 열을 앞 열의 탭으로 · 저장 꼴은 그대로 · 접은 사실을 돌려준다) · `presets(screen)` · `serialize` / `parse`.

### 5.3 그리기
- 작업 공간 = 그리드 상자 하나(`.ws-grid`) · 열 폭 = `grid-template-columns`(G5 의 구분선이 바꾼다) · 판 = 열쇠 있는 자식(`.ws-panel[data-panel]` · role tabpanel) · 칸마다 머리(탭 목록 + 판 메뉴).
- DOM 순서 = 읽는 순서(열 → 칸 → 탭) · 같은 부모 안에서 순서만 바뀐다 · 가려진 판은 `hidden`.
- 열마다 위 · 아래 칸 비율이 달라도 그리드 상자는 하나다 — 행 트랙을 20등분(`h` 는 0.05 걸음)하고 칸 = 행 구간 · 칸 머리(높이 고정)는 같은 구간 위에 겹쳐 두며 판은 그 높이만큼 내려 둔다.
  열마다 상자를 따로 두면 판이 열을 옮길 때 부모가 바뀌어 다시 마운트되므로(§1 상태 보존) 그 길은 버린다.
- 작업대는 계정 확인 뒤에 선다(G5 관측) — 저장한 배치를 그때 읽어 바로 그리므로 서버 그림 · 수화와 어긋나지 않는다.
- 판 배치에서 페이지는 구르지 않고 칸마다 구른다(G5 와 같은 높이 규칙 — `100vh − 머리줄 − 80px` · CSS 만).
- 좁은 창(1280 × 800 미만)에서는 같은 상자가 한 열 그리기로 바뀐다 — 판을 읽는 순서대로 쌓고(가린 판 없음) 탭 · 판 메뉴 · 구분선을 그리지 않으며 페이지가 구른다. 그 자리에 한 줄 "창이 좁아 판을 한 열로 쌓아 보입니다. 넓히면 저장한 배치로 돌아갑니다."
  탭 목록이 없으므로 판의 역할은 tabpanel 이 아니라 이름 있는 구역(region · 판 이름)으로 바꾼다(속성만 바뀌고 다시 마운트되지 않는다).
- ★기본 배치 ↔ 판 배치를 켜고 끌 때만★ 절이 다시 그려진다(DOM 이 다르다) — 드문 조작이고 실행 결과 · 판정은 화면 상태라 남으며, 절 안의 입력은 처음 값으로 돌아간다 · POST 0(시험이 건다).

### 5.4 처음 배치(프리셋) — 도구는 배치를 '추천'하지 않는다(이름은 쓰임의 묘사)

- **켜고 끄기**: '배치' 메뉴 단추 하나 — 분봉은 두 칸일 때의 `.itd-out-bar`('설정 접기' 옆 · 한 열에서는 그리지 않음) · 판 배치에서는 작업 공간 위 막대(`.ws-bar`) · 내 계좌는 기존 상자를 움직이지 않는 자리(2a-2 계획 절에서 잰다).

- **판 메뉴**(칸 머리의 단추 · APG 메뉴 단추): 옮기기(첫째 · 둘째 · 셋째 열 · 새 열 · 위 칸 · 아래 칸) · 이 칸만 크게(다시 누르거나 Escape 로 되돌림) · 닫기(닫기 있는 판만).
- **탭**: 기존 `rove` 와 같은 키(← → Home End) · 판 이름은 탭 · 판은 그 이름의 구역.
- **끌어 놓기**: 탭을 끌어 다른 칸의 탭 목록(자리) · 열 가장자리(새 열) · 칸 위 · 아래 절반(새 칸)에 — 놓일 자리를 그리고 Escape 로 취소. 메뉴와 같은 `move` 를 부른다.
- **열 폭 · 칸 높이**: G5 구분선 그대로(role separator · ← → 16px · Home End) — 칸 사이는 가로 구분선(↑ ↓).
- **낭독**: 작업 공간마다 낭독 영역 하나(polite) — "‘판정’ 판을 셋째 열로 옮겼습니다." · "‘하루 유형’ 판을 닫았습니다. 배치 메뉴에서 다시 열 수 있습니다." · "창이 좁아 셋째 열을 둘째 열의 탭으로 합쳐 보입니다."
- **단축키는 두지 않는다**(WCAG 2.1.4 · 브라우저 예약 키와 겹침 — 예: F6).

- 읽기 · 쓰기는 try/catch · 못 읽거나 꼴이 틀리면 기본 배치로 열고 `.ws-note` 에 사유(예: "저장된 배치를 읽지 못해 기본 배치로 열었습니다. 모르는 판 ‘trades’ 를 뺐습니다.").
- 내보내기: 지금 배치 + 이름 붙인 배치를 JSON 파일 하나로(화면 이름 · 꼴 판 포함). 가져오기: 같은 `readLayout` 을 지나 ★다른 화면의 파일 · 다른 판 · 꼴이 틀린 파일은 거절하고 사유 목록★ — 지금 배치는 그대로.
- 이름 붙인 배치의 이름은 사용자가 적은 글이다 — 브라우저 안에만 있고 내보낸 파일에 실린다(그 밖으로 보내지 않는다). 배치 꼴에는 판 이름 · 폭 · 비율만 있고 계좌 · 종목 · 설정은 싣지 않는다.
- 서버 · 표 · 보존 분류 · 접근 지도 0줄.

## 8. 창 띄우기(2b — 따로 승인)
- 띄울 수 있는 판: 실행 · 판정 · 주문 · 가동 단추가 없는 판(분봉 결과 · 봉과 체결 · 내 계좌 주문 목록 · 잔고 · 읽기 전용 관제).
- 띄운 창의 머리 띠: 출처 등급 칩 · 합성이면 합성 알림 · 내 계좌라면 계좌 모드와 비상 정지 단추(같은 문 · 같은 확인 시트).
- 주 창이 다른 주소로 가거나 닫히면 띄운 창을 닫고 판은 제자리로 · 띄운 창을 닫아도 제자리로 · 다크 반(`html.dark`) · 스타일을 따라 옮긴다.
- 수단(2b 감사): 자체(`window.open` + React portal + 스타일 복제) 또는 FlexLayout 의 창 띄우기 — §3.3 의 규칙으로.
- 시험: 팝업 열림 · 닫힘 · 주 창 이동 · 띄운 창의 비상 정지 · 합성 표시 · 시행 수 불변.

## 14. 주장의 범위
`structural` — 배치를 바꾸는 장치이고 어떤 숫자의 뜻 · 증거 등급도 바꾸지 않는다. 쓰임이 나아지는지는 이 환경에서 잰 폭 · 높이 · E2E 의 동작까지이며 실제 트레이더의 작업 시간은 재지 않는다.
라이브러리 사실은 패키지 파일의 관측이고 문서 사이트 · 실제 동작(상태 보존 · 첫 그림 · 서버 그림)은 재지 않았다(미상).
