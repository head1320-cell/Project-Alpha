# 캔버스 성과 그림 문법 — 백테스트 계열 셋 (설계 · 2026-11-09)

## 1. 왜

사용자 요청: *"백테스팅 같은 통계분석의 성과에 대한 디자인을 잘 만들어 줘. 먼저 캔버스 툴, 나중에 다른 툴에도. UI/UX 측면도. 깊이 생각하고 구상해 줘."*

읽기 전용 조사에서 본 것:
- 캔버스에서 성과를 보여 주는 노드 셋(7번 **과거로 돌려 보기** `backtest` · **백테스트 불러오기** `backtest_load` · **전략 묶음**
  `strategy_backtest`)이 각자 다른 모양으로 그린다. 7번은 영어 라벨(CAGR·Sharpe·MDD) + 선 하나, 전략 묶음은 낙폭을 숨은 오른쪽
  축에 띠로, 불러오기는 억 단위 선 하나.
- 서버가 이미 주는 수를 화면이 버린다: 낙폭 곡선 · 리밸런싱마다 회전율 · 비용(impact) · 소르티노·칼마·꼬리 지표(`metrics`) ·
  시뮬레이션 시작일(학습 구간) · 기준일.
- 그림이 "무엇을 모르는지" 말하지 않는다. 믿음 칩(trust)·재지 않은 것(unmeasured)은 글로만, 그림과 떨어져 있다.
- recharts `Tooltip`(떠다니는 툴팁)을 쓴다 — ADR-003 §2.4 "툴팁 금지 · 사유는 보이는 줄에" 와 어긋나고 키보드로는 값을 읽을 수 없다.

## 4. 설계

### 4.0 원칙 셋 (CLAUDE.md §2 + dataviz 를 이 화면에 번역)

1. **결론은 증거보다 강할 수 없다 → 그림이 모르는 것을 그림 안에 적는다.** 시간축 밑에 **증거 띠**가 있어, 어느 구간이 배우기만 한
   구간이고, 언제 리밸런싱했고, 어디가 기준일이고, 합성 데이터인지를 그림이 스스로 말한다. 사유는 글로 늘 보인다(툴팁 아님).
2. **어떤 질문에 답했는지 밝힌다.** 머리에 "이 결과가 답하는 것: 과거에 이 규칙대로 비중을 전달했다면 어땠나(전달) · 답하지 않는 것:
   신호가 미래를 맞히는지(예측 스킬) · 돈이 되는지(경제적 가치)" 를 적고, 뒤의 둘은 관문 레일의 `oos`·`economic` 역 상태를 그대로
   보인다. 다음 구간 예측(conformal)은 **곡선 위에 그리지 않는다** — 따로 떨어진 글 절이다.
3. **색은 일을 하나만 한다.** 수익·낙폭(등락) = `--tx-up/--tx-down` + 부호 · 포트폴리오 선 = 잉크(`--pg-ink`), 벤치마크 = 회색
   (`--pg-mute`) — 파랑(`--pg-blue`)은 행동 색이라 데이터에 쓰지 않는다 · 갈래 비교(≤ 4) = `--mc-c-1..4` + 직접 라벨 · 증거 상태 =
   `--pg-ok/--pg-assume/--pg-unknown/--pg-fail` + 글자 라벨(색만으로 말하지 않는다).

### 4.1 읽는 순서 — 자세히 탭(요약) 과 성과 시트(전부)

자세히 탭(폭 300~600):

```
┌ 과거에 이 규칙대로 했다면 이랬어요            ← 서버 explain.title 그대로
│ 연 +8.8%                                      ← 서버 headline(hero · 28px)
│ [백테스트·합성데이터] [연습용 데이터] [룩어헤드 미상]   ← PerfLabel · 기존 칩 (pg-perf · [data-lookahead])
│ 총수익 +31.2%   가장 크게 빠진 폭 −18.4%   위험 대비 수익 0.71   ← .pg-kv (계약 유지 · 셋~넷)
│ ┌─ 자산 곡선 + 낙폭(물속) ──────────────────────┐
│ │ ×1.31 잉크 선 · 벤치마크 회색 · 오른쪽 끝 값 라벨      │
│ │ ───────────────────────────────── 1.0 기준선      │
│ │ ▁▂▃ 낙폭 파랑 wash 아래로 (같은 x · 같은 폭)        │
│ │ ░░░[배움]│══════╷══╷═══╷═══════╷═══│ 기준일 ← 증거 띠 │
│ └──────────────────────────────────────────────┘
│ 읽는 줄: 2025-03-14 · 포트폴리오 ×1.12 (+12.0%) · 벤치마크 ×1.05 · 낙폭 −3.1% · 이날 리밸런싱 회전율 9%
│ 해마다: 2024 ▌+12.3%  2025 ▐−4.1%  2026(10개월) ▌+6.0%      ← 등락 막대 · 부분 연도 표시
│ 믿어도 되나요?  [확인] … [가정] … [몰라요] …           ← explain.trust (기존)
│ ▸ 재지 않은 것 N가지                                  ← explain.unmeasured (기존)
│ ▸ 지표 모두 보기(묶음 여섯)   ▸ 표로 보기            ← <details>
│ 다음 구간 예측 (분포 무가정) …                        ← 기존 Conformal(.pg-bt-cf)
│ [크게 보기]                                           → 성과 시트
```

성과 시트(`Sheet` 재사용 · 새 modifier `.pg-sheet--wide` = `min(960px, 100vw - 32px)`):

1. 머리 — 같은 제목·hero·라벨 + **질문 띠**(답하는 것/답하지 않는 것 + 관문 `oos`·`economic` 역 상태 점, `GateRail` 의
   `pg-stn--{state}` 재사용).
2. 큰 그림 — 같은 부품, 높이 360.
3. 기간별 — 해마다 표(수익·가장 크게 빠진 폭·거래일·부분 연도) + 달마다 격자(연×월, 등락 두 팔 색 + 칸 안 숫자, 글자는 잉크).
4. 큰 낙폭 사건 셋 — 시작·바닥·회복(없으면 "아직 회복 못 함")·깊이·바닥까지/회복까지 며칠.
5. 지표 모두 — 여섯 묶음(수익 · 위험 · 위험 대비 수익 · 분포 · 거래·회전 · 비용) · 못 잰 칸은 "산출 불가 — 사유".
6. 리밸런싱 기록 — 날짜 · 회전율 · gross/net(롱숏일 때만).
7. 다음 구간 예측 — 기존 Conformal.
8. 데이터와 한계 — trust · unmeasured · 룩어헤드 축 · notes · belief_note 를 한 목록으로.
9. 표로 보기 — 모든 그림의 표 쌍둥이.

### 4.2 그림 하나 — `PerfCurve` (자산 곡선 + 낙폭 + 증거 띠 + 읽는 줄)

- **직접 그린 SVG**(recharts 아님). 까닭: 읽는 줄·증거 띠·키보드 십자선은 recharts 툴팁 모델 밖이고, 저장소의 견고성·위험 그림
  (`RobustnessResults.tsx`·`RiskResults.tsx`)이 이미 이 방식이다. 폭은 `ResizeObserver` 로 재서 px 로 그린다(viewBox 확대로 글자가
  커지는 것을 피함 — 300~960px 에서 글자 크기 고정).
- 마크(dataviz): 선 2px round · 벤치마크 1.5px `--pg-mute` 실선 · 낙폭 = `--tx-down` 12% wash + 1.5px `--tx-down-ink` 선 ·
  격자 1px 실선 `--pg-line`(2~3줄) · 기준선(1.0 또는 시작 금액) 1px `--pg-mute`.
- 세로축: 7번은 "처음을 1로"(×1.31), 불러오기·전략 묶음은 원(만·억 서버 값 서식). 단위는 서버 뷰에서 정해진 대로 — 화면이 환산하지 않는다.
- 점 수: 서버 곡선을 폭에 맞춰 솎되(최대 폭/2 점) **양 끝·최고점·낙폭 바닥**은 반드시 남긴다 — 솎아서 가장 큰 낙폭이 사라지지 않게.
- 직접 라벨: 오른쪽 끝에 포트폴리오·벤치마크 끝값 두 개 + 범례 줄(두 계열이면 범례 필수 — dataviz).
- **증거 띠**(x축 밑 14px): ① 배움 구간 `coverage.start`~`dates[0]`(있을 때) 옅은 빗금(그림 안 글자는 두지 않는다 — 세로축 눈금
  글자와 부딪힌다 · 글은 띠 범례가 맡는다) ② 시뮬레이션 구간 실선 ③ 리밸런싱 날 짧은 눈금(`rebalances[].date`) ④ 기준일
  (`coverage.as_of_effective`) 표식 ⑤ 합성 데이터면 띠 전체 45° 빗금 + 띠 범례에 "연습용 데이터"(글자 함께). 띠 범례는 그림 아래
  항목 줄 — 항목마다 띠와 같은 모양의 표식(빗금·눈금·▲) + 글("처음 n일은 배우기만" · "리밸런싱 n번" · "기준일 …" · "연습용 데이터")이고
  가운뎃점으로 잇지 않는다. 전략 묶음·불러오기는 ①③④ 가 서버에 없으면 그 항목만 비운다(지어내지 않음) — 리밸런싱은 **아는 만큼만**:
  날짜가 있으면 눈금 + 횟수, 횟수만 알면 "리밸런싱 n번 (날짜는 기록에 없어요)", 0이면 "리밸런싱 없음", 모르면 아무 말도 하지 않는다
  (모름 ≠ 0). 데이터가 실제인지 모르면(`perf_label.data_real` null) "데이터가 실제인지 몰라요".
- **읽는 줄**(`.pg-pf-read`, `aria-live="polite"`): 기본은 마지막 날. 포인터 이동·`ArrowLeft/Right/Home/End` 로 가장 가까운 날짜에
  십자선이 붙고 줄이 바뀐다. 날짜 · 포트폴리오 값(+누적 수익률, 등락 잉크색) · 벤치마크 · 낙폭 · 그날 리밸런싱이면 회전율. 값은 늘
  보인다 — 떠다니는 툴팁 0.
- 미상 처리: `bench_curve` 가 null 이면 범례에 "벤치마크 없음". 곡선 값이 null 인 날은 선을 끊는다(0 으로 잇지 않음).
- 움직임 없음(십자선 이동은 즉시).

### 4.3 색 — 일별 배정

| 일 | 토큰 | 비고 |
|---|---|---|
| 포트폴리오 선 | `--pg-ink` | 데이터만 진하게 |
| 벤치마크 선 | `--pg-mute` | 강조-문맥 |
| 낙폭(물속) | `--tx-down` 12% + `--tx-down-ink` 선 | 등락 규칙(손실 = 파랑) |
| 해마다·달마다 수익 | `--tx-up`/`--tx-down` 채움, 글자는 `--pg-ink` + 부호 | 두 팔 diverging · 중립은 `--pg-soft` |
| 갈래·전략 비교(≤4) | `--mc-c-1..4` | 검증기 통과 · 직접 라벨 필수 |
| 증거 띠 상태 | `--pg-ok`/`--pg-assume`/`--pg-unknown`/`--pg-fail` | 글자 라벨 동반 |

새 토큰은 만들지 않는다. 부품은 역할 변수(`--pf-ink/--pf-mute/--pf-down/--pf-down-ink/--pf-up/--pf-line/--pf-surface/--pf-soft`)를
읽고, 캔버스에서는 `.pg-theme` 이 그 변수에 `--pg-*`·`--tx-*` 를 넣는다. 다크는 같은 토큰의 `.dark` 값이 받는다 — `contrastAudit` 로 잰다.

### 4.4 지표 묶음 — 네 질문을 섞지 않는다

- 요약 셋~넷(패널 `.pg-kv`): 총수익 · 가장 크게 빠진 폭 · 위험 대비 수익(샤프) · (벤치마크 있으면) 벤치마크 대비.
- 여섯 묶음(시트·패널 details): 수익 · 위험 · 위험 대비 수익 · 분포 · 거래·회전 · 비용. 영어 약어는 처음 한 번 풀어 쓴다.
- 못 잰 칸: "산출 불가 — 사유" 한 줄(0·빈칸 금지).

### 4.5 서버 추가 — `src/engine/quant_metrics.py` 에 순수 함수 둘

- `period_returns(dates, equity)` → `{"yearly": [{year, return_pct, max_drawdown_pct, n_days, partial}], "monthly": [{year, month,
  return_pct, n_days, partial}]}` — 부분 기간은 `partial=True` 로 표시하고 **연환산하지 않는다**.
- `drawdown_episodes(dates, equity, top=3)` → `[{peak_date, trough_date, recovery_date|null, depth_pct, days_to_trough,
  days_to_recover|null}]` — 깊이순 · 회복 못 했으면 `null`.
- 싣는 곳: `walk_forward` 출력 `periods`·`drawdowns` · 불러오기 뷰(`equity` 에서) · 전략 묶음 뷰(`curve` 에서). `explain_backtest`·
  `_explain_strategy`·`_explain_load` 에 사실 한 줄(`drawdown_fact` — "가장 깊은 낙폭은 … 고점에서 n일 만에 x% 빠진 것이었고, 고점을
  되찾기까지 m일 걸렸어요." / "아직 고점을 되찾지 못했어요.").
- 불러오기 뷰의 낙폭: 저장된 `drawdown_curve` 는 비율(−0.15)이고 통계 `max_drawdown_pct` 는 %(14.9)라, 뷰가 % 로 옮겨 **이름에 단위를
  적은** `drawdown_pct` 로 싣는다(7번 `drawdown_curve` 와 같은 단위 · 화면이 단위를 추측하지 않게 — `tests/test_allocation_graph_bl3w1.py`).
- 세 노드의 지표 키가 조금씩 다르다(7번 `cagr_pct` · 불러오기 `cagr`·`win_rate`·`num_trades`·`profit_factor` · 전략 묶음
  `annualized_return_pct`·`sharpe_ratio_full`) — 화면의 지표 묶음은 같은 뜻의 키를 같은 한글 라벨로 적되 **있는 키만** 그린다. 키를 서버에서
  고치지 않는다(각 엔진의 응답 계약 · 값 골든).

### 4.6 상호작용·접근성

- 그림 묶음은 `role="group"` + `aria-label` · 십자선 키보드 · 표로 보기(`<details>` 안 `<table>`).
- 그림·숫자의 글자는 `--pg-ink/--pg-body/--pg-mute` 만(등락 숫자만 `--tx-*-ink`).
- 다크: 토큰만 · `contrastAudit('.pg-side')`·시트 라이트·다크. 툴팁(`title=`) 0.

### 4.7 글

제목·헤드라인·사실·믿음·재지 않은 것은 서버 `explain` 그대로. 화면 고유 라벨은 해요체·한글("연 수익률" · "위험 대비 수익(샤프)" ·

## 5.1 실물 대 와이어프레임 (구현 뒤 기록 · 2026-11-09)

라이트·다크 스크린샷(패널 세 노드 · 시트 · 800px 바닥 시트)을 §4.1 와이어프레임과 대조했다. 읽는 순서·그림 하나·증거 띠·읽는 줄·
해마다·지표 묶음·표 쌍둥이·시트의 아홉 절은 와이어프레임 그대로다. 눈으로 보고 **바꾼 것**:

- 그림 안의 "배움 n일" 글자를 뺐다 — 세로축 눈금 글자(`×1.29`)와 붙어 한 글자처럼 읽혔다. 빗금은 그대로고 글은 띠 범례가 맡는다(§4.2).
- 띠 범례를 가운뎃점으로 이은 한 줄 글에서 **항목 줄**(표식 + 글)로 바꿨다 — 글 규칙(가운뎃점 메타 문자열 금지)과 범례 모양(선 범례와 같은
  문법)을 맞추려고. 읽는 줄의 "이날 리밸런싱 · 회전율" 도 "이날 리밸런싱 (회전율 n%)" 로.

- 불러오기의 낙폭 단위(비율 vs %)를 서버 뷰가 `drawdown_pct` 로 옮겨 적는다(§4.5) — 화면이 ×100 을 추측하지 않게.

  날짜 칸이 붙어 보여 칸 사이를 띄웠다.
- 지표 묶음의 `<dl>` 에 `.pg-kv` 를 붙이지 않는다 — ".pg-kv 총수익" 이 BL3 W1 의 E2E 계약(요약 숫자 하나)이라 둘이 잡혔다. 모양은 같은
