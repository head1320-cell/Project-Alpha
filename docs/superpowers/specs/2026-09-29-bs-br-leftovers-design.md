# BS — BR "하지 않은 것" 마무리 설계 (2026-09-29)

사용자 지시: "하지 않은 것 중에 '머리 줄의 국면 줄'만 빼고 이어서 다 해". 계획 원본은 세션 계획 파일
(`happy-percolating-falcon.md`)이다. 이 문서는 **정한 것과 그 이유**만 남긴다.

## 사용자 결정 (AskUserQuestion)

| 질문 | 답 |
|---|---|
| 가입 방식 | **관리자가 계정 발급**. 공개 가입·초대 코드는 만들지 않는다. |
| 합치기 방법·몫 | **기본값은 그대로**. 고를 때만 쓰이는 방법을 더한다: 위기 상관 반영 · 엔진에 있는 방법 노출 · 몫 직접 정하기 · 탐색에서 찾은 더 나은 방법. CLAUDE.md §3 의 별도 승인 사항으로 사용자가 승인했다. |
| 카드 크기 | **내용에 맞춰 줄이기**(실측). 합치기 카드 236 > 열 230, `NODE_W` 176 ≠ 164 두 어긋남도 고친다. |

가입을 공개로 열지 않는 이유: 로그인만 하면 열리는 보호 라우트에 실계좌 잔고·주문 이력·일별 손익이 있다
(`src/api/protected_routes.py` 의 `REQUIRE_LOGIN` 항목들). 누구나 가입할 수 있으면 누구나 이것을 본다.

## BS1 · 계정 — 정한 것

- **보안 상태는 새 테이블 `user_security`** 에 둔다. `users` 에 열을 더하면 운영 DB 에 `ALTER` 가 필요하고, 실패하면 ORM 조회 전체가 깨진다.
  새 테이블은 `create_all` 이 만들고, 행이 없으면 기본값(판 0 · 바꿀 차례 아님)이다. 예전 계정은 그대로 로그인된다.
- **토큰 판(`tv`)**: 비밀번호를 바꾸거나 초기화하면 판이 1 오르고, 판이 다른 토큰은 `get_current_principal` 에서 401 이다.
  예전에는 비밀번호를 바꿔도 옛 토큰이 12시간 살았다. 사라진 계정의 토큰도 401 이다. 계정 DB 에 닿지 못하면 503 이다 —
  확인하지 못한 것을 통과로도 거절로도 접지 않는다.
- **처음 로그인**: 관리자가 준 임시 비밀번호로는 `require_login`·`require_admin`·`require_self_or_admin` 라우트가 403 이다.
  비밀번호 바꾸기(`require_login_to_change_password`)와 `/auth/me` 만 열린다.
- **비밀번호 규칙**(순수 `src/domain/password_policy.py`): 8자 이상 · 72바이트 이하(bcrypt 가 뒤를 자른다) · 지금과 다름 ·
  아이디와 다름 · 저장소가 만든 적 있는 값(`frm123!`·`temp`·`changeme`) 아님. 구성 규칙(대문자·특수문자)은 넣지 않았다
  (NIST SP 800-63B §5.1.1.2). 화면이 같은 규칙을 미리 보이고, 두 목록이 같은지는 pytest 가 본다.
- **지금 비밀번호를 5번 틀리면 15분 429**. 프로세스 로컬이다(`--workers 1`).
- **발급**: 임시 비밀번호는 서버가 만들고 응답에 한 번만 싣는다. 목록은 해시·비밀번호를 싣지 않는다.
- **admin 기본 비밀번호 상태는 계정을 본다**. 예전 판정은 환경변수만 봤다. 그 값은 admin 행을 처음 만들 때만 쓰이므로,
  "설정했지만 계정은 아직 기본값을 받는" 배포를 configured 라고 말했다.
- **옆문 계정**: `update_user_portfolio`·`log_trade` 가 비밀번호 `"temp"` 로 계정을 만들던 것을 아무도 모르는 비밀번호로 바꿨다.
- **로그**에는 이름만 남기고 비밀번호·토큰·임시 비밀번호는 남기지 않는다(caplog 테스트).
- **화면** `/settings`(`.set-*` = E2E 계약): 신원 머리 → (바꿀 차례면 안내) → 비밀번호 → 화면 테마 → (관리자) 계정 관리 → 로그아웃.
  토큰만 쓰므로 `DARK_READY` 에 들어간다. 세션·테마 모듈은 두 기능이 함께 쓰므로 `entities/session`·`shared/theme` 으로 내렸다
  (FSD: 같은 계층 슬라이스끼리 import 금지).

## BS2 · 카드 — 정한 것

- **크기는 한 자리**(`entities/portfolio-graph/size.ts`): 카드 폭 150 · 합치기 236 · 열 간격 80(열 230) · 줄 틈 28 ·
  보통 카드 본문 124 · 합치기 224 · 포트가 많으면 `46 + 포트 × 22`. 배치(`mapLayout`·자동 정리·갈래 띠·비교 노드 자리)와
  CSS 폭(`--pg-node-w`)이 모두 이 값을 읽는다. 예전에는 CSS 164 · 배치 176 · 줄 170 이 따로 있었다.
- **세로는 내용 높이 + 틈**: 고정 줄 170 대신 카드마다 `cardHeight + 28` 로 쌓는다. 합치기 다음 열은 합치기의 넓은 폭만큼 민다.
- **선 요약 라벨은 원천 카드 오른쪽 틈에** 둔다(선 가운데 아님). 폭은 64px 로 줄바꿈하고, 한 포트에서 여러 선이 나가면
  첫 선에만 단다(같은 요약이 겹쳐 쌓였다).
- **고른 노드 막대**: 아래 자리가 모자라면 위로, 가운데 두면 떠 있는 판 밑으로 들어가면 고른 노드의 끝에 맞춘다.

## BS4 · 합치기 방법 — 정한 것

- **기본값은 그대로**(`risk_parity`). 기존 방법의 몫·비중·view 키는 방법을 더하기 전에 얼린 골든과 같다
  (`tests/test_bs4_golden.py`). 새로 생긴 키는 엔진 `fallback` · view `method_compare`·`market` 뿐이다.
- **새 방법(고를 때만)**:
  - `crisis_risk_parity` 위기 때 위험 똑같이 — 시장 대용(견고성 절과 같은 `market_proxy`)이 가장 나빴던 10% 날의
    ★평균을 빼지 않은 2차 적률★로 위험을 똑같이 나눈다. 계획은 수축 공분산이었지만, 실측에서 위기일마다 시장의 3배로
    떨어지는 전략에 33.3% 를 줬다(평소 위험 균형 20.3%) — 공분산은 늘 같이 떨어진 몫을 평균으로 빼 버린다. 적률로는 8.0%.
    시장 대용이 없거나 · 위기일이 20일 미만이거나 · 시장 흐름이 짧으면 **실패 + 사유**(평소 공분산으로 가지 않는다).
    시장 흐름은 전략 흐름과 **끝을 맞춘다** — 합치기가 종목을 줄 세우는 방식과 같고, 믿음 칸이 그렇게 말한다.
  - `max_diversification` 분산 효과 최대 — Σwσ/σ_p 를 롱온리 SLSQP 로 최대화. 못 풀면 실패.
  - `manual` 몫 직접 · `risk_budget` 위험 예산 직접(합 100) · `score` 점수 비례 — 엔진에는 이미 있던 둘을 노드에 열었다.
- **입력이 없으면 노드가 실패한다**: 엔진은 점수·예산이 없으면 조용히 위험 똑같이로 갔다. 노드는 비어 있는 전략 이름을
  들어 실패하고, 엔진은 같은 경우에 `fallback` 을 싣는다(`/combine-sleeves` 도).
- **대체 드러내기** `fallback{used, from, reason}`: 점수·예산 없음 · 점수 모두 0 · 모르는 방식 · 흔들림 최소가 풀리지 않음
  (예전에는 `_opt` 가 None 을 내면 **터졌고**, 예외일 때만 조용히 역변동성이었다 — 이제 둘 다 역변동성 + 표시) · HRP 예외.
  노드 믿음 칸은 예전 "그 경우인지 모름" 대신 실제로 대체했는지(또는 풀렸는지) 말한다.
- **방법 비교표**(자세히 탭, 관측): 입력이 필요 없는 일곱 방법을 같은 흐름·같은 공분산에서 — 몫 · 합친 흔들림 · 분산 효과 ·
  실질 개수(1/Σw²). 못 잰 줄은 사유. "어느 방법이 낫다는 뜻이 아니에요".

## BS5 · 다크 — 정한 것

- **라이트는 한 픽셀도 바꾸지 않는다** — 다크를 입히기 전에 13 라우트의 라이트 계산 스타일(글자·바탕·테두리·SVG 칠)을
  `frontend/e2e/golden/light-styles.json` 에 얼렸다. 요소 종류별로 골든에 없던 스타일 조합이 생기면 실패한다.
- **세 층**:
  1. 레거시 토큰(`--bs-*`·`--text-muted`·상태색·`--color-bull/bear`)을 `.dark` 에서 뒤집는다.
  2. 글자로 적은 색은 생성기(`frontend/scripts/gen-dark-modules.mjs`)가 `globals.css` 의 생성 구역에
     `:where(.dark) <원래 선택자>` 짝으로 만든다 — 특이도 0 이라 라이트와 같은 순서로 겨룬다. 인라인 hex 는 코드 변환
     (`frontend/scripts/hex-to-tokens.mjs`)이 `var(--hx-{t|b|d}-xxxxxx)` 로 바꾼다(라이트 값은 같은 hex).
  3. 그래도 남는 것은 손으로("BS5 손질" 절).
- **채운 강조·상태색 위 글자** = `--on-accent`(라이트 흰색, 다크 #09090b). 다크의 강조·상태색은 글자로 읽히게 밝아서
  흰 글자가 2.3~3.6:1 이 된다 — 강조색은 글자·바탕 두 쓰임을 동시에 만족하는 값이 없다(명도 0.18~0.19 사이에만 존재).
- **다크 판정**(E2E `dark-modules.spec.ts`, 실제 테마 경로로 켬): 7 모듈 + 매크로 스튜디오 5 + 파생 + 매크로 탭 8 +
  스크리너·백테스터 팩터 고르기 + 백테스터 매도·유니버스 + 기업 분석 뒤 + 백테스트 진행·비교 — 글자 AA(SVG 는 fill) ·
  비활성 조작부 제외(WCAG 1.4.3) · 밝은 **판**(글자를 품었거나 48×48 이상) 없음.
- **예외**: 첫 화면·개발 화면은 밝게, 실거래·다중 백테스트·현실성 관리 화면은 늘 어둡게(`DARK_EXCEPTIONS`). 안내 문구는 이
  예외만 말한다.

## 하지 않는 것

- 공개 가입·초대 코드 · 로그인 시도 제한(비밀번호 바꾸기에만 둔다)
- 합치기 몫을 정하는 흐름의 끝 맞춤을 날짜 맞춤으로 고치기 — 배분 경로 변경이라 관측·제안만 한다(BS3)
- 실거래 전략 기록(저장소에 없다) · 첫 화면(`/`)의 다크 · 늘 어두운 관리 화면 셋의 라이트화 · 머리 줄 국면 줄
