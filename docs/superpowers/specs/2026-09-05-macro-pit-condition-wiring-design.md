## 0. 왜 — ★기계는 있는데 아무도 부르지 않는다★

`aa3c4ba` 로 `pit_macro.series_as_of()` / `pit_series_for_bars()` 와
`resolve_macro_token(df, token, as_of=)` 를 만들었다. **그런데 운영 코드에서 그
`as_of` 를 넘기는 호출부가 하나도 없다.** 실측이다:

```
resolve_macro_token( 호출부 → src/kis_strategies/condition_strategy.py:60 단 한 곳
                              resolver(df, name)      ← as_of 를 안 넘긴다
_base_series(df, token)    → 시그니처에 날짜 자체가 없다 (호출부 4곳)
macro_lookahead            → 코드베이스에 존재하지 않음
```

즉 지금 PIT 경로는 **테스트에서만 닿고**, 조건식 백테스트의 매크로는 100% 라이브
(= 여러 번 개정된 최신값)다. 계획서의 커밋 ③("조건식이 `as_of` 를 넘기고, 라이브는
룩어헤드로 라벨")은 기계만 만들고 배선을 하지 않았다.

두 번째 사실: **조건식이 노출하는 매크로 토큰 12개 중 개정되는 것이 하나도 없다.**

```
ECOS 4개 (US달러환율·국고채 1/3/10년)  → 제공자에 빈티지 엔드포인트 없음(영구)
FRED 8개 (DGS1/2/3/5/7/10/20/30)      → 일별 시장 관측치라 개정되지 않음
```

반면 **개정되는 계열 8개는 이미 레지스트리에 있고 빈티지 백필 대상**인데 조건식에서
손이 닿지 않는다(`vintage_targets()` 21개 중). 그래서 이 스펙은 **배선 + 개정 계열
토큰화**를 한 덩어리로 한다.

★한쪽만 하면 정반대 효과다★ — 배선 없이 개정 계열만 토큰으로 열면, 실제로 개정되는
값을 **최신 개정본으로 과거에 먹이게** 된다. 지금(개정 없는 계열만 있는 상태)보다
나쁘다.

## 3. 배선 — 실행 스코프 컨텍스트 하나

`_base_series` 에 날짜를 실어 나를 필요가 없다. 네 호출부 전부 `df` 를 넘기고
**`df.index` 가 곧 봉 날짜**다. 대신 실행 스코프 객체 하나를 넘긴다.

```python
class MacroPitContext:                        # 실행 1회당 1개
    calendar: pd.DatetimeIndex                # 실행 달력 (참조 종목 인덱스 = 워밍업 포함)
    obs:  dict[str, list[MacroObservation]]   # 계열당 스토어 ★1회★ 조회
    path: dict[str, str]                      # 토큰 → "pit" | "live" | "blocked"
    series: dict[tuple, pd.Series]            # (토큰, 프레임 인덱스 모양) → 누적 결과
```

### ★판정의 기준은 종목 프레임이 아니라 실행 달력이다★

`_base_series` 는 **종목별 프레임**을 받는다. 그런데 종목마다 상장일이 달라, 프레임의
첫 봉을 기준으로 판정하면 **2010년 상장 종목은 `live`, 2020년 상장 종목은 `pit`** 이
되어 한 실행 안에서 같은 토큰이 두 가지 의미를 갖는다. 그러면 "토큰단위
전부-아니면-전혀" 가 깨진다.

그래서 세 가지를 각각 다른 주기로 한다:

| | 몇 번 | 기준 |
|---|---|---|
| 스토어 조회 | 계열당 1회 | — |
| **PIT/라이브 판정** | **토큰당 1회** | **실행 달력**(`kis_backtest_engine.py:539` 의 `all_dates` — 워밍업 포함) |
| 누적 계산 | 프레임 인덱스 모양당 1회 (메모) | 그 프레임 |

KRX 종목은 거래일 달력을 공유하므로 실제 인덱스 모양은 실행당 한두 개다. 이렇게
가르면 "어느 달력이 정본인가" 를 정할 필요가 없고, 조회 횟수도 계열 수로 묶인다.

ctx 는 **실행 달력 없이는 만들지 않는다** — 달력을 모르면 판정 기준이 없고, 기준
없는 판정은 위의 종목별 갈림을 되살린다.

★"ctx 없음" 이 백테스트에서 조용한 라이브 통로가 되면 안 된다★ — 백테스트 경로에서
실행 달력은 `:539` 에서 **항상** 결정되므로 ctx 도 항상 만들어진다. `macro_ctx=None`
은 **스크리너·실시간 전용**이고, 그 경계를 §3 의 트립와이어가 지킨다.

```
_base_series(df, token, *, macro_ctx=None)
    macro_ctx 없음 → 라이브 (스크리너·실시간 경로 — ★기존 동작 불변★)
    macro_ctx 있음 → PIT 판정 (백테스트 경로)
```

### ★캐시가 선택이 아니라 필수인 자리★

호출부를 세면 `_token_series`(`condition_strategy.py:882`)와
`prepare_panel`(`:564`)은 **종목마다**, 엔진의 `_check_market_timing`
(`kis_backtest_engine.py:1730` — ★실제 이름은 `_market_timing_on` 이다. 초안의
`_check_market_timing` 은 존재하지 않는 함수였고, 트립와이어의 "못 찾으면 실패"
단언이 그것을 잡았다★)은 **봉마다** 부른다. `macro_observation_store.load()`
는 PK 선두 컬럼 조건이라 **범위 스캔**이다(★스펙 초안의 "전체 스캔" 은 틀렸고
2026-09 구현 중 실측으로 정정했다★). 비싼 것은 `as_of` 필터가 그 계열의 전 빈티지·
전 기간 행을 다 가져온 뒤 **파이썬에서** 걸리는 부분이다(계열당 수만 행).
캐시가 없으면 200종목 × 3조건, 혹은
2,500봉만큼 그 스캔이 돈다.

그래서 `pit_macro` 를 **로더 + 순수 누적기**로 가른다.

- 로더: `series_id → 관측 리스트` (ctx 가 캐시. 실행당 계열별 1회)
- 누적기: `(관측 리스트, 봉 날짜들, lag_months) → Series` (순수 함수, 메모리)

부수 효과로 누적기가 **DB 없이 테스트된다**.

### 구멍 하나와 그 마개

이 설계의 유일한 구멍은 **새 호출부가 ctx 를 안 넘기고 조용히 라이브로 새는 것**이다.
"플래그를 두면 결국 라이브가 기본이 된다" 는 원칙과 상충하는 자리라, 정적
트립와이어로 막는다 — 백테스트 경로의 `_base_series` 호출부가 전부 ctx 를 넘기는지
`inspect.getsource` 로 검사한다. (어제 `callable()` 검사가 **존재하지 않는 함수**를
통과시킨 뒤, 이 방식이 `backfill_history`·`refresh_instrument_master` 부재를 즉시
잡아낸 전례가 있다.)

★모듈 전역 카운터를 쓰지 않는다★ — 엔진에 워커 스레드가 있어 동시 실행이 서로의
수치를 오염시킨다.

## 4. 전부-아니면-전혀를 ★임계값 없이★ 판정한다

`pit_series_for_bars` 의 누적기에서 `known` 은 **줄지 않는다**. `usable` 이 한 번
비지 않으면 이후 봉에서도 비지 않는다. 따라서 값이 없는 봉은 **반드시 앞쪽 연속
구간**이고, 중간에 구멍이 나지 않는다. 그래서:

> **변환까지 끝낸 시리즈의 ★실행 달력 첫 봉★ 에 값이 있으면 전 구간 PIT,
> 없으면 전 구간 라이브 + 라벨.**

(첫 봉의 기준이 종목 프레임이 아니라 실행 달력인 이유는 §3 참조.)

매직 넘버가 없고 "커버리지 70%" 같은 자의적 기준도 필요 없다. 대신 이 규칙은
**누적기의 단조성에 의존**하므로 단조성 자체를 테스트로 못 박는다. 전제인 **봉 날짜
오름차순**도 함께 검사한다.

YoY 토큰은 lag 값까지 필요해 레벨 토큰보다 NaN 접두가 길다 — 그래도 접두이므로
규칙은 그대로다. **변환을 먼저 하고 첫 봉을 본다.**

## 5. 변환은 ★같은 빈티지 안에서★ 계산한다

`US물가(전년비)` 는 분자와 분모가 **그 시점에 알려져 있던 같은 빈티지**에서 나와야
한다. 2023-03 봉에서 2022-03 CPI 를 **2024년 개정본**으로 나누면, 룩어헤드를
없애려다 분모로 다시 들여온다.

```
pit_series_for_bars(series_id, bar_dates)                     ← ★시그니처 불변★
pit_pair_for_bars(series_id, bar_dates, *, lag_months=k)      → (현재값, lag 값)
```

★2026-09 정정 — kwarg 를 붙이려던 초안이 틀렸다★ 기존
`test_macro_pit_wiring.py::test_the_panel_is_read_once_not_per_bar` 가 `load()`
**정확히 1회**를 못 박고 있어, `pit_series_for_bars` 를 두 번 부르는 설계는 그
계약을 깬다. 그래서 **한 번 읽어 두 시리즈를 주는 함수를 새로** 두었다. 부수
효과로 분자와 분모가 **같은 스냅샷**에서 나오는 것이 구조로 보장된다.

기간 이동은 **달력 연산**이다: `YYYY-MM-DD` 파싱 → k개월 차감 → **정확히 일치하는
기간** 조회. "known 목록에서 12칸 뒤" 로 세지 않는다 — 결측이 하나만 있어도 조용히
어긋난다. 파싱되지 않는 기간(스토어에 `YYYYMM` 이 섞여 있다)은 **추측하지 않고**
`None` + 사유다.

**공식은 한 벌, 쌍(pair)의 출처만 둘이다.**

| | PIT | 라이브 |
|---|---|---|
| 쌍 만들기 | `pit_pair_for_bars`(읽기 1회) | 관측 축에서 **달력** k개월 이동 후 봉 정렬 |
| 공식 | `(v0/vk − 1)×100` · `v0 − vk` · `v0` | **동일 함수** |

★계약 테스트★ — 개정이 **없는** 픽스처(빈티지 = 라이브)에서 두 경로는 **같은 숫자**를
내야 한다. 공식이 갈라지면 여기서 죽는다. ★공표 지연을 0 으로 둔 픽스처를 쓴다★ —
두 경로는 값이 **보이기 시작하는 시점**이 다르고(그것이 PIT 의 요점이다), 지연을
남겨 두면 타이밍 차이가 공식 차이로 오인된다.

★수치 안전★ — YoY 는 나눗셈이라 `vk == 0` 이면 `inf` 가 아니라 `None` 이다
(CLAUDE.md 파생식 가드 규칙).

## 6. 라벨 — `signal_path` 와 같은 모양

```python
{"pit": n, "live": n, "blocked": n,
 "pit_pct": float | None,               # ★미측정 ≠ 0%★
 "tokens": {"US물가(전년비)": {"path": "live", "reason": "...",
                              "revision": {"bars": .., "flip": ..,
                                           "flip_pct": .. | None}}},
 "note": "..."}
```

★매크로 토큰을 **안 쓴** 실행은 이 키 자체가 `None` 이다★ (`intraday_meta` 선례).
★그러나 **썼는데 전부 라이브**면 `pit_pct: 0.0` 이다★ — 그건 측정된 사실이고,
거기서 `None` 을 내면 룩어헤드가 "안 썼다" 와 같은 모양으로 은폐된다.

세는 단위는 **실행당 토큰 1개**다(전부-아니면-전혀이므로 봉 단위가 아니다).

흐름은 `signal_path` 와 같다:

```
engine 결과 "macro_lookahead"
   → src/api/backtest_run_routes.py 가 텔레메트리에 복사 (signal_path 와 같은 방식)
   → BacktestResults 의 기존 "진단 · 데이터 범위" 카드에 live > 0 일 때 한 줄
```

## 7. 세 상태를 ★섞지 않는다★

```
pit      빈티지로 전 구간 평가됨
live     빈티지가 없어 라이브로 평가됨 — ★룩어헤드★, 라벨 부착
blocked  값을 내지 못함 — 조건 평가 안 됨 + 사유
```

| 상황 | 판정 | 왜 |
|---|---|---|
| 첫 봉에 빈티지 값 있음 | `pit` | |
| 정상 조회했는데 행이 없음 / 첫 봉 미달 | `live` | 사용자 선택 — 쓰되 라벨 |
| ECOS 토큰 | `live` | 제공자에 빈티지 없음(영구) + 앞선 결정 |
| **조회가 예외로 실패** | `blocked` | ★미상 ≠ 없음★ |
| `FRED_API_KEY` 없음 | `blocked` | 라이브도 불가 |

예외를 `live` 로 떨어뜨리면 **DB 가 잠깐 죽었을 때 전 실행이 조용히 룩어헤드 모드로
바뀌고**, 화면의 `live` 라벨은 "확인했더니 빈티지가 없었다" 로 읽힌다. 하지 않은
진술이다.

★폴백은 리졸버 안이 아니라 ctx 층에서 일어난다★ — `resolve_macro_token(as_of=...)`
는 지금처럼 **PIT 요청에 PIT 만** 낸다(침묵 폴백 금지 계약 유지). 전부-아니면-전혀
판정과 라이브 대체는 그 위 ctx 가 하고, **그래야 라벨이 붙는 자리와 값이 나오는
자리가 같다.**

## 8. 테스트

**단위 (DB 없이)** — 누적기를 순수 함수로 갈랐으므로 픽스처로 직접 검사한다:
단조성(값 없는 봉은 앞쪽 연속) · 봉 날짜 오름차순 전제 · 달력 lag · 결측 기간 →
`None` · `YYYYMM` 미파싱 → `None` + 사유.

**계약** — 개정이 없는 픽스처에서 **PIT 경로 == 라이브 경로**.

**골든** — `macro_ctx` 를 안 넘기는 기존 백테스트는 **결과 비트 동일**.

**성능** — 스토어 조회 횟수가 **계열 수와 같고 봉 수·종목 수와 무관**함을 센다.
누적 계산 횟수도 **프레임 인덱스 모양 수**로 묶이는지 함께 센다.

**판정 일관성** — 상장일이 다른 종목 둘을 넣어도 한 토큰의 판정이 **하나**인지.

**토큰** — 8개 각각이 의도한 축(레벨/YoY/전월차)으로 평가되는지.

### 변이 배터리 (한 번에 하나씩, 앵커 유일성 먼저)

| | 변이 | 죽여야 하는 것 |
|---|---|---|
| H1 | 분모(lag)만 라이브에서 가져온다 | ★같은 빈티지 계약★ — 룩어헤드를 분모로 재유입 |
| H2 | 첫 봉이 비어도 `pit` 으로 센다 | 라이브가 PIT 로 위장 |
| H3 | 공표 전 봉을 첫 값으로 채운다 | 룩어헤드 |
| H4 | lag 를 "목록에서 k칸 뒤" 로 센다 | 결측 하나에 조용히 어긋남 |
| H5 | ctx 없이도 PIT 를 쓴다 | ★짝★ 스크리너·실시간 동작 불변 |
| H6 | ctx 를 안 넘기는 호출부를 추가 | 트립와이어가 잡는가 (테스트의 테스트) |
| H7 | 라이브 판정을 안 센다 | 룩어헤드 은폐 |
| H8 | 매크로 토큰이 없는데 `pit_pct: 0.0` | ★미측정 ≠ 0%★ |
| H9 | 봉마다 스토어를 읽는다 | O(봉²) 회귀 |
| H10 | `vk == 0` 에 `inf` 를 낸다 | 수치 안전 |
| H11 | 빈 `vintage_id` 행을 인정 | 순환 거짓 — 가드가 새 경로에도 사는가 |
| H12 | 예외를 `live` 로 떨어뜨린다 | ★미상 ≠ 없음★ |
| H13 | 판정 기준을 실행 달력 대신 종목 프레임 첫 봉으로 | 한 실행 안에서 같은 토큰이 종목마다 다른 의미 |

## 9. ★내가 확인할 수 없는 것★

이 컨테이너에는 `macro_observations` 도 `FRED_API_KEY` 도 없다. **토큰 8개 중 실제로
몇 개가 `pit` 이 될지 모른다** — 백필은 2015 시작·스로틀(`MACRO_VINTAGE_MAX_CALLS`
기본 400/회)이라 깊이가 얕다. 어제 계획서에 "3/8 → 8/8" 을 적었다가 되돌린 것과 같은
종류의 추정이므로, **숫자를 적지 않고 측정 장치(`macro_lookahead`)를 답으로 둔다.**

또 하나 — **개정 계열 8개가 실제로 얼마나 개정되는지도 이 저장소에서 측정하지
않았다.** CPI·GDP·고용은 개정된다고 알려져 있지만, 그 크기가 조건식 판정을 뒤집을
정도인지는 빈티지가 쌓인 뒤 `macro_lookahead` 와 결과 차이가 답한다. **이 스펙이
주장하는 것은 "룩어헤드를 제거했다" 가 아니라 "룩어헤드가 있었는지 측정 가능하게
했다" 이다.**
