## 2. 역DCF — 새 모델이 아니라 기존 함수의 역함수

`valuation_models.py:216 compute_dcf(...)` 는
`가정(성장률·마진·WACC·영구성장) → 내재가치` 다. 역DCF 는 그 반대다:
**현재 시가총액을 정당화하려면 어떤 가정이 필요한가.**

- 미지수 하나(예: 향후 N년 FCF 성장률)를 두고 `compute_dcf(...) == market_cap` 을
  **1차원 근 찾기**로 푼다. scipy `brentq` 는 이미 의존성에 있다(QuantLib·scipy 사용 중).
- 단조성이 깨지거나 구간에 근이 없으면 **숫자를 내지 않고 사유를 낸다**
  (`{available:false, reason}`).
- ~~`compute_dcf:238` 의 `wacc = max(wacc, 0.03)` 클램프와 `(wacc - g) > 0.001` 가드가
  만드는 불연속이 실재한다.~~
  **★구현하며 정정(2026-08-22) — 격자 실측★** FCF 성장률을 미지수로 두면 **그 둘은
  불연속을 만들지 않는다.** `wacc` 는 `params.ke`·자본구조·`tax_rate` 에서만 나오고
  `fcf_growth_rates` 가 들어가지 않으며(실측: g=−0.30 과 g=+0.40 에서 둘 다 8.27%),
  `(wacc - g)` 의 `g` 는 `params.terminal_growth_rate` 이지 미지수가 아니다(둘 다 2.0%).
  함수 이름이 그럴듯해 보였을 뿐 **미지수와 무관한 상수**다.

  진짜 불연속은 셋이고 전부 실측했다(mock 삼성전자, 41점 격자):
  1. `per_share = max(0, equity_value/shares)` — **g ≤ −0.125 에서 0 으로 평평**.
  2. `round(per_share, 0)` — 원 단위 **계단함수**(계단 폭 Δg ≈ 1.7e-6 당 1원).
     → 허용오차를 가격이 아니라 **성장률**에 걸고, 달성 내재가와 시장가의 격차를
     함께 보고한다.
  3. `fcf_base <= 0 or shares <= 0` → 모든 g 에서 `available=False`, **근이 아예 없다.**
     ★적자·마이너스 FCF 기업이 정확히 여기다★(CLAUDE.md: mock 은 항상 흑자다).

  `(wacc - g) > 0.001` 은 **영구성장률을 미지수로 둘 때** 진짜 절벽이 된다 — TV 가
  통째로 0 으로 떨어진다. 그 축의 브래킷 상한이 WACC 아래인 근거가 이것이다.
- 산출: 시장내재 성장률 · **현재 가정과의 격차**. 이것이 "시장은 무엇을 믿고 있는가"
  이고, 언더라이팅의 출발점이다.
- ~~시장내재 마진~~ **★정정★** `compute_dcf` 는 FCF 를 **수준**으로 받지 매출×마진으로
  받지 않는다 — 매출과의 연결이 함수 안에 없으므로 진짜 내재 마진은 **매출 구동 DCF**
  라는 새 모델을 요구한다(Brief §18 후순위). 대신 이미 푼 해에서 파생되는 것만 낸다:
  FCF 궤적(새 가정 0)과, **오늘 매출을 고정했을 때**의 비율을 `assumes_flat_revenue`
  라벨과 **함께만**. 라벨 없이 "내재 마진" 이라 부르면 그것이 조용한 날조다.
- **현재 가정과의 격차**는 기본 성장 궤적의 기하평균이 아니라, 기본 경로가 낸 주가를
  재현하는 **상수 성장률을 같은 solver 로** 풀어서 낸다 — 궤적 공식을 두 곳에 두지
  않고 사과 대 사과가 된다.

## 3. 확률적 밸류에이션 P10~P90

**★구현하며 실측한 것 (2026-08-22) — 설계에 없던 결론 셋★**

**① 모델 불일치가 파라미터 불확실성보다 크다.** mock 삼성전자 실측:
통합 분포는 P90/P10 = **1.36** 인데, 같은 파라미터에서 RIM 57,152 / DCF 20,596 /
DDM 19,432 로 **2.94배** 갈린다. 통합값 하나의 P10~P90 만 내면 **더 큰 쪽이 평균에
지워진다.** → 모델별 분포를 함께 내고 `model_disagreement` 를 따로 보고한다
(P2.5 `target_weight_range` 의 "평균으로 접지 않는다" 와 같은 원칙).

**② 지배 파라미터가 β 다 — 폭을 지어낸 바로 그것.** ±1σ 일변량 충격:
β **6,025** > erp 4,504 > rf 4,468 > g 2,225. 계획은 rf 로 봤으나 틀렸다.
`PriceFactorsStore._beta`(`:314`)가 `cov/var` 점추정만 주고 **회귀 표준오차를 노출하지
않아** β 의 폭만은 근거가 없다. 분포를 가장 넓히는 것이 우리가 가장 모르는 값이므로
`dominant_driver` 와 `widths[*].measured` 를 **함께** 읽어야 한다.

**③ 폭 중 측정된 것은 하나도 없다.** 처음엔 β 만 `measured:false` 로 두려 했는데
그러면 나머지 셋이 측정된 것처럼 읽힌다. `_KE_STEPS`/`_G_STEPS`(±1%p)도 누군가 고른
**탐색 범위**이지 추정 표준오차가 아니다 → 넷 다 `measured:false`. 폭은 그 상수에서
**파생**시켜(베끼지 않았다) 격자를 넓히면 분포도 넓어진다.

부수 확인: 일변량 격자는 결합 불확실성을 과소평가한다(유도 ke ±1.6%p > 격자 ±1%p) —
`induced_ke` 로 남긴다. `price_percentile` 은 역DCF 와 **교차검증**된다(71,000원 →
100분위 · 역DCF 내재 11.4% vs 우리 3.2%).

TV 발산 표본은 `valuation_sandbox` 와 **같은 `_TV_GAP`** 으로 기각하고 센다 —
클램프하면 경계에 질량이 쌓여 분포가 인위적으로 좁아진다. 유효 표본이 요청의 25%
미만이면 분위수가 아니라 사유를 낸다.



같은 세 함수(`compute_rim`/`compute_dcf`/`compute_ddm`)를 **파라미터 분포로 감싼다.**
새 밸류에이션 모델을 만들지 않는다.

- `ValuationParams` 의 `risk_free_rate`·`market_premium`·`beta`·`terminal_growth_rate`
  에 분포를 준다. 상관을 무시하지 않는다 — 최소한 Rf 와 g 는 같이 움직인다.
- 표본 N 회 → 내재가치 분포 → **P10/P25/P50/P75/P90**.
- ★현재 주가가 그 분포의 몇 분위인지★ 를 함께 낸다. 이것이 football field 를
  "그림" 에서 "확률 진술" 로 바꾼다.
- **분포의 폭을 축소해 보이게 하지 않는다.** 표본이 적거나 가정이 넓으면 넓게 나온다.
  P4-MACRO 의 conformal 처리와 같은 원칙 — 구간을 좁혀 잘 맞히는 것처럼 보이게 하지 않는다.

## 4. 매크로 민감도 — P4-MACRO 자산 재사용

**★구현하며 실측한 것 (2026-08-22) — 설계에 없던 결론 넷★**

**① `regime_drivers` 재사용은 이 자리에 안 맞는다.** 그 모듈은 **국면 확률**을
지표별로 쪼갠다(가치함수가 `quadrant_probs`). 값함수에 기업이 들어가지 않으므로
"종목 ↔ 매크로" 민감도로 쓸 수 없다. 실제로 재사용한 것은 `macro_collector` ·
`regime_transitions.regime_path` · **P2.5 의 `conditional_market`**(월 국면 라벨).

**② 채널이 있는 것과 없는 것을 나눠야 한다.** C.3 의 네 예 중 **하나만** 산출 가능:

| 예 | 가능? | 이유 |
|---|---|---|
| `+100bp 10Y → 적정가치` | ✅ | `rf → ke = rf + β·erp`, `kd = rf + 1.5%p` — **모델의 항등식** |
| `GDP −2σ → EPS` | ❌ | EPS 는 밸류에이션 모델의 **입력**이지 출력이 아니다 |
| `USD +10% → EPS` | ❌ | 같은 이유. 매출 구성 데이터가 없다 |
| `Oil +30% → EBIT` | ❌ | **유가 계열이 수집기에 없다**(61계열 확인) |

셋은 `available:false` + 사유로 낸다. 연간 재무 10행으로 매크로→EPS 회귀를 지어내는
것이 정확히 이 문서가 막으려는 날조다.

**③ 충격이 비대칭이다.** mock 삼성전자: −100bp → **+11.62%** vs +100bp → **−9.54%**
(비율 1.22). 한 방향만 재서 "민감도 −9.5%" 로 내면 볼록성이 사라진다 → 양방향을
따로 내고 비대칭을 숫자로 남긴다.

**④ 모델별 반응이 4배 갈린다.** 같은 −100bp 에 DCF **+25.82%** vs RIM **+6.32%** vs
DDM +12.69%. 통합값만 내면 평균이 그것을 지운다 — 모델별로 함께 낸다(P2-3 과 동일).

**통계 채널**은 코어 5계열(KR_10Y·KR_BASE_RATE·KR_CPI·USD_KRW·KOSPI)을 **코드에
고정**하고 **전부** 보고한다 — 61계열을 훑어 t값 큰 것만 내면 다중검정 보정 없는
데이터 마이닝이다(Gemini 가 지적한 차원의 저주). 실측 59개월에서 다섯 계열 모두
|t| < 2 · R² ≈ 0 이었고, **그 결과를 그대로 낸다.** 구조적 블록과는 `method` 로
분리해 절대 한 표에 섞지 않는다 — 항등식과 표본 추정은 다른 종류의 숫자다.



Company 경로에 `macro` 참조가 **0건**이다. 이미 만든 것을 붙이기만 하면 된다:

- `src/services/macro_collector.py` — ECOS 40 + FRED 21 계열.

## 5. 구조화된 논지 + kill 조건 → 신호 → 백테스트 (프롬프트 6·7)

  백테스트가 이미 쓰는 단일 필드 계약이다.
  ★새 DSL 을 만들지 않는다★ CLAUDE.md: 새 필터 kind 는 `validate()` 의 bypass 튜플에
  반드시 등록.

### ★실측 (P2-5) — 다리는 실재하지만 좁다★

변환은 성립한다. 다만 **건널 수 있는 폭**을 재 보니 좁았다:

| 구분 | 실측 | 의미 |
|---|---|---|
| `FIELD_BY_ID` 전체 | **157** | 논지가 쓸 수 있는 필드 |
| 조건식 토큰으로 도달 가능 | **92** | 수동 별칭 29 + 스토어 라벨 별칭 63 |
| 도달 불가 | **65** | `momentum_12_1`·`max_drawdown_1y`·수급 계열 등 |
| PIT 토큰(`_PIT_FUND_TOKENS`) | **12** | 봉별 시점 재무 — 룩어헤드 없음 |
| 그중 `FIELD_BY_ID` id 와 맞물림 | **5** | `per`·`pbr`·`psr`·`pcr`·`roe` |

★그 5개도 `financials_history` 가 적재돼야 PIT 로 돈다★
`condition_strategy.py:864-874` 가 ①PIT 우선 → ②스냅샷 상수 폴백(opt-in
`allow_snapshot_fundamentals`, 코드가 직접 "look-ahead 근사" 라고 적어 둔 것)
순서로 동작한다. 이 컨테이너에는 적재돼 있지 않다(`load_history("005930") == []`).

그래서 P2-5 의 산출물은 "된다/안 된다" 가 아니라 조건마다의 **3단 분류**다:

1. `backtestable` — PIT 토큰 + 시계열 적재 → 룩어헤드 없이 백테스트 가능
2. `screen_only_backtest_lookahead` — 올릴 수는 있으나 스냅샷 상수라 **룩어헤드
   근사**. opt-in 이 필요하고, 켜면 그 사실이 라벨로 남는다.
3. `screen_only` — 조건식 토큰이 없어 못 올린다(65개)

"kill if ROE < 8%" 를 쓴 사람은 1번을, "kill if 12-1 모멘텀 < 0" 을 쓴 사람은
3번을 **미리** 안다. 그것이 이 슬라이스가 주는 정보다.

숫자는 상수가 아니라 기록이다 — 분류는 매번 상류 레지스트리를 실제로 읽는다.
숫자가 달라졌다면 상류가 바뀐 것이므로 **먼저 그것을 확인**할 것.

## C.1 CompanySnapshot 의 정량 근거 (실측)

`scripts/bench_company.py` 로 잰 것(벤치 문서 §6.5):

| 관측 | 값 | 스냅샷이 바꾸는 것 |
|---|---|---|
| 콜드 페이지 로드 | 83 ms (엔드포인트 8개) | 1회 조회로 축약 가능 |
| **`comps_table` DB 쿼리** | **48** | 피어 집합을 스냅샷에 담으면 재조회 0 |
| **`risk_deep` 내부 중복** | `_annual_rows` **2회** | 한 번 읽어 넘김 |
| 딥 탭 재무이력 읽기 | **3회** | **1회** |
| `evaluate` 호출 | **3회**(base/bull/bear) | 재무 1회 + 가정 3벌 |

★이 표에서 주장하지 **않는** 것★ `evaluate` 3회의 반복 비용은 실측 0.2 ms 로 사실상
0 이다 — DART 키가 없어 mock 재무로 계산하기 때문이다(`is_mock: true`). 실 키
환경에서는 재무제표 파싱이 3번 반복되므로 이 값은 **하한**이고, "스냅샷이 X ms 를
아낀다" 는 문장은 **실 키 재측정 전까지 쓰지 않는다.**

확실한 것은 시간이 아니라 **구조**다: 같은 재무이력을 3번 읽고, 같은 피어 질의를
48쿼리로 매번 다시 하고, 같은 가정 3벌을 위해 전체 스택을 3번 돈다.

## C.3 (§19) 매크로 민감도 — 출력 형식을 고정한다

`.md` 가 요구한 형태는 서술이 아니라 **수치**다:

```
+100bp 10Y  → 적정가치 −8.4%
GDP −2σ     → EPS −11.2%
USD +10%    → EPS +4.7%
Oil +30%    → EBIT +5.1%
```

계약:
- **AI 가 서술하지 않는다**(`.md` §19). 계산된 수치이고 provenance 가 남는다.
- 각 줄은 `{shock, unit, target, value, method, n_obs, available, reason}` 를 갖는다.
- 표본이 얇으면 **숫자를 내지 않고 사유를 낸다** — 매크로 계열이 60개월이므로
  이것이 기본 경로가 될 수 있다. P4-MACRO 가 `span` 으로 세운 관례와 동일.
- 재사용: `regime_drivers`(정확 Shapley) · `macro_collector`(ECOS 40 + FRED 21) ·
  `regime_ensemble`.
