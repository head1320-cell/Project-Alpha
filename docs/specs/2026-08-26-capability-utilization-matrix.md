## 0. 6차원 정의와 측정 방법

| # | 차원 | 어떻게 쟀나 |
|---|---|---|
| 1 | **제공자 제공** | 저장소가 **이름을 부르는** 엔드포인트 |
| 2 | **repo 구현** | 클라이언트 함수/URL 상수가 존재 |
| 3 | **실제 수집** | 그 함수를 부르는 **파이프라인**이 존재 |
| 4 | **영속화** | DB/파일에 쓴다 |
| 5 | **소비** | 프로덕션/연구 코드가 **읽는다** |
| 6 | **미사용** | 2 ✔ 인데 3 ✗ |

### ★이 표가 말할 수 없는 것★

이 환경은 **오프라인**이다(외부 호출 차단). 그래서 **1번 열은 "제공자 카탈로그
전체" 가 아니라 "저장소가 이름을 부르는 것" 의 상계**다. ECOS `StatisticTableList`
처럼 우리가 이름을 아는 것은 셀 수 있지만, **모르는 엔드포인트는 이 표에 아예
나타나지 않는다.**

★따라서 "제공자가 주는 것의 N% 를 쓰고 있다" 는 비율을 이 표로 주장하지 않는다.★
이 표가 답하는 것은 좁다 — **"우리가 아는 것 중 무엇이 어디까지 왔는가."**

## 4. 구현 중 드러난 것 — ★셋이 red 로 잡혔다★

**① 저장 원시함수에 부작용을 넣었다** `save_master_flags` 안에서 DB 미러링을 했더니,
그 함수를 **픽스처 설치용**으로 부르는 다른 테스트 3개가 프로세스 공용
`sqlite:///risk_system.db` 에 행을 남기고 "마스터가 없으면 비어 있다" 가 깨졌다.
→ 미러링은 **적재 파이프라인**(`kis_master_parser`)으로 옮겼다. 저장 원시함수는
캐시 writer 이고 DB 미러링은 적재 정책이다.

**② 두 사유를 대체했다** `not_ingested` 를 먼저 보고 `reason` 을 갈아치웠더니,
"미검증인데 값을 냈다" 를 지키던 기존 가드에서 **'미검증' 이라는 말이 사라졌다**.
VKOSPI 는 미검증 **이면서** 미수집이다 → 사유를 **더한다**.

**③ 사유 판정을 행 단위로 했다** `adj_close` 가 NULL 인데 `return_1d` 는 있는 행을
"계산 안 함" 으로 셌다. 체인이 **위에서** 끊기면 아래 행들이 정확히 그 모양이 된다
→ 판정은 **티커 단위**여야 한다("그 티커에 조정된 행이 하나라도 있는가").

변이 7종 전부 사망.
