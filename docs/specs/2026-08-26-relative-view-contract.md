## 0. 질문과 ★답이 바뀐 지점★

직전 메모는 "행합 0 뷰" 를 primary production candidate 로 묶었다. 근거는
B(자산군 상대)와 C-상대(팩터 상대)가 **같이** 이겼고 공통점이 행합 0 이라는 것.

**Phase 3 이 그 인과를 분해했고, 주된 원인은 행합이 아니었다.**

| conf | 전체 ΔCE | **기하** (행합 0) | **Ω 축소** | 기하 몫 |
|---|---|---|---|---|
| 10 | +0.018357 | +0.000601 | +0.017756 | **3.3%** |
| 25 | +0.027373 | +0.004592 | +0.022781 | **16.8%** |
| 50 | +0.041338 | +0.016020 | +0.025318 | **38.8%** |

★원인의 61~97% 는 **Ω 가 작아진 것**이다.★ 이유는 구조적이다 —
`Ω = diag(P τΣ Pᵀ) · (100−conf)/conf` 규약에서 **스프레드 행은 공통인자가 상쇄되어
분산이 작다**(측정: `PᵣΣPᵣᵀ / PₐΣPₐᵀ = 0.2578`, 즉 Ω 가 **3.88배 작다**).
같은 `conf` 를 주어도 상대 뷰는 **자동으로 더 확신하는 뷰**가 된다.

### ★그러나 기하는 다른 것을 산다 — 그리고 그것은 진짜다★

Ω 를 A 의 것으로 묶어도(`R-omega-matched`) 사라지지 않는 효과가 있다:

| conf | | A-level | R-Ωmatched | 회전율 비 |
|---|---|---|---|---|
| 10 | Sharpe / 회전율 | 0.254 / 8.34% | 0.251 / **3.18%** | **38%** |
| 25 | | 0.327 / 17.82% | 0.347 / **7.76%** | **44%** |
| 50 | | 0.398 / 25.78% | 0.480 / **16.31%** | **63%** |

★같은(또는 더 나은) 결과를 **절반 이하의 거래**로 낸다.★

**그래서 정리는 이렇다:**

| 채널 | 무엇을 사나 | 등급 |
|---|---|---|
| **기하(행합 0)** | ★전달 효율★ — 단위 거래당 결과 | `structural` 방향 + `synthetic_mechanism` 크기 |
| **Ω 축소** | ★공격성★ — 더 큰 베팅 | ★규약의 부산물★ — 경제적 성질이 아니다 |

★Ω 축소를 "상대 뷰가 더 낫다" 의 근거로 쓰면 안 된다.★ 그것은 `conf` 를 올린 것과
같은 일이고, A 에도 `conf` 를 올려주면 얻어진다(직전 신뢰도 스윕이 그것을 보였다).

## 1. 11개 질문에 대한 답

### Q1. 행합 0 이 `RelativeView` 를 정의하기에 충분한가 — ★아니다★

`[+1, −1, 0, …]` 과 `[+100, −100, 0, …]` 은 둘 다 행합 0 이지만 같은 주장이 아니다.
정의에는 **정규화가 함께** 필요하다. 최소 계약:

```
RelativeView := (행합 ≈ 0)  AND  (Σ|w| 가 선언된 값)  AND  (Q 가 그 행의 단위)
```

### Q2. 정확히 0 이어야 하나, 경제적으로만 중립이면 되나 — ★후자가 본질★

**본질은 "예산을 늘리지 않는다" 이고, 행합 0 은 현행 최적화기에서의 대리다.**

- 롱온리·완전투자(`Σw = 1`, 현금 0, 레버 0)에서 예산은 이미 고정 → 행합 0 이
  예산중립과 **동치**.
- 현금 밴드(`cash_min/max_pct`)나 그로스 레버(`gross_max_pct`)가 열리면 **갈라진다**
  — 그때는 "행합 0" 이 아니라 "순 노출 변화 0" 이 기준이어야 한다.

권고: 계약은 **`budget_neutral` 이라는 의미**로 쓰고, 검사는 현행 최적화기 설정에
맞춰 `|Σ(row)| ≤ ε` 로 한다. ε 은 `GROSS_MIN`(1e-12)이 아니라 **행 노름 상대**로:
`|Σ(row)| ≤ 1e-9 · Σ|w|`. 절대 허용오차는 스케일이 큰 행에서 무의미하다.

### Q3. 불균등 다리는 어떻게 정규화하나 — ★기본은 거부★

`Σ(+) ≠ |Σ(−)|` 이면 순 노출이 생겨 예산중립이 깨진다. 세 선택지 중:

| 안 | 동작 | 판정 |
|---|---|---|
| ★거부 + 사유★ | 스킵 목록에 남긴다 | **권고** — 조용한 절대 뷰화를 막는다 |
| 다리별 정규화 | `+` 를 `1/n₊`, `−` 를 `−1/n₋` 로 | 명시 옵션(`normalize="legs"`)으로만 |
| 전체 재정규화 | 행 전체를 `Σ|w|` 로 나눔 | ★금지★ — 불균형을 없애지 못한다 |

`view_rows.group_spread_row` 는 **이미 다리별 정규화**를 하고, 빈 다리는 `ValueError`
로 거부한다("한쪽 다리만 있는 스프레드는 절대 뷰가 된다"). 그 규칙을 일반화한다.

### Q4·Q5. `magnitude_pct` 의 의미 — ★그 행의 단위 · 연율 스프레드★

```
Q = P μ,   magnitude_pct = |Q| × 100,   direction = sign(Q)
```

`view_rows.py` 가 이미 그렇게 문서화돼 있다: *"스프레드 뷰의 3% 는 'EQ−FI
스프레드가 연 3%' 이지 '각 자산이 3%' 가 아니다."*

★재정규화하지 않는 이유★ Ω 의 base 가 `diag(P τΣ Pᵀ)` 라 행 노름에 비례해 함께
커지므로 자기정합적이다. **그런데 바로 그 자기정합성이 Phase 3 의 Ω 축소를 낳는다**
— 자기정합은 *단위* 문제를 풀지 *확신* 문제를 풀지 않는다.

### Q6. BL 은 이 뷰를 어떻게 읽나

`bl_posterior(Π, Σ, P, Q, Ω)` — 사전분포 `Π = δΣw_mkt` 를 **언제나** Q 쪽으로 섞는다.
행합 0 이면 사후는 **스프레드만** 이동하고 수준은 Π 가 잡는다. ★그래서 상대 뷰는
"수준 추정잡음을 흘려보내지 않는" 것이 아니라 **수준을 사전분포에 위임**하는 것이다.★

### Q7. EP 는 이 뷰를 어떻게 읽나 — ★같지 않다★

`ep_posterior_mu` 는 **부등식** `d · (P μ) ≥ mag` 로 읽는다.

- 이미 만족돼 있으면 **아무것도 하지 않는다**(사후 = 사전). 측정: 상대 뷰 37.1% ·
  절대 뷰 0.0%.
- 위반일 때만 **경계까지만** 당긴다.
- 사전분포가 균형 Π 가 아니라 **시나리오 균등가중(트레일링 평균)** 이다.

★그래서 BL 과 EP 의 사후를 **레벨로 비교하지 않는다**.★ 사전이 다르다.

### Q8. EP 에 신뢰도를 어떻게 표현하나 — ★표현하지 않는다★

`confidence_used: False`. 이것은 **결측이 아니라 아키텍처 사실**이다.
BL 의 `conf` 와 EP 의 무엇을 같은 축에 놓으면 안 된다.

EP 에서 "확신" 에 해당하는 것을 굳이 찾는다면 그것은 **`magnitude` 자체**다 —
요구를 세게 하면 더 크게 당긴다. 그러나 그것은 Ω 와 **다른 종류의 손잡이**이고,
BL 의 `conf` 처럼 뷰를 부드럽게 섞는 것이 아니라 제약 경계를 옮기는 것이다.

★권고★ EP 계열 보고에서는 `conf` 칸을 **`—` 로 인쇄한다**(0 이나 공백이 아니라).
`t3_transmission.py` 가 이미 그렇게 한다.

### Q9. 뷰의 자산이 유니버스에 없으면

현행: `dropped_assets` 에 남기고 **남은 행을 그대로 쓴다**(`build_view_rows`).
절대 뷰에서는 옳다 — 남은 자산에 대한 주장이 여전히 유효하다.

★상대 뷰에서는 틀렸다★ → Q10.

### Q10. ★결측으로 예산중립이 깨지면 — 이것이 가장 위험한 칸★

`{EQ0:+1/3, EQ1:+1/3, EQ2:+1/3, FI0:−1/3, FI1:−1/3, FI2:−1/3}` 에서 FI2 가 빠지면
행합이 `+1/3` 이 된다. ★그 순간 상대 뷰가 조용히 **절대 뷰로 둔갑한다**★ —
그리고 Phase 3 이 보였듯 절대 뷰는 완전히 다른 전달 특성을 갖는다.
응답에는 "뷰 1개 적용됨" 이라고 나온다. **보이지 않는 결함이다.**

권고(셋 중 하나를 뷰가 **선언**한다):

| 정책 | 동작 | 언제 |
|---|---|---|
| ★`strict`(기본)★ | 예산중립이 깨지면 **스킵 + 사유** | 매크로가 만든 뷰 |
| `rebalance_legs` | 남은 다리를 재정규화해 중립 복구 | 사용자가 명시 |
| `allow_drift` | 현행 동작 유지 | ★상대 뷰에는 금지★ |

`kind == KIND_WEIGHTED` 이고 원래 행이 중립이었다면 기본은 `strict`.

### Q11. 네 가지 상대 뷰의 구분 — ★행 생성 규칙이 아니라 **그룹 소스**★

| 종류 | `P` 행의 출처 | 선행조건 |
|---|---|---|
| **security relative** | 사용자가 종목을 직접 지정 | 없음 |
| **asset-class relative** | 정준 `AssetClass` 분류 | ★Phase 7 계약★ |
| **factor relative** | 팩터 노출 행렬(β 등)의 **디민** | 팩터 모델 |
| **economic-exposure relative** | `EconomicExposure` 매핑(일대다) | ★Phase 7 계약★ |

★넷의 `P` 행 생성 코드는 같아야 한다★ — `view_rows.row_from_spec` 하나. 다른 것은
**가중치를 누가 계산해 주는가**뿐이다. 그래서 타입 계층은 다음과 같이 얕게 둔다:

```
RelativeView(budget_neutral)          ← 계약이 사는 곳
  ├─ SecurityRelativeView
  ├─ AssetClassRelativeView           ← 그룹 소스: AssetClass
  ├─ FactorRelativeView               ← 그룹 소스: 팩터 노출(디민)
  └─ EconomicExposureRelativeView     ← 그룹 소스: EconomicExposure (일대다)
```

★경제적 의미론이 타입을 가르고, 구현은 하나를 공유한다.★
