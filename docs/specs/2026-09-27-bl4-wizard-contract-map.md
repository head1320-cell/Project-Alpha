# BL4 · 마법사 E2E 계약 대응표 — 지우기 전에 옮긴 것 · 사라지는 것

> 계획 `happy-percolating-falcon.md` §BL4 (B4-0). ADR 002 §9 의 "마법사 제거는 별도 승인" 은 BL 시작 때 사용자 답
> ("마법사 고유 기능은 캔버스로 먼저 옮기고, 옮긴 것을 확인한 뒤 마법사를 지운다")으로 승인됐다.
> **규칙** — 마법사 E2E 가 지키던 정직성 계약마다 셋 중 하나다: **이전됨**(캔버스·다른 화면의 테스트가 같은 계약을 지킨다 —
> 파일:제목) · **N/A**(기능 자체가 사라짐 + 사유) · **빈칸**(허용하지 않는다 — B4-1 에서 먼저 채웠다).
> ★같은 계약을 두 곳이 지키는 순간을 만든 다음 한 곳을 지운다★ — 아래 "이전됨" 의 캔버스 테스트는 마법사가 있는 동안 통과했다.

`PG` = `frontend/e2e/portfolio-graph.spec.ts`. 백엔드 계약은 기존 pytest 가 그대로 지킨다(라우트는 지우지 않는다).
