# 전달계층(transmission) 감사 — 매크로 뷰가 비중까지 가는 경로

> 계획: `docs/plans/2026-08-25-macro-vnext-plan.md` §1.13 · MS1-b0 보고서
> **프로덕션 코드 변경 0** — 전부 읽기 전용 실측이다.

## 0. 이 감사가 시작된 이유 — ★내 해석이 틀렸다★

MS1-b0 보고서에서 나는 BL/EP 부호 차이를 *"신호가 약하다는 증거"* 로 적었다.
사용자가 그것을 바로잡았다 — **"매크로 뷰 전달이 하류(사후/최적화기)에 매우
민감하다"** 가 더 방어 가능한 해석이라는 것이다.

★측정해 보니 사용자 해석이 맞다.★ 근거는 §1·§2 이고, 감사 도중 **실제 결함 하나**와
**내 또 다른 과장 하나**가 추가로 드러났다(§3·§4).

## 1. 단계별 변화량 — 파이프라인 어디서 커지는가

월간 ΔL1(=연속한 두 리밸런싱 사이의 L1 변화), 70회 리밸런싱, 합성 패널.

| 단계 | B1 평균 | B1 중앙값 | N 평균 | N 중앙값 |
|---|---|---|---|---|
| π (국면확률) | — | — | 0.3137 | 0.0523 |
| 조건부 μ (연율) | 0.4036 | 0.2150 | 0.2224 | 0.1339 |
| 뷰 신뢰도 | 0.4097 | 0.0700 | **0.0000** | 0.0000 |
| Σ (연율) | 0.1088 | 0.0116 | 0.0536 | 0.0123 |
| 사후 μ (BL) | 0.2695 | 0.1605 | 0.1545 | 0.0905 |
| **목표비중 (BL)** | **0.7160** | 0.3281 | **0.6484** | 0.4132 |
| 사후 μ (EP) | 0.4818 | 0.2422 | 0.2603 | 0.1348 |
| **목표비중 (EP)** | **0.5838** | **0.0159** | **0.6996** | **0.0000** |
| B0 목표비중 (BL) | **0.0000** | 0.0000 | — | — |
| B0 목표비중 (EP) | 0.1567 | 0.0000 | — | — |

**셋을 읽어야 한다**

1. ★`B0/BL` 비중이 **정확히 정지**해 있다★ — 뷰가 없으면 BL 은 균형비중 그대로다.
   즉 **회전율 20배는 전부 조건부 계층에서 나온다**(B0 의 1.65% 는 표류 보정뿐).
2. ★BL 은 감쇠하고 **최적화기가 증폭한다**★
   조건부 μ `0.404` → 사후 μ `0.270`(**×0.67 감쇠**) → 목표비중 `0.716`(**×2.65 증폭**).
   고전적인 평균-분산 오차 증폭이다.
3. ★EP 는 **중앙값 ≈ 0, 평균은 크다**★ (B1 중앙 `0.016`/평균 `0.584`,
   N 중앙 **`0.000`**/평균 `0.700`). 대부분 안 움직이다 **가끔 통째로 튄다.**
   BL 은 매달 고르게 움직인다(중앙 `0.33`/평균 `0.72`).

### ★BL/EP 부호 차이의 정체★

같은 조건부 μ 를 넣는데 한쪽은 **고르게 퍼뜨리고** 한쪽은 **드물게 점프**시킨다.
이것은 **신호의 성질이 아니라 사후분포의 성질**이다 — 사용자 해석이 옳고, 내
"신호가 약하다" 는 결론은 근거가 부족했다. 정정한다.

| 시나리오 | 평균 회전율 |
|---|---|
| N/BL 현행 | **32.42%** |
| 신뢰도 50 → 25 | 20.49% |

## 3. ★감사가 찾은 실제 결함★

`regime_mixture_moments` 는 `shrinkage_lambda` 를 **국면별 dict** 로 낸다:

```
혼합: {'Goldilocks': 0.0203, 'Reflation': 0.0122, 'Stagflation': 0.0472, 'Disinflation': 0.1302}
하드: 0.0122  (float)
```

그런데 `allocation_backtest._regime_override_at` 은
`float(lam) if isinstance(lam, (int, float)) else 0.0` 이라 **dict 면 조용히 0.0** →
`conf = 50.0`(최대)이 매 리밸런싱에 박힌다.

**더 큰 문제** MS1-a 에서 만든 **분해 Ω 신뢰도가 `walk_forward` 에 배선돼 있지 않다.**
라우트만 쓴다. 즉 ★MS1-b0 평가는 계약 4를 한 번도 시험하지 않았다★ — 그리고 §2 의
사다리대로라면 그 신뢰도(≈8)를 썼을 때 회전율은 **32.42% → 7.71%** 였다.

### ★내 이전 주장 하나를 정정한다★

"이 결함 때문에 N 이 B1 보다 불리했다" 고 말하려 했는데 **틀렸다.** B1 의 λ 도
0.0122 라 `conf ≈ 49.4` 로 사실상 같다(실측 35.80 vs 35.75). 결함은 진짜지만
**두 팔의 비교를 왜곡하지는 않았다.**

## 4. 신호 품질 vs 거래 강도

| | B1 | N |
|---|---|---|
| 단면 IC 평균 | −0.0181 (t=−0.24, n=70) | −0.0583 (t=−0.82, n=70) |
| 방향 적중률 | 0.5071 | 0.4857 |
| 뷰 산포(자산 간 μ 최대−최소) | 0.1808 | 0.0955 |
| 평균 회전율 | 35.80% | 32.42% |

★이 IC 를 "신호가 없다" 로 읽으면 안 된다★ — 이 합성 패널은 국면이 **공통인자의
드리프트·변동성**을 바꾸도록 만들어졌다. 즉 **타이밍 신호**이지 **종목선택 신호**가
아니고, 단면 IC 가 0인 것은 **설계상 당연**하다.

### ★진짜 발견 — 신호의 성질과 전달 형태가 어긋나 있다★

| | |
|---|---|
| 신호의 성질 | **타이밍** (국면이 공통인자의 평균/분산을 바꾼다) |
| 전달 형태 | `_conditional_views` 가 **자산별 절대 뷰**로 바꾼다 = **단면** 장치 |
| 결과 | 18.1%p 짜리 단면 산포를 주장하는데, 그 산포의 대부분은 **베타 추정잡음**이다 |

타이밍 신호를 단면 뷰로 전달하면 최적화기는 **존재하지 않는 종목 간 차이**를 매달
새로 쫓는다 — 그것이 회전율 32% 의 내용물이다.

**분해 결론**: 거래 강도는 **신뢰도가 지배**(50→8 에서 −76%). 신호 품질은 이 패널에서
단면 기준 **측정 불가**(설계상 0). 둘을 곱해 판단할 근거는 아직 없다.

## 6. ★실계열 MS1-b 검증의 최소 데이터 요건★

`real_share > 0` 이 되기 전에는 어떤 결과도 경제적 증거가 아니다.

### 6.1 매크로 계열

| 항목 | 최소 요건 | 왜 |
|---|---|---|
| 깊이 | ★**240개월(20년)**★ | `probe_all()['frontier_sample']` 기준. 현재 **60** |
| 국면당 표본 | 4국면 × **≥24개월** | `conditional_moments` 하한이 자산당 3행 |
| 축 구성 계열 | 성장축·물가축 **각 3개 이상** | 하나 빠져도 축이 죽지 않게 |
| 공표지연 | 계열별 **선언** → `publication_lag: declared` | PIT 3필드 중 둘째 |
| 개정 상태 | ★`revision_bias: "unmanaged"` **영구 라벨**★ | ECOS 는 빈티지 미제공 — 없앨 수 없고 **표시**만 가능 |
| 출처 | ECOS(BOK) + FRED | FRED 는 ALFRED 빈티지가 있어 **일부 계열만 revision-free 가능** |

### 6.2 자산 수익률

| 항목 | 최소 요건 |
|---|---|
| 자산 수 | **6~10** (하한 `3×N` 행이 국면 표본을 넘지 않게) |
| 깊이 | 매크로와 **같은 구간** + `min_train` 여유 (≥ 240 + 12개월) |
| 자산군 | 국면이 실제로 가르는 축 — 주식·국채·크레딧·달러·원자재 **최소 4축** |
| 빈도 | **일별** (연율화·CVaR 계산에 필요) |
| 생존편향 | 지수/ETF 수준으로 회피 (개별종목이면 상장폐지 포함 필수) |

### 6.3 국면 추론

| 항목 | 요건 |
|---|---|
| 산출 | 월별 라벨 + `transition_posterior` 행별 사후 |
| look-ahead | `zscore_at` 후행 윈도우 · walk-forward 절단 경로 (**이미 구현·테스트됨**) |
| 전이 표본 | 국면 전이 **≥30회** (Dirichlet 사후가 사전분포에 지배되지 않게) |
| 예측 | `k_step_forecast` + `forecast_coverage` 워크포워드 적중률 **동반 보고** |

### 6.4 라벨링 (모든 산출물)

```
look_ahead_free : true|false
publication_lag : declared(개월) | unspecified
revision_bias   : unmanaged | vintage_backed     ← ★계열별로 달라야 한다★
real_share      : 실계열 / 전체계열
```

★`revision_bias` 는 지금 전역 상수 하나다.★ FRED/ALFRED 계열은 `vintage_backed`,
ECOS 계열은 `unmanaged` 로 **계열별**로 붙일 수 있어야 한다.

### 6.5 판정

`real_share > 0` **그리고** 위 요건이 충족된 실데이터에서 계획 §1.13.4 판정 규칙을
통과하기 전까지 ★MS1 이 경제적으로 검증됐다고 말하지 않는다.★
