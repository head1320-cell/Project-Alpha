# 데이터 권리 대장 — 원천마다 '무엇에 쓸 수 있는가' (2026-11-14 · 틀)

> **상태: 틀. 확인된 칸만 채웠고 나머지는 ★미상★이다.** [로드맵](../plans/2026-11-14-pb-trader-tool-roadmap.md) 0단계의 산출물이며,
> 채울 것은 [회사 질문지](../plans/2026-11-14-company-questions.md) E 절의 답이다.
> 이 문서가 답하는 질문은 **데이터 무결성 가운데 '권리'**다 — 값의 품질(정확성·시점 정합)은 다른 문서가 본다.

## 0. 왜 필요한가

같은 시세라도 쓰는 방식에 따라 계약과 요금이 다르다. 코드가 원천에 연결돼 있다는 것은 ★그 값을 고객 화면에 보여 줘도 된다는 뜻이 아니다★.
권리를 모르는 원천을 고객 제공 경로에 쓰면, 값이 맞아도 쓸 수 없는 제품이 된다.

## 1. 권리의 종류 (이 대장의 칸)

| 칸 | 뜻 |
|---|---|
| 본인 | 계정 주인이 자기 투자·연구에 쓴다 |
| 내부 | 법인·조직 안에서 여러 사람이 쓴다(밖으로 내보내지 않는다) |
| 표출 | 다른 사람(고객)의 화면에 값을 보여 준다 |
| 재배포 | 값을 내려받게 하거나 API 로 넘긴다 |
| 보관 | 받은 값을 저장해 두고 다시 쓴다(기간 제한 · 해지 뒤 삭제 의무) |
| 파생값 | 받은 값으로 계산한 것(지표·점수·백테스트 결과)을 내보낸다 |

칸의 값: **가** · **불가** · **계약** (별도 계약·요금이 있어야 가능) · **미상**. 근거가 없는 칸은 미상이다 — "아마 될 것"으로 채우지 않는다.

## 3. 지금 읽을 수 있는 것 (채운 칸에서)

- 고객 화면에 값을 보여 줄 권리가 **확인된 원천은 아직 하나도 없다**. 지금 연결된 원천은 모두 '본인 가' 또는 미상이다.
- 불가로 둔 것: FnSpace(약관 요약에 근거) · yfinance(제공자와 맺은 계약이 없다 — 조항을 확인한 것이 아니라 이 대장의 결정이다). 이 둘은 고객 제공 경로에서 뺀다.
- 그래서 고객 제공 단계의 시세는 ★회사 시스템 안에서 쓰는 길★(회사가 이미 가진 계약 범위 — 질문지 C4)이 먼저 확인할 길이다.

## 4. 운영 규칙 (대장을 쓰는 방법)

1. 새 원천을 코드에 붙이기 전에 이 표에 한 줄을 먼저 적는다(미상이어도 적는다).
2. 칸을 채울 때는 근거(약관 조항 · 견적서 · 답변의 날짜와 상대)를 함께 적는다. 구두로 들은 것은 '구두'라고 적는다.
3. 고객 제공 경로(유통 관문 뒤)에 쓰는 원천은 '표출' 칸이 **가** 또는 **계약(체결됨)** 이어야 한다. 미상은 불가로 다룬다.
4. 약관은 바뀐다 — 칸마다 확인 날짜를 남기고, 고객 제공 전에 다시 본다.
