# 화면 용어집 · 문체 규칙 (2026-11-11 · ADR 005)

화면에 보이는 글자를 쓸 때 따르는 기준이다. 프론트 소스(`frontend/src`)와 서버가 화면으로 보내는 문장 모두에 걸린다.
지키는지는 `tests/test_frontend_voice.py`(해요체 래칫)와 `frontend/e2e/helpers.ts::voiceAudit` 가 본다.
코드 주석과 문서의 말투는 대상이 아니다.

## 1. 문체

| 자리 | 쓰는 꼴 | 예 |
|---|---|---|
| 라벨 · 제목 · 칩 · 표 머리 | 명사형(개조식) | 수익성 · 괴리율 · 연환산 변동성 |
| 단추 | 동작 명사 | 재계산 · 조회 · 저장 · 실행 · 재시도 · 상세 · 삭제 |
| 상태 | 명사형 | 계산 중 · 조회 실패 · 저장 완료 |
| 설명 · 안내 · 사유 문장 | 합니다체 평서문 | 무위험수익률 3.5%, 베타 1.0 가정으로 산출했습니다. |
| 요청 | ~하십시오 | 값을 입력하십시오. |

- 해요체(~어요·~예요·~세요·~죠·~까요)는 쓰지 않는다. 물음표·느낌표·권유형("~해 봐요")도 쓰지 않는다.
- 예외 둘: ① 되돌릴 수 없는 일을 묻는 **확인 대화상자**는 "~하시겠습니까?"로 쓴다("이 주문을 취소하시겠습니까?"). ② 사용자가 직접 치는 글(AI 에게 묻는 말)과 그 미리 채운 예문은 사용자의 말이라 고치지 않는다.
- 의문형 제목·설정 질문("어떤 조건으로 거를까요?")은 명사형으로 쓴다(`스크리닝 조건`) — §3.5.
- 한 문장에 한 가지만 말한다. 주어가 화면에 이미 보이면 생략한다("현재가가 … 높습니다" → 칩 `괴리율 +75%`).
- 낭독기용 글자(`aria-label`)도 같은 문체다.

## 2. 상태 문구 — 같은 꼴로 쓴다

| 예전 | 지금 |
|---|---|
| X를 불러오는 중이에요 | X 조회 중 |
| 계산하는 중이에요 · 확인하는 중이에요 · 적재하는 중이에요 | 계산 중 · 확인 중 · 적재 중 |
| X를 불러오지 못했어요 | X 조회 실패 |
| X를 계산하지 못했어요 · 내지 못했어요 | X 산출 실패 (모형이 값을 못 내면 `산출 불가` + 사유) |
| X를 재지 못했어요 · — (못 쟀어요) | X 측정 불가 |
| X를 확인하지 못했어요 · 받지 못했어요 | X 확인 실패 · X 수신 실패 |
| 서버에 닿지 못했어요 | 서버 연결 실패 |
| 서버가 사유를 보내지 않았어요 | 사유 미수신 |
| X가 없어요 · 아직 X가 없어요 | X 없음 |
| 몰라요 · 모름 · 값 없음 | 값 자리는 `N/A` · 이름표에 붙으면 `미상`(`수량 미상` · `시각 미상` · `데이터 출처 미상`) |
| 사유 미상 · 사유 없음 | 사유 미상 |
| 저장했어요 · 복사했어요 | 저장 완료 · 복사 완료 |
| 높아요 · 낮아요 · 평균보다 높아요 | 높음 · 낮음 · 평균 상회(하회) |
| 켜져 있어요 · 꺼져 있어요 | 사용 · 미사용 |
| 아직이에요 · 끝까지 갔어요 | 대기 · 완료 |
| 다시 시도 · 다시 계산하기 · 계산하기 | 재시도 · 재계산 · 계산 |
| 자세히 · 지우기 · 풀기 | 상세 · 삭제 · 해제 |
| ~할 수 있어요 | ~할 수 있습니다 (라벨이면 `~ 가능`) |
| ~해 주세요 | ~하십시오 |

- ★미상 ≠ 0★ 은 그대로다. `N/A` 옆에는 사유를 적는다(`N/A · 재무 미적재`). 0 이나 빈칸으로 그리지 않는다.
- 실패와 "값이 없음"을 섞지 않는 것도 그대로다 — `조회 실패`(서버에 못 닿음)와 `데이터 없음`(닿았는데 없음)은 다른 말이다.

### 3.12 분봉 백테스트 (백테스트 › 분봉 규칙 `/backtest/intraday` · 2026-11-14 — 처음 자리 `/intraday` 는 넘김)

매매일지의 낱말(§3.11)을 그대로 쓴다 — 두 화면의 숫자는 같은 엔진에서 나온다. 이 화면에만 있는 낱말:

| 직접 구성 | 규칙 틀 일곱 옆의 여덟째 종류(2026-11-15 · 서버 종류 이름 `custom`). 매개변수 칸 대신 지표와 연산으로 조건을 짓는다. `자유 조건식`은 설계 문서의 이름이고 화면에는 쓰지 않는다 · `커스텀`·`사용자 정의`라고 쓰지 않는다 |

| 조건 검사 · 마디 · 겹침 깊이 | 다 채운 조건을 서버가 읽어 규칙의 글과 거절 사유를 내는 일 · 조건 나무의 크기를 재는 두 수(상한 64 · 12). 검사는 시행으로 기록되지 않는다. `검증`·`노드`·`뎁스`라고 쓰지 않는다 |
| 이 틀을 조건으로 풀기 · 내 시행에서 불러오기 | 편집기를 빈 화면에서 시작하지 않게 하는 두 길 — 고른 틀이 만드는 조건을 싣는다 · 돌려 본 설정의 규칙만 싣는다(종목 · 기간 · 포지션 · 비용은 그대로). `템플릿 가져오기`·`프리셋`이라고 쓰지 않는다 |
| 지수이동평균 · MACD · MACD 신호선 · MACD 오실레이터 · ATR · 당일 고가 · 당일 저가 | 직접 구성에 더한 지표(2026-11-16 · 서버 지표 등록부). 전부 그날의 봉으로만 계산한다 — 앞 봉의 값을 이어 쓰는 것(지수이동평균 · MACD · ATR · RSI)은 여러 날을 이어 계산한 차트의 값과 다르고, 그 사실은 규칙의 주석이 말한다. MACD 에서 신호선을 뺀 값은 `MACD 오실레이터`로 쓴다(`히스토그램`·`막대`라고 쓰지 않는다). 당일 고가 · 당일 저가는 그 봉을 포함한다 |
| 단기 기간 · 장기 기간 · 신호 기간 | MACD 의 매개변수 이름. 매개변수가 여럿인 지표는 칸 앞에 그 이름을 보인다(하나뿐이면 단위만 보인다). `빠른`·`느린`·`시그널`이라고 쓰지 않는다 |
| N봉 전 값 · 봉 전 | 수를 N봉 앞의 값으로 미는 연산(2026-11-16 · 서버 연산 `ago`). 칸은 `[N] 봉 전 [값]`, 규칙의 글은 `1봉 전 당일 고가`. 앞에 N개 봉이 없으면 값이 없다. `이전 값`·`시프트`·`래그`라고 쓰지 않는다 |
| 분봉 백테스트(노드) · 분봉 결과 조회(노드) | 캔버스 '백테스트' 묶음의 노드 둘(2026-11-14). 앞의 것은 설정을 확인하고 단추로 실행하며, 뒤의 것은 남긴 결과를 읽는다. 조건식 백테스트의 `백테스트 결과 조회`와 가른다 |
| 분봉 백테스트 실행(단추) | 계산 · 판정 · 시행 기록을 한 번에 하는 단추. `시작`이 아니다(백그라운드 실행이 아니라 그 자리에서 끝난다) · `저장`이 아니다 |
| 이 실행의 관문 일곱 | 캔버스의 결과 판에서 분봉 관문 표를 가리키는 말. 캔버스 위쪽의 증거 관문(여덟 — §3.7)과 다른 표다 |
| 규칙(판의 줄) · 조건(설정 판의 칸) | 캔버스의 분봉 판 셋(설정 · 결과 조회 · 가동 요청)과 결과 고르기 목록에서 `규칙 틀` 아래의 `규칙` 줄은 규칙을 풀어 쓴 글이다(서버 `rule_text` · 2026-11-15 — 틀에도 적는다: 이름표는 매개변수를 말하지 않는다). 글을 읽지 못하면 서버의 사유를 그 자리에 적고, 종류 이름으로 때우지 않는다. 설정 판의 `조건` 칸은 직접 구성의 편집기다(백테스트 › 분봉 규칙과 같은 부품 · 캔버스 카드 위에는 놓지 않는다) |
| 정하지 않음 | 직접 적는 칸을 비운 상태. `0`·`없음`으로 쓰지 않는다 — 비운 수수료율은 0bp 가 아니라 미상이다 |

### 3.13 괴리 보고 (내 계좌 › 매매일지의 '백테스트와 견주기' · 백테스트 › 분봉 규칙의 '실제 체결과 견주기' · 2026-11-14)

분봉 백테스트(§3.12)와 매매일지(§3.11)의 낱말을 그대로 쓴다. 이 판에만 있는 낱말:

| 낱말 | 뜻 · 쓰는 법 |
|---|---|
| 괴리 | 백테스트가 가정한 체결과 실제 체결의 차이. 절 이름은 `백테스트와 견주기` · `실제 체결과 견주기`로 쓰고, `괴리`는 문서와 완료 알림에서 쓴다 |
| 실제 체결 | 올린 체결 내역의 줄. 설계 문서의 `증권사 체결`과 같은 자리지만 화면에서는 `실제 체결`이라 쓴다(올린 파일의 출처를 도구가 확인하지 못한다) |
| 짝지은 체결 · 놓친 신호 · 규칙 밖 매매 | 종목 · 날짜 · 방향이 같고 시각 차이가 허용 시간 안인 한 쌍 · 시뮬레이션에만 있는 체결 · 올린 체결에만 있는 것(규칙의 종목 · 기간 안에서). 시각으로 센 사실이지 평가가 아니다 — `실수`·`위반`이라고 쓰지 않는다 |
| 규칙에 없는 종목 · 기간 밖 | 견주지 않고 따로 뺀 줄. `규칙 밖 매매`로 세지 않는다(줄 수와 종목을 적는다) |
| 짝짓기 허용 시간 | 짝으로 보는 시각 차이의 한도(1분 · 5분 · 15분). ★`가정`이다★ — 세 값에서의 건수를 늘 함께 적는다. `허용 창`·`윈도`라고 쓰지 않는다 |
| 불리함 | 매수는 비싸게, 매도는 싸게 체결된 만큼(+). 원 · 틱 · bp 이고 기준은 시뮬레이션 체결가. ★등락 색을 입히지 않는다★('+' 가 불리라 색과 부호가 어긋난다). `슬리피지`는 백테스트의 가정을 가리킬 때만 쓴다 |
| 하루 단위 | 체결 시각이 없는 파일을 종목 · 날짜 · 방향으로 묶어 견준 방식. 판 맨 위에 사유와 함께 적는다 |
| 견주기(단추) | 고른 분봉 백테스트의 설정을 그대로 다시 돌려 올린 체결과 견주는 단추. `비교`가 아니다(`비교`는 백테스트 실행 기록의 비교 화면이다) |

### 3.14 국면 앙상블 · 합의의 군집 두 방법 (캔버스 '국면 앙상블' · '국면 합의도' · 매크로 화면 · 2026-11-16)

| 낱말 | 뜻 · 쓰는 법 |
|---|---|
| 군집(GMM) · 군집(k-평균) | 성장 · 물가 좌표를 묶는 두 방법(서버 키 `cluster` · `kmeans`). 서버 해설에서는 `군집 모형(GMM)` · `군집 모형(k-평균)`. 둘은 같은 좌표를 묶어 서로 독립이 아니다 — 합의의 다수를 독립된 표의 수로 읽지 않는다 |
| 난수 시드별 최다 답 · 과반 · 과반 미만 | 난수 시드 10개(설정값)로 다시 적합한 답 가운데 가장 많이 나온 국면 · 그 수가 시드 수의 절반을 넘는가(10개 중 5개는 과반이 아니다). 같은 자료에서 같은 답이 나오는지일 뿐 답이 맞는지가 아니다 — `안정적`·`신뢰도`라고 쓰지 않는다. `씨앗`은 문서의 말이고 화면은 `난수 시드`(§3.8) |

| 시드에 따라 갈리는 방법 있음 · 난수 시드에 따라 답이 갈리는 도구가 있습니다 | 판정이 모두 같아도(만장일치) 시드별 최다 답이 과반이 아닌 방법이 있을 때 띠 · 합의 블록에 붙는 말. 그때 띠는 초록이 아니라 주의 색이다. 만장일치를 `확정`·`확실`이라고 쓰지 않는다 |

### 3.15 국면 예측 비교 (캔버스 '국면 예측 비교' · 매크로 화면의 같은 이름 블록 · 2026-11-16)

| 낱말 | 뜻 · 쓰는 법 |
|---|---|
| 국면 예측 비교 | 후보 여섯의 k개월 뒤 국면 예측을 같은 시점 · 같은 실현값으로 채점해 나란히 보이는 표. ★어느 후보도 고르지 않는다★ — `추천`·`최적`·`가장 좋은 모형`이라고 쓰지 않고, 이긴 행을 칠하지 않는다(행 순서는 서버의 고정 순서) |
| 후보 이름 여섯 | 오늘 국면 유지 · 기저율 · 전이 예측 · GMM 시작 분포 × 전이 · GMM 지금 값 · k-평균 시드 비율. 서버 `regime_skill.CANDIDATE_NAMES` 한 곳 — 화면이 이름을 따로 짓지 않는다 |

| 브라이어 | 확률 예측의 오차 Σ(p − o)² 의 평균 — 0(확신하고 맞힘) ~ 2(확신하고 틀림) · 낮을수록 잘 맞혔다 |
| 유지 대비 | 기준선 브라이어 − 후보 브라이어의 평균. 양이면 기준선보다 확률을 잘 맞혔다(음수 부호는 `−`) |
| 순차 증거(국면) | §3.12 의 순차 증거와 같은 도구를 브라이어 차(−2 ~ 2 — 상한 가정 없이 성립)에 쓴 것. 기준 = 견준 후보 수 5 ÷ α 0.05 = 100 · 지나온 시점의 최고값으로 견준다 · ★1개월 앞에서만★ 계산한다(그 이상은 평가가 겹친다 — 계산하지 않았다고 적는다). 기준을 넘은 칸은 색이 아니라 `*` 와 범례로 말한다 |
| 평가 시점 · 워크포워드 | 채점한 시점의 수(20개 미만이면 표 대신 사유) · 각 시점에서 그때까지의 자료만으로 후보를 세워 채점하는 방식 |
| 계산 시작(단추) | 매크로 화면의 이 블록은 단추를 눌러야 계산한다 — 시점마다 군집 모형을 다시 적합해 첫 계산에 수십 초가 든다. 화면을 열 때마다 부르지 않는다 |

### 3.16 국면 가중 방식 (캔버스 '추정 설정' · '포트폴리오 최적화' 결과의 '국면 가중' 절 · 2026-11-16)

| 낱말 | 뜻 · 쓰는 법 |
|---|---|
| 국면 가중 방식 | 경기 국면 반영을 켰을 때 보유 기간의 국면 분포를 무엇으로 잡는지. 이름 셋은 §3.15 의 후보 이름과 같은 말이다(서버 `allocation_graph_explain.WEIGHTING_PLAIN` 한 곳 · 이름의 출처는 `regime_skill.CANDIDATE_NAMES`) — 옛 이름 `확정 국면` · `확률 가중`은 쓰지 않는다 |
| 오늘 국면 유지 | 오늘 국면이 보유 기간 내내 이어진다고 가정한다(그 국면에 확률 1 · M4 전의 기본값). 해설은 `가정`으로 적는다 |
| 전이 예측 | 오늘 국면에서 출발해 과거 경로의 전이행렬(사후평균)로 보유 기간의 국면 분포를 잡는다 |
| GMM 시작 분포 × 전이 | 지금 점의 GMM 소속 확률(난수 시드 10개 평균)에서 출발해 같은 전이행렬로 잡는다. ★같은 경로의 워크포워드 점수가 있을 때만 쓴다★ — 없으면 전이 예측으로 산출하고 그 사유를 적는다(조용히 바꾸지 않는다) |
| 근거 관문 | ★기본값(M4)★ — 같은 경로 · 보유 기간의 워크포워드 브라이어로 `GMM 시작 분포 × 전이`와 `전이 예측` 가운데 하나를 고르는 규칙. GMM 이 `오늘 국면 유지`와 `전이 예측`보다 ★엄격히 낮을 때만★ GMM(같은 값은 낮지 않다) · 아니면 전이 예측. `오늘 국면 유지`는 점수가 가장 낮아도 후보가 아니다(사유가 그 사실을 적는다). §3.15 의 후보 이름이 아니라 고르는 규칙의 이름이다(서버 `regime_gmm_start.GATE_NAME` 한 곳) |
| 관문의 선택 · 고름 | 관문 표에서 관문이 고른 후보를 ★글자로★ 적는 칸(`고름`) — 색이나 굵기만으로 말하지 않는다. 고른 것과 산출한 방식이 다르면(고른 GMM 을 세우지 못함) 열화 걸음이 그 뒤를 말한다 |
| 견주지 못함 | 점수가 없어(평가 시점 부족 · 후보가 서지 않음 · 축 값 없음) 세 후보를 견주지 못했다는 표시 — 표를 그리지 않고 서버 사유 한 줄만. 점수를 지어내지 않는다 |
| 고른 쪽의 점수는 낙관적 | 같은 자료로 세 후보를 견줘 고른 값이라 고른 쪽의 점수가 실제보다 좋게 나온다는 가정 줄(견준 후보 셋) — 견줬을 때만 붙인다 |
| 요청한 방식 · 산출한 방식 | 사용자가 고른 방식과 실제로 쓴 방식. 다르면 사유를 `가정` 색의 글로 붙인다(색만으로 말하지 않는다) |
| 열화 걸음 · 넘어갔습니다 · 산출했습니다 | 요청한 방식을 쓰지 못해 다른 방식으로 옮겨 간 한 걸음 — 걸음마다 그 걸음의 두 방식과 사유를 한 문장으로 적는다. 두 걸음(GMM 시작 분포 × 전이 → 전이 예측 → 오늘 국면 유지)이면 앞 걸음은 `넘어갔습니다`, 산출한 방식에 닿은 걸음만 `산출했습니다`. 결과 판의 사유 줄과 해설의 대체 줄이 같은 글이다 |
| 시작 분포 | GMM 시작 분포 × 전이의 출발점 — 지금 점이 각 국면에 속하는 확률. `보유 기간 평균`은 혼합에 쓴 국면 분포의 보유 기간 평균 |
| 추정 불가(국면 분포) | 혼합이 그 국면의 조건부 적률을 추정하지 못해 빼고 남은 국면으로 재정규화했다는 표시. `0%` 로 그리지 않고 서버 문장(국면 · 사유 · 뺀 확률 질량)을 붙인다 |
| 다시 뽑기 | 달을 복원 추출로 다시 뽑아 GMM 을 다시 적합했을 때 지금 점이 같은 국면에 가장 크게 속한 횟수(관측). 시작 분포를 바꾸지 않고 문턱도 없다 · `부트스트랩`은 화면에 쓰지 않는다 |
| 난수 시드(안정성) | 지금 점의 GMM 최다 국면이 난수 시드 몇 개에서 같았는지(§3.14 와 같은 말). 시드에 대한 민감도이지 자료가 바뀔 때의 강건성이 아니다 — 그것은 `다시 뽑기`가 따로 잰다 |

### 3.17 하루 유형 (백테스트 › 분봉 규칙의 '하루 유형' 절 · 2026-11-16)

| 낱말 | 뜻 · 쓰는 법 |
|---|---|
| 하루 유형 | 장 시작 구간의 가격 경로가 닮은 표본끼리 묶은 것. ★모양의 요약이지 예측이 아니다★ — `패턴`·`신호`·`좋은 유형`이라고 쓰지 않고 유형에 순위를 매기지 않는다 |
| 표본 | 종목 하나의 하루(그 종목 그날의 장 시작 구간 경로 하나). 세는 낱말은 `표본`이다 — `날`은 날짜에만 쓴다(학습 기간의 `날 n일`은 날짜 수). 서버 필드도 `samples` 이고 `days` 는 날짜 목록뿐이다 |
| 장 시작 구간(분) | 그날 그 종목의 ★첫 봉부터★ 정한 분 수(5 ~ 120). 첫 N개 봉이 1분마다 하나씩 있어야 표본이 된다. 그림의 가로축은 시계 시각이 아니라 `첫 봉부터 m분째` |
| 첫 봉 시가 대비 bp | 경로의 단위 — 첫 봉 시가를 0 으로 둔 종가의 bp. 부호는 `+` · `−`(U+2212) · 모든 판이 같은 세로축 |
| 중심 경로 | 유형마다 그 유형 표본들의 중심(e-means 의 중심). 판 하나가 유형 하나다 |
| 유형 번호 | 구간 마지막 분의 값이 낮은 것부터 매긴 번호. 번호에 다른 뜻은 없다 |
| 흩어짐 | 그 유형 표본들이 중심 경로에서 떨어진 정도(RMS · bp). 표본이 없는 유형은 미상(N/A — 0 이 아니다). `변동성`이라 쓰지 않는다 |
| e-means | 메타 FAIR 의 faiss 군집화 방법 이름 그대로 쓴다(근사 k-평균). 우리말로 옮기지 않는다 |
| Lloyd(시작 10번) | 같은 자료로 표준 k-평균(Lloyd)을 시작점 10번으로 돌린 것 — e-means 의 손실을 견주는 기준. 두 손실과 그 차이(%)만 적고 `더 정확한`·`더 나은` 같은 평가어를 붙이지 않는다 |
| 손실(평균 제곱 거리 · bp²) | 표본과 그 표본이 배정된 중심 사이 제곱 거리의 평균. 보이는 숫자와 문장은 서버가 짓는다 |
| 조정 랜드 지수 | 두 배정이 얼마나 같은지(1 = 같음). 난수 시드 1234 의 배정을 나머지 넷과 견준다. `신뢰도`·`안정적`이라 쓰지 않는다 — 시드에 대한 민감도일 뿐이다 |
| 난수 시드 | §3.14 · §3.16 과 같은 말(`씨앗`은 쓰지 않는다) |
| 뺀 표본 | 학습에 쓰지 않은 표본 — 사유마다 서버 문장과 수를 적는다(구간이 모자람 · 가격이 0 이하 · 봉을 준비한 쪽이 건너뛴 사유는 분봉 백테스트의 `건너뛴 날`과 같은 문장) |
| 학습 기간 | 쓰인 표본의 처음 날과 끝 날(요청한 기간의 끝이 아니다). 입력 칸의 처음 값은 규칙 설정 기간의 ★바로 앞 같은 길이★ — 학습한 날로 규칙을 판정하지 않게 |
| 내 모형 | 내가 학습한 모형 목록(본인 것만 · 지우는 길 없음). 합성 분봉으로 학습한 모형에는 `합성` 표지 · 운영에서는 합성 모형을 보이지 않고 그 수를 적는다 |
| 다시 학습하지 않았습니다 | 같은 표본 · 같은 설정이면 같은 모형이다(열쇠가 같다) — 남겨 둔 그 모형을 보인다 |
| 학습 ≠ 시행 | 규칙을 돌린 것이 아니므로 시행 횟수에 세지 않는다 |
| 하루 유형 조건 | 직접 구성의 지표 `하루 유형`(모형 · 유형 번호). 그날 그 종목의 첫 N분이 그 유형으로 배정되면 창의 마지막 봉부터 1, 아니면 0 — 창이 끝나기 전 · 창이 어긋난 날은 값이 없다(미상 · 조건을 충족하지 않는다). 글은 `하루 유형 3번(모형 1a2b3c4d)` · T2 · 2026-11-17 |
| 모형 선택 | 편집기의 모형 칸은 비어서 시작한다(도구는 모형을 고르지 않는다). 목록은 내 모형만이고 고른 모형의 유형 수가 번호 칸의 상한이다. 모형이 없으면 어디서 학습하는지 안내한다 |
| 판정 시작일 전 | 학습 기간의 끝 날이 판정 기간의 첫날보다 앞이어야 한다 — 겹치거나 뒤의 모형은 거절하고 사유를 적는다(`표본 안`으로 돌려 계산하지 않는다) |
| 규칙이 쓴 하루 유형 모형 | 결과 · 매매일지의 견주기 · 캔버스 판의 사실 줄 제목 — 학습 기간 · 종목 수 · 판정 종목과 같은지 · 합성이면 그렇다고(서버 문장 그대로) |


### 3.18 시장 국면 (백테스트 › 분봉 규칙의 '시장 국면' 절 · K1 · 2026-11-17)

| 낱말 | 뜻 · 쓰는 법 |
|---|---|
| 시장 국면 | 지수(코스피 · 코스닥)의 20거래일 수익과 실현 변동성이 닮은 날끼리 GMM 으로 묶은 것. ★이름표이지 예측이 아니다★ — `강세장` · `약세장` · `위험 국면`처럼 뜻을 붙인 이름을 쓰지 않고 국면에 순위를 매기지 않는다. 매크로 화면의 `국면`(§3.15 · §3.16 — 경기 사분면)과 다른 것이다 |
| 국면 번호 | 적합 창에서 국면(GMM 성분)의 20거래일 실현 변동성(σ20) 평균이 낮은 것부터 매긴 번호(1 이 가장 낮다). 번호에 다른 뜻은 없다. 화면은 `변동성이 낮은 것부터`로 줄이지 않고 어느 변동성인지 적는다 — 국면별 통계의 실현 변동성(그 기간 그 국면으로 센 날들의 일 수익)과 순서가 다를 수 있다(국면이 없는 걸음 열 개 가운데 국면 2 에서 7개 · 국면 3 에서 8개가 어긋났다 — 잰 값 · 시험이 건다) |
| 국면 수 | 사용자가 2 ~ 4 에서 고른다. 칸은 비어서 시작한다(도구는 국면 수를 고르지 않는다 — BIC 로도 고르지 않는다) |
| 소속 확률 | 그날이 각 국면에 속할 확률(합 1). ★전 거래일 종가까지★로 계산한다 — 그날 종가는 쓰지 않는다. 퍼센트 소수 한 자리 · 값이 없으면 `N/A` |
| 가장 큰 국면 | 그날 소속 확률이 가장 큰 국면. 값이 없는 날은 `국면 미상 · {사유}`(서버 문장 그대로 · 0 이나 국면 1 로 그리지 않는다) |
| 적합 창 | 달마다 그달 첫 거래일 전의 750거래일로 다시 적합한다(고정 길이). 750거래일이 모자라는 달은 계산하지 않고 필요 · 있는 날 수를 적는다 — 같은 종가에서는 같은 날이 언제 다시 봐도 같은 값. 창의 특징이 변하지 않으면(평평한 가격 등) 나누지 않고 사유를 적는다. 화면의 적합 줄은 `3번(달마다 한 번)`처럼 적는다 — `달마다 3번`은 한 달에 세 번으로 읽힌다 |
| 특징(20거래일 수익 · 실현 변동성) | 20거래일 로그 수익과 그 기간 일 로그 수익의 표본 표준편차 × √252(연율). 종가 21개가 모두 0 보다 커야 센다 |
| 난수 시드 | §3.14 · §3.16 과 같은 말. 시드 열 개로 적합해 번호를 맞춘 뒤 확률을 평균한다 |
| BIC | 같은 자료에서 국면 수 2 · 3 · 4 를 각각 적합한 값(낮을수록 자료에 잘 맞음). 나란히 적을 뿐 국면 수를 고르지 않는다 — `최적`이라 쓰지 않는다 |
| 난수 시드 일치도 | 시드 0 의 배정을 나머지 시드와 견준 조정 랜드 지수(최소 · 평균). ★국면이 있다는 증거가 아니다★ — 국면이 없는 합성 걸음(변동성 일정)에서도 1 에 가깝게 나온 경우가 있다(잰 값 · 시험이 건다). 높다고 `안정적인 국면`이라 쓰지 않는다 |
| 국면 전환 | 값이 있는 날끼리 가장 큰 국면이 바뀐 횟수 |
| 국면별 통계 | 가장 큰 국면으로 센 날 수 · 비중 · 그 날들의 일 로그 수익 평균 · 실현 변동성(연율). 관측이며 결정에 쓰지 않는다 — `국면 2 의 수익이 높다`를 권고로 쓰지 않는다 |
| 합성 지수 일봉 | 모의 모드의 지수 일봉 — 변동성이 일정한 걸음이라 국면이 없는 자료다. 맨 위에 서버 사유와 함께 적고 장치 확인용이라고 쓴다 |
| 국면 띠 | 날마다 막대 하나 · 아래부터 국면 1 · 칸 높이가 그 국면의 소속 확률. 한 색상의 밝기 단계(국면 1 이 바탕에 가장 가깝다) · 값이 없는 날은 빗금 |

### 3.19 국면별 성과 나눔 (분봉 결과의 '시장 국면별로 나눠 보기' 절 · K2a · 2026-11-17 — 캔버스 '분봉 결과 조회' 판의 같은 절 · K2c)

| 낱말 | 뜻 · 쓰는 법 |
|---|---|
| 시장 국면별로 나눠 보기 | 방금 남은 시행의 일별 손익을 그날의 시장 국면(가장 큰 확률 · §3.18)별로 나눈 것. ★관측이며 결정에 쓰지 않는다★ · 시행을 새로 남기지 않는다(시행 수 불변). `국면 조건을 넣으면 나아진다`로 읽히지 않게 절 머리와 한계 문장이 적는다. 단추는 `국면별로 나누기` |
| 그날의 국면 | 그날 시가 전에 아는 값 — 전 거래일 종가까지로 계산한 소속 확률(§3.18)의 가장 큰 국면 |
| 국면 미상 | 그날의 국면을 알 수 없던 거래일(지수 일봉이 없는 날 · 적합 창이 덜 찬 달 등). 서버 사유별 날 수를 적고 ★0 이나 국면 1 로 세지 않는다★. 미상 줄의 `확률 0.5 미만` 칸은 `N/A`(그날 확률이 없다) |
| 확률 0.5 미만 | 가장 큰 국면의 확률이 0.5 보다 작았던 날 수(그 국면이 근소하게 가장 컸던 날). 0.5 는 미만이 아니다. 합계 줄은 국면들의 합이다(미상 날은 세지 않는다) |
| 승률(국면별) | 이긴 거래 ÷ 거래 — 이김은 손익 칸과 같은 기준(비용 뒤 · 비용 전)이다. 거래가 0 이면 `N/A`(0.0% 가 아니다). 미상 줄 · 합계 줄도 같은 규칙이고 값은 서버가 센다(화면이 셈하지 않는다) |
| 거래 · 승률의 N/A(옛 시행) | 이 절이 생기기 전의 실행은 날마다의 거래 수를 남기지 않았다 — `N/A` + 서버 사유. 같은 설정으로 다시 실행하면 남고 시행 수(N)는 늘지 않는다 |
| 국면 전환(나눔) | 시행의 거래일 가운데 국면이 있는 날끼리 가장 큰 국면이 바뀐 횟수(§3.18 의 국면 전환은 판정 기간 전체) |
| 시행 등급 · 국면 등급 | 시행 등급은 그 시행 분봉의 출처, 국면 등급은 지수 일봉의 출처(E0 합성 · E3 실데이터). ★둘 가운데 하나라도 합성이면★ 맨 위에 합성 알림(장치 확인용 · 시장에 대한 진술이 아니다). 등급을 매길 수 없으면 `미상` + 서버 사유 — 합성 알림으로 바꾸지 않는다 |
| 나누지 않은 까닭 | 서버 문장 그대로: 일별 손익 없음 · 거래일 수와 맞지 않음 · 일별 기록을 읽을 수 없음 · 국면 계산이 국면 수 밖의 번호를 냄(계산 결함 — 시행 기록의 문제가 아니다) · 운영의 합성 시행 · (국면 쪽) 적재 없음 · 운영의 합성 지수 · 저장소 장애(없음이 아니다) |
| 하루 유형 비율(K2b) | 같은 절 안의 하위 절. 그 시행의 종목 · 기간의 표본(종목 하나의 하루)을 고른 하루 유형 모형(§3.17)으로 배정해 그날의 국면별로 센 비율. ★같은 날의 두 이름표를 겹쳐 센 관측★ — 국면은 시가 전에 알고 유형은 장 시작 구간이 닫힌 뒤에 정해진다. `국면이 유형을 예측한다` · `비율 차이가 국면의 성질이다`로 쓰지 않는다. 모형 칸은 비어서 시작(도구가 고르지 않는다) · 단추는 `하루 유형 비율 보기` |
| 유형을 정한 표본 | 그 묶음에서 유형이 배정된 표본 — ★비율의 분모★다. 창이 덜 찬 표본 등 뺀 표본은 분모에 넣지 않는다. 0 이면 비율은 `N/A`(0.0% 가 아니다) |
| 표본 안 분류 | 그 표본의 날이 모형의 학습 날(어느 종목이든)인 것 — 모형이 그날을 보고 중심을 정했다. 칸에는 `표본 안 n` 으로 따로 적고 학습 밖 표본과 같은 무게로 읽지 않게 한계 문장이 적는다. 하루 유형 조건(§3.17)은 이런 모형을 규칙에 못 쓰게 거절하지만 이 표는 거절하지 않고 가른다 |
| 뺀 표본 | 유형을 정하지 못한 표본 — 사유별 수와 서버 문장(하루 유형 학습과 같은 문장). 사유 없이 빼지 않는다 |
| 표본 등급 · 모형 등급 | 표본 등급은 ★지금 다시 읽은 분봉★의 출처(시행 등급과 따로 — 그 사이 적재가 바뀌었을 수 있다), 모형 등급은 학습한 분봉의 출처. 시행 · 국면 · 모형 · 표본 가운데 하나라도 합성이면 합성 알림. 쓴 분봉이 없으면 `미상` + `쓰인 분봉이 없습니다` |
| 세지 않은 까닭 | 서버 문장 그대로: 분봉 적재 없음 · 모형 기록이 그 모형의 유형 수 · 분 수와 맞지 않음(모형의 문제) · 국면 번호 밖(계산 결함) · 표본 기록을 읽을 수 없음 · 운영의 합성 시행 · 운영의 합성 표본 + 국면 쪽 사유 |
| 결과 판의 나눔(K2c) | 캔버스 '분봉 결과 조회' 판의 같은 절 — 화면과 같은 칸 · 같은 문으로 ★그 노드가 가리키는 시행★을 묻는다. 단추로만 묻는다(그래프 계산 · 판 열기는 묻지 않는다) · 다른 결과 노드를 고르면 앞의 답과 고른 칸을 지운다. 어느 시행의 결과인지 적혀 있지 않은 답이면 묻지 않고 그렇게 적는다. 판이 좁아 모형 칸의 글이 잘릴 수 있어 고른 모형의 이름 전체를 칸 아래 줄로 다시 적는다(넓은 화면에는 그 줄이 없다) |

### 3.20 국면 조건 (백테스트 › 분봉 규칙의 '직접 구성' · 캔버스 분봉 설정 노드 · K3 · 2026-11-17)

| 낱말 | 뜻 · 쓰는 법 |
|---|---|
| 시장 국면 확률 | 지표 이름표. 그날 시가 전에 알던 소속 확률(§3.18 — 전 거래일 종가까지)이라 하루 내내 같은 값이다. 조건에서는 0 ~ 1 의 값으로 견준다(국면 절의 퍼센트 표기와 다르다 — 0.6 은 60%). 규칙의 글은 `코스피 국면 2 확률(국면 3개)` — 지수 · 번호 · 국면 수가 함께 드러난다 |
| 지수 · 국면 수 · 국면 번호(칸) | 편집기의 세 칸. ★비어서 시작한다★(도구가 지수 · 국면 수 · 번호를 고르지 않는다 — 빈 칸은 `…를 고르십시오` · `…범위로 입력하십시오`). 번호가 국면 수보다 크면 서버가 거절한다 |
| 국면 조건 | 시장 국면 확률을 상수나 다른 시장 국면 확률과 초과 · 이상 · 미만 · 이하로 견주는 조건. ★진입 조건에만 · '모두 충족'으로만★ 잇는다(청산 조건 · 미리 건 매수 가격 · '하나 이상 충족' · '아님' · '직전 봉 동안 계속' 안은 서버가 사유와 함께 거절한다). 돌파는 쓰지 않는다(하루 내내 같은 값이라 일어나지 않는다). 미리 건 매수 가격은 국면 조건과 따로 체결된다(주석이 적는다) |
| 국면 조건 추가 | 진입 조건 자리의 단추 — 국면 조건 한 줄을 ★진입 조건 전체★와 '모두 충족'으로 잇는다(뿌리가 '하나 이상 충족'이어도 그 안에 넣지 않는다 — 틀의 뜻을 바꾸지 않는다). 보통의 `조건 추가`는 묶음 안에 줄을 더한다 |
| 규칙이 쓴 시장 국면 | 실행 · 판정 · 캔버스 판의 사실 줄 묶음(서버 문장 그대로) — 그날 시가 전 값이라는 것 · 분봉이 적재된 날 가운데 확률을 아는 날 · 모르는 날과 사유별 날 수 · 합성 지수 일봉이면 그렇다고 · 국면은 이름표라는 것. 하루 유형 묶음(`규칙이 쓴 하루 유형 모형`)과 따로 둔다 |
| 확률을 모르는 날 | 지수 일봉이 없는 날 · 적합 창이 덜 찬 달의 날. ★조건을 충족하지 않은 것으로 계산한다★(0 이나 균등 확률로 채우지 않는다 · `미만` 조건도 서지 않는다) · 사실 줄이 사유별 날 수를 적는다. 분봉이 적재된 날 가운데 아는 날이 하나도 없으면 계산하지 않고 거절한다(시행을 남기지 않는다) |
| 국면 조건을 뺀 판과 견줌 | 판정의 절 — 같은 날 · 같은 포지션 · 같은 비용으로 국면 조건만 뺀 같은 규칙을 한 번 더 돌린 두 줄(`국면 조건을 넣은 판(이 규칙)` · `국면 조건을 뺀 판`). ★시행으로 세지 않는다★(판정의 일부 · 계산량에는 센다) · 어느 줄도 칠하지 않는다 · `국면 조건이 낫다`로 읽히지 않게 한계 문장(관측 · 증거가 아님 · 이 견줌을 보고 다시 실행하면 그것도 시행)을 붙인다. 진입 조건이 국면 조건뿐이고 미리 건 매수 가격이 없으면 뺀 판을 지을 수 없어 사유를 적는다 |

### 3.21 매매 몫 결합 (캔버스 '백테스트' 묶음의 끝 노드 · K4 · 2026-11-17)

| 낱말 | 뜻 · 쓰는 법 |
|---|---|
| 매매 몫 결합 | 노드 이름. 정책 백테스트(핵심)와 분봉 백테스트(위성)를 국면별 매매 몫으로 합친 곡선과, 같은 평균 몫으로 고정한 곡선을 ★나란히★ 낸다. ★끝 노드★다 — 내는 것이 없고(비교 · 순위 · 비중 · 주문으로 가지 않는다) 단추가 없다(계산은 쓰기 0 · 시행이 아니다). AI 추천 · 말로 설계가 내놓지 않는다(도구가 몫과 자본을 고르지 않는다) |
| 핵심 · 위성 | 핵심 = 정책 백테스트의 ★비용 후★ 곡선(다시 계산하지 않는다) · 위성 = 분봉 결과 조회가 가리키는 시행의 비용 후 일별 손익(본인의 시행만 읽는다). 비용 전 손익만 있는 시행은 합치지 않는다(위성이 유리하게 보인다) |
| 매매 몫 | 전체 자본 가운데 위성(분봉 매매)에 두는 몫. `비중`(배분의 종목 비중)과 섞어 쓰지 않는다 |
| 국면별 매매 몫 | 국면 번호마다 사용자가 적는 몫(0 ~ 100%) — 칸 `국면 n 일 때 매매 몫`. ★비어서 시작한다★(도구가 표를 정하지 않는다) · 국면 수보다 큰 번호의 칸은 보이지 않고 쓰이지 않는다. 지수 · 국면 수 칸도 비어서 시작한다(§3.20 과 같은 규칙) |
| 몫을 정하는 날 · 목표 몫 | 겹친 기간의 첫날과 달마다 첫 거래일. 목표 몫 = Σ 그날 국면 확률 × 국면별 매매 몫 — 확률은 그날 시가 전에 알던 값(§3.18 — 전 거래일 종가까지 · 시장 국면 절과 같은 계산). 그날의 확률을 모르면 ★합치지 않는다★(앞 달 몫으로 미루거나 0 으로 채우지 않는다) |
| 표류 | 몫을 정하는 날 사이에는 되돌리지 않아 두 쪽의 수익에 따라 몫이 움직이는 것. 평균 몫은 표류를 포함한 날마다의 몫의 평균이다 |
| 옮긴 몫 · 옮긴 몫 비용 | 몫을 정하는 날의 목표 몫과 그날 아침 몫의 차이(절댓값). 비용 = 옮긴 몫 × 정책 백테스트의 비용 가정. 시작 자본은 핵심에 투자된 상태로 보고 ★첫날 위성으로 옮기는 몫도 비용을 낸다★. 표의 비용은 시작 자본 대비(%) |
| 매매 몫 자본 | 분봉 손익을 수익률로 바꾸는 분모(원) — 사용자가 적는다. 하한 = 진입 금액 × 동시에 보유할 수 있는 종목 수 × (1 + 수수료율) · 모자라면 서버가 거절한다(그 자본으로 살 수 없는 진입이 있다). 몫이 바뀌면 진입 금액도 같은 비율로 바뀐다고 보는 ★가정★이고 놀리는 자본의 이자는 0 이다 |
| 국면 몫 판 · 몫 고정 판 | 두 판은 같은 날 · 같은 재조정 날 · 같은 비용이고 목표 몫만 다르다 — 몫 고정 판의 목표는 국면 몫 판 목표의 ★날 가중 평균★(몫을 정한 날의 목표 × 그 몫이 적용된 거래일 수). 표의 줄은 늘 서버 순서(국면 몫 → 몫 고정)이고 ★어느 줄도 칠하지 않는다★ — `국면 몫이 낫다`로 쓰지 않는다 |
| 몫의 길 | 몫을 정한 날마다의 국면 확률 · 목표 몫 · 옮긴 몫 · 비용 표. 확률은 퍼센트(소수 한 자리) |
| 자료 등급(머리 줄) | `시행 E3 · 국면 E0 · 핵심 모의 시세` 꼴 — 시행 등급 · 국면 등급(§3.19)과 핵심의 시세(정책 백테스트의 성과 라벨: 모의 시세 · 실제 시세 · 미상). ★셋 가운데 하나라도 합성이면★ 맨 위에 합성 알림. 라벨이 없으면 `미상`(실제라고 하지 않는다) |

### 3.27 봉과 체결 (백테스트 › 분봉 규칙의 실행 결과 · G4 · 2026-11-19)

| 낱말 | 뜻 · 쓰는 법 |

### 3.29 시계열용 등각 · 규칙 기반 해설 (캔버스 '과거로 돌려 보기' 결과 판 · 크게 보기 · 매크로 › 추천 · G7 · 2026-11-19)

| 낱말 | 뜻 · 쓰는 법 |
|---|---|
| 시계열용 (교환가능성 가정 없음) | 분할 등각 상자('다음 구간 예측 (분포 무가정)') 안의 하위 묶음 이름. 같은 리밸런스 쌍을 같은 시간 순서로 적응형 등각(ACI)에 넣은 결과다. 위의 분할 등각은 교환가능성을 가정하고, 이 묶음은 그 가정 없이 ★장기 평균 놓침률만★ 보장한다(구간 하나하나의 적중을 약속하지 않는다) |
| 일평균 수익률 90% 구간(적응형) | 다음 리밸런스 구간의 구간. 분할 등각과 같은 점추정에 씌운다. 무한 구간 · 빈 구간이면 값 대신 서버 문장을 그대로 옮긴다 |
| 무한 구간 · 빈 구간 | `무한 구간` = 구간이 실수 전체인 걸음(앞 점수가 적거나 놓침이 잦아 목표 적중률을 지키는 유한한 구간을 만들 수 없을 때 · 늘 덮음으로 센다). `빈 구간` = 구간이 비어 있는 걸음(덮음이 목표보다 많아 되돌리는 걸음 · 늘 놓침으로 센다). 둘 다 자르지 않는다(자르면 보장이 깨진다) · 너비 평균은 유한한 구간만 |
| 온라인 적중률(걸음마다 앞의 점수로 지은 구간) | 걸음마다 그때까지의 점수로만 지은 구간이 그 걸음의 실현을 덮은 비율(분수와 함께). 바로 아래 줄 `그중 무한 구간 · 빈 구간` 이 두 수를 적는다(무한 구간은 늘 덮고 빈 구간은 늘 놓쳐 그 수를 보지 않으면 적중률을 잘못 읽는다) |
| 실측 적중률(보정에 쓰지 않은 뒤쪽 쌍에서 셈) | 분할 등각의 적중률. 앞쪽 쌍으로 보정하고 보정에 쓰지 않은 뒤쪽 쌍에서 센다. 온라인 적중률과 정의가 달라 곧바로 견주는 값이 아니다 |
| 보장 상한(놓친 비율의 장기 평균) | 놓친 비율의 장기 평균이 목표에서 벗어나는 폭의 상한 ±(max(α, 1 − α) + γ) / (γT). 어떤 수열에서도 선다. 이 값이 어떤 결과로도 넘을 수 없는 폭 max(α, 1 − α) 이상이면 서버가 "이 길이(T쌍)로는 보장이 서지 않습니다"라고 쓴다(α = 0.1 · γ = 0.005 에서 202쌍부터 선다 · 리밸런스 쌍 수십 개로는 서지 않는다) |
| 걸음 γ | 0.005 고정(원 논문의 실험값). 사용자 칸이 없다(결과를 보고 고르면 숨은 시행이 된다) |
| 규칙 기반 해설 | 매크로 › 추천의 '추천한 까닭' 글. 국면 적합도와 최근 12개월 성과로 지은 규칙 글이다(꼬리표 `규칙 기반 해설입니다 · 국면 적합도와 최근 12개월 성과로 지은 글입니다`). 엔진은 LLM 을 부르지 않는다(계산 · 결정 계층의 경계 · 제품 규칙 §3-2). 서버가 '규칙'이라 하지 않는 응답에는 꼬리표를 달지 않는다 |
| 쓰지 않는 말 | `신뢰구간`(등각 구간은 신뢰구간이 아니다) · `보장된 구간`(보장은 장기 평균 놓침률에 대한 것이다) · `AI 해설`(매크로 추천의 글은 규칙 글이다) · `키를 등록하면 활성화`(지키지 못하는 약속이었다 · G7 에서 지웠다) |

## 4. 답 문장의 틀

화면 맨 위의 한 줄은 서버 필드를 틀에 끼운 것이다(ADR 003 §2.6 — 화면이 판단을 만들지 않는다). 틀은 개조식으로 쓴다.

- 기업: `현재가 {P}원 · 내재가치(추정) {V}원 · 괴리율 {±g}%` + 판정 칩. 내재가치가 없으면 `내재가치 산출 불가` + 사유(0% 를 지어내지 않는다).
- 성과: `총수익률 {r}% · CAGR {c}% · MDD {m}% · 샤프지수 {s}`.
- 판단 필드가 없으면 잰 값만 적는다(`시장 스트레스 52/100`).
- 분봉 백테스트: `시뮬레이션 거래 {n}건의 비용 후 실현손익 {±P}원` · 판정은 `관문 일곱 가운데 통과 {a} · 미달 {b} · 미상 {c} 입니다.`(서버 문장 그대로). 종합 평가 문장을 만들지 않는다.
- 괴리 보고: `짝지은 {n}건의 체결가는 가정(슬리피지 {k}틱)보다 평균 {x}틱 불리했습니다.`(유리하면 `유리했습니다` · 평균이 0.05틱 안이면 `…와 평균이 같았습니다.` · 짝이 없으면 `짝지은 체결 없음`). 권고 문장을 만들지 않는다.
- 매매일지: `거래 {n}건의 비용 후 실현손익 {±P}원`. 비용을 모르는 거래가 있으면 `비용 전`으로 바꿔 쓰고 사유를 아래에 적는다. 청산된 거래가 없으면 `청산된 거래 없음`(승률을 지어내지 않는다).
