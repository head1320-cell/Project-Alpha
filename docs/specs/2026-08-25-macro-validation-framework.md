## 0. 왜 지금 이 문서가 필요한가

감사(§6)가 확인한 것: **스튜디오 중 포트폴리오에 연결된 것이 0개**다. 그래서
스펙 §18 이 "궁극 기준" 이라 한 Level 4(결정가치)로 **평가할 수 있는 대상이 없다.**
프레임워크를 먼저 세워야 어떤 모델을 승격할지 판단할 근거가 생긴다.

★그리고 프레임워크 없이 승격하지 않는다★ — 스펙 §29 의 금지사항
*"새롭다는 이유로 고전 모델을 대체하지 않는다"* 를 강제하는 것이 이 문서다.

## 1. 벤치마크 사다리 (스펙 §10)

```
Naive(마지막값·평균)
  → AR(p)
  → VAR
  → DFM
  → Elastic Net
  → RF / GBM
  → DLinear 급 단순 현대 baseline
  → TSFM
```

★규칙 두 가지★
1. **고전 벤치마크가 먼저다.** 사다리의 아래를 건너뛰고 위를 평가하지 않는다.
2. **아래를 이기지 못하면 승격하지 않는다.** "더 정교함" 은 승격 사유가 아니다.

현재 저장소 위치: `DFM` 까지 존재. `Naive`·`AR`·`VAR` 는 **비교 기준으로서**
아직 구현돼 있지 않다 — 즉 DFM 이 무엇을 이겼는지 아무도 모른다.

### 1.1 ★국면 배선의 사다리 — 세 팔 규약★

예측모형의 사다리와 **별개로**, 국면조건부 배선에도 사다리가 필요하다.
`allocation_backtest.walk_forward` 를 같은 시드·같은 비용으로 세 번 돌린다:

| 팔 | 설명 | 상태 |
|---|---|---|
| **B0** 무조건부 | 국면 배선 없음 — 사다리의 바닥 | 잰 적 **없음** |
| **B1** 하드 라벨 | `argmax`, 확률 1 | **현행 프로덕션** |
| **N** 확률 혼합 | π = `k_step_forecast(h)`, `Σ̄ = W + (h/12)D` | 제안 (MS1) |

**설계 — 팔 3 × 모델 2 × 비용 3 = ★18회★**

| 축 | 값 | 왜 |
|---|---|---|
| 팔 | B0 · B1 · N | 사다리 |
| **모델** | ★`bl` **과** `ep` 둘 다★ | 공분산 전용 모델(min_var·ERC·HRP·max_div)은 **μ 효과를 못 본다**. 실측에서 Σ 효과는 회전율 1.0%, μ 효과는 뷰 3.87%p 다 — min_var 로만 재면 "결정이 안 바뀐다" 는 **잘못된 결론**이 나온다 |
| **비용** | 0 / 10 / 30 bp | 혼합은 회전율을 올린다 |

★같은 엔진 · 같은 시드 · 같은 유니버스 · 같은 리밸런싱 주기★ — 팔 사이에서 변하는
것은 Σ 와 뷰뿐이어야 차이를 국면 배선 탓으로 돌릴 수 있다.

★규칙★
1. **N 이 B1 을 ★모든 비용 수준에서★ 못 이기면 채택하지 않는다.**
2. ★**B1 이 B0 를 못 이기면 국면 배선 자체를 재검토한다.**★ 현행이 무조건부보다
   나은지 아무도 모르는 채로 그 위에 층을 쌓는 것이 더 위험하다.

**보고 지표 (전부 필수)** — `compute_metrics()` 가 이미 내는 것을 쓴다:

| 지표 | 비고 |
|---|---|
| `sharpe` · `sortino` · `calmar` | |
| `max_drawdown_pct` (MDD) | |
| `cvar_95` (ES) | |
| `turnover_avg_pct` | 편도 `0.5·Σ|Δw|` |
| ★`n_rebalances`★ | **비율 지표 옆에 항상** |
| ★국면조건부 성과★ | `{국면: {sharpe, mdd, n_rebalances}}` |
| ★BL/EP 결정 민감도★ | 팔 간 `Δw` 의 L1 · 뷰 크기 변화(%p) · 뷰 신뢰도 변화 |
| ★기대효용 개선★ | 아래 |

**기대효용 — 실현 확실성등가로 잰다** (★사후 Σ 금지★ — 최적화에 쓴 Σ 로 효용을
재면 자기 채점이다):

```
CE   = mean(r_oos) − (δ/2)·var(r_oos)      δ = DELTA_DEFAULT = 2.5
ΔCE₁ = CE(N)  − CE(B1)      혼합이 하드 라벨보다 나은가
ΔCE₀ = CE(B1) − CE(B0)      ★국면 배선이 애초에 값어치가 있는가★
```

두 `ΔCE` 를 **비용 수준별로 각각** 낸다. 30bp 에서 `ΔCE₁ ≤ 0` 이면 "이겼다" 고
쓰지 않는다.

★두 가지를 반드시 함께 낸다★
- **비용 민감도** — 없으면 **회전율만 늘린 것을 개선으로 착각**한다.
- **국면조건부 성과 + `n_rebalances`** — Stagflation 처럼 얇은 국면(실측 n=12,
  기대 지속 3.8개월)은 표본 수 없이 보면 숫자가 거짓말을 한다.
  **`n_rebalances` 누락은 보고 미완성으로 간주한다.**

## 2. 4단 평가 (스펙 §18)

### Level 1 — 통계
| 종류 | 지표 |
|---|---|
| 점예측 | RMSE · MAE · OOS $R^2$ · 방향정확도 |
| 밀도 | 로그점수 · **CRPS** · 커버리지 · 캘리브레이션 |

★확률예측은 캘리브레이션 없이 통과할 수 없다★(스펙 하드룰). 90% 구간이 실제로
90% 를 덮는지 재지 않은 밀도예측은 Level 1 을 통과하지 못한다.

★그리고 적중률만으로도 통과할 수 없다 — **날카로움을 함께 낸다**★

| 출력 종류 | 적중 지표 | **반드시 동반할 날카로움 지표** |
|---|---|---|
| 범주(국면) | 예측집합 적중률 | **평균 집합 크기** · `sharpness = 1 − H(π)/ln R` |
| 연속 | 커버리지 | 평균 구간 폭 |

집합을 키우면 적중률은 언제든 오른다. 실측이 그 함정을 그대로 보여준다:

```
k=1  적중률 0.966  집합 2.72/4      sharpness 높음
k=3  적중률 0.889  집합 **3.81/4**  sharpness 0.206 (퍼플렉서티 3.007)
```

k=3 은 적중률만 보면 목표 0.9 에 붙지만, **4국면 중 거의 전부를 담아야 맞힌다** —
정보가 거의 없다는 뜻이다. ★적중률 단독 보고는 Level 1 미통과로 간주한다.★

그리고 그 날카로움은 **소비 쪽에서 힘으로 환산돼야 한다** — 확률이 흐릴수록 뷰가
약해지도록 `conf ×= sharpness` 를 건다(계획 §1.5). 캘리브레이션을 재 놓고 그것을
비중에 반영하지 않으면 잰 의미가 없다.

### Level 2 — 경제
성장 · 물가 · 침체 · 국면 · 수익률곡선 예측의 부호와 크기.

### Level 3 — 포트폴리오
수익 · Sharpe · Sortino · CVaR/ES · MDD · **회전율** · **거래비용** ·
국면조건부 P&L. ★거래비용 없는 Sharpe 개선은 Level 3 통과가 아니다.★

### Level 4 — 결정가치 (★궁극 기준★)
- 배분을 개선했는가
- 드로다운을 줄였는가
- 꼬리노출을 줄였는가
- **거짓 국면전환을 줄였는가**
- 리밸런싱 결정을 개선했는가

측정 방법: 같은 기간·같은 제약에서 **모델을 껐을 때와 켰을 때**의
`rebalance-decision` 결과를 비교한다. 저장소에 이미 있는 것을 그대로 쓴다 —
`conditional_market.conditional_moments` · `rebalance_policy.rebalance_decision` ·
`execution_plan.build_plan`(비용) · `backtest_attribution`(귀인).

## 3. 워크포워드 규약 (스펙 §19)

```
        ┌─ 학습 ─┬─ 검증 ─┬─ 평가 ─┐
t:      [========][=======][=======]
        ← 롤링 또는 확장 →
```

★하드룰★
- 모델선택·하이퍼파라미터는 **학습/검증 안에서만** 정한다.
- **최종 평가구간에서 튜닝하지 않는다.**
- 과거 결정은 그 시점에 **가용했던** 정보만 본다.

### PIT 강제 — 세 속성을 분리해서 잰다

★"PIT 통과" 라는 단일 불리언을 만들지 않는다★ (감사 §4.4):

| 속성 | 검증 방법 | 지금 |
|---|---|---|
| `look_ahead_free` | `as_of` 를 과거로 밀면 출력이 **따라 움직이는가** | 국면 경로는 ✅ (`zscore_at` 후행 윈도우) · 스튜디오는 ❌ |
| `publication_lag_honored` | 계열별 공표지연이 **선언돼 있는가** | ❌ 미선언 |
| `revision_free` | 빈티지가 **존재하는가** | ❌ ECOS 미제공 — ★영구 불가★ |

`macro_models/` 어느 모듈도 `as_of` 를 받지 않으므로(감사 §4) **스튜디오의**
워크포워드는 아직 정직하게 돌릴 수 없다. 반면 **국면 경로는 이미 look-ahead-free
이므로** MS1 의 세 팔 평가는 빈티지 없이 성립한다.

★**단일 `pit_verified` 불리언을 만들지 않는다**★ — 셋은 서로 독립이고, 하나가
참이라고 나머지가 참이 되지 않는다. 합치는 순간 revision bias 가 그 안에 숨고,
"PIT 통과" 라는 표시가 거짓말이 된다. 응답·스냅샷·화면 어디서도 합치지 않는다.

★revision_free 를 영원히 못 만든다는 사실을 숨기지 않는다★ — ECOS 유래 산출물에는
`revision_bias: "unmanaged"` 를 영구 라벨로 붙인다. 소프트웨어가 해결할 수 없는
데이터 벤더의 한계는 사용자에게 **노출**하는 것이 정답이지, 통과 표시로 덮는 것이
아니다.

★이제 측정은 가능하다★ 직전 슬라이스에서 mock 을 날짜 주소화했으므로,
"창을 옮기면 값이 달라지는가" 를 테스트로 잡을 수 있다
(`tests/test_mock_is_date_addressable.py` · `tests/test_factor_stack_respects_as_of.py`
가 같은 성질을 이미 팩터 스택에 대해 건다 — 같은 패턴을 재사용한다).

## 3.5 ★불변식 — 성능이 아니라 항등식★

4단 평가(§2)와 벤치마크 사다리(§1)는 **모델이 좋은지**를 묻는다. 그 앞에
**구현이 옳은지**를 묻는 층이 하나 더 있어야 한다.

| # | 불변식 | 성격 |
|---|---|---|
| I1 | 모든 국면의 μ·Σ 가 같으면 혼합은 그것으로 **정확히** 환원 | 축퇴 |
| I2 | 흡수 국면(`P[r][r]=1`)에 `π₀=e_r` 이면 하드 라벨 결과와 일치 · **비흡수면 달라야 한다** | 극한 + 반례 |
| I3 | `P=I` → 완전지속 극한 · 무기억 `P` → 독립재추첨 극한 | 두 극한 |
| I4 | 일별·월별·연율 표현이 **올바른 스케일링 후** 같은 적률 | 단위 |
| I5 | `k_step_forecast` 산출물만 배분에 닿는다 — filtered/smoothed 는 **구조적 차단** | 계약 |
| I6 | `pit_verified` 류 단일 플래그 금지 — 3차원 유지 | 계약 |
| I7 | `residual_risk="unmeasured"` 를 **영행렬로 표현하지 않는다** | 의미론 |

★규칙 셋★
1. **허용오차는 기계 정밀도(`1e−15`)** 다 — 통계적 근사가 아니라 항등식이다.
2. ★"같아야 한다" 와 "달라야 한다" 를 **짝으로** 건다★ — 앞의 것만 있으면
   입력을 무시하는 구현이 전부 통과한다(예: `P` 를 안 쓰는 구현이 I2 의 흡수
   케이스는 통과하고 비흡수 케이스에서 죽는다).
3. **불변식이 red 면 데이터가 아니라 구현을 의심한다** — 4단 평가의 지표가 나쁜
   것은 모델의 사실일 수 있지만, 항등식이 깨진 것은 언제나 버그다.

I7 은 특히 **방향**을 잡는다: 재지 않은 불확실성을 0으로 표현하면 Ω 가 작아지고
신뢰도가 **올라간다** — 안 잰 것이 확신을 키우는 구조가 된다. 미측정은
`0` 이 아니라 **선언된 보수적 하한**으로 표현한다.

## 6. 승격 기준 (baseline → production)

모델이 production 으로 올라가려면 **전부** 충족해야 한다:

1. 사다리에서 **바로 아래 벤치마크를 OOS 로 이긴다**(점 또는 밀도).
2. 확률예측이면 **캘리브레이션을 통과**한다.
3. **PIT 로 재현 가능**하다 — `as_of` 를 받고, 과거 결정이 미래를 보지 않는다.
   ★단일 `pit_verified` 로 주장하지 않는다★ — `look_ahead_free` ·
   `publication_lag` · `revision_bias` **세 필드**를 각각 낸다.
4. **Level 4 에서 측정 가능**하다 — 포트폴리오 결정을 실제로 바꾼다.
5. 실패상태 계약을 따른다.
6. 계산비용이 요청시간 예산 안이거나 배경작업으로 분리돼 있다.
7. ★**신뢰도가 휴리스틱이 아니다**★ — 뷰가 최적화에 힘을 싣는 모델은 그 힘의
   근거(Ω)를 **계산**해야 하고, 스칼라 곱으로는 승격하지 않는다.
8. **실계열로 잰 결과다** — `real_share = 0` 인 동안 통과하는 것은 기제 검증이다.

★4번이 없으면 production 이 아니다★ 화면에만 그려지는 모델은 research-only 다.
현재 스튜디오 전부가 여기서 걸린다.

★7번을 통과하는 모델도 현재 0개다★ — 조건부 뷰의 신뢰도는 `50×(1−λ)` 스칼라이고,
Ω 를 분해해 계산하면 같은 상황에서 **40.00 대신 8.22** 가 나온다(약 5배 과확신).
그리고 그 스칼라는 표본이 15개월에서 60개월로 늘어도 **값이 변하지 않는다** —
계산된 Ω 는 4.84 → 11.53 으로 움직인다. 근거를 계산하지 않은 확신은 승격 사유가
될 수 없다.

## 7. 모델리스크 (스펙 §17)

- 불일치를 **숨기지 않는다** — `ensemble.disagreement` 가 이미 그렇게 한다.
- 높은 불일치는 **확신을 낮추는 데** 쓴다(포지션 축소), 숨기는 데 쓰지 않는다.
- 결합 가중치 자체도 **OOS 로** 정한다.
- 결합해도 **개별 판정을 남긴다**(`per_tool`) — 평균은 어떤 모델도 추천하지 않은
  답이고, 그것만 내면 산포를 재려던 목적이 사라진다.

★가중 결합이 필요해지면 `src/engine/forecast_combination.py` 를 쓴다★ —
비음수 최소분산 결합이 이미 있고 중첩 상관을 다룬다. 새로 만들지 않는다.
