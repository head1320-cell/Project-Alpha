## 무엇을 요구받았나

> "AAS 탭과 매크로분석 탭의 매크로 모델을 더 정교화하고 혁신적으로 진화"

## 착수 실측이 전제를 뒤집었다

처음엔 "60개 관측으로는 정교화가 불가능" 이 결론일 줄 알았다. 재 보니 아니었다.

| 측정 | 값 | 출처 |
|---|---|---|
| 능력 레벨 | **L1** (4단계 중 2위) | `capability.resolve()` |
| L0 차단 요인 | torch ✗ · cvxpylayers ✗ · trends_api ✗ · llm ✗ · **frontier_sample ✗** | `probe_all()` |
| `frontier_sample` 요건 | 관측 **240**, 현재 **60** | `capability.py` |
| 적재 깊이 기본값 | **15년** — 주석: "BOK/FRED는 수십 년 제공" | `macro_collector.py` |
| **60의 정체** | **mock 생성기 `length=60` 하드코딩** | `macro_collector.py:526` |

★**60개월 천장은 데이터의 한계가 아니라 mock 아티팩트였다.**★ 실 키가 들어오면
기본 15년 = 180개월이고, 20으로 올리면 240이라 `frontier_sample` 이 **데이터로**
통과한다. 사용자가 "배포 후 키 투입" 을 전제하라고 한 것이 정확히 이 문을 연다.

그리고 소스별 깊이가 심하게 비대칭이었다 — FRED 21계열 vs **ECOS 11계열**.
★한국 주식 퀀트 플랫폼인데 한국 매크로가 가장 얕았다.★

## 원칙

**모델을 키우지 말고, 데이터를 키우고 사다리가 스스로 오르게 한다.**

지금 torch 를 깔고 Neural SDE 를 올리면 M1 이 적어 둔 "그럴듯한 숫자를 만드는 기계"
가 된다. 반대로 관측이 240을 넘으면 `frontier_sample` 이 **정당하게** 열리고, 그때
프론티어 모델은 근거를 갖는다.

## 데이터 축

### D3 — 적재 깊이 240개월, 저장 상한을 깊이에서 유도

`MACRO_HISTORY_YEARS` 기본 15 → **20**. 기본값이 요건에 못 미치면 **설정을 따로
만져야만 열리는 천장**이고 그건 사실상 닫힌 천장이다.

10번째 초크포인트를 찾아 닫았다 — `MacroSeries(timestamps=timestamps[-72:])`.
주석의 사유("YoY 후에도 5년 z-표본 확보")는 **하한**의 근거인데 상한으로 쓰이고
있었다. `_store_cap()` 이 깊이에서 유도하되 `_MIN_STORE_MONTHS=72` 아래로 안 간다.

★깊이 확장이 원래 있던 이름-구현 불일치를 드러냈다★ `_normalize()` 가 `mean_5y`·
`std_5y` 라는 이름으로 **전 구간**을 계산하고 있었다. 저장이 72개월일 땐 "대략 5년"
이라 티가 안 났지만, 240이 되자 mock 랜덤워크의 z 가 커져 국면이 DEFENSIVE 로
뒤집히고 타이밍 노출이 0 이 됐다. 이름이 약속한 대로 `_Z_WINDOW_MONTHS=60` 으로 고정.

**mock 길이는 60으로 되돌렸다.** 얻는 것은 "mock 으로도 240 경로를 밟는다" 뿐이고,
잃는 것은 합성 국면 상태의 안정성이다. 깊이가 실제로 필요한 곳은 실 데이터 경로다.

### D4 — mock 으로 사다리를 못 올리게 (정직성 급소)

D3 이 위험을 하나 만든다: mock 관측이 240이 되면 `frontier_sample` 이 통과해
**가짜 데이터로 L0 이 열린다.** `_min_observations` 에 **출처 조건**을 더해, 관측이
240 이상이어도 실측 소스(BOK/FRED/KRX/DART/KIS) 비중이 임계 미만이면 열지 않는다.

**D4 는 D3 보다 먼저 착수했다** — 순서를 뒤집으면 그 사이에 합성으로 열린다.

### D1 — ECOS 11 → 40 계열 + 개정 편향을 **라벨이 아니라 게이트로**

금리·수익률곡선 · 통화·신용 · 물가 · 실물·경기 · 고용 · 대외·환율 · 심리·자산 축을
채워 40계열(직접 37 + 파생 3).

★외부 리뷰의 지적은 맞았지만 처방이 약했다★ 리뷰는 "개정 편향 경고를 프론트에
노출" 하라고 했는데 **라벨은 읽고 무시할 수 있다.** 이 저장소엔 더 강한 장치가 이미
있었다 — `pit_macro.derive_usage()` 가 `has_vintage` 를 필수로 요구하고
`assert_backtest_eligible()` 이 백테스트 진입을 **예외로 중단**한다. 새 판정 로직을
만들지 않고 거기에 태웠다:

```
PROVIDER_HAS_VINTAGE = { FRED: True, ECOS: False, KRX: False, NAVER/GOOGLE: False }
```

결과적으로 ECOS 는 호출자가 `lag_known=True` 를 넘겨도 **구조적으로 FORWARD_ONLY**
이고, 같은 화면의 FRED 는 BACKTEST_ELIGIBLE 이다. **두 소스의 적격성이 다르다는
것**이 이 설계의 요점이다.

빈티지는 **제공자 속성이지 계열 속성이 아니라서** 계열마다 적지 않는다 — 40개 중
하나만 잘못 적어도 그 계열이 조용히 백테스트 적격이 된다.

레지스트리를 조회 좌표의 **단일 출처**로 승격했다(`bok_targets`·`FRED_INDICATORS`
가 코드를 각자 들고 있었다). 소비자 0개면서 실제 목록과 다른 값을 들고 있던
`BOK_INDICATORS` 는 삭제.

★신규 32계열의 통계표/항목 코드는 라이브 검증이 불가능하다★ 이 환경은 ECOS 호스트가
프록시 403이다. 전부 `verified_live=False` 이고 `source_registry` 가 mock 폴백을
막으므로, 코드가 틀리면 조용히 비지 그럴듯한 숫자로 덮이지 않는다. 국고 5년·20년은
항목코드를 자신 있게 적을 수 없어 **넣지 않았다** — 코드를 지어내 계열 수를 채우는
것은 확장이 아니라 그럴듯한 빈칸을 만드는 일이다.

### D2 — KRX·KIS 집계 계열 + **주기 혼합 규칙**

★외부 리뷰 지적 3 — 초안에 주기 정렬 규칙이 없었다★ 실측: 수집기에 리샘플 정책이
아예 없었다(`"frequency": "m"` 은 FRED 서버측 집계뿐).

| 원 주기 | 성격 | 월간 변환 |
|---|---|---|
| 일간 (스톡/플로우) | 신용잔고·시장폭·수급 | 월중 **평균** + 월간 모멘텀을 **별도 계열**로 |
| 일간 (리스크) | 변동성·스프레드 | 월중 평균 + **월중 최대** (평균이 꼬리를 지운다) |
| 분기 | DART 재무 | ffill 하되 **`stale_months`** 를 값과 함께 |
| 월간 | ECOS·FRED | 그대로 |

★원칙은 ffill 금지가 아니라 "ffill 한 값을 그 달의 관측인 척하지 않는 것"★
공표월 `stale_months=0`, 이후 1·2…로 늘고 새 공표월에 초기화된다.

**MIDAS 는 도입하지 않는다** — 240관측에 MIDAS 는 또 하나의 과적합 기계다(A8 이
4상태 HMM 을 관측 48 / 모수 32 로 기각한 것과 같은 판단).

계열 6종을 **새 클라이언트 0개**로 선언: 시장폭 · 신고가 비율 · 횡단면 변동성 ·
회전율 · 외국인/기관 순매수. 이 환경에는 집계 원천(`daily_prices`·`investor_flows`)이
**둘 다 없어서**, 값이 아니라 사유를 낸다.

### D5 — 소스 커버리지 + "이 키를 넣으면 무엇이 열리는가"

D1~D4 의 재료를 **조인만** 한다. 계열 수는 레지스트리에서 세고, 요건 가부는
`capability` 가, 빈티지 적격성은 `PROVIDER_HAS_VINTAGE` 가 답한다.

★가장 값진 가드는 키 값이 새지 않는 것★ `_configured()` 가 환경변수를 읽는 즉시
`bool` 로 접어, 반환 타입상 값을 실을 수가 없다. 값 전체뿐 아니라 접두사·꼬리
4/6/8글자도 나가지 않는지 단언한다 — 마스킹은 안전해 보이지만 길이와 접두사를 흘린다.

**실측한 비용을 도크스트링에 적었다:**

| | |
|---|---|
| `key_slots()` | 0.00초 |
| `coverage_report()` 키 없음 | 1.1초 |
| `coverage_report()` 키 있으나 호스트 불통 | **51.6초** |

사다리의 `frontier_sample` 프로브가 관측 수를 실제로 세느라 매크로를 수집하고, 키가
있으면 라이브 호출을 시도하기 때문이다. **프로브를 캐시해 가리지 않았다** — M1-C 의
"의존성이 설치되면 즉시 사다리가 열려야 한다" 가 유효하므로, 대신 `include_ladder=False`
로 호출자가 고르게 했다.

## 모델 축

### M1 — 공적분 → VECM / 차분 VAR + 코어 변수 **K ≤ 7**

실측: 이 저장소에 `coint` 0곳 · `VECM` 0곳. 금리·물가·환율·주가는 레벨이 비정상이고
장기균형을 공유하는데, 레벨에 그레인저를 그대로 걸면 **허위회귀**다.

순서를 뒤집는다 — 요한센 trace 검정 → 랭크 ≥ 1 이면 VECM, 아니면 차분 VAR.
**어느 쪽을 왜 골랐는지 응답에 글로 적고** 검정통계량과 임계값도 함께 낸다.

★외부 리뷰 지적 2 — 자유도 붕괴를 계산 **전에** 막는다★
K=40·p=1 이면 1,600 모수 vs 240 관측이라 결과가 노이즈다. "돌긴 도는데 노이즈" 가
가장 위험하다 — 숫자가 나오면 사람은 믿는다. `MAX_CORE_VARS=7` 초과는 추정하지
않고 `CoreVariableError` 로 거부한다(K=7·p=2 → 98모수 vs 240관측).

상한 초과만 예외이고 나머지 실패는 `available:false` + 사유다. 상한 초과는 **데이터가
아니라 요청이 잘못된 것**이라, 사유로 답하면 화면이 "데이터가 부족하다" 로 오독한다.

★PCA/FAVAR 를 기각했다★ 리뷰가 대안으로 제시했지만 요인은 **해석을 잃는다**.
A8 이 정확 Shapley 로 "무엇이 국면을 움직였나" 를 지표 이름으로 답하게 만들어 놨고
"주성분 3번이 움직였다" 는 그 계약을 깬다. 게다가 `tsfm_latent` 스튜디오가 이미
요인 추출을 담당한다. **차원 축소가 아니라 변수 절제로 푼다.** 나머지 30+ 계열은
그레인저 스캔·국면 드라이버·스튜디오 입력으로 계속 쓰이고 이 추정기에만 안 들어간다.

★코어 셋은 통계가 아니라 경제로 지정한다★ 통계로 고르면 그 선택이 표본을 쓰고
이후 검정의 p값이 p값이 아니게 된다(사후선택 편향).

### M2 — 국면 예측의 **실측** 적중률

A8 의 `k_step_forecast` 는 이미 90% 신용구간을 내지만 **그게 실제로 90% 를 맞히는지는
아무도 재지 않았다.** `1-α` 를 그대로 적으면 이론값을 실측인 척하는 것이다.

국면은 범주라 구간이 아니라 **예측집합**이다 — 확률 높은 순으로 담아 `1-α` 를 덮는
최소 집합. ★최소성이 핵심★ 4개를 다 담으면 반드시 맞지만 아무 정보가 없어서,
적중률과 **평균 집합 크기**를 항상 함께 낸다.

★walk-forward 로만 평가한다★ 각 시점에서 그 이전 경로만으로 사후를 세운다. 전체
경로로 세운 행렬로 과거를 채점하면 미래를 쓰는 것이고 적중률이 부풀려진다.

라이브 값이 이 설계가 왜 필요한지를 그대로 보여 준다 — **실측 96.6% vs 목표 90%,
평균 집합 2.72/4.** 집합을 키워서 맞힌 것이고, 적중률만 냈으면 "잘 맞힌다" 로 읽혔다.

### M3 — 스튜디오 앙상블에서 **불일치가 일급**

합의도가 아니라 불일치를 낸다 — 모델이 갈릴 때가 가장 정보가 많은 순간이고 평균으로
뭉개면 사라진다(A8 이 세 국면 도구를 평균 내지 않은 것과 같은 원칙).

정규화 엔트로피를 쓴 이유는 최빈값 비율이 **몇 갈래로** 갈렸는지를 구분하지 못하기
때문이다 — 2갈래 균등과 4갈래 균등이 뭉뚱그려진다.

- **미가용 도구를 합의에 세지 않는다** — 5개 중 1개만 답했는데 "만장일치" 는 거짓이다.
  합의는 2개 이상이 전부 같을 때만이고, 미가용 도구는 사유와 함께 이름이 남는다.
- **동수는 결론이 아니다** — 2:2 에서 임의로 고르면 지어낸 결론이라 `verdict=None`.
- 결합해도 `per_tool` 에 개별 판정이 남는다 — 되짚을 수 없는 결론은 연구 결과가 아니다.

### M4 — 프론티어 자리는 비워 둔다

torch/cvxpylayers 는 이 환경에서 안 열린다. `Studio` 계약의 `frontier` 자리는 그대로
비워 두고, D4 의 게이트가 "무엇이 더 있어야 열리는지" 를 계속 답한다.
**이번 단계에서 torch 를 설치하거나 프론티어 모델을 구현하지 않았다.**

## 화면 (U)

`/macro` 칵핏 **아래**에 `MacroIntelPanel` 네 블록. `.mc-*` 는 한 글자도 건드리지
않는다(15개 스펙의 계약).

네 블록이 같은 규칙을 따른다:
1. 미가용이면 숫자를 하나도 내지 않고 **사유만** 낸다.
2. 결론 옆에 그 결론의 **전제**를 적는다(어느 모형·어느 도구·몇 개 관측).
3. 경고와 한계는 접지 않는다 — A5 가 그은 경계 그대로.

라우트 4종은 **판정하지 않는다** — 엔진의 답을 그대로 싣는다. 라우트가 다시 판정하면
