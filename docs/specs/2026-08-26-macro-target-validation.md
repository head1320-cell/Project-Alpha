# 매크로 예측 대상과 사전검증 프레임 — 설계 (Phase 8)

> ★대상을 **정의**하고 평가 프로토콜을 **동결**한다. 실계열을 돌리지 않는다.★
> 선행: Phase 7 분류(자산군이 없으면 자산군 스프레드를 정의할 수 없다).

---

## 0. 지금까지 무엇이 없었나

합성 연구는 **표현**과 **전달**을 다뤘다. 그 둘은 "매크로가 맞는가" 를 **한 번도
묻지 않았다** — 국면 경로를 내가 생성했기 때문이다.

그런데 배분 성과는 언제나 나온다. ★그래서 대상을 먼저 정의하지 않으면, 무엇을
맞혔는지 모른 채 Sharpe 를 보게 된다.★

## 1. 후보 대상과 판정

| | 대상 | 판정 | 이유 |
|---|---|---|---|
| A | 종목 절대 수익 | ★주지표로 쓰지 않는다★ | 국면은 **타이밍 신호**인데 종목 단면은 **단면 장치**다. 전달계층 감사가 이미 이 불일치를 회전율의 원인으로 지목했다 |
| **B** | ★**자산군 상대 수익**★ | ★**주지표**★ | 국면이 실제로 말하는 것. 그리고 롱온리·완전투자가 표현할 수 있는 형태 |
| C | 팩터 상대 수익 | 보조지표 | B 와 기하가 같다(디민). 팩터 모델이 있을 때만 |
| D | 리스크 예산·노출 제약 | ★예측 대상이 아니다★ | μ 를 만들지 않는다. 예측 스킬 축이 **정의되지 않는다** |
| E | 계층적 결합 | ★고르지 않는다★ | A~D 중 둘 이상이 각각 검증된 뒤의 문제 |

★그리고 종목 단면 IC 를 매크로의 주지표로 쓰지 않는다.★

## 2. 검증 체인

```
매크로 상태 / 국면 확률
        ↓  (예측)
전방 자산군 스프레드 (h개월)
        ↓  (실현)
실현 전방 스프레드
```

### 가설 예시 (★결과를 보기 전에 적는다★)

| # | 조건 | 예측 | 스프레드 |
|---|---|---|---|
| H1 | `P(Reflation)` 상위 3분위 | 양(+) | `EQUITY − DURATION` |
| H2 | `P(Stagflation)` 상위 3분위 | 음(−) | `EQUITY − DURATION` |
| H3 | 인플레 확률 상위 3분위 | 양(+) | `COMMODITY − DURATION` |
| H4 | `P(Disinflation)` 상위 3분위 | 양(+) | `DURATION − EQUITY` |
| H5 | 신용 스트레스 상위 3분위 | 음(−) | `CREDIT − RATES` |

지평 **1M · 3M · 6M · 12M** (데이터가 허용하는 범위).

## 3. 측정 항목 — ★두 종류를 섞지 않는다★

### 3.1 방향/크기 (스프레드 예측력)

| 지표 | 비고 |
|---|---|
| 조건부 평균 스프레드 | 국면별 |
| **평균차** + 신뢰구간 | 상위 3분위 − 하위 3분위 |
| 적중률 (부호) | 귀무 0.5 |
| rank IC | ★자산군이 4개 이상일 때만★ — 2개면 부호검정과 같다 |
| t 통계량 | ↓ HAC 필수 |
| ★**Newey–West / HAC**★ | **중첩 지평은 반드시** — 3M 스프레드를 월간으로 보면 관측이 3겹으로 겹쳐 t 가 √3 배 부풀려진다. `lag = h − 1` 최소 |

### 3.2 확률 캘리브레이션 (국면 확률 자체의 품질)

| 지표 | 무엇을 보나 |
|---|---|
| **Brier score** | 확률의 평균제곱오차. 기후 기준선(무조건 빈도) 대비 |
| **log score** | 꼬리 확률의 과신에 민감 |
| 신뢰도 곡선 | `P̂ ∈ [0.6,0.7)` 구간에서 실제 빈도가 0.65 인가 |
| 커버리지 | 예측구간이 있을 때만. 없으면 **`unavailable`** 로 적는다 |

★두 종류가 독립이다★ — 확률이 잘 캘리브레이션돼도 스프레드 예측력이 0 일 수 있고,
그 반대도 가능하다. 하나로 다른 하나를 대신하지 않는다.

## 4. ★프로토콜 동결★ (결과를 보기 전에 고정)

| 항목 | 값 |
|---|---|
| 가설 목록 | 위 H1~H5. 사후 추가 금지 |
| 지평 | 1M · 3M · 6M · 12M |
| 분위 기준 | 상위/하위 3분위 (**확장 윈도우**, 룩어헤드 금지) |
| 유의수준 | 5%. ★다중검정 보정★ — 가설 5 × 지평 4 = 20 → Benjamini–Hochberg |
| HAC lag | `max(h − 1, 1)` 개월 |
| 표본 분할 | 있는 그대로 전체. **재분할 금지** |
| 중단 규칙 | 없음. 20칸을 **전부 보고**한다 |

★"보고할 칸을 결과 보고 고른다" 가 이 프레임이 막으려는 것 전부다.★
20칸 중 1칸이 5%에서 유의한 것은 **귀무가설에서도 기대되는 일**이다.

### ★미이행 — 이 동결은 아직 코드에 없다★ (2026-09-15 실측, AJ)

위 표는 **결과를 보기 전에** BH 보정을 못 박았다. 그런데 실측해 보니:

| | 상태 |
|---|---|
| H1~H5 를 돌리는 하네스 | ★저장소에 없다★ |
| 보정할 p 값 20칸 | ★한 번도 생산된 적이 없다★ |
| Benjamini–Hochberg 산수 | AJ1 에서 생겼다(`src/domain/multiplicity.py::bh_reject`) — ★다만 이 검증에 배선되지 않았다★ |

★지키지 않은 사전등록은 등록이 아니라 등록했다는 주장이다.★ 그리고 그것은 단순
부재보다 나쁘다 — 읽는 사람은 이 표를 보고 *"보정이 계획돼 있다"* 가 아니라
*"보정이 되어 있다"* 로 읽는다. 채점표(`2026-09-12-addendum-scorecard.md` §4)는
이 항목을 *"Bonferroni/FDR 없음"* 이라고만 적고 ★등록해 놓고 안 지켰다는 사실은
적지 않았다★ — 그 문장도 AJ 에서 함께 고쳤다.

이 미이행은 이제 **기계가 읽는 자리**에 등록되어 있다:
`src/engine/multiplicity_evidence.py::UNIMPLEMENTED_PREREGISTRATIONS`.
트립와이어(`tests/test_multiplicity_evidence.py`)가 ⑴ 이 표가 비지 않았는지
⑵ 각 항목이 실재하는 문서와 사유를 갖는지 ⑶ 보정을 사전등록한 문서가 레지스트리
밖에 있지 않은지를 지킨다. ★구현이 생기면 그 표에서 빼야 하고, 그때 이 절도 함께
고친다.★

**왜 지금 구현하지 않나** — H1~H5 를 실제로 돌리려면 자산군 스프레드 계열과 국면
확률 패널이 필요하고, 그것이 Phase 8 본체다. ★없는 검증에 보정을 붙이는 것은
보정이 아니라 장식이다.★

## 5. ★사전 등록 — 무엇이 성공인가★

성공 조건도 미리 적는다. 그렇지 않으면 어떤 결과든 성공으로 읽힌다.

| 판정 | 조건 |
|---|---|
| ★**스킬 있음**★ | H1~H5 중 **2개 이상**이 BH 보정 후 유의 **그리고** 부호가 사전 예측과 일치 **그리고** 3M 이상 지평에서 |
| **불충분** | 유의 1개 이하, 또는 부호 불일치 |
| ★**스킬 없음**★ | 전부 비유의 — ★그것도 결과다. 그렇게 적는다★ |

★"불충분" 과 "스킬 없음" 을 구분하는 이유★ 전자는 표본 문제이고 후자는 신호 문제다.
전자면 데이터를 늘려 다시 묻고, 후자면 **매크로 계층을 접는다**.
