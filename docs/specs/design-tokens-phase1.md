# Phase 1 — 브랜드 기반 디자인 토큰 (제안, 승인 대기)

> **상태: 제안. 코드 변경 없음.** 승인 전까지 `globals.css` 는 손대지 않는다.
> 요청의 명시 조건 — "레이아웃 코드는 아직 쓰지 말 것, 디자인 시스템만 확정하고 대기".
>
> 결정 두 가지가 이미 답변으로 확정됐다:
> 1. **색** — 현행 `#1200ff` 를 브랜드 프라이머리로 확정하고 그 위에 체계를 세운다.
> 2. **타이포** — **스케일 정의만.** 1,204개 CSS 선언 + 439개 인라인 `fontSize` 의
>    교체는 별도 단계로 분리한다.

---

## 0. 전제 — 이것은 신규 도입이 아니라 **정리**다

`globals.css` 6,385줄에 `:root` 8블록 · `.dark` 4블록이 이미 있다. 색은 백지가 아니라
**Zinc 계단 + 단일 강청색**으로 이미 서 있고, 값마다 대비 실측치가 주석에 붙어 있다.

그래서 이 문서는 새 팔레트를 만들지 않는다. **이미 있는 값에 이름과 역할을 주고,
없는 층(액센트 램프·타입 스케일)을 채우고, 측정으로 드러난 결함 3건을 고친다.**

### ADR 001 이 강제하는 형태

- 앞선 `:root` 4블록(L51·618·663·696)은 **바이트 불변**.
- §34 는 shadcn 이름을 `--t-*` 에 **참조로** 연결한다(`--primary: var(--t-accent)`) —
  값 복제 금지. 새 `:root` 팔레트를 세우면 그것이 바로 ADR 이 금지한 두 번째 진실이다.
- 따라서 **신규 토큰은 EOF 에 §59 로 추가**하고, 기존 `--t-*` 를 재정의하지 않는다.

## 1. 측정 — 계획 전에 잰 것

### 1.1 현행 코어 팔레트 (그대로 유지, 이름만 확정)

| 역할 | 라이트 | 다크 | 근거 |
|---|---|---|---|
| Primary / Accent | `#1200ff` `rgb(18 0 255)` | `#7c74ff` `rgb(124 116 255)` | 흰 배경 **8.50:1** · zinc-950 위 **5.49:1** |
| Background | `#ffffff` | `#09090b` (zinc-950) | |
| Surface | `#fafafa` (zinc-50) | `#18181b` (zinc-900) | |
| Border | `#e5e5e5` | `#27272a` (zinc-800) | |
| Ink (본문) | `#111111` | `#fafafa` | |
| Muted (보조) | `#71717a` (zinc-500) | `#a1a1aa` (zinc-400) | 흰 배경 4.83:1 |
| Up / 상승 | `#15803d` | `#4ade80` | `#16a34a` 가 3.16:1 로 측정돼 green-700 으로 내린 이력 |
| Down / 하락 | `#dc2626` | `#f87171` | 흰 배경 4.69:1 |

이 표의 라이트 값은 **한 글자도 바꾸지 않는다.** 브랜드 확정이란 여기서 값을 고르는
일이 아니라, 이 값들이 브랜드라고 문서에 못 박는 일이다.

### 1.2 결함 3건 (측정으로 드러남, Phase 1 에서 닫는다)

**D1 — 액센트에 램프가 없어서 113곳이 각자 만들었다.**

`--t-accent` 는 단일 값 하나뿐이다. 틴트 단계가 없으니 컴포넌트들이 직접 알파를 적었다:

```
rgba(18,0,255,·)  라이트 리터럴  113곳,  알파 13종 (.03 .04 .05 .06 .08 .12 .18 .22 .3 …)
rgba(124,116,255,·) 다크 짝        8곳
```

즉 **113곳 중 105곳은 다크에서 따라오지 않는다.** `.aas-goal` 의 `#fff` 와 같은 결함
계열이고, 표기도 `.04` / `0.04` 두 가지로 갈려 있다.

**D2 — "오류" 를 뜻하는 빨강이 라이트에 두 개다.**

| 토큰 | 값 | 흰 배경 대비 |
|---|---|---|
| `--bs-danger` → `--danger` → `--destructive` | `#dc3545` | 4.53:1 |
| `--color-bear` · `--chart-down` | `#dc2626` | 4.69:1 |

§34 의 `--destructive: var(--danger, #dc2626)` 는 폴백에 `#dc2626` 을 적어 두어 그 값을
의도한 것처럼 읽히지만, `--danger` 가 실제로 정의돼 있으므로 **폴백은 결코 발동하지
않고 `#dc3545` 가 나간다.** 둘 다 AA 는 통과하므로 화면이 깨지지 않고, 그래서 지금까지
아무도 몰랐다.

**D3 — `--color-caution` 은 본문 글자색으로 AA 미달이다.**

`#d97706` (amber-600) 흰 배경 **3.18:1**, `--muted`(`#fafafa`) 위에서는 그보다 더 낮다.
`color:` 로 쓰이는 규칙 5건: `.as-ctx-mode[data-mode="CAUTIOUS"]` · `.as-exec-dbwarn` ·
`.as-attr-warn` · `.as-rr-focus-missing` · `.as-bt-badge.mock`.

`contrastAudit()` 가 잡지 못한 이유는 감사 시점에 **그 상태들이 렌더되지 않기 때문**이다
(경고·mock·누락 상태는 특정 조건에서만 나온다). 규칙은 존재하고 조건이 오면 화면에
나온다 — 즉 잠재 결함이지 무해한 것이 아니다.

### 1.3 타이포 현황

## 2. 제안 — 색

### 2.1 액센트 램프 (D1 을 닫는다)

113개 리터럴이 실제로 쓰던 알파를 도수분포로 묶으면 세 단계로 수렴한다
(.03–.06 = 바탕 틴트 / .08–.12 = 선택 상태 / .18–.30 = 경계·강조).

```css
/* §59 — 브랜드 액센트 램프. 값이 아니라 역할로 부른다. */
:root {
  --brand:            #1200ff;              /* rgb(18 0 255)   — 8.50:1 on #fff */
  --brand-hover:      #0e00cc;              /* rgb(14 0 204)   — 기존 --bs-primary-hover */
  --brand-ink:        #07005c;              /* rgb(7 0 92)     — 18.0:1, 틴트 위 글자 */
  --brand-on:         #ffffff;              /* --brand 위 글자 */

  --brand-tint:       rgb(18 0 255 / .05);  /* 바탕 틴트 — hover row, subtle fill */
  --brand-tint-on:    rgb(18 0 255 / .10);  /* 선택·활성 상태 */
  --brand-edge:       rgb(18 0 255 / .22);  /* 경계·강조 링 */
}
.dark {
  --brand:            #7c74ff;              /* rgb(124 116 255) — 5.49:1 on #09090b */
  --brand-hover:      #9a94ff;
  --brand-ink:        #c7c3ff;
  --brand-on:         #09090b;              /* 밝은 라벤더 위 흰 글씨는 3.62:1 — 검정을 쓴다 */

  --brand-tint:       rgb(124 116 255 / .14);
  --brand-tint-on:    rgb(124 116 255 / .22);
  --brand-edge:       rgb(124 116 255 / .38);
}
```

`--t-accent` 는 **그대로 둔다** — 342곳이 참조 중이고, ADR 의 참조 연결을 깨지 않는다.
램프는 그 위에 얹히는 층이다. 113개 리터럴의 교체는 타이포와 같은 이유로 **별도 단계**.

### 2.2 Secondary — 지금 없는 역할

`--secondary` 는 `--t-surface`(회색)에 매핑돼 있어, "보조 버튼"과 "카드 배경"이 같은
토큰이다. 소비자는 8곳뿐이니 지금이 분리할 시점이다.

```css
:root {
  --secondary-fill:   #f4f4f5;   /* zinc-100 — surface(#fafafa)보다 한 단 진하게 */
  --secondary-ink:    #3f3f46;   /* zinc-700 — 10.3:1 on zinc-100 */
  --secondary-edge:   #d4d4d8;   /* zinc-300 */
}
.dark {
  --secondary-fill:   #27272a;   /* zinc-800 */
  --secondary-ink:    #e4e4e7;   /* zinc-200 */
  --secondary-edge:   #3f3f46;   /* zinc-700 */
}
```

### 2.3 상태색 — 빨강 하나, 호박 두 층 (D2·D3 을 닫는다)

```css
:root {
  --danger-fg:    #dc2626;   /* 4.69:1 — 글자·아이콘. #dc3545 를 폐기하고 이쪽으로 통일 */
  --danger-fill:  rgb(220 38 38 / .10);
  --danger-edge:  #fca5a5;

  /* ★두 층으로 나누는 이유★ amber-600 #d97706 은 흰 배경 3.18:1 로 본문 글자 AA 미달.
     칠(3:1)과 글자(4.5:1)의 기준이 다르므로 토큰을 나눈다 — --chart-up 이 3.16:1 때문에
     green-700 으로 내려간 것과 같은 판단이다. */
  --warn-fg:      #a16207;   /* amber-700 — 5.24:1, 글자 전용 */
  --warn-mark:    #d97706;   /* amber-600 — 3.18:1, 아이콘·경계·칠 전용. 글자 금지 */
  --warn-fill:    rgb(217 119 6 / .12);

  --ok-fg:        #15803d;   /* 4.85:1 — 이미 --chart-up 이 쓰는 값 */
  --ok-fill:      rgb(21 128 61 / .10);
}
.dark {
  --danger-fg:    #f87171;  --danger-fill: rgb(248 113 113 / .16);  --danger-edge: #b91c1c;
  --warn-fg:      #fcd34d;  --warn-mark:   #fbbf24;  --warn-fill: rgb(251 191 36 / .16);
  --ok-fg:        #4ade80;  --ok-fill:     rgb(74 222 128 / .16);
}
```

**의미색 규칙(불변)** — 초록은 이 제품에서 **상승/이익**을 뜻한다. 브랜드 강조색으로
초록 계열을 도입하지 않는다. 데이터 의미와 브랜드 표현이 같은 색을 쓰면 화면이 거짓말을
한다. (템플릿 예시의 "형광 그린 포인트"를 채택하지 않는 이유이기도 하다 — `#39FF14` 는
흰 배경에서 **1.4:1** 로 강조색으로 쓸 수 없다.)

**색만으로 의미 전달 금지** — 기존 규칙 유지. 상태색에는 항상 글자나 아이콘이 동반한다.

## 3. 제안 — 타이포그래피 (스케일 정의만)

### 3.1 폰트 역할 — 현행 유지, 이유를 문서화

| 역할 | 서체 | 근거 |
|---|---|---|
| Heading | **IBM Plex Sans KR** 600/700 + 음수 트래킹 | 별도 디스플레이 서체를 두지 않는다 |
| Body | **IBM Plex Sans KR** 400/500 | |
| Numeric | **JetBrains Mono** + `tabular-nums` | `.num` 관례, 427곳 참조 |

**Inter 를 쓰지 않는 이유** — 요청서가 예로 든 Inter 는 **한글 글리프가 없다.**
이 앱은 `<html lang="ko">` 이고 화면의 대부분이 한국어라, Inter 로 바꾸면 라틴만 Inter,
한글은 시스템 폴백으로 갈라져 두 서체의 메트릭이 한 줄 안에서 섞인다. IBM Plex Sans KR
은 이미 로드돼 있고 한글·라틴을 한 가족으로 덮는다 — 바꿀 이유가 없다.

**Heading 을 별도 서체로 두지 않는 이유** — 한글 디스플레이 서체 중 Plex 와 메트릭이
맞는 것이 드물고, 서체 하나를 더 받으면 이미 렌더 블로킹인 폰트 요청이 늘어난다.
권위는 **굵기 + 트래킹 + 크기 대비**로 낸다. 저장소에 이미 그 관례가 있다:
대형 헤딩 `-0.02em` ~ `-0.03em`, 대문자 모노 크롬 라벨 `+.03em` ~ `+.08em`.

### 3.2 타입 스케일

측정된 최빈값(11 · 12 · 13 · 14px)을 앵커로 삼는다. 스케일을 실사용에서 도출하면
마이그레이션 대부분이 **재디자인이 아니라 개명**으로 끝난다.

```css
:root {
  /* ── 스케일 ── 아래 두 단이 §56 하한이다 */
  --fs-chrome:  11px;   /* 크롬 라벨 하한 · 모노 · 대문자. 현행 354곳 */
  --fs-sm:      12px;   /* 산문 하한. 현행 174곳 */
  --fs-base:    13px;   /* 기본 본문. 현행 74곳 */
  --fs-md:      14px;   /* --bs-body-font-size 와 동일 */
  --fs-lg:      16px;
  --fs-h3:      18px;
  --fs-h2:      22px;
  --fs-h1:      28px;
  --fs-display: 36px;

  /* ── 행간 ── */
  --lh-tight:   1.25;   /* 수치·표·크롬 */
  --lh-normal:  1.5;    /* 산문 (현행 --bs-body-line-height 1.3125 는 한국어 본문에 좁다) */
  --lh-relaxed: 1.7;    /* 긴 설명문 */

  /* ── 굵기 ── */
  --fw-regular: 400;  --fw-medium: 500;  --fw-semibold: 600;  --fw-bold: 700;

  /* ── 트래킹 ── 저장소의 기존 관례를 토큰화한 것 */
  --tr-heading: -0.02em;   /* --fs-h2 이상 */
  --tr-normal:  0;
  --tr-label:   0.05em;    /* 대문자 모노 크롬 라벨 */
}
```

**11px 아래가 없는 것은 의도다.** 현재 8–10.5px 선언 424개는 전부 `--fs-chrome` 로
올라간다. 이것이 이 단계에서 가장 큰 시각 변화이고, **그래서 마이그레이션을 분리했다.**

### 3.3 폰트 로딩 결함 2건 (기록만, 이번 범위 밖)

답변대로 **스케일 정의만** 하므로 아래는 고치지 않고 남긴다:

- `tailwind.config.js` 의 `font-sans: ["Geist", …]` — **Geist 는 로드된 적이 없고
  `font-sans` 사용도 0회.** 죽은 설정이 존재하지 않는 서체를 가리키고 있다.
- `globals.css:1` 의 Google CDN `@import` — 렌더 블로킹. `next/font` 로 옮기면 self-host
  + `font-display` 제어가 되지만, 폰트 로딩 방식이 바뀌므로 전체 시각 회귀 검증이 필요하다.

## 4. 산출 형태

**CSS 변수(`:root` + `.dark`)를 정본으로 한다.** Tailwind config 를 정본으로 두면
값이 두 곳에 생기고, 그것이 §34 가 이미 피한 실수다. Tailwind 쪽은 참조만 한다:

```js
// tailwind.config.js — 값 복제 없음, var() 참조만
theme: { extend: {
  colors: {
    brand: "var(--brand)",
    "brand-tint": "var(--brand-tint)",
    // …
  },
  fontSize: {
    chrome: ["var(--fs-chrome)", { lineHeight: "var(--lh-tight)" }],
    sm:     ["var(--fs-sm)",     { lineHeight: "var(--lh-normal)" }],
    // …
  },
}}
```

## 6. 검증 (구현 단계에서 돌 것, 지금은 아님)

- `contrastAudit()` 라이트·다크 — 새 토큰이 닿는 모든 표면. AA 미달 0.
  **D3 의 5개 상태는 렌더되지 않아 감사가 못 봤으므로, 그 상태를 강제로 렌더하는
  스펙을 함께 쓴다** — 안 그러면 고쳤다는 사실을 아무도 증명하지 못한다.
- 앞선 `:root` 4블록 바이트 불변 확인.
