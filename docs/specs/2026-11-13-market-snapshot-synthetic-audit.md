## 4. 왜 문제인가 (이 저장소의 규율로)

1. **mock 게이트 밖의 합성값** — "`mock_allowed()` 가 유일한 판정 기준 · 운영에서는 합성값을 만들지 않는다 — 실패하면 `None`/빈값 + 사유 · 새 스토어는 반드시 이 게이트를 통과"(§6).
2. **가짜 이름** — "`\"Unknown Corp\"`·가짜 종목코드 재도입 금지"(§4). 코드는 진짜인데 이름("… Corp")과 업종이 가짜다.
3. **침묵 폴백** — 야후를 켠 운영에서 받기에 실패하면 같은 합성 스냅샷으로 바뀐다. 응답에서는 구별할 수 없다(§4 네 조건 가운데 라벨·위장 불가 미충족).
4. 영향은 **좁다**(화면 0 · 레거시 API 넷). 그래서 급하지는 않지만, API 로 이 값을 받는 쪽이 있으면 실데이터로 읽을 것이다.

### 7.5 하지 않은 것 · 미검증 · 미상

- **레거시 경로를 걷어 내지 않았다**(§5 '다') — 표 둘 · 라우트 넷 · 프론트의 쓰이지 않는 API 함수 셋은 그대로다. 운영에서 비어 있는 채로 5분마다 도는 루프(`lifecycle.py` — 0줄)도 그대로다.
- **야후를 켠 운영 경로의 값 품질은 미검증**이고, 코드 읽기로 본 것(관측)을 적어 둔다 — 고치지 않았다: 없는 값을 지어 채우는 자리가 있다
  (`sector` 없으면 `"Unknown"` · RSI 못 내면 `50` · 12개월·3개월 수익률 봉이 모자라면 `0` · 배당수익률 없으면 `0` · `macd` 는 늘 `0`(자리 채움) · `currency` 없으면 `"USD"`). "미상 ≠ 0"(CLAUDE.md §4)에 어긋난다. 이 경로는 기본으로 꺼져 있다.
- **mock 합성 행의 이름·업종은 그대로다**(`"000660.KS Corp"` · 난수 업종) — 응답에 합성 표시가 붙지만 표의 행 자체에는 출처 칸이 없다(스키마 불변).
- 실패했을 때 직전 실데이터 스냅샷을 남기는 것(낡음 표시와 함께)은 하지 않았다.
- 출처 기록은 프로세스 로컬이다 — `uvicorn --workers 1`(CLAUDE.md §6) 전제. 여러 프로세스가 같은 DB 를 쓰는 배치는 보지 않았다.
- 운영 DB(PostgreSQL)에서의 실행 · 운영 호출 기록은 보지 않았다(**미상**). 로컬은 sqlite 다.
