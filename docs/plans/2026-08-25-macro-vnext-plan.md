## 0. 감사가 계획을 어떻게 바꿨는가

계획을 세우기 전에 세운 가설 두 개가 **측정에서 무너졌고**, 그 결과 슬라이스가 바뀌었다.

| 처음 생각 | 측정 결과 | 계획에 미친 영향 |
|---|---|---|
| "예측 국면확률을 **만들어야** 한다" | `k_step_forecast` 가 사후예측 4000회 + 90% 신용구간으로 **이미 낸다** | 만들 것이 없다 → **연결**이 일이다 |
| "OOS 프레임워크가 아예 없다" | 국면 경로에는 **워크포워드 적중률이 이미 있다**(`regime_forecast`) | 발명이 아니라 **확장** |
| "프론티어는 torch 만 깔면 된다" | `frontier_sample: observed 60 / required 240` | torch 로 안 풀린다 → **보류** |
| "mock 이라도 결정가치는 잰다" | `real_series 0 / total 61` | 잴 수 있는 것은 **기제**뿐 → 승격 기준에 실계열 조건 |

★그래서 vNext 의 1순위는 새 모델이 아니다.★ 이미 있고, 이미 불확실성을 달고,
이미 워크포워드로 채점된 예측이 **포트폴리오에 닿지 않는 것**이 1순위 결함이다.

구현 전 MS1 심층 설계를 돌렸더니 **이번엔 내 MS1 명세 자체가 두 군데 틀렸다.**

## 1. ★최소 수직 슬라이스★ — MS1

> **"이미 측정된 예측 국면분포로 조건부 μ/Σ 를 혼합한다. 오늘 라벨을 확률 1 로
> 취급하는 것을 그만둔다."**

> ★심층 설계 패스(2026-08-25 2차)에서 이 절은 **전면 재작성**됐다.★ 1차 명세가 두
> 군데 틀렸고 둘 다 측정으로 드러났다 — 혼합 공식이 **차원적으로 미정의**였고(§1.3),
> "지금 국면 확률" 이 저장소에 **이미 셋 있다**(§1.4)는 것을 놓쳤다.

### 1.1 지금 무슨 일이 벌어지는가 — 현행 수학의 정확한 전개

결함이 아니라 **소비 방식의 결함**이다.

### 1.3 ★계약 1 · 지평 의미 — 한 변수에 여러 뜻을 싣지 않는다★

> ★이 절은 두 번 재작성됐다.★ 1차 명세 `Σ̄ = Σπ(Σ+μμᵀ) − μ̄μ̄ᵀ` 는 **차원적으로
> 미정의**였고(연율/일별에 따라 252배), 2차 명세 `Σ̄ = W + (h/12)D` 는 **완전지속
> 상한**이었다. 아래가 정확식이다.

#### 1.3.1 네 개의 이름 — `h` 는 폐기한다

| 이름 | 뜻 | 단위 | 출처 | 성격 |
|---|---|---|---|---|
| **`h_hold`** | **홀딩 기간** — 다음 리밸런싱까지 | 개월 | 리밸런싱 주기(월간 1 · 분기 3) | ★유일한 지평 **입력**★ |
| **`j`** | 예측 **단계** — `1 … h_hold` 의 각 중간 시점 | 개월 | `k_step_forecast(k=j)` | 내부 반복 변수 |
| **`Δ`** | **샘플링 간격** — 수익률 데이터 주기 | 일(252/년) | `returns_df` 의 성질 | ★지평이 아니다★ |
| **`d_r`** | **국면 기대 지속기간** | 개월 | `expected_duration_months`(실측 2.5~5.0) | ★출력이지 입력이 아니다★ |

- `h_hold` 는 **예측 지평이 아니다.** 예측 지평은 `j` 이고, 홀딩 기간 동안 **모든**
  `j` 가 관여한다. 종단 분포 `π_{h_hold}` 하나만 쓰면 틀린다(§1.3.3 의 9.2%p).
- `d_r` 을 `h_hold` 로 쓰지 않는다. "국면이 평균 3.8개월 지속한다" 는 **홀딩 기간을
  3.8개월로 잡으라는 뜻이 아니다** — 지속성은 이미 전이행렬 `P` 안에 들어 있다.
- `Δ` 는 연율화 계수(252)로만 등장하고 **국면 산술에 절대 들어가지 않는다.**
  (일별로 혼합해 ×252 하면 국면 간 항이 사라진다 — D/W ≈ 0.002.)

#### 1.3.2 정확식 — 주변분포가 아니라 결합분포다

```
r_[t, t+h] = Σ_{j=1..h} r_{t+j},        r_{t+j} | S_{t+j}=s  ~  (μ_s,m , Σ_s,m)
                                        h ≡ h_hold,  m = 월간 단위

μ̄_h = Σ_{j=1..h} Σ_s π_j(s) · μ_s,m                    ★π_h 가 아니라 π_1..π_h 전부★
W_h = Σ_{j=1..h} Σ_s π_j(s) · Σ_s,m                    국면 **내** (시간가변 가중)
A_h = Σ_{j,k=1..h} Cov( μ_{S_j}, μ_{S_k} )             국면 **간** 누적

  Cov(μ_{S_j}, μ_{S_k}) = Σ_{s,s'} π_j(s)·[P^{k−j}]_{s,s'}·μ_s μ_{s'}ᵀ − E_j E_kᵀ    (k ≥ j)
  E_j = Σ_s π_j(s) μ_s,m                                (k < j 는 대칭)

★Σ̄_h = W_h + A_h★
```

**시뮬레이션 검증** (2자산·2국면·`h=3`·`P=[[.85,.15],[.25,.75]]`·20만 경로):

| | 값 |
|---|---|
| 시뮬레이션 | `[[0.011051, −0.000512], [−0.000512, 0.003608]]` |
| ★**정확식 `W_h + A_h`**★ | `[[0.011038, −0.000499], [−0.000499, 0.003601]]` ✅ |
| `h·W + h²·D` — 완전지속 **상한** | `[[0.011523, −0.000697], [−0.000697, 0.003678]]` |
| `h·(W + D)` — 무지속 **하한** | `[[0.010761, −0.000432], [−0.000432, 0.003586]]` |

국면 간 항만 떼어 보면:

```
정확 A_h 대각   [0.000767, 0.000093]
h²·D 대각       [0.001143, 0.000138]   → ★1.489배 과대추정★
h·D  대각       [0.000381, 0.000046]   → 2.01배 과소추정
```

★정확값은 두 극한 **사이 어디든** 될 수 있고, 어디인지는 전이행렬이 정한다★ —
그래서 스칼라 계수(`h/12`)로 근사하면 안 된다. 2차 명세는 **상한을 답으로 착각**한 것이다.

**두 극한이 sanity check 이 된다** (테스트 T4·T5):
- `P = I`(완전지속) → `A_h = h²·D`
- `P` 의 모든 행이 동일(무지속) → `A_h = h·D`

#### 1.3.3 `π_h` 만 쓰면 안 되는 이유 — 실데이터

```
π_1 Goldilocks 0.7994 · π_2 0.6782 · π_3 0.6007 · π_6 0.4882
π̄(h=3) = (0.7994+0.6782+0.6007)/3 = 0.6928

★π_3 만 쓰면 Goldilocks 를 9.2%p 과소평가한다★
P 대각(지속성) = [0.800, 0.688, 0.737, 0.600]
```

홀딩 기간 [t, t+3] 동안의 수익은 t+3 의 국면이 아니라 **그 기간 전체의 국면 경로**가
만든다. 종단 분포는 그 경로의 마지막 한 점일 뿐이다.

#### 1.3.4 구현 규약

- 혼합은 **월간 단위**로 계산하고 마지막에 연율화한다(`×12`). ★`Δ`(일별)를 국면
  산술에 들이지 않는다★ — `conditional_moments` 가 주는 연율 μ̂·Σ̂ 를 `/12` 해서 쓴다.
- `π_j` 는 `k_step_forecast(rows, current, k=j)` 를 `j=1..h_hold` 로 호출해 얻는다.
  `P` 는 `transition_posterior` 의 행별 사후평균(`rows[i]["mean"]`).
- 응답에 `h_hold` · `pi_path`(π_1..π_h) · `pi_bar` · `A_contribution_pct = tr(A_h)/tr(Σ̄_h)`
  를 싣는다.
- ★`Σ̄_h` 의 최소고유값이 음수면 클립하지 말고 `available: false` 로 보고★
  (CLAUDE.md 수치 안전 규약).
- **계산비용은 무시할 수 있다** — R=4, `h_hold ≤ 12` 이므로 `P^m` 최대 12회,
  이중합 최대 144항.

### 1.4 ★"지금 국면 확률" 이 이미 셋 있고, 포트폴리오는 넷째를 쓴다★

1차 명세는 π 를 `k_step_forecast` 에서만 가져온다고 적었다. **불완전했다** — 같은
4국면 분류체계 위에 확률 객체가 **이미 셋** 있고, 오늘 실측값이 전부 다르다:

| # | 이름 | 코드 | 오늘 Goldilocks | 성격 |
|---|---|---|---|---|
| 1 | 축 확률 | `regime_axes.quadrant_probs(g, i, se_g, se_i)` ← `regime_ensemble._axis_probs` | **0.535** | 오늘 축 z 와 **그 표준오차**로 만든 사분면 확률 — 사실상 filtered |
| 2 | Markov filtered | `regime_ensemble._markov_probs` | **0.964** (2국면 정확히 0.0) | 성장축 2상태 filtered × 물가 하드 부호 |
| 3 | k단계 예측 | `regime_transitions.k_step_forecast` | **0.601** [0.409, 0.788] | 사분면 경로 Dirichlet 사후예측 |
| 4 | **하드 라벨 ← 포트폴리오가 쓰는 것** | `regime_path(...)["points"][-1]["regime"]` | **1.000** | 결정적 사분면. 불확실성 0 |

★한 문장: 저장소는 "지금 Goldilocks 일 확률" 에 0.535 · 0.964 · 0.601 세 답을 갖고
있는데, 최적화기에는 **1.000** 을 보낸다.★

### 1.5 ★계약 2 · 확률 의미 — 셋을 분리하고, 하나만 배분에 닿는다★

★**확정된 설계 결정**: 포트폴리오를 움직이는 확률은 **k단계 예측 하나**다.★
라이브와 백테스트가 **같은 추정량**을 써야 두 모드의 수치가 직접 비교된다.

| 이름 | 정의 | 코드 | 배분 | 백테스트 |
|---|---|---|---|---|
| **filtered current** | t 까지의 정보로 본 **현재** 국면 분포 | `regime_axes.quadrant_probs(g,i,se_g,se_i)` (0.535) · `regime_ensemble._markov_probs` (0.964) | ❌ **금지** | 진단용만 |
| **k-step forecast** | t 까지의 정보로 본 **t+j** 국면 분포 | `regime_transitions.k_step_forecast(rows, current, k=j)` | ✅ ★**유일한 허용 경로**★ | ✅ |

#### 1.5.1 공통 계약 필드

```
{ source, step_months, probs, ci90?, coverage?, sharpness, mode, usage }

  source ∈ {"filtered_axis", "filtered_markov", "k_step_forecast"}
  usage  ∈ {"portfolio", "diagnostic_only", "forbidden_in_backtest"}
```

★배분 경로는 `usage == "portfolio"` 인 객체만 받는다★ — **이름이 아니라 값으로**
거른다. 이름 규약(`"forecast" 가 들어가면 OK`)은 리팩터 한 번에 깨지고, 깨진 것이
조용하다. 값 검사는 테스트로 고정할 수 있다(T12).

`smoothed` 는 `t == T−1` 에서만 filtered 와 같으므로, **마지막 시점 단건 조회에도
`source: "filtered_markov"` 로 이름 붙인다** — `"smoothed"` 라는 문자열이 배분 근처에
나타나지 않게 한다(T13). 이름이 곧 경고다.

#### 1.5.2 날카로움과 신뢰도

`sharpness = 1 − H(π)/ln R` — 실측 π(k=3) 에서 **0.206**(퍼플렉서티 3.007),
하드 라벨은 **1.0**. 예측집합 크기 3.81/4 와 같은 사실을 다른 축으로 잰 값이다.

★단, sharpness 를 신뢰도 공식에 곱하지 않는다★ — 이유는 §1.5.3.
sharpness 는 **보고 지표**이고, 신뢰도는 Ω 를 분해해 **계산**한다.

`coverage` 는 `regime_forecast.forecast_coverage` 의 **실측**을 그대로 싣는다.
`1−α` 를 적어 넣는 것은 이론값을 실측인 척하는 것이다(M1-T 규약).

### 1.5.3 ★계약 4 · 신뢰도 — 휴리스틱을 표준으로 굳히지 않는다★

#### 먼저 정정 — 상수를 잘못 옮겼다

직전 패스 문서에 `conf = 0.35 × (1−λ)` 라고 적었다. **틀렸다.** 실제 코드는:

```python
_CONDITIONAL_MAX_CONFIDENCE = 50.0                  # allocation_routes.py:407
conf = _CONDITIONAL_MAX_CONFIDENCE * (1.0 - lam)    # 0~100 스케일
```

그리고 ★`conf` 는 임의의 노브가 **아니다**★ — `build_user_views`
(`allocation_studio.py:81-93`)가 이렇게 쓴다:

```python
scale = (100.0 - conf) / max(conf, 1.0)
Ω     = diag( max(diag(P (τΣ) Pᵀ), 1e-10) · scale )     # τ = TAU_DEFAULT = 0.05
```

`conf = 50` → `scale = 1` → **`Ω = diag(P τΣ Pᵀ)` = He–Litterman 중립점**이다.
즉 현행 설계의 앵커는 원칙적이다. **검증된 적 없는 것은 `(1−λ)` 곱**이고, 내가
덧붙이려던 `× sharpness` 는 그 위에 **두 번째 미검증 휴리스틱**을 얹는 일이었다.

#### 결정 — 스칼라를 쓰지 않고 Ω 를 분해해 계산한다

Ω 는 **뷰 오차의 공분산**이라는 정해진 의미가 있다. 그러면 추측할 것이 아니라
구성할 수 있다:

```
Ω_kk  =  Pₖ D Pₖᵀ           ← 국면 불확실성   ★이미 계산된다 — A_h 의 재료★
      +  Pₖ Σ̂_μ Pₖᵀ         ← μ̂ 추정오차      Σ̂_μ ≈ Σ_within × (12 / n_months)
      +  Pₖ Ξ Pₖᵀ            ← 잔여 모델리스크  워크포워드 실측, 초기 0
```

★독립 관측은 영업일이 아니라 **개월**이다★ — `conditional_moments` 가 `n_obs` 와
`n_months` 를 **따로** 내는 이유가 그것이고(한 달의 21영업일은 국면 라벨 하나를
공유한다), 여기서 쓰는 것은 `n_months` 다.

**분해가 낳는 신뢰도** — 3자산 fixture, `D` 는 §1.8 의 `π̄` 기준,
`conf = 100/(1+scale)`, `scale = Ω/base`, `base = τ·Σ_ii` (τ=0.05):

| `n_months` | Ω(KOSPI) | He–Litterman base | scale | **conf(KOSPI)** |
|---|---|---|---|---|
| 15 | 0.02518 | 0.00128 | 19.7 | **4.84** |
| 32 | 0.01430 | 0.00128 | 11.2 | **8.22** |
| 60 | 0.00982 | 0.00128 | 7.7 | **11.53** |

현행·제안 휴리스틱과 비교:

| 설정 | conf |
|---|---|
| **현행 프로덕션** `50×(1−λ)`, λ=0.2 | **40.00** |
| 내가 덧붙이려던 `× sharpness(0.206)` | 8.24 |
| ★**분해 계산**★ (n_months=32) | **8.22** |

★`n_months` 가 신뢰도를 움직인다는 점이 분해의 핵심이다★ — 15개월이면 4.84,
60개월이면 11.53. 스칼라 휴리스틱은 표본이 네 배가 되어도 **같은 값을 낸다**
(테스트 T20 이 그것을 잡는다).

★현행 프로덕션은 계산된 뷰 오차분산이 정당화하는 것보다 **약 5배 확신한다**
(40.00 vs 8.22).★

그리고 `× sharpness` 는 우연히 비슷한 값에 떨어지지만 **이유가 다르다** — 실제 Ω 의
대부분은 국면 엔트로피가 아니라 **μ̂ 추정오차**다. 우연히 맞는 숫자를 표준으로 굳히면
**표본이 늘어 추정오차가 줄어도 신뢰도가 따라 오르지 않는다**(테스트 T20 이 그것을 잡는다).

#### 규약

- 응답에 `confidence_model` 을 싣고 **세 항의 기여도를 각각** 낸다:
  ```
  {"kind": "decomposed_omega", "version": 1,
   "terms": {"regime": …, "estimation": …, "residual": …},
   "residual_risk": "unmeasured" | "measured",
   "n_months": …, "implied_confidence": …}
  ```
  어느 항이 뷰를 죽이고 있는지 사람이 보게 한다.
- ★**`Ξ` 의 초기값은 0 이 아니다**★ (정정 — 아래 §1.5.4). 미측정이면 **보수적 하한**
  `Ξ_kk = max((P D Pᵀ)_kk, (P Σ̂_μ Pᵀ)_kk)` 을 쓰고, MS1-b 워크포워드에서 실현 뷰
  오차 `realized_i − μ̄_i` 의 분산으로 **대체**한다. 응답은
  `residual_risk: "unmeasured"` · `residual_policy: "conservative_floor"` ·
  `residual_value` 를 함께 낸다 — "모델리스크가 0이다" 와 "아직 안 쟀다" 는 다른
  사실이고, **후자를 전자로 쓰면 안 잰 것이 확신을 높인다.**
- 기존 스칼라 경로는 `kind: "legacy_scalar"` 로 **남기되 기본값이 아니다.**
  `regime_weighting="hard"` 경로는 legacy 를 그대로 써서 **회귀 0**(T24).
- ★이 분해도 최종형이 아니다★ — `Σ̂_μ` 는 국면 라벨을 참으로 놓고 잰 조건부
  추정오차이므로 라벨 오류를 포함하지 않는다. 그 부분이 `Ξ` 로 흡수되며, 그래서
  `Ξ` 를 실측하기 전에는 **이 신뢰도 모델로 production 승격을 주장하지 않는다**
  (§8 승격기준 7번).

### 1.5.4 ★정정 — `Ξ = 0` 은 방향이 거꾸로였다★

불변식 I7 을 쓰다가 앞 패스 설계의 결함이 드러났다. `Ω = D + Σ̂_μ + Ξ` 에서
`Ξ = 0` 은 **Ω 를 작게** 만들고, `conf = 100/(1 + Ω/base)` 이므로 **신뢰도를 높인다.**

★즉 모델리스크를 재지 않을수록 뷰가 더 강해진다 — 정확히 거꾸로다.★

| `n_months` | Ω(Ξ=0) | conf(Ξ=0) | Ω(보수적 하한) | **conf(하한)** |
|---|---|---|---|---|
| 15 | 0.02518 | 4.84 | 0.04566 | **2.73** |
| 32 | 0.01430 | 8.22 | 0.02390 | **5.08** |
| 60 | 0.00982 | 11.53 | 0.01494 | **7.89** |
| 120 | 0.00726 | 14.99 | 0.01196 | **9.67** |

**하한의 근거를 가정으로 명시한다**: *모델리스크(국면 라벨 오류 · 분류체계 오설정 ·
구조변화)가 우리가 실제로 잰 항들 중 가장 큰 것보다 작을 이유가 없다.*
★추정이 아니라 **선언된 보수적 가정**★ 이며, `residual_policy` 필드가 그렇게 말한다.

★n=120 에서 하한이 `Σ̂_μ`(0.00256) 대신 `D`(0.0047) 로 넘어간다★ — 표본이 아무리
늘어도 잔여 리스크가 0으로 수렴하지 않는다는 뜻이고, 그것이 옳은 성질이다(T22b).

앞의 §1.5.3 표(4.84 / 8.22 / 11.53)는 **`Ξ=0` 기준의 상한**이므로, 실제 적용되는
값은 이 절의 오른쪽 열(2.73 / 5.08 / 7.89)이다. 두 표를 함께 남기는 이유는
**T22 가 정확히 그 차이를 잡기 때문**이다.

### 1.6 ★PIT — 완전한 빈티지 시스템 없이 look-ahead-free 가 가능한가★

**가능하다.** 단, 세 속성을 **분리해서** 이름 붙여야 한다:

| 속성 | 뜻 | 지금 | 빈티지 필요? |
|---|---|---|---|
| `look_ahead_free` | t 이후 관측이 계산에 안 들어감 | ✅ **이미 참** | ❌ |
| `publication_lag_honored` | t 시점에 실제로 공표돼 있었는가 | ❌ 미모델 | ❌ 정적 시프트로 근사 |
| `revision_free` | t 시점에 공표된 **값**인가 | ❌ 불가능 | ✅ — **ECOS 미제공** |

증거 (전부 코드 확인):

```python
# src/engine/regime_axes.py::zscore_at — 후행 윈도우만 본다
seg = [v for v in vals[max(0, idx - window + 1):idx + 1] if v is not None]

# src/engine/regime_forecast.py::_posterior_forecast — 절단 경로로만 사후를 세운다
# src/engine/allocation_backtest.py::walk_forward — R_win 은 리밸런싱 시점 이전만
```

★결론★ MS1 의 백테스트 모드는 **빈티지 시스템 없이 look-ahead-free 로 만들 수 있다.**
불가능한 것은 revision-free 이고, 그것은 소프트웨어가 아니라 **데이터 벤더의 한계**다
(ECOS 는 ALFRED 같은 빈티지를 주지 않는다 — 오늘 받은 2010-05 산업생산은 당시 속보치가
아니라 이후 확정치다).

따라서 `revision_bias: "unmanaged"` 를 ECOS 유래 산출물에 **영구 라벨**로 붙이고,
`look_ahead_free: true` 와 **같은 필드로 뭉개지 않는다.** 셋을 불리언 하나로 합치는
순간 "PIT 통과" 가 거짓말이 된다.

#### 1.6.1 ★계약 3 · 노출 형태 — 단일 불리언 금지★

| 속성 | 응답 필드 | 값 |
|---|---|---|
| `look_ahead_free` | 불리언 | 계산에 t 이후 관측이 안 들어갔는가 |
| `publication_lag` | `"declared"` + 개월수 \| `"unspecified"` | t 시점에 공표돼 있었는가 |
| `revision_bias` | `"unmanaged"` \| `"vintage_backed"` | t 시점에 공표된 **값**인가 |

★`pit_verified` 같은 단일 필드를 만들지 않는다★ — 만드는 순간 revision bias 가
그 안에 숨는다. 응답·스냅샷·문서 어디서도 셋을 합치지 않으며, 테스트 T15 가
"그런 필드가 없음" 을 고정한다. 화면도 셋을 **세 칸으로** 그린다.

#### 1.6.2 ★MS1-b 개방 조건 — vintage 계약의 "해결" 이란★

ECOS 는 ALFRED 같은 빈티지를 **영원히 주지 않는다.** 그러므로 "해결" 은 빈티지를
구하는 것이 아니라 **명시적 정책 문서로 한계를 확정하는 것**이다 (확정된 결정):

1. `docs/specs/` 에 **ECOS revision 정책 문서**를 쓴다 — 빈티지 부재 사실 · 어느
   계열이 사후 수정되는지 · 정적 공표지연을 어떻게 선언하는지 · 그 한계를 화면에
   어떻게 노출하는지.
2. 계열별 공표지연을 **선언**한다 → `publication_lag: "declared"`.
3. 모든 MS1-b 산출물에 `revision_bias: "unmanaged"` 를 **박아서** 낸다.

★셋이 다 되기 전까지 `mode: "backtest"` 는 `available: false` + 사유다.★
그리고 열린 뒤에도 **MS1-b 는 연구 산출물(스크립트 + 보고서)이지 API 표면이 아니다** —
`/allocation/optimize` 가 백테스트 수치를 응답으로 내보내지 않는다.

★정적 공표지연은 룩어헤드를 막지 못한다★ — 오늘 받은 2010-05 산업생산은 당시
속보치가 아니라 이후 확정치이므로, 1개월 시프트를 걸어도 **값 자체가 미래를 안다.**
이것이 `publication_lag: declared` 와 `revision_bias: unmanaged` 가 **다른 필드여야
하는 이유**다.

### 1.8 수치 예시 — 하드 라벨 vs 확률 혼합 (정확식으로 재계산)

3자산 통제 fixture · **실측 `P`(4국면 Dirichlet 사후평균)** · **실측 `π_1..π_3`** ·
`h_hold = 3` · 롱온리 min-var(SLSQP):

| 팔 | KOSPI | KTB | USD | vol(자기 Σ 기준) | 회전율 vs 현행 |
|---|---|---|---|---|---|
| **A 하드 라벨 Goldilocks (현행)** | 0.1028 | 0.6618 | 0.2354 | 0.0315 | — |
| ★**E 정확식 `W_h + A_h`**★ | 0.0926 | 0.6642 | 0.2432 | 0.0356 | **0.0102** |
| L 2차명세 `W + (h/12)D` | 0.0926 | 0.6609 | 0.2465 | 0.0357 | 0.0111 |
| U 상한 `W + D` (완전지속) | 0.0930 | 0.6403 | 0.2667 | 0.0361 | **0.0313** |

★상한(U)과 정확식(E)의 회전율이 **3배** 차이난다★ — 근사 선택이 실제 거래로 이어진다.
그리고 국면 간 항 자체를 보면:

```
정확 A_h 대각 (연율)   [0.0008, 0.0000, 0.0001]
(h/12)·D    대각       [0.0012, 0.0001, 0.0002]     ← 1.5배 과대
D           대각       [0.0047, 0.0002, 0.0008]     ← 6배 과대
```

**μ 쪽이 여전히 큰 지렛대다** (단, 앞 패스보다 작아졌다 — `π̄` 가 `π_3` 보다
Goldilocks 에 더 몰리기 때문):


### 1.10 프로브 · 테스트 명세

★구현 전에 각 프로브가 **의도한 이유로** red 임을 확인한다★ — red 라는 사실만으로는
프로브가 통과가 아니다.

#### 1.10.0 ★불변식 테스트 I1~I7 — 구현이 반드시 만족해야 하는 항등식★

> 아래 일곱은 **성능 지표가 아니라 항등식**이다. 하나라도 깨지면 구현이 틀린 것이지
> "데이터가 그렇다" 가 아니다. **전부 실행해서 성립을 확인했다** — 각 항목의 수치는
> 재현 명령(감사 §11.3)에서 다시 나온다.

##### I1 · 동일국면 불변식 — 모든 국면의 μ·Σ 가 같으면 혼합은 그것으로 **정확히** 환원

```
∀r: μ_r = μ₀,  Σ_r = Σ₀   ⟹   μ̄_h/h = μ₀ ,  W_h/h = Σ₀ ,  A_h = 0
```

실측 (4국면 · 임의 `P` · 임의 `π₀`):

| h | μ̄/h | W/h | max\|A_h\| |
|---|---|---|---|
| 1 | `[0.01, −0.002]` ✅ | `[0.0025, 0.0005, 0.0005, 0.0009]` ✅ | `2.7e−20` |
| 3 | 동일 | 동일 | `8.1e−20` |
| 6 | 동일 | 동일 | `5.6e−19` |

★이 테스트가 잡는 것★ π 나 `P` 가 **잘못 곱해진 경우**. 국면 간 차이가 없으면
전이행렬이 무엇이든 결과가 흔들릴 수 없다 — 흔들리면 배선이 틀린 것이다.
허용오차는 `1e−15`(기계 정밀도), **통계적 근사가 아니다.**

##### I2 · 확정국면 불변식 — π_r = 1 이면 하드 라벨 결과와 **일치**

★정밀하게 서술해야 한다★ — `π(S_t) = e_r` 만으로는 부족하다. 홀딩 기간 전체에서
`π_j = e_r (j=1..h)` 여야 하고, 그것은 **`P[r][r] = 1`(흡수 국면)** 을 뜻한다.

| 설정 | μ̄/h | W/h | max\|A_h\| | 하드 라벨과 |
|---|---|---|---|---|
| 흡수 `P[0][0]=1`, h=1 | `[0.015, −0.002]` | `[0.0025, …]` | `0.0` | ✅ **일치** |
| 흡수 `P[0][0]=1`, h=3 | `[0.015, −0.002]` | `[0.0025, …]` | `0.0` | ✅ **일치** |
| 비흡수 `P=[[.85,.15],[.25,.75]]`, h=3 | `[0.009756, −0.000176]` | — | `5.2e−4` | ❌ 불일치(정상) |

★비흡수에서 불일치하는 것이 **버그가 아니라 요점**이다★ — 오늘 국면을 확실히 알아도
3개월 뒤는 모른다. `π₁ = [0.85, 0.15]` 이 이미 원핫이 아니다.

##### I2b · ★π_path 와 P 의 상호일관성 — 어기면 A_h 가 PSD 가 아니다★

I2 를 쓰다가 나온 것이다. `π_{j+1} = π_j · P` 가 성립하지 않는 입력을 넣으면
`A_h` 는 공분산이 아니게 되고 **음의 고유값**이 나온다:

| 입력 | A_h 고유값 | PSD |
|---|---|---|
| 일관 (`π_j = π₀P^j`) | `[0.000000, 0.000582]` | ✅ |
| 비일관 (원핫을 강제 유지) | ★`[−0.000394, 0.000004]`★ | ❌ |

★그래서 구현은 `‖π_{j+1} − π_j·P‖_∞ > 1e−9` 이면 계산하지 않고 `available: false`
로 보고한다★ — 조용히 음의 분산을 최적화기에 넘기지 않는다.

##### I3 · 전이극한 불변식 — 두 극한을 **정확히** 되찾는다

| 극한 | 조건 | A_h | 기대값 | 일치 |
|---|---|---|---|---|
| 완전지속 | `P = I` | `[0.001143, −0.000397, −0.000397, 0.000138]` | `h²·D` = 동일 | ✅ |
| 무기억 | `P` 의 모든 행 = π | `[0.000381, −0.000132, −0.000132, 0.000046]` | `h·D` = 동일 | ✅ |

★I3 이 I1 보다 강하다★ — I1 은 국면 간 차이가 0인 축퇴 사례라 상수를 넣어도 통과할
수 있지만, I3 은 **두 극한 사이의 보간이 옳은지**를 잡는다. 실제 `P` 에서는
`A_h = 0.000767` 로 두 값 사이에 있다(`h²D` 의 1/1.489, `hD` 의 2.01배).

##### I4 · 연율화 일관성 — 일별·월별·연율 표현이 **같은 적률**을 낸다

★단, "같은 스케일링" 의 정의가 핵심이다★ — 국면은 **월 단위로 인덱스된 상태**다.
일별로 내려가도 **한 달의 21영업일은 같은 국면 라벨을 공유**한다.

| 표현 | μ̄ | W_h | A_h |
|---|---|---|---|
| 월별 스텝 | `[0.018449, 0.003235]` | `[0.010271, −0.000232, −0.000232, 0.003508]` | `[0.000767, −0.000267, −0.000267, 0.000093]` |
| 일별 스텝(월 블록) | 동일 | 동일 | 동일 |
| **최대 절대차** | `1.0e−17` | — | `7.4e−18` |

★그리고 함정을 같은 테스트에서 죽인다★ — 국면의 **시간해상도**까지 일별로 바꾸면
국면 간 항이 대부분 지워진다. 오답은 두 종류이고, 배수는 fixture 마다 다르다:

| 잘못된 구현 | A_h 축소 배수 |
|---|---|
| 월간 `P` 를 **매일** 적용 | 11.2배 (구현 fixture) |
| 국면을 매일 **독립 재추첨** | 42.3배 (구현 fixture) · 889배 (조사 fixture) |

★배수를 테스트에 못박지 않는다★ — **배수는 fixture 의 성질이지 불변식이 아니다.**
불변식은 "월 블록 참조와 **정확히** 같고(1e−14), 일별 해상도와는 크게 다르다" 이며,
정확한 쪽이 실질적인 가드다. (초기 조사에서 889배를 일반 성질처럼 적었는데,
구현 fixture 에서 11.2/42.3 이 나와 **fixture 의존값임이 드러났다.**)

즉 "일별 혼합" 자체가 틀린 것이 **아니라**, 일별로 내려가면서 **국면의 시간
해상도까지 일별로 바꾼 것**이 틀린 것이다. 테스트는 **둘을 갈라야** 한다 —
앞의 것은 통과, 뒤의 것은 실패.

##### I5 · 확률출처 가드 — 구조적으로 막는다

★"규약" 이 아니라 **함수 시그니처와 검증**으로 막는다.★

```

    prob.usage != "portfolio"  →  ValueError / available:false   (조용한 통과 금지)
```

- `quadrant_probs`(축 filtered) · `_markov_probs`(Markov filtered) ·
  `smoothed_marginal_probabilities` 는 **`usage != "portfolio"`** 로만 만들어진다.
- `k_step_forecast` 산출물만 `usage = "portfolio"` 를 받는다.
- ★이름이 아니라 값으로 거른다★ — 이름 규약(`"forecast"` 가 들어가면 OK)은
  리팩터 한 번에 조용히 깨진다.
- 배분 응답 블록 전체를 문자열로 훑어 `"smoothed"` 가 없음을 확인한다(T13).

##### I6 · PIT 상태 가드 — 3차원을 1차원으로 접지 않는다

```
응답에 pit_verified / pit_ok / is_pit 류 필드가 존재하면 실패
반드시 셋이 각각 존재:  look_ahead_free · publication_lag · revision_bias
```

셋은 **서로 독립**이고 하나가 참이라고 나머지가 참이 되지 않는다. 특히
`revision_bias` 는 ECOS 한계상 ★영구히 `"unmanaged"`★ 이므로, 합치는 순간
"PIT 통과" 라는 표시가 거짓말이 된다.

##### I7 · ★잔여 리스크 의미론 — "안 쟀다" 를 "0" 으로 쓰지 않는다★

**이 항목이 계약 4의 결함을 드러냈다.** 앞 패스에서 `Ξ`(잔여 모델리스크)의 초기값을
**0** 으로 두고 라벨만 붙이기로 했는데, `Ω = D + Σ̂_μ + Ξ` 에서 `Ξ = 0` 은
**Ω 를 작게** 만들고 그것은 **신뢰도를 높인다.**

★즉 모델리스크를 재지 않을수록 뷰가 더 강해진다 — 정확히 거꾸로다.★

| `n_months` | Ω(Ξ=0) | conf(Ξ=0) | Ω(보수적 하한) | **conf(하한)** |
|---|---|---|---|---|
| 15 | 0.02518 | 4.84 | 0.04566 | **2.73** |
| 32 | 0.01430 | 8.22 | 0.02390 | **5.08** |
| 60 | 0.00982 | 11.53 | 0.01494 | **7.89** |
| 120 | 0.00726 | 14.99 | 0.01196 | **9.67** |

**규약** — `Ξ` 가 미측정이면 **0 이 아니라 보수적 하한**을 쓴다:

```
Ξ_kk = max( (P D Pᵀ)_kk , (P Σ̂_μ Pᵀ)_kk )        when residual_risk == "unmeasured"
```

근거를 **가정으로 명시**한다: *모델리스크(국면 라벨 오류 · 분류체계 오설정 ·
구조변화)가 우리가 실제로 잰 항들 중 가장 큰 것보다 작을 이유가 없다.*
추정이 아니라 **선언된 보수적 가정**이며, 응답이 그렇게 말한다:

```
"residual_risk": "unmeasured",
"residual_policy": "conservative_floor",
"residual_value": …,          ← 실제 쓰인 값(0 이 아님을 보이게)
"residual_note": "모델리스크를 아직 측정하지 않았습니다. 0 으로 두면 안 잰 것이
                  확신을 높이므로, 측정된 항 중 최대값을 하한으로 씁니다."
```

★n=120 에서 하한이 `Σ̂_μ` 대신 `D` 로 넘어간다★(0.0047 > 0.00256) — 표본이 아무리
늘어도 잔여 리스크가 0으로 수렴하지 않는다는 뜻이고, 그것이 옳은 성질이다.

**테스트가 잡아야 하는 것**: `conf(unmeasured) < conf(Ξ=0)` 이 **엄격히** 성립.
`Ξ = 0` 대입은 통과할 수 없다.

```
CE   = mean(r_oos) − (δ/2)·var(r_oos)        δ = DELTA_DEFAULT = 2.5
```

### 3.1 실측 — 무엇이 실제로 벌어지는가

```

```

★표준화 입력 + 단위분산 요인 정규화 아래서 상관은 적재의 **상수배**다.★ 모양은

자체**라는 뜻이고, 그래서 상관이 정확히 1.0 이 나온 것이다. `explained_var = 0.0078`

**부수 결함 — 이름과 계산이 다르다.** `explained_var = 1 − var(res.resid)/var(Z)` 인데

### 3.4 무엇을 고치는가 (원인 규명 이후)

1. **적재를 이름으로 읽는다** — `res.model.param_names.index(f"loading.f{j+1}.y{i+1}")`.
   `res.params` 는 ndarray 이므로 `.get` 은 영원히 없다.
2. ★**Heywood 검출**★ — `sigma2_i ≤ ε` 인 계열이 있으면 `degenerate: true` 와
   **그 계열 이름**을 낸다. 지금은 필드 자체가 없다.
3. `explained_var` → `one_step_r2` 로 개명하고, 별도로 계열별 공통분산 비율
   `λ_i² var(f̂) / var(Z_i)` 를 낸다.
4. Bai–Ng(2002) 요인수 선택 — 지금은 `k ≤ 2` 하드코딩.
5. 결측 처리 — 지금은 **최소 길이로 절단**(가장 짧은 계열이 전체를 지배).

### 3.5 ★수정이 옳음을 증명하는 통계 검정★

**모형함의 공분산 재구성 검정** — 요인분석의 표준 적합도 검정이다:

```
‖ Λ̂ Ω̂ Λ̂ᵀ + Ψ̂ − S ‖_F  ≤  0.05 · ‖S‖_F

  Λ̂ = 보고된 적재 행렬        Ψ̂ = diag(sigma2)
  Ω̂ = cov(f̂)  (추정 요인)     S  = cov(Z)  (표준화 입력의 표본공분산)
```

적재라면 재구성이 맞고, 상관(= 적재의 상수배)이면 `Λ̂ Ω̂ Λ̂ᵀ` 가 `var(f̂)` 배만큼
틀어져 재구성이 깨진다. **순환논법이 아니다** — 독립된 표본 적률에 대고 재는다.

★그런데 이 검정은 **k=2 합성 fixture 에서만** 판별한다 — k=1 에서는 못 잡는다.★
실측으로 확인했다:

| fixture | 적재로 재구성 | 상관으로 재구성 | 판별비 |
|---|---|---|---|
| 실데이터 k=1 (표준화) | 0.6677 | 0.6763 | **1.01 — 판별 실패** |
| 합성 2요인 k=2 | **0.116** | **4.916** | **42.4 — 판별 성공** |

k=1 에서 판별되지 않는 이유가 곧 이 버그가 오래 살아남은 이유다(비례관계).
k=2 에서는 적재가 **편(partial)** 계수인 반면 상관은 **주변(marginal)** 이라
비례관계가 깨지고, 그래서 판별비가 42배로 벌어진다.

**★따라서 W-DFM 의 회귀 가드는 반드시 k=2 fixture 위에 세운다.★** k=1 에서만 재는
테스트를 쓰면 상관 폴백이 그대로 통과한다 — 등가 변이(equivalent mutant)를 만드는
셈이다.

**보조 검정 둘**
- **Heywood 검정** — 한 계열을 거의 무잡음으로 만든 fixture(`idio_sd → 0`) →
  `sigma2_i → 0` → 출력에 `degenerate: true` 와 그 계열 이름이 있어야 한다.
- **명명 검정** — 합성 fixture 에서 알려진 `λ_i² var(f) / var(Z_i)` 를 값으로 못박고,
  `one_step_r2` 는 그 값과 **다르다**는 것을 함께 못박는다(둘을 섞지 못하게).

### 3.6 왜 MS 사슬에서 뺐는가

LATENT 은 포트폴리오에 연결돼 있지 않아 **Level 4 로 잴 수 없다.** 고쳐도
"화면이 더 정직해진다" 까지다 — 중요하지만 결정가치는 0이다.

★그래서 순서가 아니라 **병렬**이다★ — MS1 의 진행을 막지 않고, MS1 의 결과에도
의존하지 않는다. 착수 시점은 사람이 정하면 되고, 그 전에 §3.3 의 1~2번(원인 규명)
만으로도 "지금 화면이 무엇을 보여주고 있는가" 에 대한 답이 나온다.

## 4. MS4 — TERM 예측 단계 (Diebold–Li 의 나머지 절반)

지금은 NS **적합만** 한다. Diebold–Li(2006) 의 요지는 β_{1,2,3} 을 **AR/VAR 로
예측**해 수익률곡선을 미래로 내미는 것이다. λ 는 전표본 1개로 고정돼 있어 이미
Diebold–Li 규약과 맞으므로, 추가할 것은 β 경로의 시계열 모형과 그 **예측 구간**이다.

벤치마크 사다리(검증 프레임워크 §3)를 지킨다 — **랜덤워크(오늘 곡선 = 내일 곡선)를
못 이기면 채택하지 않는다.** 채권 예측에서 RW 는 이기기 매우 어려운 벤치마크이고,
못 이기는 결과가 나오면 그것을 그대로 적는다.

## 8. 승격 기준 (감사 §4.5 를 계획에 못 박는다)

어떤 모델도 다음을 **전부** 만족하기 전에는 `production` 이 아니다:

1. 1차 문헌에 대응하는 구현이거나, 갈라진 지점이 문서화돼 있다.
2. 벤치마크 사다리에서 **더 단순한 것을 이긴다**(못 이기면 그 사실을 적는다).
3. PIT 로 재현 가능하다 — `as_of` 를 받고 과거 결정이 미래를 보지 않는다.
   ★단일 `pit_verified` 불리언으로 주장하지 않는다★ — `look_ahead_free` ·
   `publication_lag` · `revision_bias` 세 필드를 각각 낸다(§1.6.1).
4. **Level 4 에서 측정 가능**하다 — 포트폴리오 결정을 실제로 바꾼다.
5. 실패상태 계약(`available: false` + `reason`)을 따른다.
6. ★**실계열로 잰 결과다**★ — `probe_all()['frontier_sample']['real_share']` 가 0인
   동안 통과하는 것은 **기제 검증**이지 승격 근거가 아니다.
7. ★**신뢰도가 휴리스틱이 아니다**★ — 뷰가 최적화에 힘을 싣는 모델은
   `confidence_model.kind == "decomposed_omega"` 이고 `residual_risk == "measured"`
   여야 한다. 스칼라 곱(`50×(1−λ)`·`×sharpness`)으로는 승격하지 않는다(§1.5.3).

현재 **6번을 통과하는 모델은 0개**이고, **7번을 통과하는 모델도 0개**다(현행
조건부 뷰는 `50×(1−λ)` 스칼라다). MS1 을 포함해 이 계획의 어떤 단계도, 실계열이
붙고 `Ξ` 를 실측하기 전에는 `production` 라벨을 붙이지 않는다 — 붙이면 그것이
이 감사가 §0 에서 경계한 바로 그 오독이다.
