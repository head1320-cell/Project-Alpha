## 0. 감사가 계획을 어떻게 바꿨는가

계획을 세우기 전에 세운 가설 두 개가 **측정에서 무너졌고**, 그 결과 슬라이스가 바뀌었다.

| 처음 생각 | 측정 결과 | 계획에 미친 영향 |
|---|---|---|
| "예측 국면확률을 **만들어야** 한다" | `k_step_forecast` 가 사후예측 4000회 + 90% 신용구간으로 **이미 낸다** | 만들 것이 없다 → **연결**이 일이다 |
| "OOS 프레임워크가 아예 없다" | 국면 경로에는 **워크포워드 적중률이 이미 있다**(`regime_forecast`) | 발명이 아니라 **확장** |
| "프론티어는 torch 만 깔면 된다" | `frontier_sample: observed 60 / required 240` | torch 로 안 풀린다 → **보류** |
| "mock 이라도 결정가치는 잰다" | `real_series 0 / total 61` | 잴 수 있는 것은 **기제**뿐 → 승격 기준에 실계열 조건 |

★그래서 vNext 의 1순위는 새 모델이 아니다.★ 이미 있고, 이미 불확실성을 달고,
이미 워크포워드로 채점된 예측이 **포트폴리오에 닿지 않는 것**이 1순위 결함이다.

## 1. ★최소 수직 슬라이스★ — MS1

> **"이미 측정된 예측 국면분포로 조건부 μ/Σ 를 혼합한다. 오늘 라벨을 확률 1 로
> 취급하는 것을 그만둔다."**

### 1.1 지금 무슨 일이 벌어지는가

```python
# src/api/allocation_routes.py:673-676  (그리고 1742-1745 에 같은 코드가 한 번 더)
by_month, _dropped = regime_by_month_from_path(cond_path["points"])
current = cond_path["points"][-1].get("regime")      # ← 점 라벨 하나
cond = conditional_moments(returns, by_month, current)
```

`current` 는 **오늘 사분면 라벨**이다. 그 라벨의 표본만으로 μ/Σ 를 추정하고
`s_override` 로 최적화에 넣는다. 즉 **"3개월 뒤에도 오늘 국면일 확률 = 1"** 을
가정한다.

측정된 사실은 정반대다:

```
k=3 예측  Goldilocks 0.601 [0.409, 0.788]  Disinflation 0.169  Reflation 0.133  Stagflation 0.097
워크포워드 적중률  k=3 → 0.889, 평균 집합 크기 3.81 / 4
```

★적중률 0.889 는 좋아 보이지만 집합 크기 3.81/4 가 진실을 말한다★ — 3개월 지평에서
국면 예측은 **거의 정보가 없다.** 그런데 포트폴리오는 확률 1 로 쓴다. 이것은 모델의
결함이 아니라 **소비 방식의 결함**이다.

### 1.2 무엇을 하는가 — 혼합 적률

지평 `h` 의 예측분포 `π = {r: P(S_{t+h}=r)}` 로 국면별 `(μ_r, Σ_r)` 을 혼합한다:

```
μ̄ = Σ_r π_r · μ_r
Σ̄ = Σ_r π_r · (Σ_r + μ_r μ_rᵀ) − μ̄ μ̄ᵀ
```

★두 번째 항이 이 슬라이스의 핵심이다★ — 국면 간 **평균의 산포**가 공분산에
더해진다. 국면을 모를수록 Σ̄ 가 **커진다**. 확률을 평균내서 불확실성을 지우는 것이
아니라, 불확실성이 리스크로 **정직하게 옮겨간다**. 예측이 날카로우면(π 가 한 점에
몰리면) 현행 동작으로 **연속적으로 수렴**한다 — 그래서 회귀가 아니다.

`h = 0` 이면 π 는 오늘 라벨의 원핫이고 `μ̄ = μ_current`, `Σ̄ = Σ_current` 로
**비트 단위 현행**이다. **기본값은 h = 0** — 아무도 요청하지 않으면 오늘과 똑같이 동작한다.

### 1.3 어디를 고치는가 (예상 범위)

| 파일 | 변경 |
|---|---|
| `src/engine/conditional_market.py` | **신규** `mixture_moments(returns_df, regime_by_month, regime_probs, ...)` — 국면별 적률을 각각 구해 위 공식으로 혼합. `conditional_moments` 는 **건드리지 않는다**(원핫 호출로 같은 답) |
| `src/api/allocation_routes.py` | `req.conditional_horizon: int = 0` 추가. 0 이면 현행 경로 그대로. >0 이면 `regime_transitions(...)['forecast']['mean']` 을 π 로 써서 `mixture_moments` 호출 |
| 응답 | `conditional.horizon_months` · `conditional.regime_probs` · `conditional.coverage`(워크포워드 실측) · `conditional.effective_regimes`(π 가 실질적으로 덮는 국면 수) |

★π 를 만들어 내지 않는다★ `k_step_forecast` 가 이미 주는 `mean` 을 쓴다. 국면별
표본이 `MIN_OBS_PER_ASSET` 를 못 채우는 국면은 π 에서 **빼고 재정규화하되, 뺐다는
사실을 응답에 적는다**(조용한 폴백 금지 — 이 저장소의 기존 규약).

### 1.4 프로브 (구현 전에 red 임을 확인한다)

★red 인 것만으로 프로브가 통과가 아니다★ — 각 프로브가 **의도한 이유로** red 인지
메시지로 확인한다.

| # | 프로브 | 가드가 잡아야 하는 것 |
|---|---|---|
| P1 | `h=0` → `mixture_moments` 결과가 `conditional_moments` 와 **원소별 동일** | 기본 경로 회귀 |
| P2 | 두 국면 μ 가 다르고 π 가 (0.5, 0.5) → `trace(Σ̄) > trace(0.5Σ₁+0.5Σ₂)` | ★국면간 산포항 누락★ (이게 빠져도 평균은 맞다 — 조용히 통과할 수 있는 지점) |
| P3 | π 가 한 국면에 1.0 → 그 국면의 `conditional_moments` 와 동일 | 극한 일치 |
| P4 | 표본 부족 국면이 π 에 있으면 응답에 `dropped_regimes` 가 **비어 있지 않다** | 조용한 재정규화 |
| P5 | `h>0` 인 두 요청의 **최적 가중치가 다르다**(고정 공분산 fixture) | ★Level 4★ — 응답만 바뀌고 결정은 안 바뀌면 슬라이스가 무의미 |
| P6 | π 를 뒤집으면 μ̄ 가 반대 국면 쪽으로 움직인다 | 혼합 방향 |

P2 와 P5 가 이 슬라이스의 **진짜** 가드다. P1·P3 은 회귀 방지이고, 이것만 있으면
"평균만 내는" 구현이 전부 통과한다. 검증 프레임워크 §2 의 4단 평가 중
**Level 4(결정가치)** 에 해당하는 것은 **P5 하나뿐**이므로 이것을 빼지 않는다.

### 1.5 값을 못 박는 방식

★날짜 의존 fixture 금지★ — 직전 슬라이스에서 mock 상관이 날이 바뀌며 0.094 로
떨어져 가드가 깨진 적이 있다. MS1 의 P2·P3·P5 는 **통제된 공분산 fixture**로
만든다(합성 수익률 2자산, 국면별 μ/Σ 를 손으로 지정). 실계열 mock 은 P1(동일성)에만
쓴다 — 동일성은 값에 의존하지 않는다.

### 1.6 완료 조건

- 프로브 6종 green, 기존 2,758건 유지, `ruff` clean.
- `/allocation/optimize` 가 `conditional_horizon` 없이 호출되면 **응답 바이트 동일**.
- 응답이 `coverage`(실측 적중률)를 **함께** 낸다 — 사용자가 "이 예측이 얼마나
  날카로운가" 를 보지 않고 비중을 움직이지 못하게 한다.

## 2. MS2 — 매크로 모델에 `as_of` 관통 (PIT)

감사 §4: `grep -n "as_of" src/engine/macro_models/*.py` → **0건**. `load_series` 는
`collect_all(use_cache=True)` 를 부른다 — 절단일 개념이 없다.

★오늘 팩터 스택에서 검증된 패턴을 그대로 쓴다★ (`factor_exposure.resolve_proxies`
가 `as_of` / `as_of_honored` 를 함께 내는 방식):

1. `load_series(keys, months, *, as_of=None)` — `as_of` 가 있으면 그 달 이후를 절단.
2. 각 스튜디오가 `as_of` 를 받아 그대로 넘기고, 출력에 **`as_of` 와 `as_of_honored`**
   를 적는다. 계열이 절단을 지원하지 못하면 `honored=False` 로 **정직하게 표시**한다.
3. `pit_macro.ResearchUsage` 와 연결 — `backtest_eligible` 이 아닌 계열이 섞이면
   그 사실이 응답에 남는다.

★기본값은 현행 동작★(`as_of=None`). 프로브: 같은 `as_of` 로 두 번 호출하면 같은 답이고,
`as_of` 를 과거로 밀면 `span.last` 가 따라 움직인다(움직이지 않으면 절단이 안 된 것이다).

★ECOS revision bias 라벨은 여기서 강제한다★ — 이전 피드백에서 지적된 대로, 정적
공표지연 선언은 룩어헤드를 막지 못한다. ECOS 는 빈티지를 주지 않으므로 `as_of` 로
잘라도 **값 자체가 사후 수정본**이다. `as_of_honored=True` 여도
`revision_bias="unmanaged"` 를 함께 내야 하며, 이 둘을 같은 필드로 뭉개면 안 된다.

## 3. MS3 — LATENT redesign (`loadings` 가 적재가 아니다)

감사 §5.1: `res.params` 가 `ndarray` 라 `hasattr(res.params, "get")` 이 **항상 False**
→ 상관 폴백이 **100% 발동**하고, 출력에는 그 사실이 **어디에도 없다**.
(`KR_3Y` 적재가 정확히 `1.0`, `explained_var = 0.0078`.)

1. 필드명을 사실대로 — `loadings` → `factor_correlation`, 그리고 실제 적재를 쓸 수
   있으면 `loadings` 를 **별도로** 낸다. 어느 경로였는지 `method` 로 표시.
2. `explained_var 0.78%` 를 화면이 "요인이 설명한다" 로 읽지 못하게 응답에 경고.
3. Bai–Ng(2002) 요인수 선택 — 지금은 `k ≤ 2` 하드코딩.
4. 결측 처리 — 지금은 **최소 길이로 절단**(가장 짧은 계열이 전체를 지배).

★MS1 보다 뒤인 이유★ LATENT 은 포트폴리오에 연결돼 있지 않아 Level 4 로 잴 수 없다.
고쳐도 "화면이 더 정직해진다" 까지다 — 중요하지만 결정가치는 0이다.

## 4. MS4 — TERM 예측 단계 (Diebold–Li 의 나머지 절반)

지금은 NS **적합만** 한다. Diebold–Li(2006) 의 요지는 β_{1,2,3} 을 **AR/VAR 로
예측**해 수익률곡선을 미래로 내미는 것이다. λ 는 전표본 1개로 고정돼 있어 이미
Diebold–Li 규약과 맞으므로, 추가할 것은 β 경로의 시계열 모형과 그 **예측 구간**이다.

벤치마크 사다리(검증 프레임워크 §3)를 지킨다 — **랜덤워크(오늘 곡선 = 내일 곡선)를
못 이기면 채택하지 않는다.** 채권 예측에서 RW 는 이기기 매우 어려운 벤치마크이고,
못 이기는 결과가 나오면 그것을 그대로 적는다.

## 8. 승격 기준 (감사 §4.5 를 계획에 못 박는다)

어떤 모델도 다음을 **전부** 만족하기 전에는 `production` 이 아니다:

1. 1차 문헌에 대응하는 구현이거나, 갈라진 지점이 문서화돼 있다.
2. 벤치마크 사다리에서 **더 단순한 것을 이긴다**(못 이기면 그 사실을 적는다).
3. PIT 로 재현 가능하다 — `as_of` 를 받고 과거 결정이 미래를 보지 않는다.
4. **Level 4 에서 측정 가능**하다 — 포트폴리오 결정을 실제로 바꾼다.
5. 실패상태 계약(`available: false` + `reason`)을 따른다.
6. ★**실계열로 잰 결과다**★ — `probe_all()['frontier_sample']['real_share']` 가 0인
   동안 통과하는 것은 **기제 검증**이지 승격 근거가 아니다.

현재 6번을 통과하는 모델은 **0개**다. MS1 을 포함해 이 계획의 어떤 단계도, 실계열이
붙기 전에는 `production` 라벨을 붙이지 않는다 — 붙이면 그것이 이 감사가 §0 에서
경계한 바로 그 오독이다.
