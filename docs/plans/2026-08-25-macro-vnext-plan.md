## 0. 감사가 계획을 어떻게 바꿨는가

계획을 세우기 전에 세운 가설 두 개가 **측정에서 무너졌고**, 그 결과 슬라이스가 바뀌었다.

| 처음 생각 | 측정 결과 | 계획에 미친 영향 |
|---|---|---|
| "예측 국면확률을 **만들어야** 한다" | `k_step_forecast` 가 사후예측 4000회 + 90% 신용구간으로 **이미 낸다** | 만들 것이 없다 → **연결**이 일이다 |
| "OOS 프레임워크가 아예 없다" | 국면 경로에는 **워크포워드 적중률이 이미 있다**(`regime_forecast`) | 발명이 아니라 **확장** |
| "프론티어는 torch 만 깔면 된다" | `frontier_sample: observed 60 / required 240` | torch 로 안 풀린다 → **보류** |
| "mock 이라도 결정가치는 잰다" | `real_series 0 / total 61` | 잴 수 있는 것은 **기제**뿐 → 승격 기준에 실계열 조건 |

★그래서 vNext 의 1순위는 새 모델이 아니다.★ 이미 있고, 이미 불확실성을 달고,
이미 워크포워드로 채점된 예측이 **포트폴리오에 닿지 않는 것**이 1순위 결함이다.

### 0.1 ★2차 설계 패스가 계획을 또 바꿨다★ (2026-08-25, MS1 한정 심층)

구현 전 MS1 심층 설계를 돌렸더니 **이번엔 내 MS1 명세 자체가 두 군데 틀렸다.**

## 1. ★최소 수직 슬라이스★ — MS1

> **"이미 측정된 예측 국면분포로 조건부 μ/Σ 를 혼합한다. 오늘 라벨을 확률 1 로
> 취급하는 것을 그만둔다."**

> ★심층 설계 패스(2026-08-25 2차)에서 이 절은 **전면 재작성**됐다.★ 1차 명세가 두

### 1.3 ★혼합 공식 — 1차 명세는 차원적으로 미정의였다★

1차 계획서는 이렇게 적었다:

> `Σ̄ = Σ_r π_r (Σ_r + μ_r μ_rᵀ) − μ̄ μ̄ᵀ`

**이 식만으로는 구현할 수 없다.** 이것은 **1기간** 전분산법칙인데, `conditional_moments`
가 내주는 μ̂·Σ̂ 는 **둘 다 연율**이다. `μμᵀ` 항은 252² 로, 공분산 항은 252 로 스케일되므로
**어느 단위로 넣느냐에 따라 답이 252배 달라진다.**

시뮬레이션으로 확인했다 (2자산 · 2국면 · 월간 적률 · 12만 경로, h=3):

| | 시뮬레이션 | 공식 |
|---|---|---|
| 국면이 h개월 **유지** | `[[0.011622, −0.000699], [−0.000699, 0.003665]]` | `h·W + h²·D` = `[[0.011523, −0.000697], [−0.000697, 0.003678]]` |
| 국면이 매기 **재추첨** | `[[0.010757, −0.000454], [−0.000454, 0.003614]]` | `h·(W + D)` = `[[0.010761, −0.000432], [−0.000432, 0.003586]]` |

국면은 **지속된다** — 실측 기대 지속기간이 2.5~5.0개월이다. 따라서 유지 케이스가 맞고,
연율로 환산하면 (`W_a = 12W_m`, `D_a = 144D_m` ⇒ `12h·D_m = (h/12)·D_a`):

```
★Σ̄_annual = W_annual + (h/12) · D_annual★        h = 리밸런싱 지평(개월)

W_annual = Σ_r π_r Σ_r,annual                                  국면 **내** — 평균
D_annual = Σ_r π_r μ_r,annual μ_r,annualᵀ − μ̄ μ̄ᵀ              국면 **간** — 산포
μ̄        = Σ_r π_r μ_r,annual
```

- 1차 명세의 식은 **`h = 12` 인 특수해**였다 — "국면 불확실성이 딱 1년 지속" 을 암묵 가정.
- 반대로 일별 단위로 계산해 ×252 하면 `h = 1/21` 이 되어 D 항이 **사실상 사라진다**
  (실측 D/W ≈ 0.002) — MS1 이 no-op 이 된다.
- ★두 오구현 모두 §1.7 의 P1·P3 을 통과한다.★ 그래서 P2b 를 새로 세운다.

**구현 규약**
- 혼합은 **연율 μ̂·Σ̂ 위에서** 하고, D 항에만 `h/12` 를 곱한다.
- `h` 는 **리밸런싱 주기에서 파생**된다(월간 1 · 분기 3). 자유 입력이 아니다.
- 응답에 `horizon_months` 와 `D_contribution_pct = tr((h/12)D) / tr(Σ̄)` 를 함께 낸다 —
  "국면 불확실성이 리스크의 몇 %인가" 를 사람이 숫자로 보게 한다.
- ★`Σ̄` 의 양정치성을 검사한다★ — `W` 는 수축된 PSD 이고 `D` 도 PSD 이므로 이론상
  합도 PSD 지만, 수치 오차로 최소고유값이 음수가 될 수 있다. 음수면 클립하지 말고
  **`available: false` 로 정직 보고**한다(CLAUDE.md 의 수치 안전 규약).

1차 명세는 π 를 `k_step_forecast` 에서만 가져온다고 적었다. **불완전했다** — 같은
4국면 분류체계 위에 확률 객체가 **이미 셋** 있고, 오늘 실측값이 전부 다르다:

|---|---|---|---|---|
| 1 | 축 확률 | `regime_axes.quadrant_probs(g, i, se_g, se_i)` ← `regime_ensemble._axis_probs` | **0.535** | 오늘 축 z 와 **그 표준오차**로 만든 사분면 확률 — 사실상 filtered |

### 1.5 세 확률의 명시적 계약

★**확정된 설계 결정**: 포트폴리오를 움직이는 π 는 `regime_prob_forecast(h)` **하나**다.★
라이브와 백테스트가 **같은 추정량**을 써야 두 모드의 수치가 직접 비교된다.

| 이름 | 출처 | 사용처 | 금지 |
|---|---|---|---|
| `regime_prob_forecast(h)` | `k_step_forecast(rows, current, k=h)` | ★**포트폴리오의 π — 라이브·백테스트 공통**★ | — |
| `regime_prob_now` | `quadrant_probs(g, i, se_g, se_i)` | **화면 전용** — "지금 어디인가" | 포트폴리오 배선 금지 |
| `regime_prob_markov` | `regime_ensemble._markov_probs` | **화면 전용** — 2국면이 구조적으로 0 | 포트폴리오 배선 금지 |
| `regime_prob_smoothed` | `smoothed_marginal_probabilities[t], t<T` | **없음** | ★백테스트에서 사용 금지 — look-ahead★ |

`smoothed` 는 네 번째 후보가 **아니라 금지 대상**이다. 마지막 시점에서만 filtered 와
같고(감사 §5.5 정정), 과거 경로를 `smoothed[t]` 로 만들면 look-ahead 다.

**공통 계약 필드** — 넷 다 같은 모양으로 낸다:

```
{ source, horizon_months, probs, ci90?, coverage?, sharpness, mode, n_eval? }
```

- ★`sharpness = 1 − H(π)/ln R`★ — 실측 π(k=3) 에서 **0.206**(퍼플렉서티 3.007).
  하드 라벨은 **1.0**. 예측집합 크기 3.81/4 와 같은 사실을 다른 축으로 잰 값이다.
- ★뷰 신뢰도에 sharpness 를 곱한다★:
  ```
  conf = 0.35 × (1 − λ) × sharpness
  ```
  국면을 모를수록 뷰가 약해진다. 이것이 스펙의 *"확률예측은 캘리브레이션 없이 비중을
  결정하면 안 된다"* 를 코드로 집행하는 지점이다. 하드 라벨은 `sharpness = 1` 이므로
  **현행 동작에 회귀가 없다.**
- `coverage` 는 `regime_forecast.forecast_coverage` 의 **실측**을 그대로 싣는다.
  `1−α` 를 적어 넣는 것은 이론값을 실측인 척하는 것이다(M1-T 규약).

### 1.6 ★PIT — 완전한 빈티지 시스템 없이 look-ahead-free 가 가능한가★

**가능하다.** 단, 세 속성을 **분리해서** 이름 붙여야 한다:

| 속성 | 뜻 | 지금 | 빈티지 필요? |
|---|---|---|---|
| `look_ahead_free` | t 이후 관측이 계산에 안 들어감 | ✅ **이미 참** | ❌ |
| `publication_lag_honored` | t 시점에 실제로 공표돼 있었는가 | ❌ 미모델 | ❌ 정적 시프트로 근사 |
| `revision_free` | t 시점에 공표된 **값**인가 | ❌ 불가능 | ✅ — **ECOS 미제공** |

증거 (전부 코드 확인):

```python
# src/engine/regime_axes.py::zscore_at — 후행 윈도우만 본다
seg = [v for v in vals[max(0, idx - window + 1):idx + 1] if v is not None]

# src/engine/regime_forecast.py::_posterior_forecast — 절단 경로로만 사후를 세운다
# src/engine/allocation_backtest.py::walk_forward — R_win 은 리밸런싱 시점 이전만
```

★결론★ MS1 의 백테스트 모드는 **빈티지 시스템 없이 look-ahead-free 로 만들 수 있다.**
불가능한 것은 revision-free 이고, 그것은 소프트웨어가 아니라 **데이터 벤더의 한계**다
(ECOS 는 ALFRED 같은 빈티지를 주지 않는다 — 오늘 받은 2010-05 산업생산은 당시 속보치가
아니라 이후 확정치다).

따라서 `revision_bias: "unmanaged"` 를 ECOS 유래 산출물에 **영구 라벨**로 붙이고,
`look_ahead_free: true` 와 **같은 필드로 뭉개지 않는다.** 셋을 불리언 하나로 합치는
순간 "PIT 통과" 가 거짓말이 된다.

### 1.7 ★라이브와 백테스트는 별개 모드★

| | `mode: "live"` | `mode: "backtest"` |
|---|---|---|
| 데이터 | 오늘 스냅샷 | `as_of = t` 절단 (MS2) |
| π | `regime_prob_forecast(h)` | `regime_prob_forecast(h)` — **같은 식** |
| smoothed | 마지막 시점만(= filtered) | ★금지★ |
| 라벨 | `revision_bias: unmanaged` | `revision_bias: unmanaged` + `publication_lag: declared \| unspecified` |
| 비교 | ★두 모드의 수치를 같은 차트에 섞지 않는다★ | |

MS1 은 `mode: "live"` 만 완성한다. `mode: "backtest"` 는 `as_of` 관통(MS2)이 있어야
성립하므로, MS1 응답은 백테스트 모드를 **`available: false` + 사유**로 정직하게 낸다.

## 3. MS3 — LATENT redesign (진짜 결함은 Heywood 케이스다)

> ★2차 설계 패스에서 이 절도 재작성됐다★ — 1차 진단("상관 폴백이 문제")은
> **결론이 과했다.** 아래는 파라미터를 직접 덤프해서 확인한 것이다.

### 3.1 실측 — 무엇이 실제로 벌어지는가

```
정확한 적재 (res.model.param_names 로 읽음, 실데이터 k=1):
  loading.f1.y3 (KR_3Y) = -0.966294        sigma2.y3 = 0.000000   ← ★
상관 폴백이 낸 값:
  KR_3Y = -1.0  →  부호고정 후 1.0
비율 corr/load ≈ 1.035 = 1/√var(f̂),  var(f̂) = 1.071   →  **전 계열 동일 비율**
```

★표준화 입력 + 단위분산 요인 정규화 아래서 상관은 적재의 **상수배**다.★ 모양은
보존되고 스케일만 틀린다 — **그래서 아무도 못 잡았다.** 감사의 *"`loadings` 에 적재가
들어간 적이 없다"* 는 문자 그대로는 맞지만, 그 자체로는 화면을 크게 왜곡하지 않는다.

**진짜 결함은 `sigma2.y3 = 0.000000` — Heywood 케이스다.**
KR_3Y 의 고유분산이 0으로 추정됐다는 것은 "공통 요인" 이 사실 **KR_3Y 한 계열 그
자체**라는 뜻이고, 그래서 상관이 정확히 1.0 이 나온 것이다. `explained_var = 0.0078`
(0.78%)이 그 자백이다. ★출력 어디에도 이 사실이 없다.★

**부수 결함 — 이름과 계산이 다르다.** `explained_var = 1 − var(res.resid)/var(Z)` 인데
`res.resid` 는 **1기 앞 예측오차**다. 이것은 분산분해가 아니라 **예측 R²** 다.
(합성 강요인 데이터에서 0.387 이 나왔다 — 요인은 강한데 값은 낮다.)

### 3.2 무엇을 고치는가

1. **적재를 이름으로 읽는다** — `res.model.param_names.index(f"loading.f{j+1}.y{i+1}")`.
   `res.params` 는 ndarray 이므로 `.get` 은 영원히 없다.
2. ★**Heywood 검출**★ — `sigma2_i ≤ ε` 인 계열이 있으면 `degenerate: true` 와
   **그 계열 이름**을 낸다. 지금은 필드 자체가 없다.
3. `explained_var` → `one_step_r2` 로 개명하고, 별도로 계열별 공통분산 비율
   `λ_i² var(f̂) / var(Z_i)` 를 낸다.
4. Bai–Ng(2002) 요인수 선택 — 지금은 `k ≤ 2` 하드코딩.
5. 결측 처리 — 지금은 **최소 길이로 절단**(가장 짧은 계열이 전체를 지배).

### 3.3 ★수정이 옳음을 증명하는 통계 검정★

**모형함의 공분산 재구성 검정** — 요인분석의 표준 적합도 검정이다:

```
‖ Λ̂ Ω̂ Λ̂ᵀ + Ψ̂ − S ‖_F  ≤  0.05 · ‖S‖_F

  Λ̂ = 보고된 적재 행렬        Ψ̂ = diag(sigma2)
  Ω̂ = cov(f̂)  (추정 요인)     S  = cov(Z)  (표준화 입력의 표본공분산)
```

적재라면 재구성이 맞고, 상관(= 적재의 상수배)이면 `Λ̂ Ω̂ Λ̂ᵀ` 가 `var(f̂)` 배만큼
틀어져 재구성이 깨진다. **순환논법이 아니다** — 독립된 표본 적률에 대고 재는다.

★그런데 이 검정은 **k=2 합성 fixture 에서만** 판별한다 — k=1 에서는 못 잡는다.★
실측으로 확인했다:

| fixture | 적재로 재구성 | 상관으로 재구성 | 판별비 |
|---|---|---|---|
| 실데이터 k=1 (표준화) | 0.6677 | 0.6763 | **1.01 — 판별 실패** |
| 합성 2요인 k=2 | **0.116** | **4.916** | **42.4 — 판별 성공** |

k=1 에서 판별되지 않는 이유가 곧 이 버그가 오래 살아남은 이유다(비례관계).
k=2 에서는 적재가 **편(partial)** 계수인 반면 상관은 **주변(marginal)** 이라
비례관계가 깨지고, 그래서 판별비가 42배로 벌어진다.

**★따라서 MS3 의 회귀 가드는 반드시 k=2 fixture 위에 세운다.★** k=1 에서만 재는
테스트를 쓰면 상관 폴백이 그대로 통과한다 — 등가 변이(equivalent mutant)를 만드는
셈이다.

**보조 검정 둘**
- **Heywood 검정** — 한 계열을 거의 무잡음으로 만든 fixture(`idio_sd → 0`) →
  `sigma2_i → 0` → 출력에 `degenerate: true` 와 그 계열 이름이 있어야 한다.
- **명명 검정** — 합성 fixture 에서 알려진 `λ_i² var(f) / var(Z_i)` 를 값으로 못박고,
  `one_step_r2` 는 그 값과 **다르다**는 것을 함께 못박는다(둘을 섞지 못하게).

### 3.4 왜 MS1 보다 뒤인가

LATENT 은 포트폴리오에 연결돼 있지 않아 Level 4 로 잴 수 없다. 고쳐도
"화면이 더 정직해진다" 까지다 — 중요하지만 결정가치는 0이다.

## 7. 순서와 그 이유

```
MS1 (조건부 μ/Σ 혼합)  ← 유일하게 Level 4 로 잴 수 있다. 새 모델 0개.
   ↓
MS2 (as_of 관통)        ← MS1 의 결정가치를 **백테스트로** 재려면 PIT 가 먼저다.
   ↓
MS3 (LATENT)  MS4 (TERM 예측)   ← 서로 독립. 결정가치 0이므로 병렬 가능.
   ↓
MS5 (검증 확장)         ← MS3·MS4 의 산출물이 있어야 채점할 것이 생긴다.
```

★MS1 → MS2 순서가 뒤집히면 안 되는 이유★ MS1 은 "지금 이 순간의 결정" 을 바꾸므로
`as_of` 없이도 의미가 있다. 반대로 MS2 는 그것을 **과거에 대해 재현**할 수 있게
만든다 — 즉 MS2 는 MS1 의 증거를 만드는 단계다. 증거를 만들 대상이 먼저 있어야 한다.

★그래서 MS1 은 두 조각으로 갈린다★ (§1.7):

```
MS1-a  mode: "live"      — 지금 결정을 바꾼다. as_of 불필요.
MS1-b  mode: "backtest"  — B0/B1/N 세 팔 평가. ★MS2 이후에만 가능★
```

MS1-a 를 먼저 내되, `mode: "backtest"` 는 **`available: false` + 사유**로 정직하게
낸다. "아직 못 한다" 를 응답이 말하게 하고, 화면이 라이브 수치를 백테스트인 척
쓰지 못하게 한다. ★§1.13 의 세 팔 평가는 MS1-b 에 속하며, 그것이 끝나기 전에는
MS1 을 "채택" 이라고 부르지 않는다.★

## 8. 승격 기준 (감사 §4.5 를 계획에 못 박는다)

어떤 모델도 다음을 **전부** 만족하기 전에는 `production` 이 아니다:

1. 1차 문헌에 대응하는 구현이거나, 갈라진 지점이 문서화돼 있다.
2. 벤치마크 사다리에서 **더 단순한 것을 이긴다**(못 이기면 그 사실을 적는다).
3. PIT 로 재현 가능하다 — `as_of` 를 받고 과거 결정이 미래를 보지 않는다.
4. **Level 4 에서 측정 가능**하다 — 포트폴리오 결정을 실제로 바꾼다.
5. 실패상태 계약(`available: false` + `reason`)을 따른다.
6. ★**실계열로 잰 결과다**★ — `probe_all()['frontier_sample']['real_share']` 가 0인
   동안 통과하는 것은 **기제 검증**이지 승격 근거가 아니다.

현재 6번을 통과하는 모델은 **0개**다. MS1 을 포함해 이 계획의 어떤 단계도, 실계열이
붙기 전에는 `production` 라벨을 붙이지 않는다 — 붙이면 그것이 이 감사가 §0 에서
경계한 바로 그 오독이다.
