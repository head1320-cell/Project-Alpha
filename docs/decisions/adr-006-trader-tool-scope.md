## 1. 무엇을 정했나

| 물음 | 결정 | 근거(사용자의 말) |
|---|---|---|

## 2. 이 결정에서 따라 나오는 것

1. **설계 원칙 — 고객이 오래 살아남게 한다.** PB 의 수익은 `거래대금 × 수수료율 × 인정률 × 고객이 남아 있는 기간`이다. 도구의 값은 마지막 항에 둔다:
   비용·증거금·손실 한도를 전략보다 먼저 보여 주고, 비용을 뺀 뒤에도 남는 것만 통과시킨다. 고객의 회전을 늘리는 장치로 설계하지 않는다(과당매매·부당권유).
2. **'도구 제공'은 제품 구조로 사실이 되게 한다** — 경계 문서의 조건 C1~C8(종목·조건은 고객이 정한다 · 템플릿은 일반 규칙 · 고객용 표면에서 AI 보조 꺼짐 · 본인 인증·본인 실행 · 체결상 우대 없음 · 고객 정보는 고객 쪽 · 비용·이해관계 먼저 · 결과에 등급).
3. **고객에게 내놓는 길은 '회사 채택·법인 제휴' 하나다**(대형사 기준). 개인이 만든 프로그램을 비공식으로 나눠 주지 않는다. 그 전까지 고객용 표면은 유통 관문 뒤에 있다.
4. **직원 본인 실계좌로 단타·파생을 검증하지 않는다**(임직원 자기매매 기준 — 대형사·업계 공통). 본인 검증은 모의투자까지다.
5. **증권사에 묶이지 않게 만든다.** 중립 인터페이스의 기준은 대형사 REST 모양이고, 소속사(교보증권)의 C/C++ 모듈은 내 PC 에서 도는 중계로 붙인다. 고객용 형태는 데스크톱 앱이다.
6. **순서는 증거 관문의 순서다**: 데이터 무결성 → 시점 정합 → 비용 → 표본외 → 모의 → 실계좌. "전부 한다"는 범위이지 순서를 건너뛴다는 뜻이 아니다.
7. **매매일지(체결 내역 분석)를 앞으로 당긴다**(도입한 '더 좋은 방법' — 2026-11-14): 전업·헤비 트레이더의 첫 물음("내 매매의 어디서 돈이 새나")에 증권사 API·시세 계약 없이 답하고, 종목을 권하지 않는 순수한 도구이며, 뒤 단계의 기준선이 된다.

## 3. 부딪히는 기존 규칙 — ★언제 고치나★ (지금은 어느 것도 고치지 않는다)

| 기존 규칙 | 어디에 적혀 있나 | 부딪히는 결정 | 고치는 시점 · 조건 |
|---|---|---|---|
| "신호는 일봉, 체결만 분봉" | `src/data/minute_bars.py` 머리말 · 인프라 로드맵 | 분봉 인트라데이 | 분봉 묶음의 설계 승인 때. ★기존 백테스트 엔진은 고치지 않는다★ — 분봉 시뮬레이터를 옆에 새로 둔다. **→ 2026-11-14 승인됨**([설계](../superpowers/specs/2026-11-14-intraday-minute-simulator-design.md)): 이 규칙은 ★기존 엔진의 규칙으로 남고★, 분봉 백테스트(`src/engine/intraday`)가 그 옆의 예외다 — 신호도 분봉으로 낸다 |
| 틱·호가 수집 · 신규 제공자 · 시계열 저장을 하지 않는다 | [인프라 로드맵](../plans/2026-09-06-quant-db-infra-roadmap.md) '하지 않을 것' | 틱/호가 스캘핑 · 미국·파생 원천 | 틱은 로드맵 7단계에서 분봉 모델의 한계를 실측한 뒤. 신규 제공자는 그 원천을 붙이는 묶음마다 [권리 대장](../specs/2026-11-14-data-rights-ledger.md)에 먼저 한 줄 |
| "KIS 연동은 `get_kis_client()` 단일 경로" | CLAUDE.md §6 | 증권사 중립 · 소속사 연결 | 로드맵 5단계의 설계 승인 때 — '증권사를 고르는 단일 경로'로 넓힌다(단일 경로라는 성질은 지킨다) |
| "유통 표면은 인가 선언 전에 열리지 않는다" | CLAUDE.md §1 · `tests/test_distribution_blocked.py` | 고객 제공 | ★고치지 않는다.★ 고객용 표면은 이 관문 뒤에 만든다 — 여는 것은 회사 채택·제휴 기록을 운영자가 선언할 때 |
| 실거래 안전(기본 `dry_run` · 6중 안전장치 · `OrderExecutor` 단일 생성 자리) | CLAUDE.md §6 | 자동 주문 전부 | ★고치지 않는다.★ 새 실행 경로도 전부 이 안을 지난다 |
| 스크리너 3-레이어 · `ValuationScreener` · 기존 백테스트 엔진은 리팩터링 대상이 아니다 | CLAUDE.md §6 | 인트라데이 종목 선정·검증 | ★고치지 않는다.★ 재사용하거나 옆에 둔다 |

## 4. 하지 않기로 한 것 (이 결정 안에서)

- 종목을 골라 주거나 순위로 권하는 고객용 기능 · 고객별 설정값을 넣어 주는 일 · 고객 계좌에서 PB 가 대신 실행하는 일(일임).
- 헤비 트레이더에게 주문 처리상의 이점을 주는 일(ELW 스캘퍼 사건의 금지선).
- HTS 화면 조작(매크로).
- 권리를 모르는 원천을 고객 제공 경로에 쓰는 일.
- 합성 백테스트를 수익의 증거로 내보이는 일.

## 5. 이 결정이 주장하지 않는 것

- 대형사 기준은 ★설계의 기준이지 소속사의 답이 아니다.★ 고객에게 내놓기 전에는 소속사의 확인이 필요하다(질문지의 '소속사 확인' 칸).
- 규제에 대한 읽기는 법령해석·판례의 요약과 보도에 근거한다 — 법률 자문이 아니다.
- 어느 전략이 수익을 낸다는 주장이 아니다. 이 도구가 답하는 질문은 "무엇을 어떤 순서로 확인하는가"와 "무엇이 일어났는가"다.

## 6. 다시 볼 조건

- 소속사가 고객 제공을 불허한다 → 고객용 표면을 닫아 두고 본인 검증 도구로 남긴다(§2-3).
- 소속사가 REST API 를 연다 → 중계를 걷고 어댑터만 바꾼다(§2-5).
- 비용을 뺀 뒤 남는 규칙이 하나도 없다 → 그 사실이 결과다. 더 복잡한 모델로 덮지 않는다.

## 7. 보탬 (2026-11-14) — 새 기능의 자리: 새 화면보다 기존 모듈

받은 방향: "따로 화면을 만들기보다 기존에 있는 백테스터 모듈 · 캔버스 공간 모듈에서 작업. 이전에 만든 작업과 앞으로 만들 작업도 기존 모듈 활용과 융화되는 쪽으로."

- ★새 기능은 새 메뉴·새 화면이 아니라 기존 모듈 안에 자리를 잡는다.★ 새 화면은 기존 모듈 어디에도 넣을 수 없을 때만, 까닭을 적고 만든다.
- 까닭: 메뉴가 이미 열넷이었다 · 같은 일("과거로 돌려 본다" · "내 매매를 본다")이 메뉴 둘로 갈려 있었다 · 캔버스에는 이미 종목 묶음과 백테스트 노드가 있어 따로 만든 화면은 그 흐름과 이어지지 않았다.
- 합치는 깊이는 ★자리★까지다. 엔진과 결과의 정의는 합치지 않는다 — 분봉 결과는 원 단위·고정 진입 금액이라 일봉의 수익률(%) 결과·비교에 넣으려면 계좌 자본 가정을 지어내야 한다(따로 결정할 일).

| 기능 | 처음 만든 자리 | 옮기는(두는) 자리 |
|---|---|---|
| 분봉 백테스트 | 메뉴 '분봉 백테스트' · `/intraday` | 백테스트 › 분봉 규칙(`/backtest/intraday`) + 캔버스 '백테스트' 묶음의 노드 둘(설정 → 결과 조회) |
| 매매일지 | 메뉴 '매매일지' · `/trade-journal` | 내 계좌 › 매매일지(`/my-account/journal`) |
| 분봉 적재 범위 | 분봉 화면 안 | 그 자리 + 데이터 상태 화면의 '분봉' 절 |
| (앞으로) 모의투자·관제 | 없음 | 내 계좌(주문 경로·비상 정지 위에) + 캔버스 실행 노드 |
| (앞으로) 매매일지 v2 · 백테스트↔실거래 괴리 | 없음 | 내 계좌 › 매매일지 + 백테스트 › 분봉 결과 |
| (앞으로) 자유 조건식 | 없음 | 백테스트 › 분봉 규칙의 규칙 편집(기존 조건식 편집기 재사용을 먼저 본다) |
| (앞으로) 선물·옵션 | 없음 | 백테스트의 모드 + 파생상품 계산기 |

- 캔버스에 넣을 때는 캔버스의 규칙을 따른다: 계산은 기록을 쓰지 않고(`portfolio_graph.py` 규칙 6), 기록이 남는 실행은 단추가 시작한다. 분봉은 실행마다 시행 횟수를 남겨야 하므로 ★기록되는 길 하나★(단추)만 둔다 — 캔버스에서 바로 계산하는 노드는 두지 않는다.
- 옛 주소는 새 주소로 넘긴다(끊지 않는다).
