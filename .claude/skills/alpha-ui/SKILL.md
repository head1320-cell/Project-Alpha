# Project Alpha 화면 규칙 (alpha-ui)

이 스킬은 ★요약★이다. 값과 까닭의 원천은 아래 문서와 시험이고, 어긋나면 원천이 옳다(그리고 이 파일을 고친다).

| 무엇 | 어디 |
|---|---|
| 결정(단 · 밀도 · 색 · 수와 표 · 움직임 · 장치 · 가드) | `docs/decisions/adr-007-density-tiers-visual-language.md` |
| 잰 값 · 화면별 문제 · 조각 표(U0 ~ U11) · ★수정하면 안 되는 결정 스물둘(§9)★ | `docs/superpowers/specs/2026-11-20-uiux-professionalization-design.md` |
| 클래스 이름 = E2E 계약 · `:root` 앞 네 블록 | `docs/decisions/adr-001-tailwind-shadcn-aas-migration.md` |
| 차트 경계 · 화면 문구 · 용어 | `docs/decisions/adr-004-chart-library-boundary.md` · `docs/decisions/adr-005-professional-voice.md` · `docs/specs/2026-11-11-ui-terminology.md` |
| 가드 시험 | `tests/test_frontend_style_ratchet.py`(검사기 `tests/frontend_style_scan.py`) · `tests/test_css_specificity_guard.py` · `tests/test_frontend_voice.py` |

고객은 전업투자자 · 헤비트레이더다. 이 사람들에게 가장 비싼 결함은 ★수를 거꾸로 읽는 것★이고, 그다음이 줄을 견주려고 스크롤하는 것이다. 아래 규칙은 거의 모두 이 둘에서 나온다.

## 1. 고치기 전에 — 세 가지를 먼저 정한다

1. **이 화면은 어느 단인가.** 단은 '얼마나 자주 · 얼마나 많은 줄을 견주는가'로 가른다(중요도가 아니다).

   | 단(`data-tier`) | 하는 일 | 기본 밀도 | 바탕 · 반경(절 / 행) |
   |---|---|---|---|
   | 작업 `work` | 반복해 조작하고 줄을 견준다 — 표가 중심 | 촘촘 `compact` | 한 바탕 + 1px 선 · 4 / 2px |
   | 해석 `read` | 그림과 글을 읽으며 판단한다 | 보통 `regular` | 절 + 선 · 12 / 8px |
   | 설명 `present` | 남에게 보이거나 처음 본다 | 넉넉 `comfortable` | 지금 그대로 · 20 / 12px |

   화면별 배정은 ADR 007 §2 의 표에 있다. 고객에게 보이는 화면(고객 한 장 · 공유)은 어떤 설정에서도 넉넉으로 고정한다 — 받는 사람은 밀도를 고르지 않았다.
2. **이 화면이 장치에 올라 있는가.** `frontend/src/shared/ui/density/density.ts` 의 `TIER_ROUTES` 를 읽는다. ★표에 없는 화면에는 새 토큰이 걸리지 않는다★(§3). 어느 화면이 올라 있는지는 문서가 아니라 그 표가 진실이다.
3. **무엇을 건드리지 않는가.** 설계 문서 §9 의 스물둘을 먼저 본다. 자주 걸리는 것만 적으면:
   - 있는 CSS 클래스 이름을 바꾸지 않는다(E2E 계약). 새 구조에는 새 클래스를 쓰고, 옛 클래스는 스펙이 놓을 때까지 남긴다. 겉이 같다고 있는 클래스를 ★다른 요소에 다시 쓰지도 않는다★ — 스펙의 선택자가 요소 둘을 집는다(U0-e 에서 그렇게 실패했다).
   - `globals.css` 의 `:root` 앞 네 블록은 나누거나 순서를 바꾸지 않는다. 다크 생성 구역(`BS5-GEN`)은 손으로 고치지 않는다 — 생성기가 만든다.
   - recharts 는 차트 파일 안에서만 · `<canvas>` 와 Tooltip 은 쓰지 않는다(ADR 004). 새 의존성을 들이지 않는다(표 · 가상화 라이브러리 포함 — ADR 007 결정 D5).
   - 요청의 꼴(메서드 · 경로 · 본문) · 주문 경로 · mock 게이트와 합성 표시 · 스크리너 3-레이어 · 백테스트 엔진. ★겉모습을 옮기는 일이 계산이나 요청을 바꾸면 안 된다.★
   - 한 커밋이 셸과 여러 모듈을 함께 바꾸지 않는다.

## 2. 일의 순서 (화면 조각마다)

읽기 전용 감사 → 계획(패널 결론 표) → ★바꾸기 전에 얼림★(그 화면의 골든 · 재는 스크립트의 전 값) → 시험을 먼저 쓰고 빨강을 본다 → 구현 → 변이(가드가 정말 죽이는지) → 게이트 → ★스크린샷 검수★ → `docs/HISTORY.md`(무엇을 · 왜 · 무엇을 하지 않았는지).

스크린샷 검수를 건너뛰지 않는다. 표가 제 상자를 넘치는 것 · 값 없음 칸의 줄바꿈 · 좁은 화면에서 끝 칸이 잘리는 것은 계산 스타일 시험이 모두 초록인 채로 그림에서만 보였다(U0-b).

## 3. 장치 — 끄면 지금 화면 그대로

- `html` 의 속성 둘(`data-tier` · `data-density`)이 `globals.css` 끝의 토큰 블록을 다시 정한다. 둘은 늘 함께 붙거나 함께 없다.
- 밀도를 정하는 차례: ① 표에 없는 경로 → 속성 없음 ② 고정 표시(`lock`) → 넉넉 ③ 손가락 화면(`pointer: coarse`) → 넉넉 ④ 저장값(`localStorage` 의 `alpha_density`) ⑤ 단의 기본값.
- 첫 그림 전에 도는 조각(`DENSITY_BOOT` — `app/layout.tsx`)과 맞춤 훅(`useDensitySync` — 셸)은 같은 표 · 같은 차례에서 나온다. 한쪽만 고치면 `frontend/e2e/density-logic.spec.ts` 가 격자로 잡는다.
- **화면을 단에 올릴 때**(한 커밋 안에서 함께):
  1. `TIER_ROUTES` 에 한 줄 + `density-logic.spec.ts` 의 허용 목록(줄을 더하면 그 시험이 실패하게 되어 있다).
  2. 그 화면의 규칙을 새 토큰으로 옮긴다 — 그 화면의 범위 선택자 아래에서. ★단 전체에 거는 규칙(예: `[data-tier] button:focus-visible`)을 두지 않는다★ — 속성이 `html` 에 있어 셸 크롬과 다른 화면까지 바뀐다.
  3. 그 화면의 라이트 골든만 다시 얼리고(`UPDATE_LIGHT_GOLDEN=1`), `node scripts/golden-diff.mjs --rev HEAD --expect-routes <그 경로>` 로 다른 화면이 그대로인지 건다. 출력은 커밋 메시지에 싣는다.
  4. 밀도 셋 × 두 테마에서 목표 크기 24px · 대비 · 합성 표시가 남아 있는지 그 화면의 스펙으로 건다.
- 견본: `/dev/density`(장치가 실제로 도는 자리) · `/dev/ui`(제품이 쓰는 공용 부품과 밀도 견본). 새 공용 부품은 카탈로그에 표본을 더한다. ★제품이 쓰지 않는 부품을 카탈로그에만 두지 않는다★(U0-e 에서 열셋을 걷었다).
- **사용자 전환**: `DensityPicker`(`shared/ui/density` — 자동 · 촘촘 · 보통 · 넉넉). 저장값을 쓰고(자동이면 지운다) 그 자리에서 속성을 다시 단다. 손가락 화면 · 고객 화면에서는 고르는 칸 대신 '고정합니다' 글자를, 경로 표 밖에서는 아무것도 그리지 않는다. 처음 놓인 자리는 종목 찾기의 결과 도구 줄이고 셸로 올리는 것은 U6. 토스 화면(`.tx-page`)에 놓으면 셸의 초점 색 규칙이 더 세다 — 그 화면의 범위 규칙이 잉크를 준다(종목 찾기의 `.tx-page.scr` 처럼).

## 4. 토큰 — 새 값을 짓지 않는다

| 토큰 | 촘촘 | 보통 | 넉넉 | 뜻 |
|---|---|---|---|---|
| `--tx-row-h` | 28px | 34px | 44px | 표 · 목록의 줄 높이 |
| `--tx-cell-x` | 8px | 12px | 16px | 칸의 좌우 여백 |
| `--tx-fs-table` / `--tx-fs-th` | 12 / 11px | 13 / 12px | 14 / 13px | 칸 글자 / 표 머리 글자 |
| `--tx-ctl-h` | 26px | 30px | 40px | 단추 · 입력의 높이 |
| `--tx-gap-sec` / `--tx-pad-sec` | 8 / 12px | 16 / 16px | 24 / 24px | 절 사이 / 절 안 |

- 글자 척도 11 · 12 · 13 · 14 · 16 · 18 · 22 · 28px(`--fs-*`). 본문의 바닥은 12px — 11px 은 표 머리 · 꼬리표에만.
- 간격 4 · 8 · 12 · 16 · 20 · 24 · 32px(`--sp-*`) + 촘촘한 표 안의 2 · 6px.
- 반경 2 · 4 · 8 · 12 · 20 · 999px(`--tx-r-1` ~ `--tx-r-5` · `--tx-r-pill`). 절 · 행은 `--tx-r-sec` · `--tx-r-row`(단이 정한다).
- 깊이 여섯 단 `--tx-z-*`: 바탕 0 · 붙은 것 10 · 겹친 판 20 · 떠 있는 것 30 · 시트와 대화 40 · 알림 50. (`--z-*` 는 Z-Score 색의 이름이다 — 깊이에 쓰지 않는다.)
- 중단점 480 · 640 · 900 · 1280 · 1600px. 판 배치 안의 판은 창 폭이 아니라 판 폭(컨테이너 질의)에 반응한다.
- 누르는 것은 어떤 밀도에서도 24 × 24px 이상 · 손가락 화면의 입력 글자는 16px 이상.

척도 밖의 날 값(글자 크기 · 반경 · `z-index` · hex · 중단점)을 새로 적으면 래칫이 실패한다. 이름공간은 `--tx-*` 이고 새 토큰은 파일 끝 블록에(`.dark` 짝은 바로 뒤) 더한다.

## 5. 색 — 뜻 하나에 값 하나

1. **등락색**(`--tx-up` · `--tx-down` 과 `-ink` · `-soft`)은 ★수와 그 표식에만★ — 등락률 · 손익 · 수익률 · 차이 · 봉 · 막대. 늘 부호와 함께. 한국 관례(상승 빨강 · 하락 파랑)다. 예외는 매수/매도 조작부 하나.
2. **상태색**(`--tx-danger` · `--tx-warn` · `--tx-ok`)은 ★수에 입히지 않는다★. 늘 아이콘 또는 낱말과 함께.
3. **강조는 잉크다.** 주 단추 · 켜진 메뉴 · 고른 탭은 `--tx-accent`, 초점 고리는 `--tx-focus` 2px. 파랑은 하락과 본문 속 링크(`--tx-link`)에만 남는다. 옛 강조 토큰(`--tx-cta` · `--tx-blue`)의 ★값★은 건드리지 않는다 — 옮기는 화면의 규칙만 `--tx-accent` 로 바꾼다.
4. 판정 칩 · 출처 표지는 중립 색조. **합성 표시**는 `--tx-warn` + 낱말이고 ★어떤 밀도 · 어떤 배치에서도 숨기지 않는다★.
5. 새 색을 들이지 않는다. 다크도 같은 규칙이다.

빨강이 상승과 위험에 함께 쓰이는 것은 값으로 가르지 않는다(둘 다 관례다) — 규칙 2 와 자리(알림 상자 · 띠)로 가른다. 그래서 '위험한 수를 빨갛게'는 하지 않는다: 그 수는 상승으로 읽힌다.

## 6. 수와 표

- **수**: 본문 글꼴 + `tabular-nums` · 오른쪽 맞춤 · 같은 열은 같은 소수 자리 · 단위는 머리에 · 음수는 부호 '−'. 서식은 `frontend/src/shared/lib/krFormat.ts` 를 쓴다(새 서식 함수를 짓지 않는다).
- ★값이 없으면 `N/A` + 사유★(`shared/ui/tx` 의 `Unknown`). 0 · 빈칸 · 줄표로 그리지 않는다 — '미상 ≠ 0'이고, 보이는 줄표는 문체 규칙이 막는다.
- 고정폭 글꼴은 식별자(종목 코드 · 실행 번호)에만 + 왼쪽 맞춤. 달마다 격자 · 열지도는 가운데 맞춤.
- **표**: 머리 고정 · 가로로 구를 때 첫 열 고정 · 줄은 1px 선(줄무늬 없음) · 고른 줄은 줄 전체의 바탕 · 이름(`caption` 또는 `aria-label`) · 정렬 머리에 `aria-sort`.
- 절보다 넓은 표는 ★절 안에서★ 가로로 민다(쪽이 밀리면 안 된다). 좁은 화면에서 끝 칸까지 닿는지 본다.
- **공용 표**(`frontend/src/shared/ui/table` · U1) — 새 표는 이것으로 그린다. 공용 표 밖에 새 `<table>` 을 그리면 래칫이 실패한다(파일 목록).
  - `DataTable` 에 열 명세(`id` · `header` · `num` · `sortable` · `sticky` · `width` · `fill` · `cell`)와 줄 · `rowKey` 를 건넨다. ★상태(정렬 · 쪽 · 고른 줄)는 부르는 쪽이 든다★ — 부품은 그리기와 자판만 맡는다. 표 이름은 `label`, 값 없음의 사유는 `note`(표의 설명으로 이어진다), 옛 E2E 갈고리는 `className` · `wrapClassName` · `rowClassName` 으로 같은 요소에 남긴다.
  - 자판: 줄 하나만 탭 순서 + ↑ ↓ Home End PageUp PageDown · Enter/Space 로 고른다. 옆 판이 열린 동안 고른 줄이 초점을 따라가게 하려면 `followFocus`.
  - 순수 규칙(`table.ts` — 브라우저 없이 시험한다): `sortRows`(★값 없는 줄은 어느 방향에서도 끝★ · 같은 값은 들어온 순서) · `nextSort` · `restoreSort`(저장한 정렬은 지금 표에 있는 열일 때만) · `pageSlice` · `toCsv`(표지 · CRLF · 값 없음은 빈칸 · 식으로 읽힐 글은 못 박는다).
  - 칸: 값 없음은 `Na`(+ 표의 `note`) · 막대는 `BarValue`(높을수록 좋은 것처럼 방향이 분명한 열에만 — 낮을수록 좋은 값의 막대는 거꾸로 읽힌다) · 쪽 넘김은 `Pager`.
  - 정렬을 바꾸면 쪽을 ★같은 손잡이에서★ 첫 쪽으로 돌린다(효과로 되돌리면 한 그림 동안 다른 쪽의 줄이 비친다).
  - 내보내기는 줄마다 출처 열을 붙이고(꼴은 `widgets/screener/screenerCsv.ts`), 그 값은 ★그 결과를 만든 요청★의 것이다 — 새 요청이 도는 동안에도 앞 결과가 보이면, 결과를 받을 때 요청을 함께 든다.
- 툴팁을 쓰지 않는다 — 새 `title=` 속성도 래칫이 센다. 뜻은 보이는 글자로 적는다.

## 7. 움직임 · 초점 · 문구

- 작업 · 해석 단: 등장 모션 · 무한 모션 · 값이 바뀐 듯한 번쩍임을 쓰지 않는다(바뀐 시각은 글자로).
- 전환은 바뀌는 속성만 150ms 이하. ★`transition: all` 을 쓰지 않는다★ — 초점 고리까지 늦춘다(잰 결함이다). 초점 고리는 전환 없이 즉시.
- 겹쳐 뜨는 것(시트 · 메뉴)만 여닫힘 150 ~ 220ms · 줄인 모션에서는 즉시.
- 접근성의 바닥: 조작 요소마다 이름(보이는 글자와 이어진 것이 먼저) · 자판 초점이 보인다 · 보이지 않는 요소가 탭 순서에 없다 · 색만으로 말하지 않는다.
- 화면 문구: 개조식 + 합니다체 · 용어집의 낱말 · 해요체와 보이는 줄표(— · –)를 쓰지 않는다. 금지 표현(검증됨 · 입증됨 · 견고함 · 투자 우위 등)은 증거가 저장소에 있을 때만.

## 8. 가드가 실패하면

| 실패 | 뜻 | 할 일 |
|---|---|---|
| 래칫의 수가 ★늘었다★ | 척도 밖 값 · `title=` · 낱 `<table>` · `transition: all` 을 새로 넣었다 | 토큰 · 공용 부품으로 바꾼다. 정말 늘려야 하면 까닭을 `docs/HISTORY.md` 에 적고 기준선을 올린다 |
| 래칫의 수가 ★줄었다★ | 위반을 걷었다 — 좋은 일인데 기준선이 낡았다 | 같은 커밋에서 기준선을 내린다(낡은 기준선은 다음 위반이 들어올 틈이다) |
| 등락색 선택자 목록이 달라졌다 | 등락색을 새 선택자에 썼거나 걷었다 | 수와 그 표식인지 본다 — 맞으면 목록을 고치고, 아니면 색을 뺀다 |
| 수 칸의 상태색(0 고정)이 실패 | 수에 위험 · 경고 · 정상 색을 입혔다 | 색을 빼고 아이콘 · 낱말을 곁에 둔다. 이 기준선은 올리지 않는다 |
| 라이트 골든(`dark-modules.spec.ts`)이 실패 | 의도하지 않은 화면이 달라졌다 | `golden-diff` 로 어느 경로 · 어느 범위인지 보고 선택자의 범위를 좁힌다. 의도한 화면만 다시 얼린다 |
| '`globals.css` 하나' 시험이 실패 | `frontend/src` 에 다른 `.css` 파일을 만들었다 — 검사기가 보지 못하는 자리다 | 규칙을 `globals.css` 로 옮긴다 |
| 다크 `--check` 가 실패 | 라이트 규칙을 고치고 생성 구역을 다시 만들지 않았다 | `node scripts/gen-dark-modules.mjs` |
| `api-no-reuse.spec.ts` 가 실패 | 새 스펙이 `@playwright/test` 를 바로 가져왔다 | `test` · `expect` 를 `./fixtures` 에서 가져온다 |

가드를 새로 쓸 때는 ★심은 위반을 세는 시험★과 ★허용된 꼴은 세지 않는 짝★을 함께 두고, 가드마다 변이를 심어 죽는지 본다(CLAUDE.md §5).

## 9. 돌리는 명령

```bash
# 저장소 뿌리 — 스타일 가드(빠르다)
KIS_USE_MOCK=1 python -m pytest -q tests/test_frontend_style_ratchet.py tests/test_css_specificity_guard.py tests/test_frontend_voice.py

# frontend 폴더 — CI 와 같은 검사
npx tsc --noEmit && npx eslint src --max-warnings=-1 && npm run lint:fsd
node scripts/gen-dark-modules.mjs --check
npm run build

# frontend 폴더 — 화면 스펙. ★E2E 는 빌드한 서버(next start)를 본다 — 소스를 고쳤으면 다시 빌드한다★
npx playwright test e2e/density.spec.ts e2e/density-logic.spec.ts e2e/dark-modules.spec.ts e2e/dev-ui.spec.ts --trace off

# frontend 폴더 — 전후를 같은 자로 잰다(읽는 법 · 한계는 scripts/ux-measure/README.md)
node scripts/ux-measure/measure.mjs <결과 폴더> '^screener$'
```

묶음의 끝에는 전체 게이트(`make all` + 전체 E2E)를 돈다. E2E 프로세스 둘을 함께 돌리지 않는다(서버와 임시 DB 를 나눠 쓴다).

## 10. 자주 밟는 것

- **특이도.** 칸 규칙이 등락색을 덮거나(견본에서 실제로 잉크로 그려졌다), 셸의 전역 초점 규칙(`.terminal-main button:focus-visible`)이 새 고리를 덮는다. 계산 스타일을 스펙으로 확인한다 — 선언을 적었다고 그려지는 것이 아니다.
- **글자로 훑는 검사의 한계.** 래칫은 인라인 `style` 속성에 적은 값 · 실행 중에 지은 클래스 이름 · Tailwind 유틸리티 값을 보지 못한다. 그쪽으로 날 값을 옮기는 것은 고친 것이 아니다.
- **실행 중에 이름을 짓는 토큰 가족**(`--cat-*` · `--pg-port-*` · `--pg-band-*` · `--itd-mr-s*` · `--mc-c-*` · `--mc-lv-*`)은 글자로 세면 쓰임 0 으로 보인다. '쓰이지 않는 토큰'을 걷기 전에 `var(--이름-${…})` 꼴을 찾는다.
- **셸 · 공용 부품은 그 화면의 스펙만으로 끝나지 않는다.** 건너뛰기 링크를 넣으며 본문에 `tabindex` 를 늘 달았더니 본문이 클릭 초점을 가로채 캔버스의 Ctrl+A 가 죽었다(관련 스펙 11개는 통과했고 CI 의 전체 E2E 가 잡았다). 셸 · `shared/ui` 를 고치면 자판 · 초점에 기대는 스펙(`canvas-*` · Tab 을 쓰는 스펙)까지 본다. ★초점을 받을 수 있는 조상을 새로 만들지 않는다★ — 꼭 필요하면 그때만 달고 뗀다.
- **재는 값은 한 번 잰 값이다.** 시간(LCP · 조작 지연)은 이 기계의 것이고 퍼짐을 재지 않았다 — 두 빌드를 견줄 때는 같은 기계에서 여러 번 잰다.

## 11. 주장의 범위

이 규칙들이 거는 것은 구조다(`structural`): 토큰과 장치가 뜻대로 돌고, 끄면 지금 화면 그대로이며, 날 값이 더 늘지 않는다는 것까지다. 화면이 읽기 쉬워졌다 · 트레이더의 일이 빨라졌다는 재지 않았다(ADR 007 §11 — 가설이다). 보고에 그렇게 적지 않는다. 투자 타당성과는 무관하다.
